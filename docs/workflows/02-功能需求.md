# 02 — 功能需求

> 版本：v1 | 阶段 2/4 | 对应 SKILL：待建 | 上游：[01-功能策划](01-功能策划.md)

## 触发条件

功能规划文档已确认，需要将其转化为可指导 AI 逐行写代码的技术规格。

## 流程定位

```
[功能规划文档] → 本阶段 → [功能需求文档]
                              ↓
                       → 阶段 3：界面交互UI
                       → GAME002-功能开发 Step 5（代码实现）
```

本阶段是**策划 → 代码**的翻译层。从"玩家看到什么"翻译成"代码需要什么"。

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 读策划文档 | 确认 AI 理解正确 | 读功能规划文档，提取所有技术相关描述 |
| 2. 模块影响分析 | 确认模块归属 | 判断触及哪些模块、是否需要新建、明确不动的模块 |
| 3. 数据定义 | 确认 CSV 结构和数值 | 梳理数据字段、判断是否需要新 CSV/Resource |
| 4. 信号契约设计 | 审核信号设计 | 设计模块间通信：谁发射、谁接收、什么参数 |
| 5. 逻辑流程 | 检查分支是否完整 | 写主流程和分支流程的步骤描述 |
| 6. 边界条件穷举 | 补充边界场景 | 穷举所有"不该发生但可能发生"的情况 |
| 7. 三层归属 + 反模式自查 | 抽查 | 检查代码分层是否合理、是否有反模式 |
| 8. 最终确认 | 逐章确认 | 修正争议点 |

## 执行步骤

### 1. 读策划文档

AI 将功能规划文档逐段翻译为技术视角：
- "界面有卡片网格" → 需要 CardList + CardItem 模板
- "点击卡片弹出面板" → 需要信号 + Panel 场景

### 2. 模块影响分析（§2）

AI 输出三个清单：
```
触及的现有模块：XXManager — 新增 X 方法 / 修改 Y 逻辑
需要新建的模块：XXPanel — 一句话职责
不需要动的模块：XX — 理由
```

### 3. 数据定义（§4）

- 列出所有涉及的数据字段：名称、类型、所在位置、操作（读/写/减）
- 判断是否需要新 CSV：如需 → 定义列名/类型/默认值
- 判断是否需要新 Resource 类

### 4. 信号契约（§5）

每个新信号写清楚：
```
信号名（发射者 → 接收者）：signal_name(param: Type)
  发射者：[模块]
  接收者：[模块]（由 GameManager 连线）
  时机：[什么情况下发射]
```

### 5. 逻辑流程（§6）

用步骤描述主流程 + 所有分支：
```
主流程：
  1. [操作] → [哪个模块的哪个方法]
  2. ...

分支：
  - 条件不满足 → 怎么处理
  - 异常情况 → 怎么处理
```

### 6-8. 后续章节

AI 继续填写 UI 表现（§7）、美术需求（§7-附）、边界条件（§8）、三层归属（§9）、反模式自查（§10）、验收标准（§11）。

> §7-附「美术与体验需求」是下游阶段 3 的**直接入口**。

## 约束与规则

- **先规划后需求**：策划文档没确认，不开始需求文档
- **不确定写"待定"**：宁可标注不确定，也不凭空猜测
- **边界条件是重点**：大多数 Bug 不是主流程错了，是边界没覆盖
- **信号契约是架构文档**：以后改代码先看信号契约，确认不会断连线
