# 状态同步

> 版本：v1 | 最后更新：2026-08-14 | 对应 SKILL：—（人工/AI 按本文档执行）

## 触发条件

- **会话开始时**：每个 AI 读完 MEMORY.md 后，快速核对「状态文档最后更新日期 vs 最近工作日志日期」
- **滞后 > 3 天** 时：执行本流程同步状态
- **任何 AI 完成跨项目/体系级产出后**：当天同步相关状态文档

## 为什么要做

2026-08-14 系统体检发现：状态文档停在 08-02，12 天产出全部未登记，`asset-pipeline/PROGRESS.md` 写「等待启动」而实际已投产。**新会话读到的项目状态是错的，决策就建立在过期信息上。** 本流程把「状态同步」从偶尔为之变成例行检查。

## 需要同步的状态文档（与锁清单一致）

| 文档 | 同步内容 | 需锁 |
|------|---------|------|
| `docs/目标规划.md` | 产品状态/进度/已完成目标 | ✅ |
| `docs/个人待办.md` | 任务增删改/归档 | ✅ |
| `memory/MEMORY.md` | 索引条目增删（含已完成项目归档） | ✅ |
| `memory/project-当前目标.md` | 季度进度/最近完成/待办 | ✅ |
| `AI_COLLABORATION.md` | 活跃项目表/身份表 | ✅ |
| `projects/*/PROGRESS.md` 或 `STATUS.md` | 项目自身阶段/进度/阻塞 | ❌ 项目文件，无需全局锁 |

## 滞后判定

1. 读 `docs/目标规划.md` 顶部「最后更新」日期
2. 读 `works/` 最近修改的日志文件日期
3. 若「最后更新」早于最近日志 3 天以上 → 判定滞后，执行同步
4. 若目标规划已更新但 `PROGRESS.md`/记忆索引未跟上 → 一并核对

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 判定滞后 | — | 读取文档日期 + 最近日志，报告滞后清单 |
| 2. 确认范围 | 确认哪些文档本次同步 | 列出待改文件与改动点 |
| 3. 取锁 | — | 按锁协议逐文件建锁（30 分钟过期） |
| 4. 更新 | — | 登记产出、改状态、刷新「最后更新」 |
| 5. 放锁 | — | 删除锁文件，确认 `.ai-locks/` 清空 |
| 6. 提交 | 确认后可提交 | 按提交规范带 `[身份标签]` 提交 |

## 执行步骤

### 1. 滞后检查（每次会话开始，1 分钟）

```bash
# 状态文档最后更新（取头部日期）
head -5 docs/目标规划.md

# 最近工作日志
ls -t works/*.md | head -3
```

### 2. 对照登记产出

- 从 `works/` 中收集上次同步日之后的所有日志
- 按类别登记：产品进度 / 已完成目标 / 系统规模 / 待办状态
- **同一主题更新已有文件，不新建**（memory 规则）

### 3. 锁协议

修改 `docs/目标规划.md`、`docs/个人待办.md`、`AI_COLLABORATION.md`、`memory/` 下文件前：
1. 检查 `.ai-locks/` 无同名锁
2. 建锁 `.ai-locks/[身份标签]-[目标文件名].lock`（含 locked_at/expires_at，30 分钟）
3. 修改完成后删除锁
4. 有锁且未过期 → 等待并报告用户

### 4. 提交规范

```
[身份标签] type: 中文描述

Co-Authored-By: AI名称 <邮箱>
```

> type 允许：feat / fix / docs / refactor / test / chore / learn / journal / assets

## 产出物

- 各状态文档更新至当天实况（含「最后更新」日期）
- `.ai-locks/` 恢复为空
- 可选：今日 `works/` 日志追加一条状态同步记录

## 约束与规则

- **只读不需要锁**
- **禁止自动解决 Git 冲突** — 保留标记报告用户
- 不确定的进度数值：宁可写「待确认」也不拍脑袋
- 状态同步 ≠ 重写目标：只更新事实，不改战略方向（战略调整需用户参与）
