## 1. 流程总览

```
人类想法
    │
    ▼
┌─────────────────┐
│ ① 功能简报      │  ← 1 份 .md，~2 页
│   确认 #1        │
└────────┬────────┘
         │
    ┌────┼────┐
    ▼    ▼    ▼
┌────┐┌────┐┌────┐
│②HTML││③资产││④程序│  ← 三线并行，AI 一口气产出
│ 原型││ 清单││ 规格│
└──┬─┘└──┬─┘└──┬─┘
   │     │     │
   ▼     ▼     ▼
┌────┐┌────┐┌────┐
│Lovart││Lovart││Godot│  ← 资产生成 + 代码实现
│ 概念图││sprite││.gd  │
└──┬─┘└──┬─┘└──┬─┘
   │     │     │
   └──┬──┴──┬──┘
      ▼     ▼
     确认 #2    视觉效果 + 代码 review
      │
      ▼
     确认 #3    Godot 运行，对照验收标准
```

**总共：1 份策划文档 + 3 次人类确认 = 功能交付。**

## 2. 阶段 1：功能简报

**作用**：定义这个功能「是什么」。AI 所有后续执行的唯一输入源。

**结构（5 节，不可多）**：

```markdown
# [功能名称] — 功能简报

## 1. 一句话 + 流程位置
- 这个功能在游戏流程图里是哪个节点？
- 前后衔接什么？

## 2. 界面与交互
- 玩家看到什么？（界面元素列表）
- 玩家能做什么？（操作 → 反馈表）
- 什么状态？（默认 / 选中 / 禁用 / 空 / 完成）

## 3. 不在范围内的
- 明确不做什么，防 AI 自行发挥

## 4. 涉及的数据
- 需要什么 CSV？新列 / 新表？
- 数据从哪来、到哪去？

## 5. 验收标准
- 操作 → 预期结果（逐条，可 yes/no 判断）
```

**不写的内容**（AI 执行阶段自行判断）：
- 模块影响分析 → AI 读了代码才知道
- 信号契约细节 → AI 设计，注释在代码头部
- 三层归属 → AI 自检
- 数值公式 → 在 CSV 里，不在简报里

**判断标准**：人类 3 分钟读完，说"方向对，开工"。

## 3. 阶段 2：三线并行产出

AI 读完功能简报后，一次性产出三样东西。

### 3.1 HTML 交互原型

**产出**：一份可打开的 HTML 文件。

**起点**：`ui-prototypes/_template.html`（预置 CSS Token + 标准骨架 + @pixso 注释）

**引用**：[开仙门-UI设计规范](../projects/GAME-002/美术制作/开仙门-UI设计规范.md) 的 CSS 变量 + [UI组件库](../projects/GAME-002/ui-prototypes/开仙门-UI组件库.html) 的组件 HTML 片段。

**一份 HTML 原型同时服务三个下游**：

| 下游 | 用法 |
|------|------|
| 人类 | 打开浏览器看效果，确认交互逻辑 |
| Lovart | Playwright 截图 → 作为概念图布局参考 |
| 程序员/AI | 写 Godot UI 代码时的视觉规格源 |

**落位**：
```
策划文档/03-功能规格/{日期}-{功能名}/{日期}-{功能名}-HTML原型.html
ui-prototypes/{功能名}.html  （同步拷贝）
```

### 3.2 四维资产清单

**产出**：一份完整资产表，嵌入在 HTML 原型目录下。

**四维覆盖**：

| 维度 | 编号 | 包含 |
|------|------|------|
| **A** 静态资产 | A1, A2, ... | 背景、卡片底板、图标、按钮、立绘、插画 |
| **V** 视觉特效 | V1, V2, ... | 选中光晕、过渡动画、粒子、HP条变色 |
| **S** 音效 | S1, S2, ... | UI点击、确认、浮现、战斗反馈 |
| **M** 动画/动效 | M1, M2, ... | 精灵表、帧动画、形态切换序列、待机循环 |

**详细模板见 [§6](#6-四维资产清单)**。

**推导逻辑**（AI 自动完成）：
```
HTML 原型里的每个元素 → 对应 A 类资产（尺寸/颜色从 CSS 提取）
HTML 原型里的每个交互 → 对应 V 类特效 + S 类音效（触发时机从交互描述提取）
策划简报里的动作描述 → 对应 M 类动画（帧规格从设计规范提取）
```

### 3.3 程序规格

**产出**：不是一份独立文档，而是写在 `.gd` 代码文件**顶部的注释块**。

```gdscript
##
## [功能简报] 选择器灵
## 简报日期：2026-07-27
##
## 模块影响：
##   修改 — main_peak_select_panel.gd (面板逻辑)
##   修改 — game_manager.gd (信号连接)
##   不动 — economy_manager, wave_manager, battle_flow
##
## 信号：
##   复用 — start_game_requested(profile_id: String) 已有
##   复用 — intro_finished 已有
##   新增 — 无
##
## 数据：
##   读 — spirit_profile_config.csv (get_all_spirit_profiles)
##   写 — main_peak.set_meta("spirit_profile", profile_id)
##
## 流程：
##   开场结束→显示面板→点击卡片→高亮+按钮启用→
##   点击开始→发射信号→set_form→切换到PREPARATION
##
## 验收对照（简报 §5）：
##   1. 开场后看到器灵选择面板  ✅
##   2. 卡片点击高亮+按钮亮起    ✅
##   3. 空选中点开始无响应        ✅
##   4. 确认后进入经营阶段        ✅
##

extends Control
class_name MainPeakSelectPanel
## ...
```

**为什么这样**：
- 人类 review 代码时一眼看到，不用翻另一份文档
- AI 写代码前先写这段注释，等于迫使自己理清思路
- 和代码一起版本管理，永远不会"文档过期"
- 意外的新会话：AI 读 `.gd` 顶部就能理解上下文

## 4. 阶段 3：资产生成

### 4.1 Lovart 概念图（基于 HTML 原型）

**流程**：
```
1. Playwright 打开 HTML 原型 → 截 1280×720 PNG
2. upload 截图到 Lovart → 获得 CDN URL
3. 附带截图 + UI色板.png + Prompt模板 → chat
4. 下载结果 → 保存到 美术制作/01-原画需求/UI/
```

**Prompt 模板**（来自 [美术绘制规范 v2 §4.9](../projects/GAME-002/美术制作/开仙门-美术绘制规范-v2.md)）：

```text
Chinese xianxia dark fantasy game UI design,
{screen_name} screen, {layout_mode} layout, 1280x720,
Use the attached reference image for exact layout structure.
Color palette: [引用 UI 设计规范色值],
Typography: title 28px, body 14px, caption 11px,
Style: dark minimalist game UI, pixel art direction,
  Chinese xianxia atmosphere, no photorealistic, no 3D rendering,
Godot engine production reference
```

**关键**：MUST 附带 HTML 截图作为 `--attachments`。纯文字 prompt 会导致布局跑偏。

### 4.2 静态资产 + 动画精灵表

- **A 类资产** → Lovart 生成单个 PNG（图标/立绘/背景）
- **M 类动画** → Lovart 生成 spritesheet（水平 stripe，N帧×W×H）
- **V 类特效** → 优先 Godot Tween/Shader 实现，复杂粒子再走 Lovart
- **S 类音效** → Lovart Audio 生成

**生产顺序**：P0 资产立即生产，P1 排入队列，P2 延后。

## 5. 阶段 4：引擎落地

### 5.1 代码实现

程序规格已写在 `.gd` 顶部注释。AI 直接按注释 + 现有代码风格实现。

**执行顺序**：
1. 先读现有代码（相关 .gd + CSV）
2. 自问：能复用吗？需要改信号吗？需要新节点吗？
3. 写代码（遵循三层架构 + 信号解耦）
4. 对照简报验收标准自测

### 5.2 落地验证

人类在 Godot 中运行，逐条过验收标准：

```
[ ] 操作A → 预期结果A
[ ] 操作B → 预期结果B
[ ] 异常操作 → 预期错误反馈（不崩溃）
```

差异记入美术体验需求文档的「引擎实现差异清单」。

### S — 音效

| # | 音效 | 触发时机 | 风格 | 优先级 | 来源 |

| # | 动画 | 帧规格 | 帧数 | FPS | 触发 | 优先级 | 来源 |

## 8. 人类确认点

流程中只设 **3 个确认点**，不多不少：

| # | 时机 | 看什么 | 决策 |
|---|------|--------|------|
| **确认 1** | 功能简报写完后 | 方向对不对、范围对不对 | 开工 / 修改简报 / 放弃 |
| **确认 2** | HTML 原型 + 资产清单 + 代码完成后 | 交互逻辑、视觉方向、代码架构 | 通过 / 修改 / 重来 |
| **确认 3** | Godot 运行后 | 对照验收标准，逐条过 | 交付 / 修 bug |
