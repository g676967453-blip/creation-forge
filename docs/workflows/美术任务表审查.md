# 美术任务表审查

> 版本：v1 | 最后更新：2026-07-29 | 对应 SKILL：`/art-review`
> 定位：主业主美工作 — 飞书美术排期表标准化审查

## 触发条件

用户说 `/art-review` 或 "审查美术表" 或 "美术排期审查" 或 "检查美术任务"。

## 这是什么

对飞书「美术排期表」执行 4 目标标准化审查，输出结构化分析报告。

设计原则：**数据在飞书，审查在本地，报告落盘存档**。不修改飞书数据，只读取分析。

## 流程总览

```
飞书项目 A/B/C/D/E 美术排期表
        │
        ▼
  lark-cli base 读取数据（+record-search / +data-query）
        │
        ▼
  ┌─────────────────────────────────────────────┐
  │  目标一：基础状况核查                          │
  │  目标二：风险逾期检查                          │
  │  目标三：信息规范性                            │
  │  目标四：综合分析报告                          │
  └─────────────────────────────────────────────┘
        │

  审查报告 .md → 主美工作/审查报告/YYYY-MM-DD-项目名.md
```

| 步骤 | 人 | AI |

## 4 审查目标

### 目标一：基础状况核查

回答三个问题：**有多少活？谁在干？什么时候交？**

| 指标 | 数据来源 | 计算方式 |
|------|---------|---------|
| 总任务量 | `全部记录` | COUNT |
| 按业务类型分布 | `业务类型` | GROUP BY 计数 + 占比 |
| 投入人力 | `执行人` | DISTINCT 人数 + 人均任务量 |
| 近30天到期 | `计划截止时间` | FILTER 30天内，按日汇总 |
| 按优先级分布 | `优先级` | GROUP BY P0-P5 计数 |
| 按进度分布 | `进度` | GROUP BY 未开始/进行中/已完成/暂停/作废 |

### 目标二：风险逾期检查

基于 `制作风险` 公式字段 + `距交付日` 字段：

| 风险等级 | 判定 | 行动 |
|---------|------|------|
| 🔴逾期 | `距交付日` < 0 且 `进度` ≠ 已完成/作废 | 立即跟进 |
| ⚠️即将逾期 | `距交付日` 0-3天 | 重点监控 |
| 🟡未排期 | 无计划开始/截止时间 | 补充排期 |
| 🟢正常 | 其余 | 常规跟踪 |

**逾期原因交叉分析**：
- 按 `业务类型` 分组看哪类逾期最多
- 按 `执行人` 看谁的任务逾期集中
- 按 `开发阶段` 看逾期集中在研发/量产/优化哪个阶段

### 目标三：信息规范性

| 检查项 | 规则 |
|--------|------|
| 必填字段空值 | `主任务`、`业务类型`、`执行人`、`计划截止时间` 不为空 |
| 逻辑一致性 | `进度=已完成` 但 `实际截止时间` 为空 → 异常 |
| 日期合理性 | `实际截止时间` ≥ `计划开始时间` |
| 优先级合理性 | P0 任务不该出现「未排期」 |
| JIRA 链接 | `业务类型` 非「团队管理/请假/其它」时建议填写 |

### 目标四：综合分析报告

每份报告包含：
1. **关键数字**：总任务 / 完成率 / 风险率 / 人力
2. **健康度排行**：各业务类型完成率排序
3. **人力负载**：人均任务量 Top 5，超标预警
4. **趋势预判**：下月到期量、瓶颈类型
5. **行动建议**：优先级排序的待办清单（最多 5 条）

## 执行步骤

### 1. 选定审查范围

向用户确认：
- 审查哪个项目？单个项目名 / "全部"
- 审查深度？快速（目标一+二）/ 标准（全部4目标）/ 深度（+命名合规检查）

### 2. 连接飞书读取数据

对每个目标项目执行：
```bash
# 获取字段结构
lark-cli base +field-list --base-token <token> --table-id <table_id> --as user

# 获取全部记录（或按条件筛选）
lark-cli base +record-list --base-token <token> --table-id <table_id> --as user --limit 500

# 聚合查询（用于统计）
lark-cli base +data-query --base-token <token> --table-id <table_id> --as user --query '...'
```

### 3. 执行 4 目标分析

对读取到的数据，按各目标的指标逐项计算和判定。

### 4. 生成并输出报告

按模板格式输出报告到 `主美工作/审查报告/YYYY-MM-DD-项目名.md`。

报告同时以对话消息形式呈现关键发现。

## 约束与规则

- **只读不写**：绝不修改飞书表格数据，审查是纯读取分析操作
- **项目独立性**：每次审查可指定单个或全部项目，报告分项目输出
- **报告存档**：`主美工作/审查报告/YYYY-MM-DD-项目名.md`
- **风险不夸大**：逾期判定以 `制作风险` 公式字段为准，不自行发明标准
- **缺失数据处理**：字段为空时标注"未填写"，不跳过不猜测
- **命名规范检查**（深度审查）：需用户提供资产文件路径，对照 `docs/specs/asset-export-and-naming-spec.md` 检查
