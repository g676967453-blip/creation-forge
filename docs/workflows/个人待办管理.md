# 个人待办管理

> 版本：v1 | 最后更新：2026-07-28 | 对应 SKILL：`/todo`

## 触发条件

- 用户说 `/todo` 或 "添加任务" 或 "记录一个待办" 或 "我有个事要做"
- 用户说 "任务列表" 或 "今天做什么" 或 "我的待办" 或 "待办有哪些"
- 用户说 "完成任务 [ID]" 或 "[ID]做完了" 或 "取消 [ID]"
- 用户说 "扫描待办" 或 "提取任务" 或 "检查有什么可以加的任务"
- 用户说 "导入 1,3,5" 或 "全部导入"（配合提取流程）
- 用户说 "归档任务" 或 "周度归档"（通常是周日或周一）

## 人机分工

| 操作 | 人 | AI |
|------|-----|-----|
| 手动添加任务 | 口述任务内容、优先级、截止日 | 推断分类 → 生成 ID → 写入表格 → 回复确认 |
| 完成任务 | 说"[ID]做完了" 或 "完成 [ID]" | 状态改为 ✅ 已完成，移到表格末尾 |
| 取消任务 | 说"取消 [ID]" | 状态改为 ❌ 已取消，移到表格末尾 |
| 查看任务 | 说"我的待办" "今天做什么" | 读取文件，按分类+优先级排序展示 |
| 扫描提取 | 说"扫描待办" "提取任务" | 扫描数据源 → 列候选清单 → 等确认 |
| 确认导入 | 说"导入 1,3" 或 "全部导入" | 生成 ID → 写入对应分类表格 |
| 周度归档 | 说"归档" | 已完成/已取消任务从活跃区移到归档区 |

## 执行步骤

### 1. 手动添加任务

用户口述任务内容时，AI：

1. **推断分类**（用户未指定时）：
   - 提到公司/外包/团队/评审 → 🏢 个人日常任务（主美工作）
   - 提到小红书/发帖/内容/选题 → 📱 小红书自媒体任务
   - 提到 GAME-002/开仙门/游戏功能/bug → 🎮 独立游戏开发任务
   - 提到 造化坊/仪表盘/工作流/CLAUDE.md/工具 → 🔧 造化坊迭代优化任务
   - 生活琐事/缴费/预约 → 🏠 日常管理任务
   - 无法推断时，向用户确认分类

2. **推断 ABC 分类**（用户未指定时）：
   - **A - 要事**：和季度项目目标直接相关、需要深度思考/创造力（编码/设计/规划）。用 255 工作法执行
   - **B - 紧急**：突发但可推迟的事、他人依赖的任务截止日临近
   - **C - 杂事**：低认知负荷的行政/整理/归档类任务。适合低能时段处理
   - 不确定时默认 A，并向用户确认

3. **推断能量需求**（用户未指定时）：
   - **高能**：需要深度专注的创造性工作（写代码/设计/策划）
   - **中能**：需要一定注意力但可并行的工作（审查/沟通/测试）
   - **低能**：机械性/重复性工作（整理/归档/报销/发票）
   - 不确定时默认中能，并向用户确认

4. **生成 ID**：读取文件，取该分类当前最大序号 + 1

5. **写入表格**：追加新行，状态默认 📋 待办，格式：
   `| {ID} | {任务} | 📋 待办 | {ABC} | {能量} | {优先级} | {截止日或—} | {备注或—} |`

6. **更新"最后更新"时间戳**

7. **回复确认**：`✅ 已添加 {ID}：{任务} → {分类名}（{ABC}类·{能量}·{优先级}）`

### 2. 完成任务 / 取消任务

1. 读取 `docs/个人待办.md`，搜索指定 ID
2. 将状态改为 ✅ 已完成 或 ❌ 已取消
3. 将该行移到该分类表格末尾（保持活跃区干净）
4. 回复确认

### 3. 列出任务

用户说 "我的待办" / "今天做什么" / "任务列表" 时：

1. 读取文件，提取所有活跃任务（非完成/非取消）
2. 按分类分组展示
3. 每个分类内按 ABC + 优先级排序（A 🔴 → A 🟡 → B 🔴 → B 🟡 → C）
4. 高亮今日到期或有截止日的任务
5. 显示汇总统计（各分类活跃数、总计）
6. **能量时段推荐**（当用户说"今天做什么"时自动触发）：
   - 🌅 上午 → 优先推荐「A 类 + 高能」任务
   - ☀️ 下午 → 优先推荐「A 类 + 中能」任务
   - 🌙 晚上 → 优先推荐「B/C 类 + 低能」任务

可选变体：
- "今天有什么" → 按当前时段推荐 + 高优任务
- "早上做什么" → 只列 A 类高能任务
- "下午做什么" → 只列 A/B 类中能任务
- "晚上做什么" → 只列 B/C 类低能任务
- "游戏开发有什么" → 只列独立游戏开发任务
- "所有任务（含已完成）" → 展示全部

### 4. 扫描提取任务（从已有数据源）

> ⚠️ **关键约束**：AI 绝不主动执行此步骤。必须等用户明确说"扫描待办"或"提取任务"。

**步骤 4a：扫描数据源**

AI 读取以下文件，提取候选任务：

| 目标分类 | 数据源 | 提取逻辑 |
|---------|--------|---------|
| 📱 小红书 | `projects/xiaohongshu/` 帖子目录 | 检查发布频率，如连续 3 天以上无新帖 → 候选"恢复小红书发布节奏" |
| 📱 小红书 | `works/` 近 7 天日志 | 有产出但未转为帖子的 → 候选"将 XXX 制作成小红书帖子" |
| 🎮 游戏开发 | `GAME-002/策划文档/05-元文档/路线图/开仙门-V0.1-任务管理表.md` | 提取「进行中」「未开始」的高优先级条目作为高层里程碑 |
| 🔧 造化坊 | `docs/workflows/改进追踪.md` | 提取状态为「进行中」的改进项 |
| 🔧 造化坊 | `tools/collect-data.ts` → `goalsIssues[]` | 提取严重度为 🟡 累积/便利性 的问题 |
| 🔧 造化坊 | `tools/collect-data.ts` → `goalsAI[]` | 提取优先级为 🔴 优先/🟡 建议 的建议 |
| 🔧 造化坊 | `works/` 近 7 天日志 | 日志中明确标记待跟进的 → 候选 |

**步骤 4b：去重过滤**

- 将候选任务与 `docs/个人待办.md` 中已有任务对比
- 已存在（任务描述高度相似）的跳过，标注 "⚠️ 已存在：{已有ID}"
- 已存在于归档区且完成时间在 2 周内的跳过

**步骤 4c：列出候选清单**

格式：

```
📋 候选任务清单（共 N 条，来源标注在右侧）

| # | 分类 | 候选任务 | 建议优先级 | 来源 |
|---|------|---------|-----------|------|
| 1 | 🎮 | 祝福3选1UI面板制作 | 🔴 高 | GAME-002 任务管理表 |
| 2 | 🔧 | 改进追踪 IMP-003 已完成待验证 | 🟡 中 | 改进追踪.md |
| 3 | 📱 | 将「器灵界面流水线跑通」制作成帖子 | 🟡 中 | works/ 近期日志 |

回复「导入 1,3」导入选中项，「全部导入」导入全部，「跳过 N」排除某项。
```

**步骤 4d：确认导入**

用户说 "导入 1,3" 或 "全部导入" 时：
1. 为每个确认的任务生成 ID
2. 写入对应分类表格
3. 回复 `✅ 已导入 N 条任务`
4. 用户可以说 "第3条放到造化坊" 覆盖 AI 的分类推断

### 5. 周度归档

1. 扫描所有 5 个分类表格
2. 将状态为 ✅ 已完成 和 ❌ 已取消 的行从活跃区移除
3. 在 "📦 周度归档" 区新增当周子标题（如 "### 第31周（07-28 ~ 08-03）"）
4. 写入归档表格：来源分类 emoji、原 ID、任务名、完成日期、耗时评估（如有）
5. 回复归档摘要：`📦 已归档：N 个已完成，M 个已取消`

## 约束与规则

- **数据唯一来源**：`docs/个人待办.md` 是任务数据的唯一存储
- **ID 不可重用**：归档后 ID 不回收，序号持续递增
- **已完成保留至归档**：完成后不立即删除，保留在活跃表格末尾，下次归档时移走
- **AI 不主动操作**：不主动添加、提取、修改任务。所有操作由用户指令触发
- **提取需确认**：扫描提取的候选清单必须经用户勾选确认后方可导入
- **仪表盘为只读视图**：仪表盘通过 `loadPersonalTasks()` 读取数据展示，不直接修改任务文件
- **保持与 GAME-002 任务板和仪表盘项目看板的独立性**：各有各的职责，不互相替代
- **Markdown 表格格式**：保持对齐，修改时重写整个分类表格确保格式一致
