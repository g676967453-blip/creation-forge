# 工作日志记录

> 版本：v1 | 最后更新：2026-07-28 | 对应 SKILL：`/write-log`

## 触发条件

- 用户说 `/write-log` 或 "记录日志" 或 "写日志" 或 "记录到日志" 或 "总结今天"
- 每天对话结束时用户要求归档当日工作

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 回顾当日 | 说"记录日志" | 回顾本次会话完成的工作 |
| 2. 整理内容 | 口述补充细节、确认标题 | 按 `works/_template.md` 结构生成日志 |
| 3. 写入 | — | 生成 `works/YYYY-MM-DD-描述.md` |
| 4. 确认 | 检查内容准确性 | — |

## 执行步骤

### 1. 回顾当日

AI 回顾本次会话中完成的工作：
- 新建/修改了哪些文件
- 解决了什么问题
- 产出了什么成果
- 关联哪个项目

### 2. 整理内容

按 `works/_template.md` 的结构组织内容：

```
# [YYYY-MM-DD] 标题

## 📋 问题解决日志
- 遇到了什么
- AI 怎么协作的
- 产出结果
- 关联项目

## 🎬 视频生产草案（三幕结构）
- 第一幕：遇到了什么问题
- 第二幕：AI 怎么协作解决的
- 第三幕：效果展示
- 一句话总结（金句候选）
- 配图/视频素材清单
```

### 3. 写入

- 文件命名：`works/YYYY-MM-DD-简短描述.md`
- 简短描述用中文，控制在 20 字以内
- 写入后告知用户文件路径

### 4. 确认

用户检查内容是否准确，可要求修改标题或补充细节。

## 产出物

| 产出 | 位置 |
|------|------|
| 工作日志 | `works/YYYY-MM-DD-描述.md` |

## 约束与规则

- **一事一记**：每个日志聚焦一个主题。多主题时拆分为多个文件
- **必须含视频草案**：即使当天不做视频，也要填写三幕结构为后续储备素材
- **关联项目明确**：标注属于造化坊基础设施 / 小红书 / GAME-002 / asset-pipeline
- **AI 不主动写**：等待用户说"记录日志"才执行，不自动创建
- **文件名唯一**：同一天同主题不重复创建
- **遵循模板**：结构以 `works/_template.md` 为准
