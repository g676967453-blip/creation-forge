# 04 — 美术资产

## 触发条件

美术需求文档已确认，需要将资产初稿转化为可执行的生产清单。

## 流程定位

```
[美术需求文档 §4 资产初稿] → 本阶段 → [资产清单]
                                        ↓
                                 ┌──────┼──────┐
                                 ▼      ▼      ▼
                             asset-   代码    Godot
                            pipeline  绘制   引擎实现
```

本阶段是**执行入口**。产出的每个资产条目都有足够信息，下游执行者（asset-pipeline / 代码 / 引擎）拿起来就能开工。

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 资产规格化 | 确认每个资产的尺寸和格式 | 逐资产填完整规格表 |
| 2. 优先级标注 | 确认 P0/P1/P2 分级 | 按功能依赖标注优先级 |
| 3. 来源标注 | 判断哪些 AI 能生成、哪些要人手画 | 分析每个资产的最佳生产方式 |
| 4. A/V/S 编号 | 确认编号体系 | 统一编号，确保可追溯 |
| 5. 最终确认 | 逐项检查 | 输出可执行清单 |

## 执行步骤

### 1. 资产规格化

从美术需求文档的资产初稿出发，逐项补全规格：

| 字段 | 说明 | 示例 |
|------|------|------|
| 资产名称 | 描述性名称 | 器灵选择背景 |
| 类型 | UI元素/图标/插图/动画帧/VFX/SFX | 全屏贴图 |
| 尺寸 | W×H px | 1280×720 |
| 格式 | PNG/PSD/精灵表/OGG/WAV | PNG |
| 色彩/风格约束 | 具体的视觉方向描述 | 深色云海，星光粒子，金色点缀 |
| 所属界面 | 关联到 UI 场景清单中的哪个界面 | SpiritSelectUi |

### 2. 优先级标注

| 优先级 | 含义 | 判断标准 |
|--------|------|---------|
| **P0** | 上线必须 | 没有它，功能完全不可用 |
| **P1** | 首版可用代码占位，正式版必须有 | 没有它功能能用但不好看 |
| **P2** | 锦上添花 | 有更好，没有也行 |

### 3. 来源标注

| 来源 | 适用场景 | 后续流程 |
|------|---------|---------|
| **AI 生成** | 图标、底板、背景图、精灵 | asset-pipeline → Lovart |
| **代码绘制** | 纯色矩形、简单边框、文字 | ColorRect/StyleBoxFlat/Label |
| **复用现有** | 已有资产可直接使用 | 引用已有文件路径 |
| **外包/手绘** | 角色立绘、关键视觉 | 手动流程 |

> AI 生成的条目必须附带 **Prompt 方向**（一句话描述给 Lovart 的 prompt）。

### 4. A/V/S 编号

统一编号，确保每个资产可被精确引用：

| 前缀 | 类型 | 示例 |
|------|------|------|
| **A** | Asset — 静态资产（UI/图标/插图/精灵表） | A1, A2, A3... |
| **V** | VFX — 视觉特效（粒子/光效/过渡） | V1, V2, V3... |
| **S** | SFX — 音效（UI音/技能音/环境音） | S1, S2, S3... |

### 5. 最终确认

人逐项检查：
- [ ] 每个资产的规格是否足够具体（AI 能生成 / 代码能写）？
- [ ] P0 有没有遗漏的？
- [ ] AI 生成条目有没有 Prompt 方向？
- [ ] 编号有没有重复/跳跃？

## 约束与规则

- **每个条目都可执行**：拿到清单的人不需要再问任何问题
- **AI 生成条目必须有 Prompt 方向**：不能只写"AI生成"，要写"生成什么"
- **编号不可跳跃**：A1-A2-A3，不要 A1-A5
- **优先级不是建议，是合约**：P0 不完成，功能不上线
