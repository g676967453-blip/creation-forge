# 创建项目

> 版本：v1 | 最后更新：2026-07-30 | 对应 SKILL：/new-project

## 触发条件

| 用户说的 | 场景 | AI 模式 |
|----------|------|---------|
| "我想做 XX" / "我有一个游戏想法" | 模糊想法阶段 | **协作者**：一起头脑风暴，帮用户把模糊想法变清晰 |
| "新建项目" / "开始一个新游戏" / "创建一个项目" | 明确意图 | **导师**：引导用户走完整流程，解释每个决策的意义 |
| "帮我快速搭一个 Phaser 项目" / "脚手架" | 明确技术选型 | **加速器**：直接执行脚手架，减少解释 |

**不适用场景：**
- 在已有项目中添加新功能 → 走 [功能开发-流水线](功能开发-流水线.md)
- 只改已有项目配置 → 直接改代码
- 临时实验/尝试 → 直接用 sandbox 分支，不需要完整项目初始化

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 确定方向 | 描述想法、目标、预期产出 | 提问引导，帮助从模糊想法中提取核心（协作者模式）。参考 4 类项目模型 |
| 2. 确定类型和技术栈 | 选择项目类型，确认技术栈 | 分析项目特征 → 归入 4 类之一 → 推荐技术栈，说明推荐理由和替代选项 |
| 3. 项目初始化 | 提供项目名称、基本参数 | 执行脚手架或手动创建目录结构（加速器模式）。复制模板、修改配置、安装依赖 |
| 4. 注册到体系 | 确认注册信息（描述、状态等） | 更新 `造化仪表盘/tools/collect-data.ts` 中的 projects[] 数组 + 变更日志 |
| 5. 创建项目 CLAUDE.md | 口述项目特有的规则和规范 | 按项目类型生成 CLAUDE.md（参考现有项目的 CLAUDE.md 结构） |
| 6. 第一份工作记录 | 口述初始想法细节、待办事项 | 生成 `造化仪表盘/works/YYYY-MM-DD-创建项目名.md`，包含初始规划 |
| 7. 同步仪表盘 | 打开 HTML 验证 | 执行 `/update-dashboard` 刷新仪表盘 |

## 执行步骤

### 步骤 1：确定方向

AI（协作者模式）提问引导：

- 你想做什么？（一句话核心）
- 做完后长什么样？（产出物形态）
- 为什么要做这个？（动机/学习目标）
- 预期多久完成？（时间尺度）
- 有没有参考或灵感来源？

AI 根据回答初步判断项目类型（不直接告知用户，带到步骤 2 确认）。

### 步骤 2：确定项目类型和技术栈

四类项目模型（对应造化坊现有体系）：

| 类型 | 特征 | 技术栈 | 现有模板 | 目录路径 |
|------|------|--------|---------|----------|
| 🎮 游戏 (game) | 可玩的交互式产品 | Phaser 3.80+ / Godot 4.x / Three.js | `templates/game-phaser/`（完整脚手架）<br>`templates/game-godot/`（占位符） | `projects/{项目名}/` |
| 📱 自媒体 (media) | 定期内容产出，有发布平台 | HTML/CSS + Puppeteer / 飞书 API | 参考 `xiaohongshu/` 结构 | `projects/{项目名}/` |
| 🔧 工具/管线 (pipeline) | 批量处理、自动化脚本、生产基础设施 | Node.js/TypeScript + 相关 API | 参考 `asset-pipeline/` 结构 | `projects/{项目名}/` |
| 📝 其他 (other) | 学习笔记、文档集、静态站点等 | 按需选择 | 无模板，手动创建 | `projects/{项目名}/` |

AI 推荐技术栈时需给出：

- **推荐理由**（1-2 句）
- **替代选项**（1 个）
- **选型风险**（如 Godot 模板是占位符，需手动搭建）

人最终拍板。

### 步骤 3：项目初始化

按类型分支：

**3a. 🎮 游戏 - Phaser（有完整脚手架）：**

```
npm run scaffold → 交互式选择 → 自动创建目录+配置+README → npm install
```

当前 `tools/scaffold-game.ts` 仅支持 Phaser + 旧 originals/sandbox 子目录结构。需确认是否直接修改脚手架使其适配当前扁平 `projects/` 结构，还是先手动创建后改造脚手架。

**3b. 🎮 游戏 - Godot：**

无脚手架，手动创建：

1. 在 `projects/` 下创建 `{项目名}/` 目录
2. 在 Godot 中创建新项目，指向该目录
3. 按 Godot 最佳实践创建初始场景（调用 `/godot-best-practices` SKILL 辅助）
4. 创建 `README.md`（参考 `templates/game-godot/README.md` 结构）

⚠️ `templates/game-godot/` 当前是占位符。创建 Godot 项目前必须告知用户这一点，由用户决定是等待模板完善还是手动搭建。

**3c. 📱 自媒体：**

无脚手架，手动创建：

1. 在 `projects/` 下创建 `{项目名}/` 目录
2. 创建 `CLAUDE.md`（核心：定义 AI 行为规范 + 内容规范 + 设计规范）
3. 创建 `_template.md`（内容模板）
4. 如需截图：创建 `_screenshot.mjs`（参考 `xiaohongshu/`）

**3d. 🔧 工具/管线：**

无脚手架，手动创建：

1. 在 `projects/` 下创建 `{项目名}/` 目录
2. 创建 `CLAUDE.md`（核心：定义 Claude 的角色 + 能做的/不能做的 + 命令速查 + 模板指南）
3. 创建 `outputs/` 或相关产出目录
4. 创建 `README.md`

**3e. 📝 其他类型：**

手动创建基本结构：`README.md` + `CLAUDE.md`

### 步骤 4：注册到体系

AI 执行以下更新（需逐一确认）：

**4a. 仪表盘数据源** `造化仪表盘/tools/collect-data.ts` — 在 `projects[]` 数组中追加新项目条目：

```ts
{ name: "{项目名}", engine: "{引擎}", status: "active", statusText: "活跃",
  progress: "初始化", output: "—", blocker: "—" }
```

**4b. 变更日志** `docs/workflows/变更日志.md` — 在当天日期下新增一条变更记录：

```
| 系统 | 新建项目 {项目名} | 新增 | 原因：用户发起新建 |
```

### 步骤 5：创建项目 CLAUDE.md

按项目类型参考现有结构：
- **游戏项目**：参考 [projects/GAME-002/CLAUDE.md](../../projects/GAME-002/CLAUDE.md)（入口级）+ 项目内详细级 CLAUDE.md
- **自媒体项目**：参考 [xiaohongshu/CLAUDE.md](../../xiaohongshu/CLAUDE.md)（含 AI 行为规则 + 设计规范 + 截图导出流程速查）
- **管线项目**：参考 [asset-pipeline/CLAUDE.md](../../asset-pipeline/CLAUDE.md)（含 Claude 角色定义 + 能/不能做的 + 命令速查 + 汇报模板）

AI 生成 CLAUDE.md 初稿，用户补充项目特有的规则。

### 步骤 6：第一份工作记录

AI 按 `造化仪表盘/works/_template.md` 结构生成：

- 文件名：`造化仪表盘/works/YYYY-MM-DD-创建{项目名}.md`
- 内容：初始想法 → 项目类型和技术栈选择 → 初始化过程 → 下一步待办

### 步骤 7：同步仪表盘

执行 `/update-dashboard`，用户打开 `造化仪表盘/reports/造化坊仪表盘.html` 验证新项目出现在「项目状态」页签。

## 约束与规则

- **先问后建**：AI 不根据一句话直接创建项目，必须先走完"确定方向 → 确定类型"两个步骤
- **工具优先于手动**：如果存在脚手架工具（当前仅 Phaser），优先使用；不存在时手动创建并记录"该类型缺少脚手架"到 [改进追踪](改进追踪.md)
- **必须注册**：创建项目后必须更新 `造化仪表盘/tools/collect-data.ts`，不允许"项目做了但仪表盘看不到"
- **必须写 CLAUDE.md**：每个项目必须有自己的 CLAUDE.md，不给 AI 留下"项目规则空白"
- **必须写入 `projects/`**：所有项目必须在 `projects/` 层，不允许在根目录或其他位置创建项目
- **必须创建工作记录**：第一份工作记录不仅是日志，也是对初始规划的存档，方便后续复盘
- **Godot 模板警告**：`templates/game-godot/` 当前是占位符。创建 Godot 项目前明确告知
- **命名规范**：项目目录名使用 kebab-case（如 `my-game`），中文展示名在仪表盘中配置
- **不破坏现有项目**：创建新项目不触及 `projects/GAME-002/`、`xiaohongshu/`、`asset-pipeline/` 的现有文件
