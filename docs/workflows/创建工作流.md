# 创建工作流（元工作流）

> 版本：v1 | 最后更新：2026-07-30 | 对应 SKILL：/new-workflow

## 流程定位

```
此事常有 → 此物可教 → 此文可循
  ↓            ↓            ↓
发现重复    提炼为标准   创建文档+SKILL
```

这是造化坊工作流体系的**自举机制**——用工作流来定义工作流自身。这也是整个体系自我生长的引擎：每一个新工作流都让下一次"创建工作流"变得更快。

## 触发条件

| 触发器 | 说明 | AI 模式 |
|--------|------|---------|
| 发现重复性工作模式 | 用户发现"每次做 X 都差不多"，或 AI 在执行中识别到模式 | **导师**：引导用户说出模式的核心步骤 |
| 收到新需求 | 用户说"这个流程能不能像小红书写帖子一样标准化" | **导师**：分析需求 → 匹配合适的抽象层级 |
| 明确指令 | 用户说"建立一个新工作流" / "标准化这个流程" / `/new-workflow` | **协作者**：一起梳理流程，用户提供业务知识，AI 负责格式化 |
| 周度复盘发现 | 在改进追踪或复盘中发现"某类事情缺少标准流程" | **加速器**：从对话历史中提取已有模式，快速生成草稿 |

**不适用场景：**
- 一次性操作（没有重复价值）
- 纯个人偏好流程（无通用性）
- 已有工作流的微调（走工作流自身的版本迭代，不新建）

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 发现与识别 | 察觉到重复模式，或提出新需求 | 帮助分析：这个模式出现了多少次？在哪些项目中出现？（导师模式） |
| 2. 提炼标准步骤 | 描述流程中的关键决策点、判断标准、常见的特殊情况 | 从对话历史和文件记录中提取步骤序列，识别人与 AI 的分工边界 |
| 3. 编写知识层文档 | 确认流程逻辑、决策点、触发条件的准确性 | 按标准格式生成 `docs/workflows/{名称}.md` 完整文档（加速器模式） |
| 4. 创建 SKILL（可选） | 决定是否需要可执行的 SKILL 快捷指令 | 裁剪完整文档为精简执行清单，生成 `.claude/skills/{skill-name}.md` |
| 5. 注册到体系 | 确认 README 索引描述、变更日志内容 | 更新 README.md 索引 + 变更日志.md + collect-data.ts workflow[] |
| 6. 验证 | 走一遍新流程，检查是否顺畅 | 记录验证中发现的问题，作为 v1.1 改进素材 |

## 执行步骤

### 步骤 1：发现与识别

AI 询问用户并共同回答：

- 这个流程"输入端"是什么？（触发条件）
- 这个流程"输出端"是什么？（产出物）
- 这个流程需要多少步？（复杂度判断）
- 人和 AI 各做什么？（分工边界）
- 最近 3 次执行这个流程时，都发生了什么？（案例分析）
- 有没有常见的"出问题"的情况？（异常处理）

复杂度判断 → 决定流程层级：

| 流程复杂度 | 特征 | 文档层级建议 |
|-----------|------|-------------|
| 简单（3-5 步） | 触发→执行→产出，线性流程 | 单文档，直接写执行步骤 |
| 中等（5-10 步） | 有多条分支路径、需用户多次确认 | 单文档，包含多级子步骤 |
| 复杂（10+ 步，含多个子阶段） | 串行衔接、多类型产出 | 总纲 + 子文档（如 [功能开发-流水线](功能开发-流水线.md)） |

### 步骤 2：提炼标准步骤

AI 从两部分素材中提炼：

**素材 A：用户的描述**（人做什么判断）
**素材 B：对话历史 / works/ 日志**（实际发生了什么）

提炼输出：
- **步骤序列**：每一步的输入、动作、输出、确认点
- **决策点**：哪些地方需要人来判断
- **异常分支**：常见错误和兜底方案
- **人机切换点**：在哪一步 AI 退后、人上前

### 步骤 3：编写知识层文档

AI 按标准格式生成完整文档（加速器模式填充，标准结构见 [README.md](README.md) 底部模板）：

```markdown
# {流程名称}

> 版本：v1 | 最后更新：YYYY-MM-DD | 对应 SKILL：/xxx（或 待建）

## 触发条件
（覆盖明确触发语句 + 适用/不适用场景 + AI 模式切换）

## 人机分工
| 步骤 | 人 | AI |
|------|-----|-----|
（3 列表格，清晰标注切换点）

## 执行步骤
（每个步骤含子标题 + 详细操作 + AI 的具体行为描述）

## 产出物
| 产出 | 位置 |
|------|------|
（2 列表格）

## 约束与规则
（具体、可执行、每条一行）

## 关联（可选）
（链接到相关文档）
```

**命名规范：**
- 中文描述名，如 `创建项目.md` / `目标管理.md`
- 成熟的不加版本后缀（v1 稳定后去掉 v0.1 标记）
- 试验阶段版本：名称末尾加 `-v0.1`（如 `写策划案-HTML-v0.1.md`）

### 步骤 4：创建 SKILL（可选）

判断标准：

| 条件 | 是否需要 SKILL |
|------|---------------|
| 流程有明确的触发语句（如"提交代码"） | **是**——方便快捷调用 |
| 流程主要靠人做决策，AI 辅助 | 可选——至少先建文档，SKILL 等流程稳定后再加 |
| 流程是纯人工操作（如 Pixso 导入） | **否**——文档就够了 |
| 流程还在试验阶段（v0.1） | **否**——等升级到 v1 再加 SKILL |
| 流程需要数据采集/API 调用等复杂操作 | **是**——SKILL 需要包含工具调用细节 |

SKILL 文件格式（参考 `.claude/skills/new-post.md` / `.claude/skills/git-commit.md`）：

```markdown
---
description: {一句话描述，用于平台自动发现}
---

# /{skill-name} — {中文名称}

## 触发
用户说 `/{skill-name}` 或 "{中文触发短语}"

## 执行步骤
（裁剪完整文档，保留精简版步骤序列）

## 约束
（核心规则 3-5 条）

> 完整流程见 [docs/workflows/{名称}.md](docs/workflows/{名称}.md)
```

注意：SKILL 文件**不重复**完整文档的内容，只保留 AI 执行时需要的最小指令集。完整上下文在知识层文档中。

### 步骤 5：注册到体系

AI 更新以下 3 处（逐一确认后执行）：

**5a. `docs/workflows/README.md`** — 在「流程清单」表格追加一行：

```
| [{流程名称}]({文件名}) | v1 | /xxx | {一句话说明} |
```

**5b. `docs/workflows/变更日志.md`** — 在当天日期下新增：

```
| 工作流 | {流程名称} | v1 新增 | 原因：{为什么建立这个工作流} |
```

**5c. `tools/collect-data.ts`** — 在 `workflows[]` 数组中追加新条目：

```ts
{ name: "{名称}", version: "v1", skill: "/xxx", project: "全局", status: "active", category: "造化坊",
  desc: "{描述}", steps: "{步骤序列}", trigger: "/xxx 或「{触发短语}」" }
```

### 步骤 6：验证

人和 AI 一起走一遍新流程：

- 触发是否流畅？
- 步骤是否遗漏？
- 决策点是否清晰？
- 产出物是否符合预期？

发现问题不立即改文档，而是记录到 `works/` 日志，积累到一定量后统一版本升级（v1 → v1.1 → v2）。

## 产出物

| 产出 | 位置 |
|------|------|
| 知识层文档 | `docs/workflows/{流程名称}.md` |
| 执行层 SKILL（可选） | `.claude/skills/{skill-name}.md` |
| 更新后的工作流索引 | `docs/workflows/README.md`（流程清单表格新增行） |
| 变更记录 | `docs/workflows/变更日志.md`（当天日期下新增记录） |
| 更新后的仪表盘数据 | `tools/collect-data.ts`（workflows[] 新增） |
| 刷新后的仪表盘 | `reports/造化坊仪表盘.html` |
| 验证记录（可选） | `works/YYYY-MM-DD-创建{名称}工作流.md` |

## 约束与规则

- **必须走完 1-5 步**：不允许跳过"发现与识别"直接跳到"写文档"——没有分析就没有好流程
- **文档是源头，SKILL 是派生**：必须先有完整的知识层文档，再从中裁剪出 SKILL。不允许反过来
- **命名必须中文描述**：工作流名称必须让一个不熟悉系统的人一眼看懂是干什么的
- **5 章节缺一不可**：触发条件、人机分工、执行步骤、产出物、约束与规则——少一个就不是完整的工作流
- **SKILL 是可选产物**：不是每个工作流都需要 SKILL。纯人工流程、试验阶段流程不需要
- **必须注册到三大索引**：README.md + 变更日志.md + collect-data.ts workflow[]，缺一个等于没发布
- **v0.1 表示试验**：不稳定的流程用 v0.1 标记，文件名加 `-v0.1`。稳定的升级到 v1，去掉版本后缀
- **变更日志不可少**：每次新建/修改工作流必须记变更日志。没有日志 = 不可追溯 = 未来的人不知道为什么有这个流程
- **验证后再发布**：步骤 6 不是可选的，至少走一遍核心路径
- **参考但不照搬**：参考现有工作流的格式和风格，但流程逻辑必须适配当前需求，不为了统一而削足适履
