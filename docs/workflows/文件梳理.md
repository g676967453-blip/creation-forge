# 文件梳理

> 版本：v1 | 最后更新：2026-07-28 | 对应 SKILL：`/organize-files`

## 触发条件

- 用户说 `/organize-files` 或 "梳理文件" 或 "整理文件夹" 或 "文件结构乱了"
- 项目经过高速迭代后，目录结构出现熵增迹象（散落文件、职责重叠、声明与实际不符等）

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 扫描分析 | 说"梳理文件" | 全面扫描项目目录树（根目录、子目录、隐藏目录），对比 CLAUDE.md 声明的结构 |
| 2. 诊断报告 | 阅读分析结果 | 列出问题清单（严重/中等/轻微），每项标注具体位置和处理建议 |
| 3. 方案确认 | 逐项决策（删/移/合并/重命名） | 根据用户决策更新整理方案，等待最终批准 |
| 4. 执行修改 | — | 按批准方案逐项执行：删除杂物、移动文件、重命名目录、更新引用 |
| 5. 同步仪表盘 | — | 执行 `/update-dashboard`，将变更同步到仪表盘 |

## 执行步骤

### 1. 扫描分析

AI 执行以下检查：

**1a. 根目录检查**
- 列出根目录所有文件，标记不属于配置/文档的散落文件
- 检查是否有测试脚本、临时文件、二进制文件散落

**1b. 目录结构对比**
- 读取 `CLAUDE.md` 中的项目结构声明
- 对比实际目录结构，列出声明了但不存在、存在但未声明的目录

**1c. 子目录深入扫描**
- `docs/`：检查分类是否清晰，是否有文件放错位置
- `projects/`：检查各项目内部结构，嵌套 `.git`、残留工具目录
- `works/`：检查命名规范一致性
- `shared/`、`templates/`、`tools/`、`reports/`：检查是否有空目录、定位模糊的目录

**1d. 隐藏目录检查**
- `.claude/`：检查 skills/memory 结构、是否有嵌套同名目录
- `.workbuddy/`：检查是否与 `.claude/memory` 重复
- 其他 `.` 开头目录：确认用途

**1e. 命名规范检查**
- 检查同级目录下命名风格是否统一（数字前缀 vs 中文前缀 vs 英文前缀）
- 检查 `.gitignore` 是否覆盖所有应排除的目录

### 2. 诊断报告

AI 输出三级问题清单：

| 级别 | 标识 | 含义 |
|------|------|------|
| 🔴 严重 | 结构混乱 | 散落文件、重复系统、声明不符、嵌套仓库 |
| 🟡 中等 | 职责不清 | 目录混杂、命名不统一、定位模糊 |
| 🟢 轻微 | 可优化 | 空目录、gitignore 不完整、模板空壳 |

每项标注：位置、现状、建议处理方式。

### 3. 方案确认

AI 对需要决策的问题（删 vs 移 vs 合并 vs 保留）逐项提问，用户确认后形成最终整理方案。

典型决策类型：
- **删除**：临时测试文件、残留工具目录、过期重定向文件
- **移动**：散落文件归入正确子目录、错位文档移到正确分类
- **合并**：重复的记忆系统、功能重叠的文档
- **重命名**：命名不一致的目录/文件统一风格
- **更新引用**：移动/重命名后同步更新所有引用路径

### 4. 执行修改

按批准方案逐项执行：

**执行顺序原则：**
1. 先创建/迁移目标位置
2. 再删除源位置
3. 最后更新所有引用

**更新引用范围：**
- `.claude/skills/` 中的 SKILL 文件
- `docs/workflows/` 中的工作流文档
- `CLAUDE.md` 中的结构声明
- `reports/造化坊仪表盘.html` 中的内嵌数据
- 其他文档中的文件路径引用

### 5. 同步仪表盘

执行 `npx tsx tools/generate-dashboard.ts` 将变更反映到仪表盘。

> 如果仪表盘生成脚本中有硬编码的目录路径，需要先更新 `tools/collect-data.ts` 或 `tools/generate-dashboard.ts`。

## 产出物

| 产出 | 位置 |
|------|------|
| 诊断报告 + 整理方案 | 对话中呈现，关键决策写入 `works/` 日志 |
| 整理后的目录结构 | 项目根目录（Clean root） |
| 更新后的 CLAUDE.md | 根目录 |
| 更新后的仪表盘 | `reports/造化坊仪表盘.html` |

## 约束与规则

- **先分析后动手**：绝不跳过扫描分析直接修改文件结构
- **变更需确认**：所有结构性变更（删除/移动/重命名）必须用户批准
- **引用必更新**：移动文件后必须全局搜索并更新所有引用路径
- **不破坏功能**：移动前确认文件是否被工具脚本引用，更新引用后再删除源文件
- **不可逆操作警告**：删除 `.git/` 等操作前特别标注 ⚠️ 并单独确认
- **一次只处理一批**：不要把所有问题混在一起执行，按优先级分批处理
- **保留工作记录**：整理完成后在 `works/` 中生成当日日志
