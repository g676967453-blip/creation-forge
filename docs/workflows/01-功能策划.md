# 01 — 功能策划

> 版本：v1 | 阶段 1/4 | 对应 SKILL：待建 | 上游：[游戏制作流水线](游戏制作流水线.md)

## 触发条件

用户描述了一个游戏功能的想法，需要将其转化为结构化的策划文档。

典型场景：
- "做一个山峰修复功能"
- "加一个器灵选择界面"
- "战斗结算要显示得分"

## 流程定位

```
[用户想法] → 本阶段 → [功能规划文档]
                           ↓
                    → 阶段 2：功能需求
```

本阶段只看策划层面：**玩家看到什么、怎么操作、发生什么变化**。不问技术实现。

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 想法描述 | 用一句话 + 一段话说清想要什么 | 倾听，不打断 |
| 2. 范围澄清 | 回答 AI 的澄清问题 | 提 5-8 个关键问题：哪些系统受影响？边界在哪？和什么互斥？ |
| 3. 模板填充 | 确认填充内容 | 逐章填功能规划模板（8 章） |
| 4. 最终确认 | 逐章检查，确认没有遗漏 | 修正争议点，输出定稿 |

## 执行步骤

### 1. 想法描述

用户自由描述功能想法。不要求结构化，想到什么说什么。

### 2. 范围澄清

AI 参考 GDD 和现有系统，提出澄清问题：
- 这个功能在游戏哪个阶段触发？（开场 / 经营 / 战斗 / 结算）
- 涉及哪些现有系统？
- 明确不做什么？
- 有没有类似的参考功能？

### 3. 模板填充

AI 按 **功能规划文档模板**（[GAME-002 模板](../../projects/GAME-002/策划文档/05-元文档/模板/功能规划文档模板.md)）逐章填写：

| 章节 | 回答的核心问题 |
|------|--------------|
| §1 在整体流程中的位置 | 功能前后衔接什么？ |
| §2 界面描述 | 待机/操作/完成 三种状态分别看到什么？ |
| §3 交互方式 | 每个操作 → 什么反馈？ |
| §4 美术与体验需求 | 需要做哪些 UI/原画/动画/特效/音效？ |
| §5 模块边界 | 涉及哪些积木块？明确不涉及哪些？ |
| §6 数据流向 | 数据从哪个 CSV 来 → 经过谁 → 到哪个 UI？ |
| §7 与其他功能的衔接 | 进入/退出条件、互斥、前置依赖 |
| §8 什么不算 | 防止范围蔓延 |

### 4. 最终确认

人逐章检查：
- [ ] 界面有没有遗漏？
- [ ] 交互逻辑合不合理？
- [ ] 模块边界够不够清楚？
- [ ] 美术需求方向对不对？

全部确认 → 定稿 → 进入阶段 2。

## 产出物

| 产出 | 格式 | 位置 |
|------|------|------|
| 功能规划文档 | `.md` | `projects/{项目}/策划文档/功能规划/{功能名称}-规划.md` |

## 约束与规则

- **写策划，不写代码**：不要出现变量名、类名、CSV 列名
- **不确定写"待定"**：比空着让 AI 猜要好
- **边界比细节重要**：说清"不做什么"比说清"做什么"更能控范围
- **人可以中途叫停**：任何时候觉得方向不对，回到步骤 1
