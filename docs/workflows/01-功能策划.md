# 01 — 功能策划

> 版本：v1 | 阶段 1/4 | 对应 SKILL：待建 | 上游：[功能开发-流水线](功能开发-流水线.md)

## 触发条件

用户描述了一个游戏功能的想法，需要将其转化为结构化的策划文档。

典型场景：
- "做一个山峰修复功能"
- "加一个器灵选择界面"
- "战斗结算要显示得分"

## 流程定位

```
[用户想法] → 本阶段 → [功能规划文档]
                           ↓
                    → 阶段 2：功能需求
```

本阶段只看策划层面：**玩家看到什么、怎么操作、发生什么变化**。不问技术实现。

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 想法描述 | 用一句话 + 一段话说清想要什么 | 倾听，不打断 |
| 2. 范围澄清 | 回答 AI 的澄清问题 | 提 5-8 个关键问题：哪些系统受影响？边界在哪？和什么互斥？ |
| 3. 模板填充 | 确认填充内容 | 逐章填功能规划模板（8 章） |
| 4. 最终确认 | 逐章检查，确认没有遗漏 | 修正争议点，输出定稿 |

## 执行步骤

### 1. 想法描述

用户自由描述功能想法。不要求结构化，想到什么说什么。

### 2. 范围澄清

AI 参考 GDD 和现有系统，提出澄清问题：
- 这个功能在游戏哪个阶段触发？（开场 / 经营 / 战斗 / 结算）
- 涉及哪些现有系统？
- 明确不做什么？
- 有没有类似的参考功能？

### 3. 模板填充

AI 按以下 8 章结构填写：

| 章节 | 回答的核心问题 |
|------|--------------|
| §1 在整体流程中的位置 | 这个功能在游戏哪个阶段触发？前后衔接什么？ |
| §2 界面描述 | 玩家看到什么？分状态描述（进入/操作/完成/异常） |
| §3 交互方式 | 每次操作 → 什么反馈？键盘/鼠标/触屏各自怎么响应？ |
| §4 美术与体验需求 | 需要哪些 UI 元素/动画/特效/音效？分 P0/P1/P2 优先级 |
| §5 模块边界 | 涉及哪些系统模块？明确不涉及哪些？输入/输出是什么？ |
| §6 数据流向 | 数据从哪来（CSV/配置/用户输入）→ 经过谁 → 到哪去（UI/存档）？ |
| §7 与其他功能的衔接 | 进入条件、退出条件、互斥关系、前置依赖 |
| §8 什么不算 | 明确排除：哪些看起来像但不在范围内的东西 |

> 具体模板示例见各项目的策划文档模板（如 GAME-002: `策划文档/05-元文档/模板/功能规划文档模板.md`）。本 8 章为通用结构，项目模板如有增删以项目模板为准。

### 4. 最终确认

人逐章检查：
- [ ] 界面有没有遗漏？
- [ ] 交互逻辑合不合理？
- [ ] 模块边界够不够清楚？
- [ ] 美术需求方向对不对？

全部确认 → 定稿 → 进入阶段 2。

| 功能规划文档 | `.md` | `projects/{项目}/策划文档/03-功能规格/YYYY-MM-DD-功能名称/YYYY-MM-DD-功能名称-功能规划.md` |

## 约束与规则

- **写策划，不写代码**：不要出现变量名、类名、CSV 列名
- **不确定写"待定"**：比空着让 AI 猜要好
- **边界比细节重要**：说清"不做什么"比说清"做什么"更能控范围
- **人可以中途叫停**：任何时候觉得方向不对，回到步骤 1
