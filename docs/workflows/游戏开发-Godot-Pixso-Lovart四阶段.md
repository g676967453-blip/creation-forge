# 游戏开发 · Godot → Pixso → Lovart → Godot 四阶段

> **通用引擎落地工作流**。后续 Godot 项目默认按本流程推进。  
> **风格、题材、色板、分辨率、命名细则属于各项目配置**，不得写入本文件正文当作全局默认。  
> 上游设计文档流水线见 [功能开发-流水线](./功能开发-流水线.md)；轻量简报版见 [独立游戏-功能开发流程-v0.1](./独立游戏-功能开发流程-v0.1.md)。

## 1. 目标与成功标准

```
① Godot 功能 + SVG/程序占位  →  可玩、可验收体验
② Pixso 同步界面 + 资产需求  →  UI 真源 + 可执行清单
③ Lovart 出图 → Pixso 审核    →  视觉定稿（人确认）
④ 严格按 Pixso 回灌 Godot     →  运行画面可对照定稿
```

| Gate | 何时 | 谁拍板 | 通过条件（摘要） |
|------|------|--------|------------------|
| **A** | 阶段 1 结束 | 人试玩 + Agent 自检 | P0 功能可玩；占位资产表完整 |
| **B** | 阶段 2 结束 | 人 | 界面状态齐全；P0 需求表无缺口 |
| **C** | 阶段 3 结束 | 人（审美） | P0 资产 approved；无水印/未授权 IP |
| **D** | 阶段 4 结束 | 人终检 | 与 Pixso 定稿结构一致；占位已替换；回归通过 |

## 2. 分层原则（防信息混淆）

| 层级 | 路径角色 | 写什么 | 禁止 |
|------|----------|--------|------|
| **通用工作流** | 本文 `docs/workflows/` | 阶段顺序、工具接法、Gate、清单字段模板、真源纪律 | 具体画风（如某项目的像素/Q 版）、某游戏色板 hex、某项目节点名当默认 |

| **平台索引** | [README](./README.md) | 链接到本文与设计流水线 | 把单一项目的美术规范写成全局默认 |

新项目接入：复制填写文末 [§7 项目配置模板](#7-项目配置模板每个新项目填写)，风格只写在项目自己的 style/spec 里，用链接挂到 profile。

## 4. 工具连接（通用）

### 4.1 Godot（阶段 1 / 4）

当前无统一 Godot MCP 时，Agent「连接引擎」=：

1. 读写该项目工程目录（`.gd` / `.tscn` / `assets/` / `project.godot`）  
2. CLI：`Godot --path <工程目录>` 或项目自带的 open/bat 脚本  
3. 冒烟：项目自定的 checklist 或 smoke 场景  

引擎版本与可执行文件路径写在 **项目 README / profile**，不写死在本 SOP。

### 4.2 Pixso（阶段 2 / 3）

- MCP（桌面端）：`http://127.0.0.1:3667/mcp`  
- 前置：Pixso 运行中，目标设计文件为 **当前激活标签页**  
- 常用：`fetch_context`、`code_to_design`、`apply_design`、`query_nodes`、`get_export_image`、`take_screenshot`  
- 开工前建议：`initialize` → `notifications/initialized` → `tools/list` 确认工具可用  

### 4.3 Lovart（阶段 3）

- 使用会话内 Lovart 能力 / 相关 skill  
- **输入必须来自阶段 2 资产需求表**（尺寸、命名、透明底、**项目风格锁引用**）  
- 禁止脱离清单自由发挥风格或规格  

## 5. 四阶段细则

### 阶段 1 — 功能开发（Godot + SVG/程序占位）

**目标**：玩法与界面状态机可验收；观感不阻塞进度。

**Agent**

1. 在项目 Godot 工程实现逻辑、场景、UI 状态流转。  
2. **占位策略（通用，与最终画风无关）**  
   - 优先 SVG / 简单矢量 / 程序色块等快速占位  
   - 每个关键可见元素写入占位表：节点路径 ↔ 占位类型 ↔ 未来资产 key  
3. 布局与逻辑尺寸以 **项目常量** 为准（各项目自定画幅与方向）。  
4. 试玩或 CLI smoke；写简短 dev-log。  

**产出**

- 可运行工程  
- 项目内 `docs/placeholder-asset-map.md`（或等价路径）  

**Gate A**

- [ ] 约定的 P0 功能可玩、无阻塞性报错  
- [ ] 占位资产表覆盖主要可见物  

---

### 阶段 2 — Pixso 界面同步 + 美术资产需求

**目标**：Pixso 成为 **UI 真源**；产出可交给 Lovart 的需求表。

**Agent**

1. 确认 MCP 连通与当前文件上下文。  
2. 维护 UI 场景清单（界面、触发、跳转、状态）。  
3. 按 **项目画幅** 建立/更新 Frame（HTML→`code_to_design` 或 `apply_design` 等）。  
4. 图层命名宜可映射 Godot 节点（具体前缀由项目约定）。  
5. 输出资产需求表，**通用必填列**：  

| key | 类型 | 逻辑尺寸 | 格式 | 优先级 | Pixso 节点 | Godot 节点 | 风格锁引用 | Prompt 要点 |
|-----|------|----------|------|--------|------------|------------|------------|-------------|

- **风格锁引用**：只填项目文档锚点（路径 + 小节），**不在本 SOP 展开**任何默认画风。  
- 项目可增加扩展列，不得删除上表必填列。  

**产出**

- Pixso 设计页 / Frame  
- 项目 UI 原型目录（如 `ui-prototypes/`）+ `art/asset-request-<迭代>.md`（路径可按项目调整）  

**Gate B（人）**

- [ ] 界面信息架构与状态齐全  
- [ ] P0 需求表无缺口；命名符合 **该项目** 命名规范  

---

### 阶段 3 — Lovart 生产 → Pixso 审核

**目标**：出图后先在 Pixso 看整体效果，**不直接灌引擎**。

**Agent**

1. 按 P0→P1 调用 Lovart；prompt 带需求表字段 + 项目风格锁链接中的约束。  
2. 草稿与定稿目录由项目 profile 规定（常见：`art/wip/`、`art/final/`；大文件可不进 Git）。  
3. 置入 Pixso 对应槽位或导出对比截图；记录通过/驳回原因。  
4. 驳回则改 prompt 或 Pixso 微调，直至人审通过。  

**产出**

- 定稿文件 + `art/review-log-<迭代>.md`  
- Pixso「审核通过」视觉态（可选独立 Approved Frame）  

**Gate C（人）**

- [ ] 人确认：这就是要进包的效果  
- [ ] P0 全部 `approved`；无水印 / 无未授权 IP  

---

### 阶段 4 — 按 Pixso 定稿回灌 Godot

**目标**：运行画面与 Pixso 定稿可对照；替换阶段 1 占位。

**Agent**

1. 从 Pixso 导出切片（**统一倍率**，禁止同一批混用 @1x/@2x）。  
2. 按 **项目** 资源目录与导入规则入库（过滤、透明边等写在项目 scene/art 规范）。  
3. 按占位表逐行替换；UI 与玩法节点分开验收。  
4. 同画幅 Godot 截图 vs Pixso 截图对比，校准锚点/边距/字号。  
5. 跑项目 P0 回归清单。  

**产出**

- 正式资源引用完成；占位表标记 `replaced`  
- 回归记录  

**Gate D**

- [ ] P0 界面结构与 Pixso 定稿一致  
- [ ] 上线运行路径不依赖临时 SVG 占位（SVG 可仅作源文件留存）  
- [ ] 换皮未破坏功能  

## 6. UI 真源与变更纪律

1. **定稿后 UI 真源 = Pixso 人审通过稿**。  
2. Godot 只做实现与引擎侧微调（锚点、安全区、性能）。  
3. 改布局 / 层级 / 文案结构 → **先改 Pixso，再回灌**，避免双源漂移。  
4. 阶段 1 的 SVG/色块是 **合同式临时占位**：阶段 4 必须替换，或明确降级为非上线源文件。  
5. 阶段 1 占位策略 **不暗示** 最终美术风格；最终风格只来自项目风格锁 + Gate C 通过稿。

## 8. 建议迭代节奏（可按项目压缩）

| 阶段 | 人 | Agent |
|------|----|--------|
| 1 Godot + 占位 | 试玩点验收 | 逻辑、占位表、冒烟 |
| 2 Pixso + 需求表 | 确认界面与清单 | MCP 出屏、拆表 |
| 3 Lovart → Pixso | 审美审核 | 出图、贴屏、改稿 |
| 4 回灌 Godot | 终检对比 | 换皮、校准、回归 |

- 仅文案/单控件：可压缩 1 或 3。  
- **新系统界面不得跳过 Gate B / C。**

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 把某项目画风写进通用流程 | §2 分层；文审时删除默认画风表述 |
| Godot 连接弱于 Pixso | 通用层固定「文件 + CLI」；若未来有 MCP 另加附录 |
| UI 双源修改 | §6 真源纪律 + Gate D 截图对比 |
| 清单字段不够新项目用 | 允许项目扩展列，保留通用必填列 |
| 占位被误当上线资产 | Gate D 检查运行时引用 |
