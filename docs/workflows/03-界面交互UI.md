# 03 — 界面交互UI

> 版本：v1 | 阶段 3/4 | 对应 SKILL：待建 | 上游：[02-功能需求](02-功能需求.md)

## 触发条件

功能需求文档 §7-附「美术与体验需求」已确认，需要把 UI 相关描述转化为完整的视觉设计。

## 流程定位

```
[需求文档 §7-附] → 本阶段 → [美术需求文档]
                               ↓
                        → 阶段 4：美术资产拆解
                        → 代码实现（GAME002-功能开发 Step 5）
```

本阶段是**纯设计阶段**。不写代码、不碰引擎、不查 Godot 工程。

## 流程总览

```
策划解读 → 交互设计 → 视觉设计 → 资产拆解
  (1)        (2)        (3)        (4)
```

> ⚠️ 资产拆解（第 4 步）是本阶段产出，但完整规格化在阶段 4 完成。本阶段的拆解是初稿——列出有哪些资产、大致规格。阶段 4 补充完整规格表、A/V/S 编号、优先级标注。

## 人机分工

| 阶段 | 人 | AI |
|------|-----|-----|
| 1. 策划解读 | 确认 UI 场景覆盖完整 | 读需求文档，识别所有 UI 界面，输出场景清单 |
| 2. 交互设计 | 逐个界面确认交互逻辑 | 设计状态/交互流/信息架构/异常分支 |
| 3. 视觉设计 | 判断"这种感觉对不对" | 对齐风格体系，描述视觉方向，可出 Pixso 布局 |
| 4. 资产拆解 | 确认资产范围和优先级（初稿） | 逐界面拆资产，按类型分组，大致规格 |

## 执行步骤

### 子阶段 1：策划解读 → UI 场景提取

**目标**：从需求文档中识别所有涉及的 UI 界面，列出清单。

**操作**：
1. AI 读取需求文档，逐段标注涉及 UI 的描述
2. 识别每个独立 UI 界面/面板，提炼为结构化条目
3. 识别界面之间的跳转关系（A→B→C，什么事件触发）
4. 输出 UI 场景清单

**UI 场景清单模板**：

| # | 界面名称 | 用途（一句话） | 触发时机 | 所属游戏状态 | 跳转到 |
|---|---------|-------------|---------|------------|--------|
| 1 | | | | | |

**产出**：UI 场景清单表。

**判断标准**：人看完能确认"所有界面都列出来了，没有遗漏"。

---

### 子阶段 2：交互设计 → 状态 + 流程

**目标**：每个 UI 界面的交互逻辑完全明确。

**操作**：

1. **状态定义**（每个界面）：
   - 正常态、空状态、禁用态、悬停态、加载态、错误态、动画过渡态
   - 标注每个状态下哪些元素可见、哪些隐藏

2. **交互流程**：
   - 用户操作 → 界面响应 → 信号发射 → 哪个 Manager 接收
   - 用文字描述，标注关键决策点

3. **信息架构**：
   - 界面显示什么数据？数据从哪个 CSV/Resource 来？
   - 标注"数据来源：XXX"

4. **异常分支**：
   - 数据为空时显示什么？
   - 操作失败时提示什么？
   - 非法操作怎么阻止？

**人机分工**：AI 逐个界面设计 → 人逐个确认。

**产出**：交互需求文档。

---

### 子阶段 3：视觉设计 → 方向 + 布局 + Pixso

**目标**：每个界面的视觉方向完全明确。

**操作**：

1. **风格对齐**：
   - 确认与项目现有 UI 风格一致
   - 如需新风格方向，明确描述差异点和理由

2. **视觉方向描述**（每个界面）：
   - 基调/氛围
   - 主色调和辅助色
   - 关键视觉元素（标题区/主视觉区/交互热区/装饰元素）

3. **布局描述**（文字或 Pixso）：
   - 用文字描述布局结构
   - 可选：用 HTML/CSS 做原型 → Pixso 导入

4. **字体与排版**：字号阶梯、行高、对齐方式

**GAME-002 特定约束**：
- Pixso 图层命名遵循 [GAME002-UI层命名规范](GAME002-UI层命名规范.md)
- 5 固定名（Bg/Mask/Root/Icon/RedPoint）+ 5 后缀（-Ui/-Btn/-List/-Text/-Item）

**产出**：视觉方向文档 + 可选的 Pixso Frame。

**判断标准**：人看完能说"这个方向是对的，可以往下拆资产了"。

---

### 子阶段 4：资产拆解 → 美术资产初稿

**目标**：列出所有需要的资产及大致规格。完整规格化留给阶段 4。

**操作**：逐界面按类型拆解资产，按以下分类：

| 资产类型 | 包含 |
|---------|------|
| UI 元素 | 底板、边框、按钮（3 态）、面板背景 |
| 图标 | 功法/山峰/道具/状态图标 |
| 插图/原画 | 角色立绘、场景图、全屏背景 |
| 动画帧 | 精灵表、角色动画帧、序列帧 |
| VFX | 粒子特效、过渡动画、光效 |
| SFX | UI 音效、技能音效、环境音 |

**产出**：美术资产初稿（类型 + 大致规格）。

## 约束与规则

- **入口是文档，不是引擎**：不从 Godot 工程反推需求
- **设计阶段不碰代码**：产出文档即完成任务
- **人是审美终裁**：所有视觉判断由人决定
- **子阶段 4 的资产拆解是初稿**：完整规格化（A/V/S 编号、尺寸、格式、优先级）留给阶段 4
