# 功能开发-流水线

> 版本：v1 | 最后更新：2026-07-26 | 对应 SKILL：待建

## 触发条件

用户提出一个需要从头设计的新游戏功能，且该功能涉及 UI 界面和美术资产。

典型触发语句：
- "做一个 XXX 功能"
- "设计 XXX 系统"
- "加一个 XXX 界面"
- "从零画 XXX 的资产"

**不适用场景**（走其他工作流）：
- 纯 Bug 修复 → 直接改代码
- 纯数值调整 → 改 CSV，不走流水线
- 已有功能的 UI 微调 → 跳过阶段 1、2，从阶段 3 进入
- 已有资产清单的追加生产 → 直接走阶段 4 或 [道具图标-生产](道具图标-生产.md)

## 这是什么

独立游戏功能开发的标准流水线。一个功能从想法到可执行资产，走完 4 个阶段：

```
用户想法 → 功能策划 → 功能需求 → 界面交互UI → 美术资产
                ↓          ↓           ↓           ↓
            策划文档    技术规格    美术需求文档   资产清单
```

每个阶段是一个独立子 SOP，可单独引用执行。4 阶段走完后，代码和资产两条线并行启动。

## 4 阶段速览

| 阶段 | 做什么 | 核心问题 | 人确认什么 | 子 SOP |
|------|--------|---------|-----------|--------|
| 1. 功能策划 | 把想法变成结构化策划文档 | 玩家看到什么？怎么操作？ | 范围对不对、界面全不全 | [01-功能策划](01-功能策划.md) |
| 2. 功能需求 | 把策划文档翻译成技术规格 | 涉及哪些模块？数据怎么流？ | 信号设计、CSV 结构、模块影响 | [02-功能需求](02-功能需求.md) |
| 3. 界面交互UI | 把技术规格转化为视觉设计 | 每个界面什么状态？怎么交互？长什么样？ | 交互逻辑、视觉方向 | [03-界面交互UI](03-界面交互UI.md) |
| 4. 美术资产 | 把视觉设计拆成可执行资产条目 | 每个资产什么规格？谁来做？优先级？ | 优先级、AI 生成的 Prompt 方向 | [04-美术资产](04-美术资产.md) |

## 运行规则

### 串行衔接：上游不确认，下游不开工

```
阶段 1 确认完毕 → 才能进入阶段 2
阶段 2 确认完毕 → 才能进入阶段 3
阶段 3 确认完毕 → 才能进入阶段 4
```

每个阶段的**产出物**是下游的**唯一入口**。下游不允许绕过上游产出物直接从代码/引擎反推需求。

### 人机分工核心原则

| | 人 | AI |
|---|---|---|
| **职责** | 决策者：确认范围、审核架构、判断视觉、拍板优先级 | 执行者：读文档、填模板、设计流程、拆资产 |
| **不能替代** | 审美判断、游戏直觉、业务理解 | 信息整理、模板填充、边界条件穷举 |

### 阶段跳过规则

| 场景 | 允许跳过 |
|------|---------|
| 纯数据/配置改动（不改 UI） | 阶段 3、4 |
| 纯 UI 调整（不改逻辑） | 阶段 2（从阶段 1 直跳阶段 3） |
| 纯资产生产（不改功能） | 阶段 1、2、3（从资产清单直入阶段 4） |

## 约束与规则

- **串行严禁跳跃**：上游未确认，下游不得开工
- **入口是文档，不是代码**：每个阶段的输入必须是上一阶段的产出文档
- **人可以叫停任何阶段**：任何时候觉得方向不对，回到上一阶段重来
- **模板是骨架，不是牢笼**：模板覆盖 80% 的情况，特殊情况可以增删章节
- **阶段 3 和 4 可以合并**：小功能（≤3 个界面）可以边设计视觉边拆资产
