# GAME-002 功能开发

> 版本：v1 | 最后更新：2026-07-21 | 对应 SKILL：待建

## 触发条件

用户要在 GAME-002「开仙门」中开发新功能或修改现有系统。

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 需求 | 描述想要的功能 | 判断属于 6 层中哪一层，提澄清问题 |
| 2. 规划 | 确认规划文档 | 按功能规划模板输出规划文档 |
| 3. 需求文档 | 确认需求 | 按功能需求模板输出需求文档 |
| 4. 数值/配置 | 确认数值 | 填充 CSV 配置，输出数值文档 |
| 5. 代码实现 | 审核代码 | 按需求文档写 GDScript 代码 |
| 6. 测试 | 在 Godot 中运行测试 | 协助排查 Bug |
| 7. 文档同步 | 抽查验证 | 按变更传播清单同步关联文档 |

## 执行步骤

### 1. 需求分析

用户描述功能想法 → AI 参考 GDD 和现有系统判断可行性 → 提澄清问题 → 确认范围。

### 2. 功能规划

AI 按 `策划文档/05-元文档/模板/功能规划文档模板.md` 输出规划文档，包含：背景/目标/范围/模块边界/数据流/美术需求/验收标准。

### 3. 功能需求

规划确认后，AI 按 `策划文档/05-元文档/模板/功能需求文档模板.md` 输出需求文档，包含：CSV 定义/程序需求/美术需求/数值需求/信号/逻辑/边界条件。

### 4. 数值与配置

AI 设计 CSV 结构、填写数值 → 用户确认 → AI 更新对应 CSV 文件 + DataManager 加载逻辑 + Resource 类。

### 5. 代码实现

AI 写 GDScript 代码，遵循 `程序规则/Godot架构规范与模块化标准.md`：
- 三层架构（数据层/逻辑层/表现层）
- 信号解耦
- 节点路径常量管理
- 不新增 `.tres`，不引入新 addon

> 💡 **涉及 UI 界面时**：先走 [GAME002-UI制作](GAME002-UI制作.md) 流程（从策划文档产出美术需求文档），再回到本步骤做引擎实现。

### 6. 测试

人在 Godot 编辑器中运行测试，发现问题告知 AI，AI 修复。

### 7. 文档同步

AI 查阅 `总指挥-协作原则/04-质量体系/03-变更传播清单.md`，逐项检查受影响文件并同步更新。

## 产出物

| Layer | 产出 |
|-------|------|
| 系统设计 | 功能规划文档 + 功能需求文档 |
| 数值 | CSV 配置 + 数值文档 |
| 代码 | `.gd` 脚本 + `.tscn` 场景（如需要） |
| 文档 | 关联文档同步更新 |

## 约束与规则

- **CSV 是唯一真相**：数值以 CSV 为准，文档描述引用 CSV
- **先规划后代码**：6 层自上而下，上层没确认，下层不开工
- **改完代码同步文档**：不传文档 = 制造谎言
- **数据不写死在代码里**：走 CSV + DataManager
- **19 个待定设计问题**：当前阻塞经营/战斗/结算系统，需用户逐项决策后才能推进
