# 目标管理

> 版本：v1 | 最后更新：2026-07-30 | 对应 SKILL：/goals

## 流程定位

目标管理是造化坊的"上层建筑"——它不直接产出代码或内容，但它**决定什么值得做**。

```
目标管理（本流程）
    ↓ 拆解为
项目级目标 → 个人待办 → 工作日志（每日执行）
    ↓              ↓              ↓
仪表盘展示    待办任务表      造化仪表盘/works/ 记录
```

与现有体系的关系：

- **不替代** [个人待办管理](个人待办管理.md)（`/todo`）：待办是执行层，目标是规划层
- **不替代** [运转循环](../zh-CN/operational-loop.md)：循环是"遇到问题 → 解决"，目标是"给问题划定方向"
- **不替代** [改进追踪](改进追踪.md)：改进是纠偏机制，目标是前进方向

## 触发条件

| 触发场景 | 典型语句 | AI 模式 |
|----------|---------|---------|
| 定方向 | "我们下一步做什么" / "这个月主要搞什么" / "今年的目标是什么" | **协作者**：一起头脑风暴方向和优先级 |
| 做规划 | "定一个季度目标" / "设定里程碑" / "做月度计划" | **导师**：引导 SMART 化，帮助拆解 |
| 进展检查 | "看看目标完成得怎么样" / "检查进度" / "还有哪些没做" | **加速器**：快速对比计划 vs 实际 |
| 目标复盘 | "复盘这个月" / "回顾目标完成情况" / "总结一下" | **协作者**：帮用户反思"为什么做到了/没做到"，提炼经验 |
| 项目初始化后 | 刚走完 [创建项目](创建项目.md) 流程，需要为新项目设定目标 | **导师**：帮用户定义项目的成功标准 |

## 人机分工

| 步骤 | 人 | AI |
|------|-----|-----|
| 1. 定义目标（SMART 化） | 说出愿景、方向、想达成的状态 | 提问引导：具体化、可衡量化、时间化（导师模式）。从对话中提取关键信息填入 SMART 模板 |
| 2. PNAS 拆解（季度项目） | 描述完成后的画面（Picture）、确认关键要素（Noun） | 用四步引导：Picture 画面 → Noun 要素 → Activities 行动 → Sequence 排序。将模糊大目标变成可执行结构 |
| 3. 拆解为可执行步骤 | 确认优先级、调整粒度 | 在 PNAS 基础上拆解为里程碑 → 行动项三层。标注每个行动的关联项目和可用的工作流 |
| 4. 写入体系 | 确认内容准确 | 更新 `造化仪表盘/tools/collect-data.ts` goalsUser[] + 写入 `造化仪表盘/目标规划.md` + 变更日志 |
| 5. 关联到项目和工作流 | 确认关联关系 | 在目标文档中建立双向链接，关联到具体项目和工作流 |
| 6. 进展追踪 | 汇报进度、标记完成 | 对比计划 vs 实际，更新状态。识别阻塞项，判断是否需要调整目标 |
| 7. 复盘 | 反思经验教训 | 生成复盘报告：完成率、关键障碍、经验教训、下期调整建议（协作者模式） |

## 执行步骤

### 步骤 1：定义目标（SMART 化）

AI（导师模式）引导用户将模糊愿景转化为 SMART 目标：

| SMART 维度 | 引导提问 | 示例（模糊 → 清晰） |
|------------|---------|-------------------|
| **S** - 具体 (Specific) | "做完后长什么样？能描述一下吗？" | "做好游戏" → "完成 GAME-002 V0.1 的核心循环：经营→战斗→结算可游玩" |
| **M** - 可衡量 (Measurable) | "怎么判断做完了？有什么量化指标？" | "多做内容" → "小红书发布 4 期帖子 + GAME-002 完成 15 个任务" |
| **A** - 可达 (Achievable) | "以现在的资源和节奏，现实吗？" | 结合历史节奏判断：过去一个月产出 N，这个目标需要 N+，需要调整吗？ |
| **R** - 相关 (Relevant) | "这和造化坊的大方向是什么关系？" | 关联到宣言中的理念：这个目标是练习设计能力、技术能力、还是内容能力？ |
| **T** - 有时限 (Time-bound) | "什么时候完成？有中间检查点吗？" | "这个月" → "7 月 31 日前 V0.1 核心循环可玩，8 月 15 日前内容填充完成" |

AI 将结果整理为目标卡片格式：

```
## [目标名称]
> 类型：{项目目标/学习目标/内容目标/系统改进}
> 状态：进行中 | 截止：YYYY-MM-DD

### 描述
{SMART 化的一段话}

### 成功标准
- [ ] {可验证的标准 1}
- [ ] {可验证的标准 2}
```

**多目标管理：** 如果用户同时推进多个目标（如 GAME-002 + 小红书 + 资产管线），AI 帮助排优先级：

| 优先级 | 目标 | 理由 |
|--------|------|------|
| P0 本周 | GAME-002 祝福 3 选 1 UI | 阻塞核心循环，不完成后续无法推进 |
| P1 本周 | 小红书发 1 期 | 保持内容节奏 |
| P2 本月 | asset-pipeline 对接到 GAME-002 | 长期价值高但不紧急 |

### 步骤 2：PNAS 拆解（季度项目必经）

> 📖 来源：《高能要事》第 5 段位 —— PNAS 是把模糊大目标变成可执行结构的桥梁。

**仅对季度项目（3 个月尺度）执行 PNAS。** 长期目标（1 年+）走 AI原生五维关注 + 战略定位三角。

AI（导师模式）引导用户完成四步：

| PNAS | 引导提问 | 示例（GAME-002 V0.1） |
|------|---------|----------------------|
| **P** - Picture（画面） | "这个项目完成后，你打开它看到的第一眼是什么？从头到尾描述一遍使用流程。" | 打开 Godot，点「运行」→ 门派经营界面 → 点「出战」→ 战斗场景 → 弟子自动战斗 → 胜利弹窗 → 回到经营界面。无报错，帧率稳定。 |
| **N** - Noun（要素） | "实现这个画面需要哪些关键资源？引擎、工具、模块、人？列出所有要素。" | Godot 4.7、祝福选择 UI 场景、BlessingManager、DiscipleSquad、战斗结算模块、旧代码残余 |
| **A** - Activities（行动） | "需要做哪些具体行动？用「我+动词+参与人员+事件」格式。" | 我创建祝福选择场景（.tscn），我实现三选一交互逻辑，我连接 BlessingManager 数据层…… |
| **S** - Sequence（排序） | "这些行动按什么顺序做？找到第一步、第二步……第 N 步。注意依赖关系。" | ① 创建祝福场景 → ② 三选一交互 → ③ 连接数据层 → ④ 接入战斗 → ⑤ 删除旧模块 → ⑥ 端到端测试 |

AI 将结果整理为 PNAS 表格，写入 `造化仪表盘/目标规划.md` 对应项目卡片下。

### 步骤 3：拆解为可执行步骤

AI 将目标拆解为三层结构：

```
目标层：完成 GAME-002 V0.1 核心循环
  ↓
里程碑层：
  ├── M1：祝福 3 选 1 UI 面板（7-30 ~ 8-02）
  ├── M2：弟子接入战斗循环（8-03 ~ 8-07）
  └── M3：旧模块删除 + 验证（8-08 ~ 8-10）
    ↓
行动项层：
  M1-1：用功能开发-流水线产出美术需求文档
  M1-2：创建祝福选择场景（Godot）
  M1-3：实现三选一交互逻辑
  M1-4：连接 BlessingManager 数据
  ...
```

每个行动项标注：

- **关联项目**（如 GAME-002）
- **可用工作流**（如功能开发-流水线）
- **预估耗时**（如 1-2h）
- **前置依赖**（如需要 M1-1 完成）

### 步骤 4：写入体系

**4a. 创建/更新** `造化仪表盘/目标规划.md`（集中管理所有活跃目标）：

AI 生成初始结构（首次）或更新已有文档（追加/修改目标）。格式参见该文档自身的说明。

**4b. 更新** `造化仪表盘/tools/collect-data.ts` 中的 `goalsUser[]`：

```ts
{ id: "U{N}", task: "{目标名称}", detail: "{SMART 描述}", priority: "{优先级}" }
```

**4c. 写入变更日志** `docs/workflows/变更日志.md`（首次设定目标时记录系统变更）。

### 步骤 5：关联到项目和工作流

AI 在 `造化仪表盘/目标规划.md` 中为每个目标建立双向链接：

| 目标 | 关联项目 | 关联工作流 | 关联待办 |
|------|---------|-----------|---------|
| 完成 GAME-002 V0.1 | [GAME-002](../../projects/GAME-002/) | [功能开发-流水线](功能开发-流水线.md) | 个人待办 §🎮 |
| 小红书 7 月 4 期 | [xiaohongshu](../../xiaohongshu/) | [小红书-制作帖子](小红书-制作帖子.md) | 个人待办 §📱 |

用户可以选择将目标拆解后的行动项导入个人待办。AI 提示：

```
💡 目标「GAME-002 V0.1」已拆解为 3 个里程碑、12 个行动项。
是否将本周的行动项导入个人待办？说"导入待办"执行。
```

### 步骤 6：进展追踪

用户说"检查目标进度"时，AI：

1. 读取 `造化仪表盘/目标规划.md`，列出所有活跃目标
2. 对每个目标：
   - 计算完成率（已完成行动项 / 总行动项）
   - 对比计划截止日与实际进度
   - 标注阻塞项（来自 `造化仪表盘/tools/collect-data.ts` goalsIssues[]）
3. 输出进度摘要：

```
📊 目标进度（7 月 30 日）

🎮 GAME-002 V0.1 核心循环 → ████████░░ 80%（M1 完成，M2 进行中）
   ⚠️ 阻塞：祝福选择 UI 仍复用旧卡牌面板（IMP-002 跟踪中）

📱 小红书 7 月 4 期 → ██████████ 100% ✅ 已完成

🔧 asset-pipeline 对接 → ██░░░░░░░░ 20%（等待 GAME-002 V0.1 稳定后再对接）
```

如果进展严重落后于计划，AI 主动提问："当前进度比计划慢 X 天。需要调整目标截止日，还是调整优先级？"

### 步骤 7：复盘

**触发时机：** 月底 / 季度末 / 目标截止日，用户说"复盘"时。

AI（协作者模式）生成复盘报告：

```
## [YYYY-MM] 目标复盘

### 完成情况
| 目标 | 计划 | 实际 | 完成率 | 偏差分析 |
|------|------|------|--------|---------|
| ... | ... | ... | ... | ... |

### 做得好的
- {摘录 2-3 条——为什么做得好？可复制的经验是什么？}

### 待改进的
- {摘录 2-3 条——为什么没做到？根本原因是什么？}

### 下期调整
- {基于复盘，下期目标怎么调？数量？优先级？节奏？}

### 经验归档
- {值得保留的经验，写入对应项目 CLAUDE.md 或工作流文档}
```

复盘完成后，AI 将已完成目标从"活跃目标"区移到"已完成目标"区，并归档到 `造化仪表盘/目标规划.md` 对应季度下。

## 约束与规则

- **目标是方向盘，不是枷锁**：目标变了就改文档，不要为了"完成目标"而做没有价值的事。造化坊的哲学是项目推着人走，不是目标推着人走
- **不做空目标**：每个目标必须包含：SMART 描述 + 成功标准 + 至少拆解出一个里程碑。没有这三个要素的"目标"只是愿望
- **至少月度复盘**：不一定要每月初设定目标，但每月底要做一次复盘。复盘比设定更重要
- **目标数量有上限**：同时活跃目标不超过 3 个（对应造化坊 3 个活跃项目：GAME-002 + 小红书 + asset-pipeline）。超过 3 个时 AI 提醒"是否并行太多？"
- **仪表盘是视图，不是编辑口**：目标数据存储在 `造化仪表盘/目标规划.md`，`造化仪表盘/tools/collect-data.ts` 是其结构化镜像。不能绕过这两个文件直接在 HTML 中改目标
- **目标与待办不重复**：目标是"要完成什么"，待办是"今天做什么"。目标是待办的上游，但不在待办表中重复记录目标本身
- **复盘必须写结论**：不要只列完成/未完成，必须写"为什么"和"下期怎么调"
- **不强制 SMART**：SMART 是引导框架，不是合格性检查。有些创造性目标（如"探索 Godot 的音效系统"）不需要严格量化
- **PNAS 是季度项目必经步骤**：P（画面）必须具体到能看到→能摸到→能描述完整流程的程度。没有画面的项目只是待办清单
- **长期目标不硬拆 PNAS**：1 年+ 的长期目标走 AI原生五维关注 + 战略定位三角，不强行 PNAS。PNAS 是 3 个月尺度项目的工具
