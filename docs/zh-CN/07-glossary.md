# 07 — 术语表

## 游戏开发术语

| 术语          | 英文                              | 解释                                             |
| ------------- | --------------------------------- | ------------------------------------------------ |
| 精灵          | Sprite                            | 游戏中的 2D 图像对象，如角色、道具               |
| 精灵图/精灵表 | Spritesheet                       | 将多个动画帧拼在一张图中的资源格式               |
| 场景          | Scene                             | 游戏的一个独立"画面"（菜单、游戏、结束画面等）   |
| 游戏循环      | Game Loop                         | 游戏运行时不断重复的「更新→渲染」循环            |
| 帧率/FPS      | Frame Rate / FPS                  | 每秒渲染的画面数量，通常 60fps                   |
| 碰撞检测      | Collision Detection               | 判断两个物体是否接触/重叠                        |
| 物理引擎      | Physics Engine                    | 模拟重力、碰撞、弹力等物理行为的系统             |
| 瓦片地图      | Tilemap                           | 用小块图形（瓦片）拼接而成的游戏地图             |
| 刚体          | Rigid Body                        | 受物理引擎控制的物体                             |
| 粒子系统      | Particle System                   | 生成大量小图形来模拟火焰、烟雾、爆炸等效果       |
| 对象池        | Object Pool                       | 预创建并复用游戏对象（如子弹），避免频繁创建销毁 |
| 补间动画      | Tween                             | 在指定时间内平滑过渡属性值（位置、透明度等）     |
| 游戏设计文档  | GDD (Game Design Document)        | 详细描述游戏玩法、机制、关卡的设计文档           |
| UI/HUD        | User Interface / Heads-Up Display | 屏幕上显示的信息：分数、血量、小地图等           |

## Web 开发术语

| 术语         | 英文                         | 解释                                 |
| ------------ | ---------------------------- | ------------------------------------ |
| 热模块替换   | HMR (Hot Module Replacement) | 修改代码后浏览器自动更新，不丢失状态 |
| 打包/Build   | Build / Bundle               | 将源代码转换为可部署的优化文件       |
| Tree Shaking | Tree Shaking                 | 自动删除未使用的代码，减小打包体积   |
| 入口文件     | Entry Point                  | 应用的启动文件（如 main.ts）         |
| 开发服务器   | Dev Server                   | 本地开发时使用的 HTTP 服务器         |
| 懒加载       | Lazy Loading                 | 按需加载资源，减少初始加载时间       |

## TypeScript 术语

| 术语     | 英文              | 解释                                          |
| -------- | ----------------- | --------------------------------------------- |
| 严格模式 | Strict Mode       | TypeScript 最严格的类型检查模式               |
| 接口     | Interface         | 定义对象的结构（属性和方法的类型）            |
| 类型别名 | Type Alias        | 给类型起一个名字                              |
| 泛型     | Generics          | 编写可复用的、类型安全的代码                  |
| 类型守卫 | Type Guard        | 运行时检查并缩小类型范围                      |
| 联合类型 | Union Type        | 一个值可以是多种类型之一 (`string \| number`) |
| 交叉类型 | Intersection Type | 合并多个类型的属性 (`A & B`)                  |

## AI 协作术语

| 术语         | 英文                               | 解释                                         |
| ------------ | ---------------------------------- | -------------------------------------------- |
| 提示词       | Prompt                             | 给 AI 的指令或问题                           |
| 架构决策记录 | ADR (Architecture Decision Record) | 记录重要技术决策及其理由的文档               |
| 复盘         | Retrospective                      | 项目结束后回顾做了什么、学到了什么、如何改进 |
| 脚手架       | Scaffold                           | 自动生成项目基础文件和目录结构               |
| 样板代码     | Boilerplate                        | 每个项目都需要的基础代码，通常可由工具生成   |

## 项目管理术语

| 术语     | 英文                         | 解释                              |
| -------- | ---------------------------- | --------------------------------- |
| 仓库     | Repository / Repo            | Git 管理的项目存储空间            |
| 单一仓库 | Monorepo                     | 将多个项目放在一个 Git 仓库中管理 |
| 工作区   | Workspace                    | npm 的 monorepo 管理机制          |
| 提交     | Commit                       | 将修改保存到 Git 历史中           |
| 分支     | Branch                       | Git 的独立开发线                  |
| PR/MR    | Pull Request / Merge Request | 请求将分支合并到主分支            |
