# 造化坊 · 操作手册

> 给人看的。会持续更新。每个「💡 协作提示」都是在实际使用中沉淀下来的好做法。

---

## 一、这个系统是干什么的

你在做两件事，它们共用一条流水线：

1. **做游戏** — 以项目驱动，遇到问题 → AI 协作解决 → 产出结果
2. **做自媒体** — 把解决问题的过程变成小红书视频

一条循环：

```
做游戏遇到问题 → 和 AI 一起解决 → 产出结果 → 把过程记下来 → 顺便写成视频草案 → 发布
```

**不需要额外的「内容创作」时间。** 你本来就要解决的问题，就是视频素材本身。

---

## 二、每天怎么用

### 开始：你今天要做什么？

不需要提前规划。打开你正在做的游戏项目，它自然会告诉你今天要做什么——代码跑不通、缺一个素材、不知道怎么设计某个功能。任何让你停下来的东西，都是今天的起点。

### 步骤 1：复制模板

```
cp works/_template.md works/YYYY-MM-DD-简短描述.md
```

例如：

```
cp works/_template.md works/2026-07-16-phaser-collision-detection.md
```

### 步骤 2：和 AI 协作解决问题

边做边往文件里记。不用写得很正式——记关键信息就行：
- 问了 AI 什么问题
- AI 给的方案里有什么亮点
- 截图保存关键对话

### 步骤 3：问题解决后，填写完整

- 日志区块：整理一下过程
- 视频草案区块：按三幕结构填好，特别是「一句话总结」

### 步骤 4：视频草案够了就做

不强制每天发。攒了几份草案之后，挑最有分享价值的做。前期手工制作，同时留意哪些制作步骤可以丢给 AI。

## 三、文件管理速查

| 你在做什么 | 文件放哪 | 命名规则 |
|------------|----------|----------|
| 解决具体问题 | `works/` | `YYYY-MM-DD-简短描述.md` |
| 宏观选题素材 | `projects/xiaohongshu/` | 编号 + 主题 |
| 小红书视频草案 | 直接在 works/ 文件里（区块二） | 同上 |

### works/ 文件就是你的工作日志 + 内容素材库

不需要维护两个地方。做完一件事，一个文件搞定。

## 四、视频生产：从草案到发布

### 三幕结构（固定模板）

| 幕 | 内容 | 参考时长 |
|----|------|----------|
| 第一幕 | 遇到了什么问题，为什么是个痛点 | ~15 秒 |
| 第二幕 | 怎么和 AI 协作解决的，过程亮点 | ~30 秒 |
| 第三幕 | 效果展示 + 一句话总结 | ~15 秒 |

### 草案 → 制作 → 发布

1. 从 works/ 里的视频草案出发
2. 把三幕扩展为完整旁白（可丢给 AI 写）
3. 收集素材：AI 对话截图、代码对比、效果 GIF
4. 制作 PPT 式视频或图文（工具自选）
5. 发布到小红书

### 渐进自动化目标

- [ ] 草案 → AI 扩展为完整旁白脚本
- [ ] 脚本 → AI 生成分镜和画面提示
- [ ] AI 工具直接生成 PPT 视频
- [ ] AI 分析发布数据，建议下期选题

> 每次循环都比上次快一点。不追求一步到位。

## 六、协作提示

> 💡 这里会持续积累。每次发现一个好的协作方式，就加一条。

### 向 AI 描述问题时

**💡 给上下文，不要只给报错。**

```
❌ "这个报错怎么修？"
✅ "我在 Phaser 里做了一个平台跳跃，角色可以左右移动但跳跃无效。
    这是我的 jump 相关代码：[贴代码]。错误信息是：[贴报错]。"
```

AI 掌握的信息越多，给出的方案越精准。「贴代码 + 贴报错 + 说清楚你想达到什么效果」三者缺一不可。

### AI 给出方案后

**💡 先跑一遍，再追问。**

不要对着 AI 的方案在脑子里分析对不对。直接复制到代码里跑一下。跑通了——你有了效果，视频有了素材。跑不通——把新的报错贴回去，这是第二轮协作的起点，也是视频里「中间有什么调整」的好素材。

### 多线并行时

**💡 一条线一个 works/ 文件，不要混。**

同一天做了三件不相关的事 → 三个文件。每条线独立闭环。后续做视频时不用拆解。

### 关于"卡住了"

**💡 卡住超过 15 分钟就问 AI，不要硬扛。**

传统思维：「我应该自己解决」。项目制思维：「我在做游戏，卡住就是浪费时间」。15 分钟是一个合理的阈值——试过但不行，立刻问 AI。
