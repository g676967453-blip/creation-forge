# 游戏 UI 定制包装 — 五阶段生产管线

> 📌 改写自：[整体定制包装UI业务流程与内容概述.md](../整体定制包装UI业务流程与内容概述.md)
> 🏷️ 类型：方法论 / 流程框架
> ⭐ 价值评级：高 —— 完整的游戏 UI 生产管线，可直接套用

---

## 管线全景

```
阶段一      阶段二       阶段三      阶段四         阶段五
需求分析 → 概念设计 → 五图定风格 → APK包装体验 → 规范+量产线
(定共识)   (定高度)    (定视觉)    (定体验)      (定品质)
```

---

## 阶段一：需求分析 —— 定共识

**目标**：所有关键人员对项目需求达成统一认知。

### 分析清单

| 维度 | 具体内容 |
|------|---------|
| **项目需求** | 玩法特色提取、美术方向确认、用户定位确认 |
| **IP 特点** | 世界观、主要阵营、文化特色（建筑/服装/物件/符号）、官方 IP 资料 |
| **竞品分析** | 同 IP 手游与主机游戏；同类型一线大厂已上线/将上线产品 |

### 为什么这一步重要？

需求分析阶段踩坑，后面五个阶段都在填坑。**方向错了，画得再好也是错的。**

---

## 阶段二：概念设计 —— 定高度

**目标**：提出设计提案，明确期望达到的体验目标。

### 交付内容

- **设计概念效果展示**：几张关键界面的概念稿
- **设计体验目标说明**：
  - 主色调
  - 材质方向
  - 风格定义
  - 核心视觉元素
  - UI 动效方向
  - UI 特效方向
- **技术风险评估**：哪些效果能实现？哪些需要降级？

> 概念设计是定"天花板"——这个项目 UI 最好能做成什么样。

---

## 阶段三：五图设计 —— 定视觉风格

**目标**：基于静态效果图，确定 UI 风格与角色场景的适配性。

### 五张关键界面

| 界面 | 为什么选它 |
|------|-----------|
| **战斗界面** | 核心玩法界面，信息密度最高 |
| **角色系统** | 养成展示，品质感的集中体现 |
| **背包系统** | 列表+网格混合布局的代表 |
| **主界面** | 门面，用户停留时间最长的界面 |
| **登录界面** | 第一印象 |

### 为什么是"五图"？

五张图覆盖了游戏界面中最核心的布局类型：HUD（战斗）、展示（角色）、列表（背包）、大厅（主界面）、入口（登录）。**这五张定了，整个游戏的视觉语言就定了。**

---

## 阶段四：APK 整体包装体验 —— 定体验

**目标**：在手机端实现美术最小原型，让团队真正"玩"到界面。

### 必须覆盖的模块

- 登录 → 加载 → 公告
- 主界面系统
- 副本到战斗系统（完整流程）
- 角色养成系统（至少 3 个界面）
- 背包系统
- 召唤/抽卡模块

> 静态效果图看不出交互问题。**只有跑在手机上，才会发现"这个按钮太小了""这个转场太慢了"。**

---

## 阶段五：通用规范 + 量产线 —— 定品质

**目标**：建立可复制的标准，保障量产质量不滑坡。

### 通用规范清单

| 规范类别 | 内容 |
|---------|------|
| 基础框架 | 画布尺寸、适配策略 |
| 面板层级 | 弹窗/浮层/全屏的层级关系 |
| 字体类 | 字号阶梯、字重、颜色规范 |
| 按钮类 | 尺寸、状态（常态/按下/禁用） |
| 图标图形 | 风格统一、尺寸标准 |
| 资源出图 | 命名、格式、压缩规范 |
| 适配 | 异形屏、横竖屏、多分辨率 |

### 版本计划

- 明确量产开发计划和时间节点
- UI 界面重要程度分级（核心/重要/一般）
- 日常沟通反馈规则

### 人员配置时机

| 角色 | 建议到位时间 |
|------|-------------|
| UI 组长 | 概念设计到五图设计期间 |
| 执行 UI | 量产前后 |

> **量产拼的不是设计能力，是规范和流程。** 没有规范的量产 = 越做越乱。

---

## 总结：一个完整的 UI 生产管线

| 阶段 | 核心问题 | 交付物 | 关键人物 |
|------|---------|--------|---------|
| 需求分析 | 做什么？为谁做？ | 需求文档、竞品报告 | PM + 主美 |
| 概念设计 | 做成什么样？ | 概念稿、体验目标 | 主美 + UI 组长 |
| 五图设计 | 视觉语言是什么？ | 5 张关键界面效果图 | UI 组长 |
| APK 包装 | 跑起来怎么样？ | APK 原型 | UI + 程序 |
| 规范量产 | 怎么稳定复制？ | 通用规范、量产计划 | UI 组长 + 执行 UI |

### 核心洞察

1. **前三个阶段决定上限，后两个阶段决定下限**
2. **五图是最小可行决策集** —— 不多不少，刚好覆盖所有布局类型
3. **APK 原型不是可选项** —— 静态设计在手机上会有完全不同的感受
4. **规范是量产的生命线** —— 没有它，越多人做越快乱
