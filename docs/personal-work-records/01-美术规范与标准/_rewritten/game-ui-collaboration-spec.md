## 一、网格与间距系统

### 基础单位

以 **4px** 为最小网格单位。所有间距、尺寸必须是 4 的倍数。

| 常用间距 | 适用场景 |
|----------|---------|
| 8px | 紧密元素间距（图标与文字、同类按钮） |
| 16px | 标准元素间距（表单项、列表项） |
| 24px | 区块内边距、组件间距 |
| 32px | 大区块间距、屏幕边缘留白 |

> ⚠️ 少数场景会用到 20px，但应严格参照通用控件 PSD 中的范例。

### 安全区

所有界面内容必须限制在安全区内——四周距离屏幕边缘保留标准安全区距离，避免异形屏（刘海/挖孔/圆角）遮挡。

> 关键原则：**做设计时优先考虑最小分辨率，适配时向大分辨率扩展。**

## 二、双分辨率交付

每个界面需要输出 **两个版本** 的效果图：

| 版本 | 分辨率 | 用途 |
|------|--------|------|
| 基准版 | 1334 × 750 | 主设计稿，优先保证此版本视觉效果 |
| 适配版 | 1624 × 750 | 以基准版为中心锚点，上下各拓展 145px |

### 为什么是这两个尺寸？

- **1334 × 750**：主流手机基准分辨率，覆盖绝大多数设备
- **1624 × 750**：更长屏幕（如全面屏手机）的适配版本
- 两者宽度一致（750），保证横向布局不变；纵向以中心锚点拓展，保证核心内容区不偏移

## 三、资源提交规范

### 三个"必须"

1. **一个系统 = 一个 PSD**
   - 一个系统的不同界面必须新建独立 PSD 文件
   - 一个界面的不同状态（tips 气泡、页签切换）可放在同一 PSD
   - 弹窗级别的内容差异 → 新建 PSD

2. **效果图与 PSD 命名对应**
   - PSD 以系统命名（如 `聊天系统.psd`）
   - 效果图以系统为前缀 + 状态描述（如 `聊天系统_公屏.png`、`聊天系统_私聊.png`）

3. **文件夹分类标准化**
   ```
   系统名称/
   ├── 效果图/
   │   ├── 1334/    ← 基准版效果图
   │   └── 1624/    ← 适配版效果图
   ├── PSD/
   │   ├── 1334/
   │   └── 1624/
   └── 切图/        ← 需要给程序的切图资源
   ```

## 四、验收流程

### 飞书表格验收法

1. 每个系统负责人在验收表中新建一个页签，命名为系统名称
2. 将需翻新的旧效果图粘贴到对应格子
3. 完成新效果图后粘贴到旁边格子
4. 验收人对比审阅 → 反馈 → 修改

### 优势

- 新旧对比一目了然
- 反馈可追溯
- 多人并行时互不干扰
- 无需额外工具，飞书即可

---

## 五、切图原则

1. 先问再切 —— 有些切图可能需要按旧资源尺寸切，避免引擎适配问题
2. 尺寸为 2 的 N 次方（能被 4 整除）
3. 全屏背景图加 `_ignore` 后缀防止程序压缩
4. 遵循统一命名规范：`sp_{类型}_{功能}_{描述}_{后缀}`

---

## 核心要点

| 原则 | 说明 |
|------|------|
| 4px 网格 | 一切间距的基石 |
| 双分辨率 | 1334 基准 + 1624 适配 |
| 一个系统一个 PSD | 文件管理的底线 |
| 新旧对照验收 | 质量保障的最后一道关 |
