## 外包协作三阶段

### 第一阶段：前期准备

1. **确认需求与风格**
   - 明确外包范围：哪些界面/系统外包？哪些内部做？
   - 输出需求文档 + 风格参考板
   - 确定交付标准和验收门槛

2. **确认测试题**
   - 选取 1-2 个代表性界面作为测试题
   - 测试题应覆盖该项目 UI 的核心难点
   - 明确评分标准（风格还原度 / 细节完成度 / 规范遵循度）

### 第二阶段：筛选期

1. **发出测试** → 多供应商同步进行
2. **定期评价** → 过程中给反馈，观察响应速度和改进能力
3. **确定供应商** → 综合评估：质量 / 速度 / 沟通 / 价格

> 💡 筛选期不只是挑"画得最好的"，而是挑**最能协作的**。外包是长期关系，不是一锤子买卖。

### 第三阶段：生产期

1. **每月产能确认** → 提前锁定量，避免供应商排期满
2. **协作规范通知** → 发送技术规范、命名规范、提交规范
3. **反馈规则明确** → 反馈格式、响应时限、修改次数上限
4. **商务签单流程** → 验收→开票→付款的完整闭环

## 公司外包池管理

维护一个供应商数据库，至少包含：

| 字段 | 说明 |
|------|------|
| 供应商名称 | 公司/工作室/个人 |
| 是否控股 | 与公司的股权关系 |
| 人员质量 | 历史协作评价（A/B/C 级） |
| 品类价格 | 界面/图标/特效的单价 |
| 协作案例 | 过往项目 + 交付质量截图 |

> 💡 外包池的价值在于：新项目立项时不用从头筛选供应商，直接根据品类和评级匹配。

## 配套规范文档

外包管理不只是"找人干活"，需要配套的标准化文档：

1. **需求规范文档** —— 描述清楚"做什么"
2. **沟通规范** —— 钉钉/飞书/邮件，什么情况用什么渠道
3. **保密规范** —— NDA + 信息安全要求
4. **技术规范** —— 分辨率、格式、命名、文件夹结构
5. **资源提交规范** —— 怎么交、交到哪、怎么验收

## 核心原则

| 原则 | 说明 |
|------|------|
| 测试题是唯一筛选标准 | 不看作品集，看测试题还原度 |
| 反馈要快、准、统一 | 多人反馈时指定唯一对接人 |
| 供应商要分级 | A级多给量，C级逐步淘汰 |
| 规范文档先行 | 不要等出了问题再补规范 |
