# 时间、成本、质量：项目管理的铁三角

---

## 核心关系

三者互相制约，牵一发动全身：

```
      时间
      /  \
     /    \
    /      \
  成本 ———— 质量
```

| 关系 | 逻辑 |
|------|------|
| 时间 → 成本 | 缩短工期 → 加班、加人、加急采购 → 成本上升 |
| 时间 → 质量 | 赶工 → 测试不足、简化流程 → 质量下降 |
| 成本 → 质量 | 砍预算 → 降级材料/人员 → 质量下降 |

---

## 平衡方法

### 1. 先定优先级

**三者不可能同时最优。先确定什么不可妥协。**

| 项目类型 | 不可妥协 | 可变通 |
|---------|:--:|------|
| 奥运会开幕式 | 时间 | 成本、质量 |
| 医疗设备 | 质量 | 时间、成本 |
| 游戏上线 | 通常时间 | 范围（砍功能）、质量（先上线再迭代） |

### 2. "快、好、省"最多选两个

```
快 + 好 = 贵（加人加班）
快 + 省 = 差（砍流程砍测试）
好 + 省 = 慢（少人精做）
```

### 3. 三大优化方法

| 方法 | 用途 |
|------|------|
| **关键路径法（CPM）** | 找出最长的依赖链，优化它就能优化整体时间 |
| **价值工程** | 在保证核心质量的前提下，找出可以降成本的环节 |
| **敏捷迭代** | 不追求一次完美，通过快速迭代逐步逼近目标 |

## 现代扩展：项目钻石模型

传统铁三角加第四个要素——**范围（Scope）**：

```
       时间
       /|\
      / | \
     /  |  \
   范围——+——质量
     \  |  /
      \ | /
       \|/
       成本
```

范围的每一次变更，都会冲击时间、成本、质量三者。

> 游戏开发中最常见的失控场景：**策划不断加需求（范围膨胀），但时间和人力不变 → 质量和士气双崩。**

---

## 常见误区

| 误区 | 真相 |
|------|------|
| "加人就能赶工期" | 布鲁克斯定律：新人需要老人带，短期可能更慢 |
| "先赶工，后期再修质量" | 后期修复成本指数级增长，且损害团队信誉 |
| "压缩成本不影响质量" | 便宜的人/工具/流程一定会以某种形式反映到质量上 |

---

## 游戏美术场景应用

### 时间优先（赶版本）
- 分级对待：核心界面精做，一般界面够用就行
- 复用已有资产，少做新东西
- 外包并行加速

### 质量优先（品牌项目）
- 给够概念设计时间（方向错了后面全是废稿）
- 标杆界面反复打磨到满意再铺量
- 宁可延期不可降品质

### 成本优先（控制预算）
- 明确哪些内部做、哪些外包
- 建立通用控件库，减少重复造轮子
- 培训生/实习生承担简单执行工作
