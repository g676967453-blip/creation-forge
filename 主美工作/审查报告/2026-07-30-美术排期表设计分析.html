核心诊断：飞书美术排期表是一张「记录表」而非「管理表」。它能记录「谁在什么时候要做什么」，但无法有效回答「有什么风险」「谁产能高」「阶段需求变化」这三个核心管理问题。10 个公式字段因 Base 旧 schema 全部不可读——恰是风险预警、产能计算、趋势预测的关键字段。

致命缺陷：风险预警机制完全失效制作风险、距交付日、预排期风险——三个最关键的监测公式字段全部不可读。主美无法在飞书表中直接看到「哪些任务逾期了」「哪些即将逾期」，只能靠人工逐条检查日期。这是 Base 旧 schema 不计算后端公式的技术限制，非设计缺陷，但影响等同设计缺陷。

🔴
「计划 vs 实际」完全断裂绩效分析的基础公式是「实际人日 ÷ 标准人日 = 效率比」。但实际人日是公式字段（不可读），实际截止时间缺失 67%。连「这个人任务做完了没有、花了多久」都回答不了，更不用说效率。目前唯一能算的指标是「完成数量」——这是最粗糙的产能指标，完全忽略任务复杂度差异。
🔴
缺少质量维度没有任何字段记录：返工次数、审核通过/打回、Bug 数、效果满意度。一个做了 100 个图标但返工 30 次的人 vs 做了 50 个一次通过的人——当前表完全无法区分。
🟡
难度字段粗粒度仅有初/中/高三级，且未强制填写。无法做「加权产出」（如 1 个高难度 = 3 个低难度）。标准人日本身可以部分替代难度权重，但覆盖不完整。
🟡
外包 vs 内部效率无法对比缺少人员类型标签（内部/外包）。当前只能靠执行人名称中的「外包-」前缀手动识别。

🔍 跨目标共性问题

1. 公式字段不可读 — 系统性根因

10 个公式字段三项目全部不可读：制作风险、距交付日、预排期风险、组别、实际人日、角色上游资源到位时间、小周、年份、月份、辅助计算（已完成/应完成）。

这些公式恰是飞书表格的核心价值——自动计算风险等级、自动计算剩余天数、自动计算人力汇总。但因为 Base 使用旧 schema 版本不执行后端公式计算，OpenAPI 读不到计算结果。用户自己在飞书界面能看到，但 AI / 自动化工具链完全读不到。

解法：升级 Base 到新 schema 版本（开启后端公式计算），一次性解决所有项目的这个问题。

2. 实际截止时间系统性缺失

三项目 57-72% 的已完成任务没有实际截止时间。这不是个别项目的管理松懈，是流程设计的系统性缺陷——「进度」字段切到「已完成」时没有强制要求填写「实际截止时间」。

影响链：无实际截止 → 无法计算延期天数 → 无法做工期准确度回溯 → 无法做人员效率评估 → 无法优化排期估算。

🛠️ 改进建议（按优先级）

P0 · 升级 Base Schema 版本（一次性，影响全部4个目标）

将 5 个项目的飞书 Base 升级到新 schema 版本，开启后端公式计算。这将一次性恢复 10 个公式字段的 API 可读性——制作风险、距交付日、实际人日等核心字段将重新可用。这是投入产出比最高的单项改进。

P0 · 进度=已完成 时强制填写实际截止时间

在飞书表中添加校验规则：当进度字段切换为「已完成」时，实际截止时间为必填。解决三项目 57-72% 的数据缺口，使延期分析、效率评估成为可能。

P1 · 统一系统名称为必填字段

设置系统名称为必填（至少对 P0/P1 任务）。建立各项目的系统名称枚举字典，收敛命名（如指尖三国的「t 塔防战斗」和「塔防战斗内」统一）。当前火影 19.4% 覆盖率是最紧迫的改善目标。

P1 · 新增「人员类型」字段

添加单选字段：内部 / 外包-个人 / 外包-供应商。目前靠执行人名称中的「外包-」前缀识别，不可靠且无法自动统计外包占比和效率对比。

P2 · 新增「质量评级」字段（轻量版）

仅需 3 个选项：一次通过 / 修改后通过 / 需重做。不需要复杂的多维度评分。这个字段是产能绩效分析从「只看数量」升级到「数量+质量」的最小可行方案。

P2 · 统一 5 个项目的业务类型字典

当前 15-19 个分类中有 4-5 个是项目特有的。建议收敛到一套 18 类的标准字典，方便跨项目横向对比和市场盘點。

P3 · 长期：考虑跨 Base 统一视图

用飞书多维表格的数据同步能力或 API 聚合，建立一个「主美总览表」，自动汇总 5 个项目的美术排期数据到一个看板中。这是从「各项目独立管理」到「主美全局视角」的架构跃迁。
