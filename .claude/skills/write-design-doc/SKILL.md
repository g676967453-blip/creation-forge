# 写策划案 — HTML 格式 v0.1

用一份 HTML 完成功能策划案，替代多份 Markdown。

## 前置步骤（必须先执行）

在写任何内容之前，**必须按顺序读取**以下文件：

1. `docs/workflows/写策划案-HTML-v0.1.md` — 完整流程定义
2. `docs/workflows/templates/功能策划案-HTML模板.html` — CSS 骨架 + 页签结构
3. 一个已有实例（如 `projects/GAME-002/策划文档/03-功能规格/2026-07-30-器灵系统/2026-07-30-器灵系统-功能策划案.html`）— 参考标准

> ⚠️ **禁止使用 `HTML原型设计规范.md` 作为参考**。那是 Pixso 导入用的 1280×720 固定画布规范，不是策划案格式。

## 产出格式

- **格式**：一份自包含 HTML 文件（`.html`）
- **骨架**：从模板复制 `:root` CSS 变量 + 页签 JS
- **5 个页签**：功能简介 → 功能规则 → 界面说明 → 动态交互 → 资产需求
- **位置**：`projects/{项目}/策划文档/03-功能规格/{日期}-{功能名}/{日期}-{功能名}-功能策划案.html`

## 界面说明规范

- 使用 `.ui-frame`（16:9 画布，`aspect-ratio: 16/9`）+ 内部绝对定位渲染界面
- 界面比例必须与 GDD 定义一致：全屏战斗 1280×720(16:9)、桌面放置态窗口 1280×120(10.67:1)、最小化态 100×100(1:1)
- 弹窗类界面必须有底层上下文（遮罩+变暗的主界面），不能漂浮在空画布中
- 关联系统的 UI 元素必须跨文件一致（如战斗 HUD 的挂件槽位在两份策划案中位置相同）
- 左侧用黄色编号圆圈 (`position:absolute`) 标注关键交互区域，与右侧 `.ui-note` 一一对应

## 动态交互规范

- 使用 `.interact-area` + 完整状态机（idle → 入场 → 操作 → 退场 → 重置）
- 交互区域的界面比例/布局与界面说明 tab 一致（不能用简化的居中抽象替代）

## 交付前 AI 自检清单

AI 交付给人类之前必须逐项自查，全部通过才能提交：

- [ ] 5 个 tab 正常切换（JS `switchMainTab` / `switchSubTab` 无报错）
- [ ] 界面说明中每个 `ui-frame` 的元素与功能规则 tab 列出的元素一一对应
- [ ] 界面比例与 GDD/需求文档定义的窗口尺寸一致
- [ ] 关联系统的 UI 元素跨文件一致（交叉检查同屏出现的元素）
- [ ] 弹窗/面板类界面有遮罩+底层主界面上下文
- [ ] 动态交互布局比例与界面说明 tab 一致
- [ ] 资产需求表格每个条目有编号(P0/P1/P2)、规格、Prompt 方向
- [ ] 无 `mark-yellow` 残留（所有待定项已转为确定或显式标注"待定"）
