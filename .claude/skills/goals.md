# /goals — 目标管理

## 触发
用户说 `/goals` 或 "定目标" 或 "做规划" 或 "复盘" 或 "检查进度" 或 "我们下一步做什么"

## 执行步骤

### 1. 定义目标（SMART 化）
导师模式提问引导：

| 维度 | 引导提问 |
|------|---------|
| S 具体 | "做完后长什么样？" |
| M 可衡量 | "怎么判断做完了？" |
| A 可达 | "以现在的节奏现实吗？" |
| R 相关 | "和造化坊大方向什么关系？" |
| T 有时限 | "什么时候完成？" |

输出目标卡片（类型 + 状态 + SMART 描述 + 成功标准）。多目标时帮排优先级。

### 2. 拆解为可执行步骤
三层拆解：目标层 → 里程碑层（含时间范围）→ 行动项层
每个行动项标注：关联项目、可用工作流、预估耗时、前置依赖

### 3. 写入体系
- 更新 `docs/目标规划.md`（活跃目标区）
- 更新 `tools/collect-data.ts` goalsUser[]
- 写入变更日志（首次时）

### 4. 关联项目和工作流
建立双向链接表（目标↔项目↔工作流↔待办）。提示用户是否导入行动项到个人待办。

### 5. 进展追踪
读取活跃目标 → 计算完成率 → 对比计划 vs 实际 → 标注阻塞项 → 输出进度摘要（含进度条）。严重落后时主动提醒调整。

### 6. 复盘
触发：月底/季度末/目标截止日。生成复盘报告（完成情况表 + 做得好 + 待改进 + 下期调整 + 经验归档）。归档已完成目标。

## 约束
- 不做空目标：必须有 SMART 描述 + 成功标准 + 至少 1 个里程碑
- 同时活跃目标 ≤ 3 个
- 至少月度复盘——复盘比设定更重要
- 目标是方向盘不是枷锁，该改就改
- 复盘必须写"为什么"和"下期怎么调"
- SMART 是引导框架不是合格性检查
