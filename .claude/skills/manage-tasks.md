# /todo — 个人待办管理

## 触发

用户说 `/todo` 或 "添加任务" 或 "记录待办" 或 "我的任务" 或 "今天做什么" 或 "扫描待办" 或 "提取任务" 或 "完成任务 [ID]" 或 "归档"

## 数据文件

`docs/个人待办.md` — 所有操作仅在此文件中进行。表格 8 列：ID/任务/状态/ABC/能量/优先级/截止日/备注。

## 执行步骤

### 1. 手动添加任务

触发：用户口述新任务（含 "添加" "记录" "记一下" "帮我加个" 等）

1. **推断分类**（用户未指定时根据上下文推断）：
   - 公司/外包/团队/评审 → 🏢 个人日常任务（D-）
   - 小红书/发帖/内容/选题 → 📱 小红书自媒体任务（X-）
   - 游戏/bug/GAME-002/开仙门 → 🎮 独立游戏开发任务（G-）
   - 造化坊/仪表盘/工作流/工具 → 🔧 造化坊迭代优化任务（F-）
   - 生活/缴费/预约/杂事 → 🏠 日常管理任务（L-）
   - 无法推断 → 追问用户

2. **推断 ABC 和能量**（用户未指定时）：
   - ABC：A=要事(和项目目标直接相关/需深度思考) B=紧急(可推迟) C=杂事(低认知负荷)。不确定默认 A
   - 能量：高能(写代码/设计/策划) 中能(审查/沟通/测试) 低能(整理/归档/报销)。不确定默认中能

3. **生成 ID**：读取文件该分类表格，取最大序号 +1

4. **追加表格行**（8 列）：`| {ID} | {任务} | 📋 待办 | {ABC} | {能量} | {优先级} | {截止日或—} | {备注或—} |`

5. **更新 `> 最后更新`** 时间戳

6. **默认同步仪表盘**（见下方「仪表盘同步」）

7. **回复**：`✅ 已添加 {ID}：{任务} → {分类名}（{ABC}类·{能量}·{优先级}）` + 是否已刷新仪表盘

### 2. 完成任务

触发：用户说 "完成 [ID]" / "[ID]做完了" / "[ID]搞定了"

1. 搜索该 ID，将 📋待办/🟢进行中 → ✅已完成
2. 将该行从活跃区移入「📦 周度归档」当周块（与项目习惯一致：完成即归档）
3. 更新 `> 最后更新`
4. **默认同步仪表盘**
5. 回复：`✅ {ID} {任务} 已完成`

### 3. 取消任务

触发：用户说 "取消 [ID]" / "[ID]不做了" / "删除 [ID]"

1. 状态改为 ❌ 已取消，移入周度归档
2. 更新 `> 最后更新`
3. **默认同步仪表盘**
4. 回复：`❌ {ID} {任务} 已取消`

### 4. 列出任务

触发：用户说 "我的待办" / "今天做什么" / "任务列表" / "有什么任务"

1. 读取文件，提取所有 📋待办 + 🟢进行中
2. 按分类分组，组内按优先级排序（🔴 → 🟡 → 🟢）
3. 显示分类汇总统计
4. 如有今日到期任务，高亮提醒

### 5. 扫描提取任务

触发：用户说 "扫描待办" / "提取任务" / "检查有什么可以加的"

**⚠️ 绝不主动执行。提取的候选清单必须经用户确认后才导入。**

**扫描源：**
- 📱 小红书：`xiaohongshu/` 帖子目录（发布频率）+ `works/` 近 7 天日志（未转化素材）
- 🎮 游戏开发：`GAME-002/策划文档/05-元文档/路线图/开仙门-V0.1-任务管理表.md`（未完成高优先级条目）
- 🔧 造化坊：`docs/workflows/改进追踪.md`（进行中改进项）+ `tools/collect-data.ts` issues/suggestions + `works/` 近期日志

**去重**：与已有任务对比，相似者跳过并标注 "⚠️ 已存在"

**展示格式：**

```
📋 候选任务清单（共 N 条）

| # | 分类 | 候选任务 | 建议优先级 | 来源 |
|---|------|---------|-----------|------|
| 1 | 🎮 | ... | 🔴 高 | GAME-002 任务管理表 |

回复「导入 1,3」导入选中，「全部导入」导入全部，「跳过 N」排除。
```

### 6. 确认导入

触发：用户回复 "导入 1,3,5" / "全部导入" / "跳过 2"

1. 为每个确认的任务生成 ID
2. 写入对应分类表格
3. 更新 `> 最后更新`
4. **默认同步仪表盘**
5. 回复：`✅ 已导入 N 条任务`
6. 用户可说 "第3条放到造化坊" 覆盖分类

### 7. 周度归档

触发：用户说 "归档" / "周度归档"

1. 扫描所有分类，提取 ✅已完成 + ❌已取消
2. 从活跃表格移除
3. 写入 "📦 周度归档" 区当周子标题下
4. **默认同步仪表盘**
5. 回复：`📦 已归档：N 个已完成，M 个已取消`

### 8. 仪表盘同步（默认开启）

在 **添加 / 完成 / 取消 / 导入 / 归档** 成功写入 `docs/个人待办.md` 之后：

1. 执行：`npx tsx tools/generate-dashboard.ts`
2. 将 `reports/造化坊仪表盘.html` 与待办 MD **一并提交**（或同一次 commit）
3. 用户说「只改待办 / 跳过仪表盘 / 先别刷盘」时 **跳过** 本步

> 网页端完成/取消/归档：仅使用本地服务 `npx tsx tools/dashboard-server.ts`（http://127.0.0.1:3456），写本地 MD，**不经 GitHub**。

## 约束

- **仅在 `docs/个人待办.md` 中操作**（仪表盘 HTML 为衍生文件，由生成器写出）
- **ID 不可重复，不可重用已归档 ID**
- **不主动操作**：所有操作由用户指令触发
- **提取必确认**：扫描的候选任务必须经用户勾选后才写入
- **表格格式**：修改时重写整个分类表格确保对齐
- **默认刷盘**：记任务后默认同步仪表盘，除非用户明确跳过

> 完整流程见 [docs/workflows/个人待办管理.md](../docs/workflows/个人待办管理.md)
