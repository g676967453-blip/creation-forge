# /new-workflow — 创建工作流（元工作流）

## 触发
用户说 `/new-workflow` 或 "建立新工作流" 或 "标准化这个流程" 或 "这个能不能做成工作流"

## 执行步骤

### 1. 发现与识别
询问用户（导师模式）：
- 这个流程的输入/输出是什么？
- 需要多少步？（简单 3-5 步 / 中等 5-10 步 / 复杂 10+ 步）
- 最近 3 次执行时发生了什么？
- 有没有常见出错情况？

输出复杂度判断和文档层级建议。

### 2. 提炼标准步骤
从用户描述 + 造化仪表盘/works/ 日志中提取：
- 步骤序列（输入→动作→输出→确认点）
- 决策点（哪里需要人判断）
- 异常分支（常见错误和兜底）
- 人机切换点

### 3. 编写知识层文档
按标准格式生成 `docs/workflows/{名称}.md`：
```markdown
> 版本：v1 | 最后更新：YYYY-MM-DD | 对应 SKILL：/xxx

## 触发条件 | ## 人机分工 | ## 执行步骤 | ## 产出物 | ## 约束与规则 | ## 关联
```

命名：中文描述名，成熟的不加版本后缀。试验阶段加 `-v0.1`。

### 4. 创建 SKILL（可选）
判断：有明确触发语句 → 创建；纯人工/试验阶段 → 跳过。格式参考本文件。

### 5. 注册到体系
更新三处（逐一确认）：
- `docs/workflows/README.md`：流程清单表格追加一行
- `docs/workflows/变更日志.md`：当天日期下新增记录
- `造化仪表盘/tools/collect-data.ts`：workflows[] 数组追加条目

### 6. 验证
走一遍核心路径，发现问题记录到 造化仪表盘/works/ 日志（不立即改文档）。

## 约束
- 必须先走"发现与识别"再写文档，不能跳过
- 文档是源头，SKILL 是派生——不能反过来
- 5 章节缺一不可（触发/分工/步骤/产出/约束）
- 必须注册三大索引，缺一个等于没发布
- v0.1 表试验，稳定后升级到 v1 去后缀
- 每次变更必须记变更日志
