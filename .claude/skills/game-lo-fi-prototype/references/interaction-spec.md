# 交互规范 (Interaction Spec)

> 本规范定义低保真原型的交互建模方法。核心：先写状态机，再画线框图。

---

## 一、屏幕状态机

每个屏幕必须定义以下状态。高频迭代时允许只标注非 idle 状态。

### 1.1 屏幕级状态

| 状态 | 触发条件 | 视觉表现 | 交互行为 |
|------|----------|----------|----------|
| `idle` | 屏幕刚进入，数据已加载 | 正常线框样式 | 所有按钮可交互 |
| `loading` | 数据/资源加载中 | 屏幕中央 [加载中…] 占位 | 阻塞交互，不显示按钮 |
| `empty` | 数据为空（如列表无内容） | 中央显示 [暂无内容] | 仅保留返回/刷新按钮 |
| `error` | 加载失败 / 网络错误 | 中央显示 [出错了] + 重试按钮 | 仅重试和返回可交互 |

### 1.2 组件级状态

每个可交互组件（按钮/列表项/卡片/开关）至少考虑：

| 状态 | 视觉 | 低保真表达方式 |
|------|------|----------------|
| `idle` | 默认外观 | 线框黑边框 + 白背景 |
| `hover` | 鼠标悬停（PC 预览用） | 光标变为 pointer |
| `active` | 按下中 | 填充灰背景（`background: var(--lo-fill)`）|
| `disabled` | 不可交互 | 强调灰边框 + 文字（`--lo-muted`）|
| `selected` | 已被选中 | 填充灰背景 + 加粗边框 |
| `focus` | 手柄/键盘焦点 | 外圈虚线框（`outline: 2px dashed`）|

```css
/* 状态样式示例 */
.lo-btn:hover  { background: var(--lo-fill); }
.lo-btn:active { background: var(--lo-ink); color: var(--lo-bg); }
.lo-btn[aria-disabled="true"],
.lo-btn.disabled { border-color: var(--lo-muted); color: var(--lo-muted); }
.lo-btn.selected { border-width: 3px; background: var(--lo-fill); }
.lo-btn:focus-visible { outline: 2px dashed var(--lo-ink); outline-offset: 2px; }
```

## 二、屏幕流转图

每个原型在 `① 场景梳理` 阶段必须产出 **屏幕流转图**，用 ASCII 或 Mermaid 格式：

```
[标题画面] → [主菜单] → [战斗 HUD]
                ↓            ↓
           [设置面板]    [暂停菜单]
                ↓            ↓
           [返回主菜单]  [返回战斗 / 放弃]
```

每一条边标注触发动作：

```
[经营主界面] ──点击山峰卡片──→ [山峰详情]
[山峰详情]   ──点击返回按钮──→ [经营主界面]
[经营主界面] ──点击天赋按钮──→ [天赋卡选择]
[天赋卡选择] ──选择卡片确认──→ [经营主界面]
```

## 三、焦点导航

### 3.1 触摸交互（竖版手游）

- 所有可点击元素最小触控区域：**44×44px**（符合 iOS HIG / Android Material）
- 高频按钮放在拇指热区（Y: 800~1334，参考 `docs/specs/vertical-game-interaction-spec.md` 第二章）
- 按钮间距 ≥ 16px，防止误触
- 滑动操作注明方向和阈值（如「左滑 60px 删除」）

### 3.2 手柄/键盘导航（PC 移植）

- 每屏标注初始焦点元素（`autofocus` 或注释 `<!-- focus: btn_start -->`）
- D-pad 方向标注在按钮旁：`<!-- up→btn_a, down→btn_c -->`
- 弹窗打开时焦点移入弹窗内，关闭后焦点回到触发按钮
- Tab 序 = 从上到下、从左到右的自然阅读顺序

```html
<!-- 焦点导航标注示例 -->
<div class="lo-menu">
  <button class="lo-btn" autofocus>        <!-- 初始焦点 -->
    开始游戏 [↓→新游戏, →→继续]
  </button>
  <button class="lo-btn">
    继续游戏 [↑开始, ↓设置]
  </button>
  <button class="lo-btn">
    设置 [↑继续, ↓退出]
  </button>
  <button class="lo-btn">
    退出游戏 [↑设置]
  </button>
</div>
```

### 3.3 焦点陷阱

弹窗/对话框打开时，焦点必须在弹窗内循环，不能「漏」到背景层：

```
弹窗打开 → 焦点移到弹窗第一个可交互元素
Tab/↓ 在弹窗内循环 → 不会跳出弹窗
弹窗关闭 → 焦点回到打开弹窗的触发按钮
```

## 四、过渡动画声明

每对屏幕之间的切换必须声明过渡方式。低保真原型中仅用注释标注，不实现动画。

| 过渡类型 | 适用场景 | 注释写法 |
|----------|----------|----------|
| `fade` | 弹窗打开/关闭 | `<!-- tr: fade 200ms -->` |
| `slide-left` | 进入子页面（层级加深） | `<!-- tr: slide-left 250ms -->` |
| `slide-right` | 返回上级页面 | `<!-- tr: slide-right 250ms -->` |
| `slide-up` | 底部弹出面板 | `<!-- tr: slide-up 300ms ease-out -->` |
| `scale` | 卡片展开/详情 | `<!-- tr: scale 200ms -->` |
| `none` | 即时切换（HUD 数值刷新） | `<!-- tr: none -->` |

## 五、反馈机制

| 交互 | 低保真表达 |
|------|-----------|
| 按钮按下 | `:active` 背景变为填充灰 |
| 加载中 | 屏幕中央显示 `[加载中…]` 占位文字 |
| 操作成功 | 顶部短暂显示 `[操作成功]` 提示条（用虚线框模拟） |
| 操作失败 | 顶部显示 `[操作失败：原因]` 提示条 |
| 确认弹窗 | 线框弹窗 + 两个按钮（确认/取消） |
| Toast 提示 | 底部浮出的 `[提示文字]` 虚线框 |

## 六、完整屏幕流转示例（用开仙门举例）

```
[开场黑幕] ──点击任意位置──→ [器灵选择]
                                ↓ 选择器灵确认
                          [经营主界面]
                           ↓        ↓
                    天赋卡选择    山峰管理
                      ↓    ↓       ↓    ↓
                   确认   取消   详情   返回
```

每一屏的 HTML 文件通过 `<a href="02-xxx.html">` 或简单的 `location.href` 实现跳转，让整个流程在浏览器中**可点击走通**。
