# [2026-08-30] 情景认知小程序：竖版 9:16 HTML 可玩原型

---

## 📋 问题解决日志

### 遇到了什么

情景认知小程序完成了数值引擎验证（`sim.js`，难度曲线护栏全通过）后停在"原型验证中"，但缺一个能让用户**亲手体验完整一局**的交互载体——README 待办里的"明确载体与核心交互设计"一直悬空。需要把《中了500万》剧本做成竖版 9:16 的可玩 HTML 原型，验证"选择 → 即时后果 → 年度结算 → 结局复盘"的核心循环是否成立。

### AI 怎么协作的

- **需求**：用 HTML 制作竖版 9:16 可玩原型，直接体验（加速器模式）
- **方案**：单文件零依赖 `prototype/index.html`，复用 MVP 剧本 18 个事件 + 6 条原则 + 白名单数值效果；自研确定性结算引擎（年度收益 / 工资 / 支出 / 负债利息 / 现金不足自动"卖资产救急链"）；结局五级分级 + 财富曲线（canvas）+ 原则命中复盘 + 模板化 AI 点评（正式版按复盘提示词换 LLM 一局一调）
- **迭代（自查发现并修复 3 处关键 bug）**：
  1. 结算函数中收益变量声明在循环内、循环外引用 → ReferenceError
  2. 结局页 canvas 在隐藏容器中 `clientWidth` 为 0 → 曲线画不出来（先显示再绘制）
  3. **流程缺陷**：结算浮层出现时会吞掉下一个事件（事件被跳过）→ 重构为 `advance()` 状态机（结算屏障 → 显示事件）
  4. 兑现"文案承诺的机制必须真实存在"铁律：集中持仓标记承诺"熊市割肉损失 ×1.5"，补上真实惩罚实现
- **验证**：用 Node + vm 沙箱 mock DOM，跑真实代码做 3 策略 × 300 局冒烟测试

### 产出结果

- `projects/情景认知小程序/prototype/index.html` — 竖版 9:16 可玩原型（单文件零依赖，双击即玩）
- 冒烟测试（N=300/策略）：

  | 策略 | HTML 原型 | sim.js 验证报告 |
  |---|---|---|
  | 稳健（全选好） | 0% 失败，100% 自由，中位 1236万 | 0% 失败，79.3% 自由，中位 1331万 |
  | 作死（全选坏） | 100% 破产 | 83.6% 失败 |
  | 随机 | **52.3% 失败**，中位 78万 | **51.5% 失败**，中位 73万 |

  难度护栏与引擎验证结论高度吻合——"会玩必赢、乱选必亏"的类魂式曲线在交互原型中成立。
