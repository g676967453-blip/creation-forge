## 📋 问题解决日志

### 遇到了什么

火影忍者项目美术排期表有 1600+ 条任务，需要快速定位风险项：哪些已逾期、哪些今天到期、哪些还没排期。手动逐条检查需要大半天。

### AI 怎么协作的

1. **确认审查范围**：通过两次迭代调整 AskUserQuestion，最终用实际项目名（指尖三国/魔兽-H5/苍穹诀/MT/火影忍者）替代内部代号（A/B/C/D/E），审查目标从预设套餐改为多选。
2. **数据读取**：通过 `lark-cli base +record-list` 连接飞书表格，用 `--filter-json` 按「制作风险」公式字段筛选（`intersects` 运算符），同时用分页读取全量 1666 条记录（9 页 × 200）。
3. **字段映射纠正**：发现火影忍者表的字段 ID 与通用配置不同 — `距交付日` 是 `fldBuBqg3a`（非 `fldYf5WZMo`）、`开发阶段` 是 `fldD6tbW7G`（非 `fldhelninQ`）。
4. **本地分析**：用 Node.js 脚本做交叉分析 — 按业务类型/执行人/开发阶段分组统计风险分布。
5. **生成报告**：输出结构化审查报告到 `主美工作/审查报告/2026-07-29-火影忍者-风险逾期.md`。

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：主美每天要盯 5 个项目的美术排期表，每个表 1000-2000 条任务。逐条翻找逾期项 = 纯体力活，还容易漏。
- 为什么这是个问题：逾期漏掉一条，可能就是版本延期一天。火影忍者今天就有 30 项即将逾期转真正的逾期。
- 如果没有 AI 会怎样：打开飞书表格 → 滚动翻页 → 肉眼扫描风险列 → Excel 导出 → 手动做透视表 → 写邮件汇报。2 小时起步。

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「审查美术」→ 选项目 → 选审查目标
- AI 给了什么方案：直接连飞书 API 读数据 → 按公式字段「制作风险」筛选 → 分页读全量 → 本地交叉分析 → 出报告
- 中间有什么调整/追问：项目名从代号改成真实名、审查深度从套餐改成多选；字段 ID 不一致时 AI 自动重新映射
- 最终方案是什么：1 分钟出报告，6 项逾期 + 30 项即将逾期全部定位到具体执行人

### 第三幕：效果展示

- 最终效果：一份结构化报告，逾期清单 + 交叉分析（按类型/执行人/阶段）+ 5 条关键发现
- 演示方式：报告截图 + 飞书数据 → 报告 的对比
- 学到的关键点：人定方向（审查哪个项目、看哪些目标）+ AI 做脏活（读数据、交叉分析、出格式）= 主美效率工具链

### 一句话总结（金句候选）

> AI 读 1600 条任务只要 1 分钟，主美只需要做判断。
