# [2026-08-06] TBH 复刻调研与实机功能分析

---

## 需求背景
老邓想复刻 Steam 独立游戏《TBH: 塔斯克巴·英雄》（AppID 3678970），需要先调研市场数据、销售数据和实际游戏功能。

## AI 怎么协作的

### 第一轮：市场数据收集
1. 用 Steam 官方 API 抓实时数据：在线人数 139,156（GetNumberOfCurrentPlayers）、评价（appreviews 43,497 Mixed / 简中 9,118 Mostly Negative）、商店信息（appdetails）。
2. 浏览器搜 Bing + web_fetch 搜狐文章（23 万人在线、热销榜 28 名、好评率跌破 30%）+ 知乎专栏（接近 30 万在线、"一整排复刻者"）。
3. 分析痛点：变现靠 DLC+市场交易、黑红走红、市场关停等事件线。

### 第二轮：跟风产品调查
1. 浏览器抓知乎专栏正文（JS evaluate 绕过登录墙），读到核心判断："一大批 TBH-like 已经在路上了"。
2. 游民星空 7/21 文章证实：跟风产品批量赶工上架，但暂无知名爆款。

### 第三轮：实机游玩 + 画面录制
1. 老邓装 Steam + 下载游戏 → 装 OBS → 开 WebSocket → 提供密码。
2. 自研工具链：
   - `obsctl.mjs`：Node WebSocket 直连 OBS v5，支持身份认证、状态查询、开始/停止录制、截图、查场景。
   - `ocr.ps1`：Windows 自带 OCR（Windows.Media.Ocr）读中文界面文字（zh-Hans-CN）。
   - `capture_loop.ps1`：后台每 8s 抓一帧 + OCR，跑 5 分钟。
3. 踩坑与解决：
   - OBS 全黑帧（亮度 0）→ 原因：TBH 窗口最小化在任务栏 → 解决方案：还原游戏窗口后正常（亮度 14.2）。
   - OCR 中文乱码 → 写 UTF-8 文件而非依赖控制台输出。
   - OBS 认证失败 → Hello 的 authentication 对象字段不标准 → 改了认证逻辑，只要有密码就发认证。

### 第四轮：OCR 逐帧分析
1. 20 帧截图 + OCR 文本时间线，识别出完整 UI 结构。
2. 关键发现：主 HUD（等级/经验/DPS/HP/技能）、底部导航（英雄/背包/商店/编队）、装备装饰系统、贸易船（市场暂不可用）、商店 DLC、设置（缩放/透明/置顶/Shift+F11/F12）。

## 视频生产草案（简化）

### 第一幕：遇到了什么
- 核心问题：「想复刻一款爆款游戏，但怎么系统了解它的市场、数据和实际功能？」
- 为什么是问题：传统做法是人工刷 SteamDB、看评测、自己录屏分析，耗时且不系统。
- 对比：AI 助手 1 小时内完成 API 抓数据 + 浏览器爬文章 + OBS 实机录制 + OCR 逐帧分析 + 输出完整功能报告。

### 第二幕：AI 怎么协作的
- 我是这样问 AI 的：「帮我收集市场数据」「由类似跟风产品吗」「我想复刻这个游戏怎么做」「你直接能帮我玩游戏录制视频写文档吗」
- AI 给了什么方案：Steam API 实时数据 + 多篇文章交叉验证 + OBS WebSocket 远程控制 + Windows OCR 逐帧识别 → 自动化分析管线。
- 中间调整：OBS 窗口采集黑屏 → 定位问题（游戏最小化）→ 解决；OCR 乱码 → UTF-8 文件 → 解决。
- 最终方案：一键启动后台采集循环，边玩边自动记录界面文字+截图。

### 第三幕：效果展示
- 最终效果：一份涵盖市场数据、竞品分析、实机功能拆解、复刻建议的功能分析报告，附视频+逐帧数据。
- 演示：视频 → [2026-08-06 10-17-43.mp4](file:///C:/Users/admin/Videos/2026-08-06%2010-17-43.mp4)
- 学到的关键点：OBS WebSocket v5 协议、WinRT OCR 的可用性、画面分析不依赖视觉模型也能做。

> AI 助手不需要"眼睛"也能做画面级游戏分析——OCR 逐帧读屏 + OBS 远程控制，一条命令开始采集，5 分钟后输出完整功能报告。
