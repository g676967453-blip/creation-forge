# [2026-07-31] 交互规范系统 — 游戏专用组件库 + 排版规则可视化标注

## 📋 问题解决日志

### 遇到了什么

交互规范系统的"基础组件规范"只有通用 UI 控件（按钮/卡片/进度条/槽位/Tab/Badge/Toggle/Input），缺少游戏行业独有的高频组件。MD 模板中的"音效规范"和"横竖屏切换"章节从未被渲染到任何 tab-panel。左侧展示图的组件虽然放入了手机画框，但没有可视化标注——尺寸线、间距 token、字号层级完全不可见，右侧表格有数据但左侧图读不出规则。

### AI 怎么协作的

**第一阶段：新增 6 个游戏专用组件**

1. 参考 uisdc 原子设计理论和 B端设计规范思路（URL 无法访问但意图明确），结构化组织游戏组件
2. MD 模板新增 `## 游戏专用组件` 章节（6 子节 × 规格表）——玩家头像 / 英雄卡牌 / 道具框 / 技能框 / TIPS / 弹窗可视化
3. 渲染器新增 80 行 CSS + 10 个渲染函数（~500 行）——所有尺寸用 **canvas 原始值 × m.scale**，告别竖版预缩放的二次缩放 Bug

**第二阶段：补齐遗漏的页签内容**

4. 发现 MD 第 15 节"音效规范"和第 16 节"横竖屏切换"从未渲染——`renderHTML()` 的 tab-panel 中没有调用
5. 新增 `renderSoundSpec()` 和 `renderOrientationSpec()`，分别放入 tab-feedback 和 tab-foundation
6. 顺带修复 spec-parser.ts 只认 LF 不认 CRLF 的跨平台 Bug（`readFileSync` 后统一 normalize 行尾）

**第三阶段：排版规则可视化标注（dataviz 方法论驱动）**

7. 用户指出"排版规则、组件大小完全没有"——调用了 `dataviz` skill 的设计系统方法论
8. 核心原则来自 dataviz：**Mark specs 必须显式标注** / **Text wears text tokens, never series color** / **Spacers 用 surface gap 可视化**
9. 新增三层标注系统：
   - `da-size-tag`（尺寸标注）— 品牌色标签，标注 canvas 像素值（`96×96` `160×220` `72×72`）
   - `da-gap-tag`（间距标注）— 信息蓝色标签，显示间距 token + px 值（`↔── md 16px`）
   - `da-type-tag`（字号标注）— 灰色标签，标注 type-scale 级别（`H2 / Body / Caption`）
10. 每个游戏组件手机框内叠加三层标注，使用绝对定位不干扰组件本身

**第四阶段：尺寸系统修正（二次缩放 Bug）**

11. 第一版组件用竖版预缩放值（如 `56×m.scale` = 96×0.583），横版 `scale=0.315` 时二次缩放导致组件偏小一倍
12. 全面改为 canvas 原始尺寸（`96×m.scale`、`160×m.scale`），竖版 720 和横版 1334 等比对照正确

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：交互规范系统的展示图有组件但没规则——英雄卡牌放进了手机框，但看不出它的尺寸是 160×220、间距是 md 16px、字号是 H2/Body/Caption。右侧表格写了这些数据，但左侧展示图完全读不出。
- 为什么这是个问题：设计规范的价值在于"看到规则"。只放组件不放标注 = 一张截图，不是规范文档。
- 如果没有 AI 会怎样：需要在 1100 行渲染器里手工添加几十处标注定位代码——每个组件的每个标注位置都要手动算坐标。

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的："左侧展示图的排版规则、组件大小，完全没有"—— AI 调用了 dataviz skill 的设计系统方法论。
- dataviz 给了什么核心原则：① Mark specs 必须显式标注尺寸 ② Text wears text tokens（文字用层级色，不用数据色）③ Spacers 用 surface gap 可视化
- AI 怎么落地的：新增三层标注系统——`da-size-tag`（品牌色尺寸标签）、`da-gap-tag`（信息蓝间距标签）、`da-type-tag`（灰色字号标签），全部绝对定位叠加到手机框内
- 中间有什么调整：第一版组件用了竖版预缩放值，横版时二次缩放全偏小一倍。改为 canvas 原始尺寸 × m.scale 后彻底解决。还修复了 spec-parser 只认 LF 不认 CRLF 的跨平台 Bug。
- 最终方案：每个游戏组件手机框 = 网格覆盖 + 组件展示 + 三层标注（尺寸/间距/字号），读者一眼能读出全部设计规则。

### 第三幕：效果展示

- 最终效果：打开 HTML，切到"布局组件"页签——英雄卡牌展示图上叠着 `160×220` 尺寸标签、`↔── md 16px` 间距标签、`H2 / Label / Caption` 字号标签。组件和规则同时可见。
- 演示方式：浏览器打开竖版/横版规范 HTML → 布局组件页签 → 滚动查看 6 个组件 + 标注
- 学到的关键点：规范文档的展示图需要同时传达"长什么样"和"为什么这样"——标注层是设计系统的可视化语言。

### 一句话总结（金句候选）

> 规范文档里的组件，不仅要让人看到"长什么样"，还要读出"为什么这样"。
