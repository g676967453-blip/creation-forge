### AI 怎么协作的

核心纠偏：第一版工作流方向搞反了——从引擎代码反推需求（逆向工程）。用户指出正确流程是 **策划文档 → 功能需求 → 美术需求**（正向设计）。

重写 v2 工作流（4 阶段纯设计）：策划解读 → 交互设计 → 视觉设计 → 资产拆解。然后用开场黑幕实战验证：

1. 读取现有 intro_screen.gd 代码和 Pixso 设计稿
2. 按功能需求模板 11 章节 → 输出需求文档
3. 按 v2 工作流 4 阶段 → 输出美术需求文档
4. 参考小红书流程，用纯内联样式 HTML 制作交互原型

过程中发现：
- 开场黑幕是「全屏界面—极简型」，零美术资产需求——证明了工作流对"不需要资产"的界面同样有效
- Pixso MCP 初次会话 SSE 握手失败，重启会话后通过 HTTP 直连（Streamable HTTP 传输）成功建立连接

### 2026-07-22 续：Pixso 导入完成

通过直接 HTTP 调用 Pixso MCP（`http://127.0.0.1:3667/mcp`），使用 MCP Streamable HTTP 协议：

1. `initialize` → 获得 session ID
2. `code_to_design` → HTML 原型导入 Pixso 画布 ✅
3. `apply_design` → 重命名 Frame 为「开场黑幕」 ✅
4. `get_export_image` → 导出 PNG 预览 → `ui-prototypes/开场黑幕_Pixso导入预览.png` ✅

技术细节：Pixso MCP 使用 Streamable HTTP 传输（非经典 SSE），要求请求头同时接受 `application/json` 和 `text/event-stream`。

### 2026-07-22 续2：UI 图层架构与命名规范 v2 + 三界面实战验证

**核心问题**：导入 Pixso 后图层名为 HTML 标签（`div`/`p`），丢失语义。引擎（Unity/Godot）需要可解析的命名规则来拼接界面。

**对标参考**：Unity UI 框架（`StoreUi → Bg → Root → CloseBtn → TabList → Tab1 → ...`），提炼 5 固定名 + 5 后缀体系。

**产出**：

| 产出 | 文件 | 说明 |
|------|------|------|
| 规范 v2 | `docs/workflows/GAME002-UI层命名规范.md` | 5 固定名（Bg/Mask/Root/Icon/RedPoint）+ 5 后缀（-Ui/-Btn/-List/-Text/-Item） |
| HTML ×3 | `ui-prototypes/器灵选择/经营主界面/山峰菜单.html` | 按规范标注 @pixso 注释 + DOM 顺序修正 |
| Pixso ×3 | 器灵选择(3:752) / 经营主界面(3:866) / 山峰菜单(3:931) | 全自动 7 步导入 + 居中校准 |
| PNG ×3 | `*_Pixso预览.png` | 视觉存证 |

**关键技术发现**：

1. **DOM 反序**：`code_to_design` 将 absolute 元素的 DOM 顺序**反转**到 Pixso 图层树。DOM：`Root → Mask → Bg` → Pixso：`Bg → Mask → Root`
2. **全自动导入（7 步）**：`code_to_design` → 找 html Frame → `I()` 创建命名 Frame → `query_nodes` 找 section → `M()` 移入 → `D()` 删壳 → `U()` 居中校准
3. **M() 移入后必居中**：section 可能偏移，须显式设 `x:0, y:0` 并校验尺寸

## 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：游戏 UI 制作流程混乱，AI 协作时不知道从哪里开始
- 为什么这是个问题：AI 习惯从已有代码反推需求，但正确的开发流程是设计先行
- 如果没有 AI 会怎样：需要产品经理写 PRD、美术出设计稿、开发看文档实现——三个角色串行

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：直接指出第一版工作流搞反了，要求正向设计
- AI 给了什么方案：v2 工作流——4 阶段纯设计（策划解读→交互设计→视觉设计→资产拆解）
- 中间有什么调整：从"代码反推"翻转为"策划文档输入"，去掉了引擎实现阶段
- 最终方案：工作流聚焦「策划→美术需求」转化，产出标准 5 章美术需求文档

### 第三幕：效果展示

- 最终效果：一条完整文档链路：功能规划 → 功能需求 → 美术需求 → HTML 原型
- 演示方式：文档截图 + HTML 原型演示
- 学到的关键点：工作流的入口决定了一切——从策划文档进，产出的是设计；从代码进，产出的是逆向笔记

### 一句话总结（金句候选）

> 工作流的入口错了，后面全错。UI 制作的起点是策划文档，不是 Godot 工程。
