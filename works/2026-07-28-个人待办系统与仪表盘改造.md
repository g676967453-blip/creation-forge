## 📋 问题解决日志

### 遇到了什么

需要为造化坊建立统一的个人任务管理中心，替代分散在飞书 Base、仪表盘硬编码、GAME-002 任务表等处的任务管理。同时发现仪表盘「任务看板」和新建「个人待办」功能重叠，工作流清单分类也需要更贴合实际项目结构。

### AI 怎么协作的

1. **设计阶段**：扫描现有系统（works/、collect-data.ts、GAME-002 任务表、docs/workflows/），提出三层分离方案：数据层 Markdown → 采集层 TypeScript → 展示层 HTML
2. **实现阶段**：按「知识层文档 + SKILL 执行层」双层层模式创建完整系统，包含 7 种操作（添加/完成/取消/列出/扫描提取/确认导入/周度归档）
3. **集成阶段**：
   - 飞书 Base 读取：通过 lark-cli 补授权（wiki/bitable/base 三个域），读取「核心目标」「循环任务」「每日待办日志」三表，导入 17 条任务
   - 任务看板合并：11 条历史里程碑迁入归档区，删除旧页签和硬编码数据
   - 工作流面板改造：标签改名、分类重组（造化坊/自媒体/游戏开发/SKILL仓库）、工作流行点击弹详情
4. **问题修复**：emoji 正则解析、飞书 API 权限缺失（两次补授权）、任务池表不可访问（TableIdNotFound）

### 产出结果

| 产出 | 路径 |
|------|------|
| 任务数据文件 | `docs/个人待办.md`（25 条任务 + 11 条历史归档） |
| 工作流文档 | `docs/workflows/个人待办管理.md` |
| SKILL 文件 | `.claude/skills/manage-tasks.md` |
| 数据采集 | `tools/collect-data.ts`（新增 `loadPersonalTasks()`，移除旧 `tasks[]`） |

| 文档同步 | README.md、变更日志.md、仪表盘更新.md 全部更新 |

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：任务管理分散在飞书 Base、仪表盘硬编码代码、GAME-002 文档等多处，信息割裂、维护成本高
- 为什么这是个问题：每次新增/完成任务都要改 TypeScript 代码重新生成仪表盘，无法快速响应
- 如果没有 AI 会怎样：需要手动在飞书和代码之间来回迁移数据，工作流和任务管理互相独立无法联动

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「新建一个任务代办系统，目标个人日常任务、小红书自媒体任务、独立游戏开发任务、造化坊迭代优化任务、日常管理任务」
- AI 给了什么方案：Markdown 作数据库 → TypeScript 解析器 → HTML 仪表盘展示，双层层模式（知识文档 + SKILL 指令）
- 中间有什么调整/追问：
  - 「需要集成到仪表盘」→ 新增采集函数和页签
  - 「从已有项目提取任务」→ 扫描 GAME-002 任务表/改进追踪/飞书 Base
  - 「任务看板和个人待办是否重叠」→ 合并为统一系统
  - 「工作流清单分类不合适」→ 改造为造化坊/自媒体/游戏开发
- 最终方案是什么：一个 Markdown 文件管理全部 25 条任务，AI 对话随时增删改，仪表盘自动同步展示

### 第三幕：效果展示

- 最终效果：对话中说「添加任务」或「我的待办」即可管理，仪表盘 8 页签完整展示工作流和任务
- 演示方式：打开 reports/造化坊仪表盘.html → 工作流页签点击行看弹窗 → 个人待办页签切换分类
- 学到的关键点：Markdown 做轻量数据库 + AI 做读写接口 = 零依赖的个人管理系统

### 一句话总结（金句候选）

> 最好的工具不是最复杂的那个，是你在对话里说一句话就能用的那个。
