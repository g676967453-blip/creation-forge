# 2026-07-28 独立游戏功能开发流程 v0.1 定义

---

## 做什么

经过一整天对器灵界面流水线的跑通、Lovart 三轮迭代、规范体系搭建，最终收敛为一套**「独立游戏单人+AI 协作」的功能开发标准流程**。

核心变化：从原来 5-6 份文档、5-6 次确认的"重型流程"，收敛为 **1 份简报 + 3 线并行 + 3 次确认**。

## AI 怎么协作的

1. 跑通器灵界面全链路，暴露三个系统性缺口（策划模板、HTML 设计规范、Lovart 视觉约束）
2. 搭建三套规范体系（三份执行模板 + UI 设计规范 + 组件库 + 色板图 + Lovart Prompt 模板）
3. 讨论后收敛：**对于单人+AI 协作，最好的文档就是最少的文档**
4. 程序规格 = 代码顶部注释，数值规格 = CSV 备注，美术规格 = HTML 原型本身
5. 最终形态固化为 [独立游戏-功能开发流程-v0.1](../docs/workflows/独立游戏-功能开发流程-v0.1.md)

## 视频生产草案

### 第一幕：问题

独立开发者 + AI 协作，做功能经常陷入两种极端：要么不写文档直接写代码（后面越改越乱），要么写一堆文档维护不过来（文档变成负债）。能不能找到一条**刚好够用**的中间路线？

### 第二幕：AI 怎么协作解决

- 先走通一个案例（器灵界面），故意暴露所有问题
- 从案例中提炼出「哪些文档真的有用、哪些只是自我感动」
- 关键发现：程序规格不应该是独立文档——写在代码顶部注释里，和代码一起版本管理，永远不会过期。美术需求不需要长篇文字——HTML 原型本身就是最精确的规格。
- 收敛为：1 份功能简报 → 3 线并行（HTML原型+资产清单+程序代码）→ 3 次确认

### 第三幕：效果

- 展示完整流程文档的结构
- 展示 HTML 原型 → Lovart 概念图的参考图链路
- 展示 .gd 代码顶部注释 = 程序规格
- 核心认知：**对于单人+AI，最好的文档就是最少的文档**

### 金句候选

> 传统团队的文档是为了人类之间的沟通。单人+AI 的文档是为了 AI 的执行——多一行都是浪费。
