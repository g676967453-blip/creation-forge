## 0. 先读这段（给新会话 / 其他 AI）

## 1. 六段标准循环总览

```
① 需求输入        ② 规格化          ③ Prompt 工程        ④ 生成迭代           ⑤ 验收             ⑥ 归档交付
[人/项目文档] → [批次规格表] → [模板+色彩约束] → [Lovart 无限模式] → [人眼+清单] → [后处理 → 桌面]
     │               │                │                │                 │                │
  需求/参考图      型号·尺寸·命名    Prompt 定稿       草稿→成品→迭代       PASS/FAIL        落盘+汇报+登记
    👤人类          🤖AI+👤确认       🤖AI             🤖AI 执行           👤人类终审         🤖AI 执行
```

| 段 | 做什么 | 产出 | 责任人 | 主要检查点 |
|----|--------|------|--------|-----------|
| ① 需求输入 | 明确"要什么资产、给谁用、什么风格" | 结构化需求（含参考图） | 👤 人类发起 | 需求可被翻译成 Prompt；有项目美术规范引用 |
| ② 规格化 | 定 类型/尺寸/格式/命名 → 建**批次规格表** | 批次规格表（§6） | 🤖 起草 + 👤 确认 | 型号/尺寸/命名三要素齐（防坑#11-14） |
| ③ Prompt 工程 | 模板填变量 + 项目色彩约束 + 强制关键词 | Prompt 定稿 | 🤖 AI | 模板变量无遗漏（坑#14）；英文直写；禁裸头身短语（坑#10） |
| ④ 生成迭代 | 草稿 NBP → 方向确认 → 成品模型；同主题复用 thread | 候选图 → 精修图 | 🤖 执行 + 👤 选向 | 先草稿后成品；批次行-图三要素核对（坑#11-13） |
| ⑤ 验收 | 人眼看 + 通用清单对照 | PASS/FAIL 结论 | 👤 人类终审 | [04-质量验收标准.md](04-质量验收标准.md) §1-6 |
| ⑥ 归档交付 | 后处理脚本链 → 桌面落盘 → 汇报 → 项目侧登记 | 桌面最终 PNG + 汇报 | 🤖 AI | 尺寸精确/命名合规/桌面路径（§5） |

## 2. 各段执行细则

### ① 需求输入

- 来源可以是：人类一句话 / 项目美术需求文档（如 [GAME-002 原画需求](../../projects/GAME-002/美术制作/01-原画需求/)）/ 美术体验需求模板（系统层 `docs/workflows/templates/美术体验需求模板.md`）。
- 需求必须能回答三问：**什么资产**（类型/数量）、**给谁用**（哪个项目、哪个界面/场景）、**什么风格**（风格参考图 > 文字描述；项目规范优先）。
- 产出 = 一句话规格 + 参考图 URL（如需要）+ 落进批次规格表第一列。

### ② 规格化（批次规格表 = 单一事实源）

- **每个批次开工前必须先建规格表**（模板见 §6），存 `../outputs/{项目}/_batches/{批次}.md`。
- 表内一次性定死：每张资产的 **型号/尺寸/命名/目标桌面路径/验收人**；后续所有步骤对照此表，避免"行-图错位"（坑#11-13 的血泪教训）。
- 批次完成后表格保留为过程数据（repo 内合法，媒体不进 repo）。

### ③ Prompt 工程

- 取对应模板（§4 映射表），只填变量、保留全部**强制关键词**（模板内已标注），叠加该项目的**色彩约束/禁止色**（如 GAME-002 色彩互斥矩阵，位于 `../../projects/GAME-002/美术制作/开仙门-美术绘制规范-v2.md`）。
- 语言纪律：**英文直写**（中文经 Lovart 转译会语义漂移，坑#9）；头身比用**分数锚点句**、禁裸 "X heads tall"（坑#10）。
- 方法细节见 [02-Prompt工程.md](02-Prompt工程.md)。

### ④ 生成迭代（Lovart）

- 账号默认**无限模式**（免费排队）；如需快速出图再临时 `set-mode --fast`，用完切回。
- **先草稿后成品**：草稿 = Nano Banana Pro 验证方向（2-3 候选）；方向经人类确认后，成品用 §4 映射的成品模型。
- **同主题同 thread**：迭代修改必须带 `--thread-id`（改什么说什么，见 01-协作模型 反馈纪律）。
- **批次行-图核对**：批量 chat 返回后，下载前先核对产物与规格表行一一对应（坑#11/12/13；必要时用汇总表映射，勿盲信顺序）。
- 处理 `final_status`：`done`（有产物）/ `pending_confirmation`（**先问人类再 confirm**，不自动确认）/ `timeout`（`result` 补收）/ 静默失败 `generation_succeeded=false`（换模型或改 Prompt 重试）。
- 生成期间保持浏览器 Lovart 页面关闭（Canvas 编辑与 API 冲突）。

### ⑤ 验收

- **人眼是最终裁判**：AI 可辅助核对技术项（尺寸/命名/格式/品红残留/像素边缘），审美项必须人类点头。
- 通用清单：[04-质量验收标准.md](04-质量验收标准.md)（像素保真/色彩合规/构图/题材/技术规格/横向一致性）。
- 同系列 2+ 张后必须做横向一致性对比（风格/像素密度/光照/比例）。
- FAIL → 回到 ④（复用 thread）→ 重新验收；同批次多张时逐行记录状态。

### ⑥ 归档交付

1. **后处理链**（按类型选脚本，见 §4 脚本列；参数按规格表目标尺寸）；
2. **落盘桌面** `{桌面}/asset-pipeline-outputs/{项目}/{类型}/{命名}.png`（路径解析见 §5）——媒体**绝不**进仓库；
3. **汇报**：按 [../CLAUDE.md](../CLAUDE.md)「生成完成汇报模板」给出 状态/本地文件/链接/线程/模型/积分/工作流/画布；
4. **登记**：批次规格表该行 → `已归档`；游戏项目侧按需复制进 `assets/` 或绝对路径引用。

## 3. 桌面产出目录规范（意图 3 硬规则）

```
{桌面}/asset-pipeline-outputs/
└── {project-name}/
    ├── portraits/   ← 角色原画（胸像/半身/全身）
    ├── sprites/     ← 精灵表
    ├── icons/       ← 图标（功法/物品/建筑）
    ├── vfx/         ← 特效帧动画
    └── ui/          ← UI 元素
```

- **{桌面} 解析规则**：以实际机器为准 —— 本机（09-05 实测）`C:\Users\Administrator\Desktop\`；换机器先 `echo $USERPROFILE`，**勿照抄文档用户名**（曾致路径全线失效）。
- **命名**：`{项目标识}_{资产类型}_{角色/物体}_{变体}.png`（示例：`GAME-002_portrait_sword-master_bust.png`）。
- **repo 只收**：本文档/工作流/模板/脚本/批次规格表与过程 JSON/参考图（`_references/`、`cankao/`）。媒体产出进 repo = 违规。

## 5. 本机运行配方（2026-09-05 实测）

```powershell
$env:PYTHONUTF8=1                          # 防 GBK 解码崩溃（读 state.json）
$env:HTTPS_PROXY='http://127.0.0.1:7897'   # 外网直连被重置，必须代理
$env:HTTP_PROXY=$env:HTTPS_PROXY
# 装载凭据（~/.lovart/credentials.env）后：
python "C:\Users\Administrator\.agents\skills\lovart-api\agent_skill.py" <命令>
```

- Lovart 基址与桌面根的用户名**以实际机器为准**；官方 skill 基址在本机为 `.agents\skills\lovart-api`（repo 内 `lovart.ps1` 查找链不含该路径，直接用上面的 python 调用）。
- 完整命令速查见 [../CLAUDE.md](../CLAUDE.md)「Lovart 命令速查」。
