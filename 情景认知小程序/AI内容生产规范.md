# AI 内容生产规范 — 事件扩写流程

> 日期:2026-08-08 · 适用范围:所有剧本的事件内容生产 · 原则:脊椎人工,血肉 AI,审核入库

## 一、事件数据 Schema(与 sim.js 一致,JSON 化)

```json
{
  "id": 19,
  "name": "事件名(6字内)",
  "stage": 1,
  "scene": "情景文案(2-3句,含具体数字与人物)",
  "needScam": false,
  "options": [
    {
      "text": "选项文案(承诺的机制必须真实存在)",
      "g": ["p3"],
      "b": [],
      "effect": { "cash": -500000, "scam": true, "expense": 0, "debt": 0, "growth": 0, "stable": 0, "property": 0 },
      "feedback": "局中反馈语(黑色幽默,1句)"
    }
  ]
}
```

**铁律**:effect 里写的每一项数值变化,都必须在选项文案中能找到对应承诺;文案承诺的机制必须真实存在(教训来自原型验证:空头文案导致难度曲线失真)。

## 二、可选数值效果(白名单)

| 效果 | 说明 | 参考量级 |
|---|---|---|
| cash | 现金增减 | 小额1-50万 / 大额100-300万 |
| expense | 月支出增减(永久) | +1万~+3万/项 |
| debt | 负债增减 | 10万~200万 |
| stable | 稳健资产增减 | 50-200万 |
| growth | 进取资产增减 | 50-300万 |
| property | 房产增减 | 80-200万 |
| scam | 骗局标记(资金视为已损失) | true/false |
| concentrate | 集中持仓标记(熊市损失×1.5) | true/false |
| locked | 资金锁定标记(提前支取损失2%) | true/false |

## 三、事件族与参数化规则

1. 人情类(亲戚/发小/同学/伴侣):参数 = 关系 × 金额 × 理由。金额参考:可损失额度 ≤50万为"聪明",≥100万或担保/借名为"危险"。
2. 骗局类(荐股/P2P/币圈/海外存款/课程):参数 = 骗局类型 × 渠道(微信群/银行/讲座/朋友)× 收益率。红线:承诺收益率 >8% 且"保本" = 骗局信号。
3. 市场类(牛熊/板块/消息股/楼市):参数 = 涨跌幅度 × 时间点。教训:追涨杀跌、割肉、All in 均为坏选项。
4. 消费类(车/房/奢侈品/教育):参数 = 品类 × 金额 × 家庭压力。教训:消费升级永久抬高月支出,是隐性通胀。
5. **同族互斥**:同一决策族的多个事件(如"买房"族:换大房子/丈母娘买房)每局最多出现 1 个,防止同族叠加击穿现金流(family 字段标记)。
6. **模型变量**:玩家有月收入(0.8万);现金不足时自动"卖资产救急"(进取9折→稳健95折→房产85折→最后才负债);"第一笔安排"类锚点事件固定最早出现。

## 四、LLM 扩写提示词规范(离线批量)

```
你是理财情景游戏的编剧。基于以下模板扩写 5 个变体,输出 JSON 数组。

【模板】{模板 JSON}
【原则库】p1保命钱(含保险) p2先存后花 p3天上不掉馅饼 p4别放一个篮子(含长期) p5买资产不买负债 p6救急不救穷
【规则】
1. 只允许绑定上述 6 条原则,禁止引入新原则
2. 每条选项绑定 0-2 条原则,好选项 g、坏选项 b,禁止好坏混标
3. 数值效果只能使用白名单,量级参考模板
4. 文案承诺的机制必须真实存在于 effect 中
5. 情景必须符合中国现实语境,禁止出现具体产品名、收益承诺、荐股内容
6. 反馈语用黑色幽默,1 句,20 字内
7. 输出合法 JSON,不要任何解释文字
```

## 五、人工审核清单(入库前必查)

1. 事实数字准确性:通胀、税率、收益率等数字需 2-3 个来源交叉核对
2. 原则绑定正确性:选项与原则语义一致,禁止原则错配
3. 机制真实性:文案承诺 ↔ effect 一一对应
4. 合规红线:无具体产品推荐、无收益承诺、无"稳赚"表述、无荐股倾向
5. 平衡性:坏选项损失在量级范围内,好选项收益不超模板
6. 敏感词:涉政、涉黄、歧视、地域黑等一律否决

## 六、入库流程

1. 编剧(人工)设计模板 → 2. LLM 批量扩写变体(离线) → 3. 人工按审核清单逐条过 → 4. 接入 sim.js 跑 2000 局 × 4 策略,验证难度曲线护栏(稳健 100% 守住+、大众新手 ≥50% 失败、韭菜 ≥80% 失败) → 5. 通过后入库发布

**难度曲线护栏**:任何新增事件不得改变三条基准线(稳健 0% 失败 / 新手 ≥50% 失败 / 韭菜 ≥80% 失败)。若曲线漂移,优先调事件数值,不调基准线。
