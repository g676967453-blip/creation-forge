# 【Steam 路径】

## 1. 时间线总览

| 阶段 | 时间节点 | 关键动作 | 目标 |
|------|---------|---------|------|
| 商店页面上线 | **能展示的第一天**（Chris Zukowski） | Steamworks 创建商店页 → Capsule 图片 → 标签 → Trailer + 截图 | 不等到"准备好"——病毒传播随时发生 |
| 愿望单积累期 | 商店页上线 → 发布（至少 4-6 月） | 社交媒体宣传 → Demo key 分发 → 参加 Steam 游戏节 | 愿望单 [____] |
| Steam Next Fest | 发布前 1-2 季度 | 提交 polished demo → 准备直播 → 积累社区 | 愿望单集中增长（单次 7,000+ = 金级） |
| 抢先体验（EA） | [日期/条件] | 定价 → 发布 EA → 收集反馈 | 验证市场 + 现金流 |
| 正式发布 | [日期/条件] | 发布周 → influencer 覆盖 → 社区运营 | 首周销量最大化 |

## 2. 90 天发布计划

| 时段 | 动作 |
|------|------|
| **D-90 ~ D-60** | 锁定发布日期（避开 AAA 大作和 Steam 大促）→ 最终优化商店页 → 发布日公告 → Demo bug-squash |
| **D-60 ~ D-30** | 社交内容转向核心玩法展示/迷你教程 → 密集 influencer 外联（30-50 人，优先 nano/micro 创作者）→ 社区活动 |
| **D-30 ~ D-Day** | 商店页压力测试 → 协调创作者首日覆盖 → **清空日程——发布周全职投入** |

## 3. 发布周清单

| 动作 | 说明 |
|------|------|
| 每日热修 | 致命 bug 24-48h 内修复 |
| 每条评论回复 | 差评尤其——礼貌、感谢、说明修复计划 |
| 已知问题公开 | 社区公告列出已知问题，避免重复差评 |
| 追踪流量来源 | Steamworks 后台分析 |
| 发布感谢 devlog | 公开玩家数据/里程碑，保持可见活跃 |

## 4. Five Update Visibility Rounds

| 规则 | 说明 |
|------|------|
| ❌ 不用在发售首两周 | 还在享受首发流量 |
| ❌ 不用在 Steam 季节性大促 | 展示不显示但计时器仍在跑 |
| ✅ 留给重大内容补丁 | 新功能、EA→正式版过渡 |
| ✅ 首发后等 3-4 周 | 再启动第一轮 |
