## 0. 立项前自检——先定义体验，再选择玩法

> ⚠️ **玩法 ≠ 体验**。不要说"我想做一个 Roguelike 卡牌游戏"（这只是玩法），要说"我想让玩家在每局 15 分钟内体验步步为营的生存压迫感"（这才是体验）。同一个玩法可以对应海量体验。从体验出发，你才有真正的设计自由度。

### 体验目标（单选或排序前 2）

- [ ] 紧张感 / 生存压迫
- [ ] 成长的满足感 / 变强的快感
- [ ] 探索与发现的惊喜
- [ ] 策略优化的智力快感
- [ ] 社交互动与归属感
- [ ] 放松与沉浸
- [ ] 竞争与排名驱动

### 3选2 选择

你的核心玩法由哪两个构成？（选 3 个则第 3 个必须降级为轻量辅助）

- [ ] 🏗️ **建造**（种田/城市营造/基地建设/沙盒）—— 代表：星露谷物语、环世界、饥荒
- [ ] 🎭 **角色扮演**（NPC好感度/剧情探索/日常故事/流程关卡）—— 代表：波西亚时光、守墓人
- [ ] ⚔️ **战斗**（塔防/装备养成/Roguelike/地牢）—— 代表：八方旅人、吸血鬼幸存者

> ⚠️ **关键约束**：玩法内核不超过 3 个，与开发体量无关，只与玩家专注度有关。

## 3. Design Pillars（设计支柱）

> **定义**：3-5 条不可妥协的指导原则。它们是你做所有设计决策时的仲裁标准——如果新功能不支撑任何一根支柱，就砍掉。

| 2 | [支柱名] | [描述] | [测试方法] |
| 3 | [支柱名] | [描述] | [测试方法] |
| 4 | （可选） | | |
| 5 | （可选） | | |

示例：
- **"紧张但公平"** —— 玩家在失败后能解释自己错在哪，而非觉得游戏耍赖。测试：每次死亡画面显示死因。
- **"每一次运行都是独特故事"** —— 不是因为随机种子不同，而是因为玩家做出了不同的有意义选择。测试：连续 3 局录像，逐个比对决策分歧点。
