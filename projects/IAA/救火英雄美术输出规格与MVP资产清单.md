## 0. 一页结论（给制作的人看）

| 项 | 规定 |
|---|---|
| 画幅 | 竖屏 **9:16**；逻辑分辨率 **450×800**；交付默认 **@2x = 900×1600**（买量/商店图另见 §3） |
| 风格 | 清爽卡通 Q 版；轮廓清晰、色块干净；**禁止**写实厚涂进局内 |
| 构图 | 正面平视大楼、无透视；窗户网格约占画面 **≥80%**；底部操作区极窄 |
| 版权 | 不抄 FC《Flying Hero》造型 / 关卡布局 / 音乐；全部原创或授权 |
| MVP 范围 | **小猫完整** + 窗/火三态 + 蹦床 + 核心道具 6 + 基础 UI 5 + 定稿概念 1；小狗可「换头/换色」 |
| 非 MVP | 熊猫/卡皮巴拉/哪吒全动画、多主题大楼、合成皮肤、完整买量 20 套（进 P1） |
| 验收 | 仓库有定稿图+色板；关键层可从程序绘替换为 PNG；命名 100% 符合本表 |

## 1. 风格锁定（Style Lock）

### 1.1 必须遵守

1. **气质**：明快、可爱、消防主题；夜景火场可以有，但角色与 UI 仍要「卡通可读」，不要赛博丧。
2. **透视**：大楼立面 **完全正面**；窗户横平竖直；禁止大透视、仰视、斜 45° 楼体。
3. **信息优先级**：玩法物体（窗/火/人/蹦床/主角）＞装饰；装饰不得抢对比度。
4. **角色比例**：两头身～两头半；局内主角体量小（对齐原型「球」尺度），**不要**做成半屏大立绘进关卡。
5. **统一描边**：建议 2–4 px 逻辑描边（@2x 对应 4–8 px），深色描边，禁止细碎线稿噪音。

### 1.2 色板（与现有原型对齐，可微调但需整包替换）

| Token | Hex | 用途 |
|---|---|---|
| `bg.night` | `#0B0F1A` | 页面/夜空底 |
| `bg.facade` | `#1A2340` → `#12182B` | 楼体渐变参考 |
| `fire.main` | `#FF8A3C` | 主强调、按钮、火焰主色 |
| `fire.hot` | `#FF3B30` | 高级火焰 / 危险 / 失败 |
| `gold` | `#FFD24A` | 金币、标题高光、选中态 |
| `safe` | `#7EF0A0` | 正向反馈、获救 |
| `water` | `#7FD4FF` | 水/灭火器/冷却 |
| `suit.cat` | `#FFB74D` | 小猫服 |
| `helm.cat` | `#E64A19` | 小猫盔 |
| `text.main` | `#FFFFFF` | 主文字 |
| `text.sub` | `#FFE9C9` | 次文字 |

> 定稿后将本表复制为 `art/style/palette.json`（可选）；AI 出图提示词必须带上 3–5 个主色 hex。

### 1.3 与 Lovart 概念图的关系

- `_lovart_prompt.txt` 为 **构图与氛围母版**。
- **买量 / 商店 / 启动图** 可贴近概念图的手绘感。
- **局内 sprite** 必须降复杂度：同角色、同配色、同消防符号（红盔 / 反光条 / 水带），去掉厚涂与大场景纵深。

## 2. 技术规格（输出硬约束）

### 2.1 分辨率与倍率

| 用途 | 逻辑尺寸 (1x) | 交付尺寸 (默认 @2x) | 格式 |
|---|---|---|---|
| 游戏舞台参考 | 450×800 | 900×1600 | — |
| 局内 sprite / UI 切片 | 见 §4 元件表 | 逻辑×2 | PNG-24，**透明底** |
| 全屏背景 / 启动闪屏 | 450×800 | 1080×1920 可另出 @2.4 | PNG 或 WebP |
| 角色选择/商店卡 | 160×200 | 320×400 | PNG 透明或浅底 |
| 概念定稿 / 买量静帧 | — | **1080×1920** | PNG/JPG |
| 图标（微信/抖音） | 按平台 | 平台要求（常 512²） | PNG |

- 默认只交 **@2x**；若引擎/小游戏需要 @3x，再统一放大，禁止同一批混用倍率。
- 透明 PNG：**预乘 alpha 关闭**；边缘禁止白边/黑边；不要 JPG 冒充透明图。

### 2.2 画布与安全区（对齐原型常量）

```
逻辑画布 W=450  H=800
HUD 带      y ≈ 0–56
窗户网格顶  GRID_TOP = 80
窗格        7 列 × 48×48，间隙 4
楼体外边距  FACADE 左右自动居中
地面操作区  y ≈ 660–800（H-140 起）
蹦床基准    PW=92  PH=18  PY=H-150
弹射体半径  r≈7（绘制上主角约 28–40px 高）
```

**安全区**

- 顶部：系统刘海/胶囊预留，关键 HUD 不要贴 y=0。
- 底部：拇指滑动区，装饰可有，**可点控件不要只放在最底 24px**。
- 左右：窗格与角色勿贴边；导出 sprite 四周留 **2–4 px（1x）透明 padding**。

### 2.3 文件命名（强制）

```
{域}_{对象}_{状态或动作}_{可选序号}.png
```

| 域 | 含义 | 示例 |
|---|---|---|
| `char` | 角色 | `char_cat_fly_00.png` |
| `win` | 窗户 | `win_fire_lv2.png` |
| `prop` | 道具 | `prop_bag.png` |
| `fx` | 特效 | `fx_splash_00.png` |
| `ui` | 界面 | `ui_btn_main.png` |
| `bg` | 背景 | `bg_night_city.png` |
| `meta` | 定稿/色板/参考 | `meta_style_lock_v1.png` |

规则：

- 全小写英文；单词用 `_`；禁止空格与中文文件名。
- 角色 id 固定：`cat` / `dog` / `panda` / `capy` / `nezha`。
- 序列帧两位数：`00` 起。
- 同一语义只有一版定稿进 `art/final/`；草稿进 `art/wip/`。

### 2.4 目录约定（建议落在本项目下）

```
IAA/
  art/
    style/           # 定稿、色板、禁止参考说明
    wip/             # AI 草稿、未精修
    final/
      characters/
      windows/
      props/
      fx/
      ui/
      bg/
    export/          # 图集、JSON（可选）
    ads/             # 买量静帧/封面（P1）
  救火英雄美术输出规格与MVP资产清单.md   # 本文件
```

> 大体积生成图若不进 Git，可镜像到桌面产出目录，但 **final 清单与命名仍以本表为准**，并在 PR/日志里写本地路径。

### 2.5 图集与程序对接（HTML 原型期）

- 单图切片优先；需要打包时再出 spritesheet。
- 若沿用原型导出习惯：可提供 `fire-hero-assets.json` 风格清单：`{ key, name, w, h, x, y, scale }`，**w/h 写逻辑像素**。
- 关键替换层（程序优先读图，缺图 fallback 程序绘）：

| 层级 | key 前缀 | 说明 |
|---|---|---|
| 角色 | `char_*` | 弹射体 + 蹦床左右消防员 |
| 窗户 | `win_*` | normal / fire_lv1–3 / rescue / rescue_red |
| 蹦床 | `prop_trampoline*` | 含正常/着火 |
| 道具 | `prop_*` | 掉落物与商店 icon 共用 |
| UI | `ui_*` | 按钮与面板可先 CSS，图优先标题与主按钮 |

## 3. 分类输出标准

### 3.1 角色（Characters）

| 项 | MVP 要求 |
|---|---|
| 识别 | 猫头/狗头等物种特征在 **24×24 px 逻辑缩略** 仍可辨 |
| 服装 | 消防盔 + 反光条 +（可选）小水带；物种差异优先做在 **头/耳/尾** |
| 朝向 | 默认「头朝上」；左右可用镜像，不必交两套（哪吒技能除外） |
| 帧 | MVP 只要求 §4 列出的帧；不要先做 8 向走 |

## 5. 验收标准（Definition of Done）

### 5.1 单资产

- [ ] 命名、尺寸、透明底符合 §2  
- [ ] 在 **逻辑 1x 缩小** 下主体可辨（尤其窗火与道具）  
- [ ] 无水印、无 AI 乱码、无第三方 IP 特征  
- [ ] 与色板无严重冲突（例如金币不是灰色）

### 5.2 MVP 包

- [ ] §4.1–4.5 全部 `[x]`  
- [ ] 定稿图与局内猫角色 **同一物种设定、同一盔服符号**  
- [ ] 原型或包体截图：至少 **猫飞行 + 三级火 + 救援窗 + 蹦床** 为 PNG，非纯程序几何人  
- [ ] 主菜单可见 `ui_logo_title` 与主按钮图（或等价美术字）

1. `meta_style_lock_v1.png`  
2. 局内截图 ×2（灭火 / 救人）

## 6. 生产流程（AI + 精修）

```
风格锁（1 张定稿）
    → 拆元件提示词（角色/窗火/道具/UI）
        → AI 出 3 选 1
            → 人工精修（轮廓、色、透明边、缩略可读）
                → 按命名入 art/final
                    → 程序替换关键层
                        → 真机 9:16 截图验收
```

**提示词公共后缀（建议每次都带）**

```
竖屏手游 Q 版卡通，清晰色块，粗描边，消防主题，
正面无透视，透明背景（若是元件），无文字无水印，
主色 #FF8A3C #FFD24A #0B0F1A，两头身，可读性强
```

**角色公共设定（猫）**

```
卡通猫救火员，红/橙消防盔，亮色消防服带反光条，
小身体，表情干净，不写实，不做成真人比例
```

## 附录 A. 界面清单与交互流

### A.1 画布（再声明）

| 项 | 值 |
|---|---|
| 比例 | 竖屏 **9:16** |
| 逻辑分辨率 | **450 × 800**（唯一碰撞/布局坐标） |
| 局内美术默认交付 | **@2x = 900 × 1600** |
| 全屏闪屏 / 概念 / 买量 | **1080 × 1920** |
| 屏幕适配 | 舞台 CSS 等比居中缩放，不改逻辑坐标 |

布局分区（逻辑 px）：HUD ≈ y0–56；窗格顶 `GRID_TOP=80`；7×(48×48) 间隙 4；地面区自 `H-140`；蹦床基准 `PW=92, PH=18, PY=H-150`。

|---|---|---|---|---|---|

**结论：** 上线必备 **8** 个 UI 结构 + **1** 个局内画布；微创新完整时 **+补给队** 为第 9 页。

### A.3 交互要点

| 界面 | 主要交互 |
|---|---|
| 主菜单 | 开始；看广告领币；进角色选择 |
| 局内 | **按住滑动**控蹦床；开局点击/键 **发射**；暂停；哪吒条件显示技能键 |
| 暂停 | 继续 / 回主菜单 |
| 角色选择 | 已拥有直接装备；金币购买；哪吒可广告解锁；返回 |
| 通关 | 广告双倍金币；下一关（经补给队或直进） |
| 补给队 | 买英雄/道具；广告刷新；可跳过消费进下一关 |
| 失败 | 广告复活（每关 1 次）；重开；主菜单 |
| 广告层 | 播放完成回调发奖 |

### A.4 界面流

```
主菜单 ─┬─ 开始 → 局内 ─┬─ 通关 → [双倍广告?] → 补给队 → 下一关
        │              ├─ 失败 → [复活广告?] → 局内 / 重开 / 菜单
        │              └─ 暂停 → 继续 / 菜单
        ├─ 角色选择 → 菜单
        └─ 菜单领币广告
```
