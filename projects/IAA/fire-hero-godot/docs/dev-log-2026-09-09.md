## 今日完成

### 0. 背景与决策
- 用户反馈「关卡配置与场景画的房子位置对不上」：背景 PSD 里可交互窗格位于 x≈98–110 / 300–310、y≈323–473、纵向节距 ≈72px——与旧 7 列网格（`cx=45+col*52+24`，行 0–5 只到 y 388）**结构性错位，任何网格参数都无法对上**
- 用户明确方向（AskUserQuestion 三连，全部采纳推荐项）：**① 每关完全独立自由摆放（数量/位置任意）② 编辑器自由拖拽为主 ③ 存量 6 关自动迁移成坐标作初始布局**
- 范围外（不做）：`fire-hero-iaa.html` 原型改动、程序化关（≥7）改动、资产改动、窗尺寸扩展

### 1. 统一数据模型（编辑器 ↔ Godot 同语义）
- 关卡 = `{name, windows:[{type:'F'|'f'|'g'|'R'|'r', x, y}]}`；**x/y = 窗中心像素（整数），画布 450×800**
- 迁移公式两端注释互注：`cx = 45 + col*52 + 24`、`cy = 80 + row*52 + 24`
- 导出排序：y 升序再 x 升序

## 关键问题与解决
| 问题 | 解决 |
|------|------|
| 网格窗位与背景楼房结构性错位（节距 52 vs ~72px） | 用户决策自由坐标；两个系统语义各自独立，编辑器里叠真实背景拖摆对齐 |
| 规划稿 L5/L6 锚点计数有误 | 冒烟锚点用生成器实测：L5 15 窗（7火/6救+2红）、L6 18 窗（10火/4救+4红） |
| 空手配关 vs 程序化边界 | `has_hand_layout` 按索引路由；文件头 + scene-config-rules §4.3 双重文档化该语义 |
| 编辑器选中/拖拽依赖 DOM 下标 | wndEl 写 `data-i`，children 顺序 == windows 数组顺序（拖拽不改序，安全） |
