## 今日完成

### 0. 背景与决策
- 用户反馈「关卡配置与场景画的房子位置对不上」：背景 PSD 里可交互窗格位于 x≈98–110 / 300–310、y≈323–473、纵向节距 ≈72px——与旧 7 列网格（`cx=45+col*52+24`，行 0–5 只到 y 388）**结构性错位，任何网格参数都无法对上**
- 用户明确方向（AskUserQuestion 三连，全部采纳推荐项）：**① 每关完全独立自由摆放（数量/位置任意）② 编辑器自由拖拽为主 ③ 存量 6 关自动迁移成坐标作初始布局**
- 范围外（不做）：`fire-hero-iaa.html` 原型改动、程序化关（≥7）改动、资产改动、窗尺寸扩展

### 1. 统一数据模型（编辑器 ↔ Godot 同语义）
- 关卡 = `{name, windows:[{type:'F'|'f'|'g'|'R'|'r', x, y}]}`；**x/y = 窗中心像素（整数），画布 450×800**
- 迁移公式两端注释互注：`cx = 45 + col*52 + 24`、`cy = 80 + row*52 + 24`
- 导出排序：y 升序再 x 升序

### 2. Godot 侧（v0.1.5）
| 文件 | 改动 |
|------|------|
| `scripts/autoload/level_db.gd` | `layouts` → 6 关 dict 数组字面量（生成脚本从旧字符网格迁移）；删 `COLS/cell_at/load_from_json_string`；**保留并启用 `has_hand_layout()`** |
| `scripts/game/level_builder.gd` | `build()` 按 `has_hand_layout` 路由；新增 `_build_hand()` 逐条建砖；`_spawn_entry(parent, type_char, x, y)` 直赋 `brick.position=Vector2(x,y)`；程序化逻辑不动 |
| `scripts/game/brick.gd` | 删 `grid_col/grid_row`（零读取，已核实） |
| `scripts/game/game_root.gd` | L229 空关兜底 → `spawn_single_fire(brick_host, 225.0, 104.0)`（= 旧网格 (3,0) 格中心） |

### 3. 冒烟验证（临时场景 `tools/smoke_free_layout.{gd,tscn}`，跑完已删）
- 断言全 PASS：`layouts.size()==6`；`has_hand_layout(1..6)=true`、`has_hand_layout(7)=false`；level 1–6 逐砖 `position ≈ Vector2(x,y)`（≤1e-3）；fire/rescue 计数 == 锚点表 `[[7,5,2],[9,6,2],[11,6,4],[12,7,3],[15,7,6],[18,10,4]]`（L5/L6 是生成器实测值，规划稿的 14/6/6、19/10/6 有误）；同关坐标无重复、均在画布内；`build(7)` 程序化 >0 且 x∈[45,405]；**空手配关语义**（清空 L1 → build 返回 0 砖而非程序化 → 还原）
