# 《救火英雄》游戏测试与反馈

> 测试对象：`fire-hero-iaa.html`（单文件原生 HTML 原型）  
> 对照基准：`fire-hero-game-rules.md` / `微创新需求规格.md` / `救火英雄IAA游戏企划.md`  
> 测试类型：代码走查 + 机制对照 + 体验验收（静态分析）  
> 日期：2026-03-26｜版本：v1.0  
> 结论摘要：**P0 核心循环与微创新主路径已基本落地；存在若干高优先级可玩性/逻辑缺陷，建议修完再做外测。**

---

## 0. 一句话结论

原型已具备「双通道胜利 + 抓人救援 + 正负道具 + 广告点位 + 角色/补给队」的可玩骨架，**可作为 M1 内部试玩包**；但 **蹦床宽度判定不一致、新开局清空金币存档、补给队道具跨关失效、广告态状态恢复不稳** 会直接影响手感与经济闭环，应优先修。

## 3. 缺陷清单（按严重度）

### 🔴 P0 — 影响核心手感 / 经济 / 关卡公平

#### BUG-01 主球接球/接人判定仍用固定 `PW`，忽略 `paddle.w`

**现象**：长条加宽、锤子变窄后，**画面上的蹦床变了，主球接球判定几乎不变**；道具接取、第二球、BONUS 金币却用 `paddle.w`，判定体系分裂。

**证据**：

```text
主球接球：  ball.x 与 paddle.x … PW …（固定 92）
主球 stuck： ball.x = paddle.x + PW/2
跳楼接人：  … PW …（固定）
道具接取：  … paddle.w …（可变）✅
第二球：    … paddle.w …（可变）✅
```

**影响**：

- 吃到「长条」手感提升不明显 → 正向反馈失效  
- 吃到「锤子」视觉变窄但接球仍宽 → 负向道具威胁不足 → **复活广告钩子变弱**  
- 小猫「接人判定 +10%」只作用在 `people`，对主球携带救援落点无帮助  

**建议修复**：

- 所有水平判定与 clamp 统一为 `paddle.w`  
- `stuck` 时球跟 `paddle.x + paddle.w/2`  
- 拖拽/键盘边界：`Math.min(W - paddle.w - 8, …)`  

---

#### BUG-02 `startGame()` 强制 `S.coins = 0`，打断金币存档闭环

**现象**：`loadSkins()` 会恢复 `coins`，但点「开始灭火 / 重新开始」直接清零。

**影响**：

- 菜单「看广告 +50 金币」在正式开局前无效  
- 补给队攒币、角色解锁进度被「再开一局」抹掉  
- 与规格「金币经济闭环 + 持久化」冲突  

**建议修复**：

- 新开局 **保留** `S.coins` 与 `ownedSkins`  
- 仅重置：`level/score/lives/powerLevel/reviveUsed` 等局内状态  
- 可选：主菜单增加「重置存档」调试入口，避免误清  

---

#### BUG-03 补给队购买的限时道具在进下一关时被清掉

**流程**：过关 → 商店买 `wide/boost/up` → `btnShopNext` → `nextLevel()` → `buildLevel()`。

**问题**：

- `buildLevel` 重置 `timerBoost=0`、`pierceTimer=0`  
- `paddle.w` 未在 `buildLevel` 显式复位，但 `timerBoost` 清零后逻辑上「限时」已无  
- 商店文案写「下关增益」，实际是 **当前（已结束）关的全局变量**，进下一关大概率吃不到  

**建议修复**（二选一，推荐 A）：

- **A. 挂到下一关开局 buff**：`pendingBuffs = {wide, boost, up…}`，`buildLevel` 末尾 apply  
- **B. 改文案为「立即生效（仅本关残留）」并禁止在结算后买限时道具**（体验更差，不推荐）  

`up`（灭火等级）应跨关保留（`S.powerLevel` 已是全局，但商店里对 **当前 bricks** 减 hp 无意义，应改为只升 `powerLevel`，下关 `buildLevel` 用新等级重算 `req/hp`）。

---

#### BUG-04 广告状态 `S.state='ad'` 结束后未恢复原状态

**现象**：`showAd` 把状态设为 `ad`；`closeAd` 只执行回调，**不恢复** `menu/levelup/over/playing`。

**影响**：

- 主循环 `if (S.state==='playing') update`：广告后若回调未显式改 state，可能卡住  
- 过关双倍路径：回调进商店，但 state 仍可能是 `ad`（商店不依赖 playing，表面能点）  
- 菜单领币后 state 留在 `ad`，直到再点开始  

**建议修复**：

```text
showAd(cb, resumeState)
closeAd → S.state = resumeState || prevState
```

并保证：双倍/刷新/解锁/复活各自传入正确恢复态。

### 🟠 P1 — 体验偏差 / 规则不完整 / 易误导

#### BUG-05 红窗「跳光自动过关」未做

规则 P0：人员跳光 → 直升机灭剩余火自动过关。  
原型：红窗不计入 `rescueLeft`，跳楼只是加分项；**不会**因跳光触发过关。

**建议**：若本关仅剩红窗人员且全部跳出，可 `fireLeft=0` 或直接 `levelComplete`（轻量即可）。

---

#### BUG-06 携带救援时再次撞救援窗会覆盖/丢逻辑

`hitBrick` 救援分支不检查 `ball.carrying`：已抓人时再撞救援窗会 `splice` 新窗并覆盖 `carrying`，**可能吞掉上一个人且不回补 rescue 计数**。

**建议**：`if (ball.carrying) { 只反弹不抓; return; }` 或自动结算上一次后再抓。

---

#### BUG-07 掉命补救援窗不增加 `rescueLeft` / 位置可能重叠

`loseLife` 在 `carrying` 时 push 新 rescue 窗，但：

- 未 `S.rescueLeft++`（若原来普通窗已 splice 且未获救，计数在抓取时就没减——需再确认不变量）  
- 抓取时 **未减** `rescueLeft`（设计正确），掉命只是把窗加回来 → 计数仍一致  
- 但随机格可能与现有砖重叠，造成叠窗难打  

**建议**：找空位生成；生成后 `rescueLeft = 统计普通救援窗`。

---

#### BUG-08 穿透 buff（boost）直接拆火砖且不走掉落/正常灭火分

```text
pierce 命中：score+2，直接 splice，fireLeft-1，无 maybeDropItem
```

导致：

- 收益远低于正常灭火  
- 负/正道具掉落被跳过  
- 与「无敌穿透」预期（穿墙不灭 或 高效灭火）不一致  

**建议**：明确设计——  
- 若「只穿不灭」：碰撞忽略 fire，不减 hp；  
- 若「强力灭火」：走 `hitBrick` 或至少完整结算 + 掉落。

---

#### BUG-09 哪吒第二球掉出屏幕直接消失，不扣命也不回收技能

设计可接受为「临时球」，但：

- 10 秒内掉出即没，玩家感知「技能浪费」  
- 第二球不抓人、不接道具，技能教学不足  

**建议**：掉出不扣命（保持）；UI 显示剩余秒数；首次使用强引导。

---

#### BUG-10 通关文案固定「扑灭成功」

救人通道过关也显示灭火成功，削弱双通道可读性。

**建议**：

- 灭火达成：`✅ 火势扑灭！`  
- 救人达成：`✅ 全员获救！`  
- 都达成：`✅ 完美救援！`  

---

#### BUG-11 双倍金币可重复？ / 按钮未防二次点击

`btnDouble` 每次 `S.coins += levelBonus`，未见 `doubled` 标记；若广告回调可多次，会重复加。

**建议**：`levelDoubled` 标志；领取后隐藏/禁用按钮。

---

#### BUG-12 插屏点位未做

企划：每 2–3 关插屏。原型仅激励视频模拟。M1 可接受，M2 上线前补。

## 4. 体验反馈（试玩向）

### 4.1 做得好的地方

1. **目标双通道**在 HUD（🔥x · 🧑y）可见，比「清砖」更接近原版灵魂。  
2. **抓人带回**有「抓住人! 带回蹦床」字样，操作叙事清楚。  
3. **正负道具 + 火球着火**为 IAA 复活留下合理失败点。  
4. **角色/补给队/广告模拟**链路完整，适合演示「选品→换皮→微创新」。  
5. 竖屏 9:16、相对拖拽操作，符合小游戏直觉。  
6. 分层绘制与夜景氛围完整，原型完成度高于一般灰盒。

### 4.2 手感问题

| 点 | 反馈 | 优先级 |
|---|---|---|
| 判定与描边不一致 | 见 BUG-01，必须修 | P0 |
| 弹射初速度随机角 | 开局略不可控；可改为固定向上 + 轻微偏移 | P1 |
| 球速随反弹微增 | 后期可能过滑；建议按关卡表封顶 | P1 |
| 救援必须「接住弹起」 | 好；但失败惩罚+叠窗风险需打磨 | P1 |
| 哪吒技能按钮偏小 | HUD 区易误触暂停；技能可放到右下 | P2 |

### 4.3 商业化 / IAA 反馈

| 点位 | 评价 |
|---|---|
| 复活 | 逻辑对；需保证负向道具真能制造「差一点」 |
| 双倍 | 钩子清晰；防重复领取 |
| 菜单+50 币 | 好演示；勿被开局清币废掉 |
| 商店刷新 | 有；缺「看广告额外解锁一件」P1 |
| 角色广告解锁 | 哪吒双通道正确 |
| 插屏 | 缺失，上线前补频率与关闭体验 |

**关键洞察**：IAA 不靠「多塞广告」，而靠 **失败可归因 + 成长差一口**。BUG-01/03 会同时削弱「失败」与「成长」，比缺两个点位更伤。

### 4.4 微创新体感

| 角色 | 预期 | 实际体感预判 |
|---|---|---|
| 小猫 | 更好接 | 移速有；接球主判定无加宽 → **体感偏弱** |
| 小狗 | 救人更赚 | 数字 +50% 明显，适合冲分 |
| 熊猫 | 灭火猛 | +1 段伤害，高火关有感 |
| 卡皮巴拉 | 抗火 | 概率抗 + 自灭，需 UI 提示「稳定」触发 |
| 哪吒 | 双球爽 | 有爆发；缺时长条与教学 |
