# 03-变更传播清单

> 用途：修改某个数据实体时，按此清单追踪所有需要同步更新的文件。
> 原则：**改 A 不检查 B = 制造文档债。**

---

## 一、单一真相源层级

```
CSV 数据（最高权威——唯一数值真相源）
  ↓ 驱动
GDScript 代码（逻辑实现，必须与 CSV 字段一致）
  ↓ 反映
设计文档（描述设计意图，但数值以 CSV 为准）
  ↓ 参考
规划/审计文档（开发过程产物，有明确时间戳）
```

**矛盾裁决**：CSV > 代码 > 设计文档。发现不一致 → 以 CSV 为准 → 标记文档待更新 → 告知用户。

## 三、CLAUDE.md 交叉验证表（修改后必检）

任何修改完成后，检查 CLAUDE.md 中的交叉验证表是否需要更新数值：

| 验证项 | 当前 CSV 实际值 |
|--------|----------------|
| 功法数量 | `form_config.csv` 行数 - 1 |
| 卡牌数量 | `card_config.csv` 行数 - 1 |
| 敌人数量 | `enemy_config.csv` 行数 - 1 |
| 器灵 HP | `main_peak_config.csv` max_hp |
| 山峰数量 | `peak_config.csv` 行数 - 1 |

## 四、使用流程

```
1. 确认变更类型（功法？卡牌？敌人？公式？）
2. 查本清单对应条目 → 列出所有受影响文件
3. 逐文件修改
4. 检查 CLAUDE.md 计数是否需要更新
5. 修改过的文档标注验证日期
6. 在开发日志中记录变更
```

**反模式**：
- "先把代码改了，文档以后再说" → 文档永远不会被更新
- "这个数值很小，不用更新文档" → 积累成 60+ 处矛盾
- "我不确定这个文档还有没有人看，先不管" → 下一个人看到过期数据做错误决策

---

## 五、验证日期标注格式

数值/设计文档头部标注：

```markdown
> **数据验证日期**：YYYY-MM-DD
> **验证来源**：form_config.csv / enemy_config.csv / main_peak_config.csv
```

超过 7 天未验证的文档，AI 在阅读时自动提醒"此文档数据可能过期"。
