# 功能规划文档模板

> 这份文档描述**玩家看到什么、怎么操作、发生什么变化**。是策划层面的规划，不涉及代码细节。
> 配合《功能需求文档模板》使用：**规划文档定范围 → 需求文档定细节 → AI 按架构规范执行**。

---

## 9. 验收标准

> 玩家视角。"做了什么 → 看到什么"。

1. [操作] → [预期结果]
2. [操作] → [预期结果]

**范例**：
1. 启动游戏 → 看到选择器灵面板，三张卡片均未选中，"开始"按钮置灰
2. 点击一张卡片 → 该卡片高亮，其他不变，"开始"按钮可点击
3. 切换选择 → 新高亮旧恢复
4. 确认开始 → 面板消失，进入主场景，器灵图标为所选类型

## 和详细需求文档的关系

```
功能规划文档（这份）              详细需求文档（另一个模板）
─────────────────────            ─────────────────────────────
策划视角，讲流程和界面             代码视角，讲模块和数据
不确定的实现细节写"待定"           必须是确定的（变量名/路径/类型）
用来对齐团队对功能范围的认知       用来指导 AI 逐行实现
范围性描述（要做什么/不做什么）     执行性描述（怎么做）
AI 读完后能理解"意图"             AI 读完后能直接写代码
```

**使用流程**：
1. 用规划文档模板写初稿（你）
2. AI 检查模块边界、数据流是否合理（对照架构规范）
3. 定稿后，AI 帮你转成详细需求文档
4. 你确认需求文档
5. AI 按需求文档 + 架构规范开发
