## 3. 游戏状态枚举

```gdscript
enum GameState {
    SAVE_CHECK,        # 存档检测（<100ms，无 UI）
    MAIN_MENU,         # 主菜单
    INTRO,             # 开场黑幕
    MAIN_PEAK_SELECT,  # 器灵选择（v0.1 仅百世书）
    DESKTOP_IDLE,      # 桌面放置态
    BATTLE,            # 全屏战斗态
    BATTLE_RESULT,     # 战斗结算
    MINIMIZED,         # ⏳ V0.2 启用（枚举位保留，v0.1 不实现）
}
```

状态转移：

```
SAVE_CHECK ──有存档──→ MAIN_MENU ──继续──→ DESKTOP_IDLE（读档+离线收益）
    │                                        │
    └──无存档──→ INTRO → MAIN_PEAK_SELECT ──→ DESKTOP_IDLE（首次存档）
                                             │
        [⚔️挑战] 灵气≥100 ──→ BATTLE ──胜利/免死──→ BATTLE_RESULT ──→ DESKTOP_IDLE
```

战斗内子状态：`COUNTDOWN`（3s 倒计时）→ `FIGHTING` ⇄ `BLESSING_SELECTION`（升级暂停弹窗）。

## 4. 资源与经济规则

### 4.1 资源管理器（最终名称）

**`EconomyManager` 是唯一的资源管理器**（Autoload，已存在：`autoload/economy_manager.gd`）。
旧名称 `Warehouse` 一律作废，任何文档/代码不得再使用。

三种资源：

| 资源 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 灵气 | `spirit_energy` | int | 挂机产出 + 战斗奖励；消耗于挑战、修复山峰 |
| 女娲石 | `nuwa_stone` | int | 胜利奖励；修复山峰通用材料（每峰 1 个） |
| 流派秘宝 | `secret_treasures` | Dict | 键 = 山峰 ID（6 种）；修复对应山峰消耗 1 个 |

API 契约沿用[仓库系统 spec](../../03-功能规格/2026-07-30-仓库系统/2026-07-30-仓库系统-功能需求.md) §5.1（`add_energy/spend_energy/get_resources` 等），不变。

### 4.2 经济公式（全部迁入 game_config.csv，见数据规范）

| 参数 | v3.0 定值 | 旧值/冲突来源 |
|------|-----------|--------------|
| 灵气基础速率 | **10 /秒** | 旧 CSV 隐含 25/s（spirit_auto_base=5 / interval=0.2）→ 废弃 |
| 在线挂机总速率 | `(10 × (1 + level × 0.1) + 已修复山峰数 × 2) × buff` | 器灵加成 10%/级、山峰 +2/s，三处 spec 一致 ✓ |
| 点击器灵收益 | **+20 灵气/次**，CD **5s** | 旧 CSV spirit_click_base=10 → 废弃 |
| 挑战消耗 | **100 灵气/次** | 三态切换/全屏战斗态 spec 一致 ✓（无 CSV，新增） |
| 离线收益 | `10 × min(离线秒数, 86400)`，**24h 封顶**，不含加成与 buff | 存档 spec ✓（SPIRIT_ENERGY_RATE 常量迁入 CSV） |
| 挂机加速 buff | 胜利后灵气产出 **×1.5，持续 30 分钟**；再次胜利刷新时长不叠加；离线照常流逝 | 结算 spec ✓ |

### 4.3 山峰修复消耗

| 山峰 | 消耗 | 顺序 |
|------|------|------|
| 剑峰（peak_sword） | 灵气 500 | **必须首修** |
| 其余 5 峰 | 对应秘宝 ×1 + 女娲石 ×1 + 灵气 5,000 | 自由选择 |

### 4.4 战斗奖励（胜利）

| 奖励 | 数量 | 说明 |
|------|------|------|
| 女娲石 | ×1 | 修复山峰通用材料 |
| 流派秘宝 | ×1 | 6 种中随机 |
| 灵气 | 击杀数 × 1 | 战斗击杀奖励 |
| 挂机加速 buff | ×1.5 / 30min | 限时增益 |

失败（百世书免死）：无奖励、无惩罚、挑战消耗的 100 灵气不返还。

## 5. 山峰规则

### 5.1 六座山峰（ID 统一为 `peak_*`）

| 山峰 ID | 名称 | 修复后解锁祝福线 | 修复顺序 |
|---------|------|-----------------|---------|
| `peak_sword` | 剑峰 | ricochet（弹射） | 必须首修 |
| `peak_buddha` | 佛峰 | shield（护盾） | 自由 |
| `peak_magic` | 法峰 | split（分裂） | 自由 |
| `peak_beast` | 兽峰 | pierce（穿透） | 自由 |
| `peak_artifact` | 器峰 | range（范围） | 自由 |
| `peak_soul` | 魂峰 | damage（伤害） | 自由 |

### 5.2 规则

1. 每座山峰**仅修复一次**（6 次上限），修复后**永久保留**（写入存档），不随战斗重置。
2. 剑峰未修复时点击其他山峰 → 不弹面板，浮字「需先修复剑峰」。
3. 修复即时效果：器灵等级 +1（0→6）、解锁对应祝福线、外观进化一阶（spirit_growth.csv 视觉阶段）。
4. **山峰升级**（旧 CSV upgrade_cost_base/per_level）**不存在**——修复即终态，废弃升级规则。
5. 修复触发自动存档。

## 6. 祝福规则

### 6.1 九条祝福线与山峰解锁关系（统一）

| 祝福线 ID | 名称 | 类型 | 前置山峰 | 初始可用 |
|-----------|------|------|---------|---------|
| `ricochet` | 弹射 | 弹道型 | peak_sword 剑峰 | ✗ |
| `shield` | 护盾 | 特殊型 | peak_buddha 佛峰 | ✗ |
| `split` | 分裂 | 弹道型 | peak_magic 法峰 | ✗ |
| `pierce` | 穿透 | 弹道型 | peak_beast 兽峰 | ✗ |
| `range` | 范围 | 数值型 | peak_artifact 器峰 | ✗ |
| `damage` | 伤害 | 数值型 | peak_soul 魂峰 | ✗ |
| `atk_speed` | 攻速 | 数值型 | —（无前置） | ✓ |
| `lifesteal` | 吸血 | 特殊型 | —（无前置） | ✓ |
| `crit` | 暴击 | 特殊型 | —（无前置） | ✓ |

- 修复 0 座山峰 → 卡池仅攻速/吸血/暴击 3 条线；修复 6 座 → 全部 9 条线。
- CSV `required_peak` 空值 = 初始可用。现有 blessing_config.csv 与上表**完全一致** ✓（主表口径；注意 `data/blessing_config.description.translation` 为旧塔防祝福的二进制残留，见第 12 章 #14）。

### 6.2 核心规则

1. **每线 3 层（tier 1/2/3）**，共 27 条；tier 3 为升阶质变（如弹射→闪电网）。
2. **触发时机**：进入战斗后开局**弹 1 次** 3 选 1；之后每次升级弹 1 次。
3. 弹窗时战斗暂停（子状态 BLESSING_SELECTION），不选不能继续。
4. 叠层：同名线最多选 3 次；选满 3 次触发质变后，该线**移出卡池**。
5. 卡池不足 3 张 → 空位补「灵气 +50」万能卡。
6. **每局重置**：进入新一局战斗，所有祝福清零（roguelike 每局独立构筑）。
7. **山峰解锁永久**：祝福线解锁关系随山峰修复永久生效（局外），战斗内效果每局重置（局内）。
8. 禁止出现「弟子攻击/弟子生命/弟子速度」等弟子祝福效果（旧 X7 决策作废）。

## 8. 结算规则

| 结果 | 触发 | 奖励 | 状态流转 |
|------|------|------|---------|
| `victory` | W15 Boss 死亡 | 女娲石×1 + 随机秘宝×1 + 灵气(击杀数×1) + 挂机加速 buff(×1.5/30min) | BATTLE → BATTLE_RESULT → DESKTOP_IDLE |
| `immortality` | 器灵 HP 归零（百世书） | 无奖励；挑战消耗不返还；器灵 HP 回满 | 同上 |
| `defeat` | 其他器灵 HP 归零 | Game Over 重开 | V0.2+（v0.1 不存在，百世书必免死） |

- Boss 与器灵同时死亡 → 免死优先，不算胜利。
- 结算后**立即触发自动存档**。
- buff 剩余时间写入存档（`buff_end_timestamp`），离线照常流逝。

## 9. 存档规则

- 位置：`user://save_data.json`（JSON，原子写入：先写 .tmp 再 rename）。
- 保存时机：战斗结算后 / 退出游戏 / 每 60s 定时 / 手动。
- 读档：启动时检测 → 校验必填字段 → 失败视为存档损坏（提示后走首次流程）。
- 战斗中退出：不保存战斗中间状态，下次从桌面态开始。

### 9.1 存档字段（v3.0 最终定义）

```json
{
    "version": 1,                    // int — 存档格式版本
    "play_time": 0.0,                // float — 累计游玩秒数
    "save_timestamp": 0,             // int — Unix 时间戳（离线收益计算基准）
    "spirit_id": "spirit_book",      // String — 绑定器灵 ID（统一 ID，见第 10 章）
    "spirit_level": 0,               // int — 器灵等级 0-6
    "peaks": {                       // Dictionary — 山峰修复状态（6 键，永久保留）
        "peak_sword": false, "peak_buddha": false, "peak_magic": false,
        "peak_beast": false, "peak_artifact": false, "peak_soul": false
    },
    "spirit_energy": 0,              // int — 灵气
    "nuwa_stone": 0,                 // int — 女娲石
    "secret_treasures": {            // Dictionary — 流派秘宝（键=山峰 ID）
        "peak_sword": 0, "peak_buddha": 0, "peak_magic": 0,
        "peak_beast": 0, "peak_artifact": 0, "peak_soul": 0
    },
    "clear_count": 0,                // int — 通关次数（V0.3 解锁新器灵用）
    "buff_end_timestamp": 0,         // int — 🆕 挂机加速 buff 截止时间戳（0=无 buff）
    "settings": {                    // Dictionary — 设置
        "master_volume": 80.0,
        "window_mode": "windowed"
    }
}
```

> 与旧存档 spec 的差异：`spirit_id` 由 `"baishishu"` 统一为 `"spirit_book"`；新增 `buff_end_timestamp`（保证 buff 可保存与恢复）。

## 10. 关键 ID 命名约定（统一）
