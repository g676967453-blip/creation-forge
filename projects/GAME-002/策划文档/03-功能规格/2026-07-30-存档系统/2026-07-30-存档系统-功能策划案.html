功能定位

一句话：自动保存游戏进度，下次启动读档恢复；离线期间挂机收益自动累积。

存档的生命周期：

首次进入桌面态 → 创建存档
  ├─ 战斗中 → 结算时自动保存
  ├─ 桌面态 → 每 60s 定时保存
  ├─ 退出时 → 自动保存 + 记录离线时间戳
  └─ 手动 → 设置菜单可手动保存
下次启动 → 检测存档 → 读档 → 离线收益结算 → 桌面态

不在范围内

  • 多存档槽位（只有一个自动存档位）→ V0.2+
  • 云存档 / Steam Cloud → V1.0+
  • 存档加密 / 防作弊 → V0.2+
  • 存档版本迁移（旧版本存档→新版本）→ V0.2+
  • 崩溃恢复（crash 时紧急存档）→ V0.2+

黄色=未定案 绿色=改动标注 蓝色=系统提示/可配置项 红色=强调

活动简述
目的：自动管理游戏进度的持久化存储，支持存档/读档/离线收益，确保玩家进度不丢失。
一、存档数据结构
一.存档内容（单一 JSON 文件，路径：user://save_data.json）
1.元信息
1）version（int）：存档格式版本号，V0.1 = 1
2）play_time（float）：累计游玩秒数
3）save_timestamp（int）：最后保存的 Unix 时间戳
2.器灵数据
1）spirit_id（string）：绑定器灵 ID（V0.1="baishishu"）
2）spirit_level（int）：器灵等级（= 已修复山峰数，0-6）
3.山峰数据
1）peaks（object）：{ "jianfeng": true, "fofeng": false, ... } 每座峰已修复/未修复
4.资源数据
1）spirit_energy（int）：灵气数量
2）nuwa_stone（int）：女娲石数量
3）secret_treasures（object）：{ "jianfeng": 0, "fofeng": 0, ... } 各流派秘宝数量
5.进度数据
1）clear_count（int）：通关次数（解锁诛仙剑/神农鼎用）
6.设置数据
1）master_volume（float）：主音量 0-100
2）window_mode（string）："windowed" | "fullscreen"
二、保存时机
一.自动保存触发条件
1.战斗结算后：胜利/失败结算完成 → 自动保存
2.退出游戏时：窗口关闭/Alt+F4 → 捕获退出信号 → 保存 + 记录离线时间戳
3.定时保存：桌面放置态下 每 60 秒自动保存一次
二.手动保存
1.设置菜单中提供「保存游戏」按钮
2.点击 → 立即保存 → 提示「已保存」
三.不触发保存的时机
1.战斗中（W1-W15 进行中）— 等结算时保存
2.开场黑幕播放中
3.器灵选择界面（尚未绑定器灵）
三、读档
一.读档流程
1.启动时检测存档文件存在 → JSON 解析 → 字段完整性校验
2.全部通过 → 加载游戏状态 → 计算离线收益 → 显示离线收益弹窗 → 进入桌面态
3.读档期间：显示主菜单 + 加载提示（V0.1 不做 loading 进度条）
二.读档失败处理
1.文件不存在 → 正常，走首次启动流程
2.JSON 解析失败 → 视为存档损坏 → V0.1 静默走首次流程，V0.2 弹提示
3.必填字段缺失 → 视为存档损坏
4.版本号不兼容 → 视为存档损坏（V0.2 做版本迁移）
四、离线收益
一.计算公式
1.离线灵气 = 离线时长（秒）× 基础灵气速率
1）基础灵气速率：待定（建议 1 灵气/秒）
2）器灵加成：待定（随山峰修复提升速率？）
二.上限
1.离线收益上限：24 小时（86400 秒）
2.离线超过 24 小时 → 按 24 小时计算，不累积超出部分
3.目的：鼓励回来收菜，不无限挂机
三.显示
1.读档成功后弹出离线收益弹窗
2.文案：「你离开了 X 小时 X 分，器灵修炼获得 💨 +N 灵气」
3.玩家点击「确认」关闭，或 3 秒后自动关闭
离线 3 小时 20 分 → "你离开了 3 小时 20 分，器灵修炼获得 💨 +12,000 灵气"
五、存储实现
一.文件格式
1.JSON 文本文件，UTF-8 编码，格式化输出（缩进 2 空格）
2.文件名：save_data.json
3.存储路径：user://（Godot 用户数据目录，跨平台自动映射）
二.写入策略
1.原子写入：先写临时文件 → 写入成功 → 替换原文件
1）防止写入过程中崩溃导致存档损坏
2.写入超时：5 秒。超时视为保存失败，不影响游戏运行
