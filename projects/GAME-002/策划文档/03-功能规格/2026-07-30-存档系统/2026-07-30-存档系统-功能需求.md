## 1. 功能概述

**一句话**：自动保存游戏进度到 user://save_data.json，下次启动读档恢复 + 离线收益结算。

**详细描述**：SaveManager（Autoload）负责游戏全生命周期的存档管理。首次进入桌面态时创建存档，战斗结算后/退出时/定时60秒自动保存。启动时检测存档 → 读档 → 离线收益计算（离线秒数 × 灵气速率，24h 上限）→ 弹窗显示 → 进入桌面态。原子写入防崩溃损坏。V0.1 单一存档位。

## 2. 模块影响分析

```
触及的现有模块：
  1. GameManager — 新增战斗结算/退出时调用 SaveManager.save()；启动时调用 SaveManager.check_save_exists()
  2. UIStateCoordinator — 新增离线收益弹窗的显隐管理
  3. DataManager — 无需修改（存档不通过 CSV）

需要新建的模块：
  1. SaveManager（autoload/save_manager.gd，Autoload）
     职责：存档检测/读档/保存/删除/离线收益计算
  2. OfflineRewardPanel（scenes/ui/offline_reward_panel.tscn + scripts/ui/offline_reward_panel.gd）
     职责：离线收益弹窗 UI（显示离线时长+灵气数字+确认按钮）

不需要动的模块：
  - MountainManager / WaveManager / Enemy相关 — 存档系统不直接操作这些模块
  - intro_screen / main_peak_select_panel — 存档系统在它们之后才创建
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式（保存） | 信号触发（game_save_requested）+ 定时器（60s）+ 退出通知 |
| 触发方式（读档） | 启动时自动调用，或主菜单「继续游戏」 |
| 前置状态（保存） | 除 INTRO / MAIN_PEAK_SELECT / BATTLE 外的所有状态 |
| 前置状态（读档） | SAVE_CHECK（启动检测）或 MAIN_MENU（继续游戏） |
| 互斥状态（读档中） | 读档期间不响应其他输入 |
| 可重复性 | 保存可重复；读档每次启动一次 |

## 4. 数据定义

### 4.1 SaveData 结构（代码中用 Dictionary，或 Resource 类）

```gdscript
# 存档数据结构
{
    "version": 1,                    # int — 存档格式版本
    "play_time": 0.0,                # float — 累计游玩秒数
    "save_timestamp": 0,             # int — Unix 时间戳
    "spirit_id": "baishishu",        # String — 绑定器灵 ID
    "spirit_level": 0,               # int — 器灵等级（0-6）
    "peaks": {                       # Dictionary — 山峰修复状态
        "peak_sword": false,
        "peak_buddha": false,
        "peak_magic": false,
        "peak_beast": false,
        "peak_artifact": false,
        "peak_soul": false
    },
    "spirit_energy": 0,              # int — 灵气
    "nuwa_stone": 0,                 # int — 女娲石
    "secret_treasures": {            # Dictionary — 流派秘宝
        "peak_sword": 0,
        "peak_buddha": 0,
        "peak_magic": 0,
        "peak_beast": 0,
        "peak_artifact": 0,
        "peak_soul": 0
    },
    "clear_count": 0,                # int — 通关次数
    "master_volume": 80.0,           # float — 主音量
    "window_mode": "windowed"        # String — "windowed"|"fullscreen"
}
```

### 4.2 是否需要新 CSV？

```
☑ 不需要新 CSV — 存档为 JSON 格式，无 CSV 配置需求。
  灵气基础速率等常量写在 SaveManager 顶部 const。
```

### 4.3 是否需要新 Resource 类？

```
□ 不需要 — 用 Dictionary 序列化/反序列化足够。
  不创建 SaveData Resource 类，避免 .tres 文件双轨。
```

## 5. 信号契约

```
信号 1（新建）：save_completed(success: bool)
  发射者：SaveManager
  接收者：GameManager
  时机：保存操作完成后发射
  参数：success — true=保存成功，false=失败

信号 2（新建）：load_completed(success: bool, data: Dictionary)
  发射者：SaveManager
  接收者：GameManager
  时机：读档操作完成后发射
  参数：success — true=读档成功；data — 存档数据（失败时为空字典）

信号 3（新建）：offline_reward_ready(hours: int, minutes: int, energy: int)
  发射者：SaveManager
  接收者：GameManager → UIStateCoordinator → OfflineRewardPanel
  时机：离线收益计算完成后发射
  参数：hours/minutes — 离线时长；energy — 灵气收益

信号 4（新建）：offline_reward_confirmed()
  发射者：OfflineRewardPanel
  接收者：GameManager
  时机：玩家点击「确认」或 3s 自动关闭后
  参数：无

信号 5（新建）：game_save_requested()
  发射者：GameManager / MainMenu
  接收者：SaveManager
  时机：需要触发保存时（战斗结算/退出/手动）
  参数：无
```

## 6. 逻辑流程

### 6.1 检测存档

```
1. GameManager._ready() → SaveManager.check_save_exists()
2. SaveManager:
   → FileAccess.file_exists("user://save_data.json")
   → 不存在 → 返回 false
   → 存在 → FileAccess.open(path, FileAccess.READ)
     → 读取文本 → JSON.parse_string(text)
     → 解析失败/null → 返回 false（存档损坏）
     → 检查必填字段（version/spirit_id/peaks/spirit_energy）
       → 缺字段 → 返回 false
     → 返回 true
3. 发射 save_check_complete(has_save) → GameManager 决定分支
```

### 6.2 保存

```
1. GameManager 发射 game_save_requested()
2. SaveManager.save():
   → 从各系统收集数据：
     - 器灵：DataManager.get_bound_spirit()
     - 山峰：MountainManager.get_all_peak_states()
     - 资源：EconomyManager.get_resources()
     - 设置：AudioServer.get_bus_volume_db() + DisplayServer.window_get_mode()
   → 构建 save_dict
   → save_dict["save_timestamp"] = Time.get_unix_time_from_system()
   → save_dict["play_time"] += 本次会话时长
   → JSON.stringify(save_dict, "  ")  # 格式化输出
   → 写入临时文件 user://save_data.tmp
   → DirAccess.rename_absolute(tmp_path, "user://save_data.json")  # 原子替换
   → 成功 → 发射 save_completed(true)
   → 失败 → 发射 save_completed(false)，记录 error 日志
```

### 6.3 读档

```
1. 主菜单「继续游戏」或启动检测通过 → SaveManager.load()
2. SaveManager.load():
   → FileAccess.open("user://save_data.json", FileAccess.READ)
   → 读取文本 → JSON.parse_string(text)
   → 解析失败 → 发射 load_completed(false, {})
   → 字段完整性校验同 check_save_exists()
   → 构建 save_dict
3. 计算离线收益：
   → now = Time.get_unix_time_from_system()
   → elapsed = now - save_dict["save_timestamp"]
   → capped = min(elapsed, 86400)  # 24h 上限
   → energy = capped * SPIRIT_ENERGY_RATE  # const: 10 灵气/秒
   → save_dict["spirit_energy"] += energy
   → 发射 offline_reward_ready(h, m, energy)
4. GameManager 应用存档数据：
   → 设置 spirit_id / spirit_level
   → 恢复山峰状态
   → 恢复资源
   → 恢复设置
   → 切换到 DESKTOP_IDLE
```

### 6.4 删除存档

```
1. 新游戏确认后 → SaveManager.delete_save()
2. SaveManager.delete_save():
   → DirAccess.remove_absolute("user://save_data.json")
   → 忽略文件不存在错误（幂等）
```

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 离线收益弹窗（打开） | 半透明黑色遮罩覆盖主菜单/桌面态。居中卡片：标题「器灵修炼归来」→ 离线时长 → 灵气数字（绿色大字）→ 确认按钮 |
| 离线收益（自动关闭） | 3s 后自动调用 closeReward()，无需玩家操作 |
| 保存成功反馈 | Toast：居中「✓ 已保存」+ 时间戳，淡入→停留 2s→淡出。不阻断操作 |
| 保存失败反馈 | V0.1 静默失败（仅 error 日志），不弹提示打扰玩家。V0.2 加入重试机制 |

## 8. 边界条件与互斥

```
☑ 存档文件写入到一半崩溃？
  原子写入（先写 .tmp → rename 替换），最坏情况丢失本次保存，旧存档完好。

☑ 存档文件被手动删除/移动？
  下次启动检测 → 文件不存在 → 视为无存档 → 首次流程。正常。

☑ 存档 JSON 被手动编辑导致字段类型错误？
  JSON 解析 + 字段类型校验。spirit_energy 为 string → 校验失败 → 存档损坏。

☑ 离线收益刚好等于上限（24h）？
  显示正常收益数字 + 小字提示「（已达 24h 上限）」。

☑ 断网/时间回拨导致离线时间戳异常？
  V0.1 不做检测。如果系统时间回拨导致 elapsed < 0 → 取 max(0, elapsed)。

☑ 战斗中强行退出？
  Godot NOTIFICATION_WM_CLOSE_REQUEST 捕获 → 不在此阶段保存战斗中间状态。
  只保存战斗开始前/结束后的状态。战斗中退出 = 不保存本次战斗进度。

☑ 60s 定时器和战斗结算同时触发保存？
  SaveManager 加锁：save() 执行中 → 后续 save() 请求排队或跳过。
```

## 11. 验收标准

### 存档创建
1. 首次进入桌面态 → user://save_data.json 文件自动创建
2. 检查 JSON 内容 → version=1，spirit_id="baishishu"，spirit_energy>0

### 自动保存
3. 战斗胜利结算后 → 检查存档文件 save_timestamp 已更新
4. 桌面态停留 60s → 存档文件 save_timestamp 更新
5. 关闭游戏窗口 → 存档文件 save_timestamp 更新为退出时刻

### 读档
6. 有存档时启动 → 检测通过 → 主菜单显示
7. 存档文件被篡改（JSON 语法错误）→ 检测失败 → 视为无存档 → 首次流程
8. 存档文件缺少 spirit_id 字段 → 检测失败 → 首次流程

### 离线收益
9. 离线 1 小时 → 读档后弹窗显示「+36,000 灵气」（速率 10/s）
10. 离线 30 小时 → 弹窗显示「+864,000 灵气」+「已达 24h 上限」
11. 离线不到 1 分钟 → 弹窗显示「不到 1 分钟」+ 少量灵气

### 新游戏清档
12. 主菜单新游戏确认 → 存档文件被删除
13. 清档后再次启动 → 无存档 → 首次流程

### 原子写入
14. 存档写入过程中kill进程 → 旧存档完好、未损坏
