## 1. 功能概述

**一句话**：消耗灵气或战斗材料修复六座山峰，每修复一座解锁器灵新能力（弹射/护盾/分裂/穿透/范围/伤害），器灵外观同步进化。

**详细描述**：在桌面放置态，玩家点击未修复的山峰，弹出修复面板。剑峰是唯一初始可修复的（消耗灵气 500），修复后解锁弹射能力。其余 5 座山峰需要战斗材料：对应流派秘宝 ×1 + 女娲石 ×1 + 灵气 5,000。修复顺序自由选择（剑峰必须首修）。每修复一座山峰，器灵等级 +1，获得对应的战斗能力，器灵外观进化一阶。

## 2. 模块影响分析

```
触及的现有模块：
  1. MountainManager — 修改：新增 repair() 方法、顺序校验（剑峰首修）、消耗检查
  2. GameManager — 修改：连接修复信号、灵气扣除、切换 SpiritManager.level_up()
  3. SpiritManager — 修改：level_up() 接收 peak_id → 查 ability_id → 应用能力
  4. Warehouse — 修改：扣除灵气/女娲石/秘宝
  5. DesktopIdlePanel — 修改：山峰列表点击事件、山峰状态刷新

需要新建的模块：
  1. RepairPromptPanel（scenes/ui/repair_prompt_panel.tscn + scripts/ui/repair_prompt_panel.gd）
     职责：修复确认弹窗——显示消耗、确认/取消按钮、材料不足提示

不需要动的模块：
  - 所有战斗模块（Enemy/WaveManager/CardManager/Projectile）— 修复在桌面态
  - IntroScreen / MainPeakSelectPanel — 前置流程
```

## 5. 信号契约

```
信号 1（复用现有）：peak_repair_requested(peak_id: String)
  发射者：DesktopIdlePanel
  接收者：GameManager（→显示修复确认面板）
  时机：玩家点击未修复山峰

信号 2（新建）：repair_confirmed(peak_id: String)
  发射者：RepairPromptPanel
  接收者：GameManager（→检查资源→执行修复）
  时机：玩家点击"修复"确认按钮

信号 3（复用现有）：mountain_repaired(peak_id: String, ability_id: String)
  发射者：MountainManager
  接收者：GameManager → SpiritManager（level_up）、DesktopIdlePanel（刷新）、EnergyAccumulator（更新加成）
  时机：修复成功后

信号 4（新建）：repair_failed(peak_id: String, reason: String)
  发射者：GameManager
  接收者：RepairPromptPanel（→显示失败提示）
  时机：资源不足或顺序不满足
```

## 6. 逻辑流程

### 6.1 修复剑峰（首修）

```
1. 玩家在桌面态点击剑峰（唯一初始可点）
2. DesktopIdlePanel → peak_repair_requested("sword")
3. GameManager → 显示 RepairPromptPanel，传入：
   → 山峰名「剑峰」
   → 消耗「灵气 500」
   → 当前灵气（从 Warehouse 读取）
4. RepairPromptPanel 显示：
   → 灵气 ≥ 500："修复"按钮可点击
   → 灵气 < 500："修复"按钮置灰 + "灵气不足"文字
5. 玩家点击"修复" → repair_confirmed("sword")
6. GameManager 检查：
   → 灵气 >= 500 ✓ → Warehouse.consume_energy(500)
   → MountainManager.repair("sword")
   → SpiritManager.level_up("sword") → level=1, 解锁 ricochet
   → 发射 mountain_repaired("sword", "ricochet")
7. 山峰变亮、器灵外观进化、DesktopIdlePanel 刷新
```

### 6.2 修复其他山峰

```
1. 剑峰已修后，其余 5 座才可点击
2. 玩家点击未修复山峰（如佛峰）
3. 显示 RepairPromptPanel，消耗：
   → 佛峰秘宝 ×1（检查 Warehouse.有该秘宝？）
   → 女娲石 ×1
   → 灵气 5,000
4. 三项都满足 → "修复"可点击；任一不足 → 按钮置灰 + 提示
5. 修复流程同剑峰：
   → 扣除资源 → MountainManager.repair() → SpiritManager.level_up()
   → 器灵获得 shield 能力
```

### 6.3 顺序校验

```
1. 若剑峰未修复，点击其他山峰 → 无弹窗，山峰区域显示"需先修复剑峰"
2. 剑峰修复后 → 其余 5 座全部可点（自由选择先后）
```

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 山峰-未修复 | 灰色+🔒图标，悬停轻微放大 |
| 山峰-已修复 | 亮色+金色边框+已解锁能力小图标 |
| 修复面板（可修复） | 山峰名+消耗列表+当前拥有资源+"修复"按钮亮 |
| 修复面板（不可修复） | 不足项红色标注，"修复"按钮置灰 |
| 修复面板（顺序不满足） | 不弹出，山峰区域浮字"需先修复剑峰" |
| 修复完成 | 山峰变亮+光效 0.5s + 器灵闪烁进化 |

## 8. 边界条件与互斥

```
☑ 6 座全修完还能点吗？→ 不能，全部亮起，无点击事件
☑ 修复中途灵气变化（挂机累积刚好够）？→ 面板实时读取当前灵气，动态更新按钮状态
☑ 多个山峰同时弹修复面板？→ 互斥，同一时间只有一个修复面板
☑ 修复成功后立即关闭游戏？→ 存档自动保存（修复是存档触发点）
☑ 已有秘宝但灵气不足？→ 按钮置灰，提示"灵气不足"
☑ 已有灵气和女娲石但缺秘宝？→ 按钮置灰，提示"缺少 XX 秘宝"
☑ 修复消耗灵气后灵气变负数？→ 不可能，逻辑层先校验
```

## 11. 验收标准

### 剑峰修复
1. 进入桌面态 → 看到 6 座山峰，仅剑峰可点击（灰色但有交互）
2. 灵气 ≥ 500 → 点击剑峰弹出修复面板，"修复"可点击
3. 确认修复 → 灵气 -500，剑峰变亮，器灵等级 0→1，解锁"弹射+1"
4. 灵气 < 500 → "修复"置灰

### 其他山峰修复
5. 剑峰已修复 → 其余 5 座变为可点击
6. 点击未修复山峰 → 消耗正确显示（秘宝+女娲石+5000 灵气）
7. 材料不足 → 按钮置灰 + 红色标注不足项
8. 材料足够 → 修复完成，山峰变亮，器灵等级+1，能力解锁

### 顺序约束
9. 剑峰未修时点其他峰 → 无弹窗，"需先修复剑峰"浮字
10. 剑峰修复后 → 可自由选择修复顺序

### 器灵成长联动
11. 修复 1 座 → 器灵 level=1
12. 修复 6 座 → 器灵 level=6，全部能力解锁
13. 读档 → 山峰状态和器灵等级与存档一致
