## 1. 功能概述

**一句话**：器灵是玩家唯一化身。V0.1 仅百世书，永久绑定，随山峰修复逐级成长（0→6 级），解锁能力+外观进化。

**详细描述**：首次启动 → 开场黑幕 → 器灵选择界面 → 选定并确认百世书 → 永久绑定（存档记录 spirit_id）。之后每修复一座山峰，器灵等级 +1，解锁对应能力（弹射/护盾/分裂/穿透/范围/伤害），外观同步进化。战斗中 HP 归零时触发百世书免死特质：不死，强制回桌面态，无惩罚。

```

     职责：器灵绑定/成长/能力管理/免死触发

     职责：桌面态中显示器灵等级进度条+已解锁能力

不需要动的模块：
  - intro_screen.gd — 现有逻辑可沿用，在 intro_finished 后由 GameManager 切换到 MAIN_PEAK_SELECT
  - Enemy 相关 / WaveManager — 器灵属性通过 SpiritManager 接口查询
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式（选择） | intro_finished → MAIN_PEAK_SELECT 状态 → 显示选择界面 |

| 互斥状态（选择中） | 不可进入战斗/桌面态 |
| 可重复性（选择） | 仅一次（永久绑定） |

## 4. 数据定义

### 4.1 SpiritData（可定义为 Resource 或 Dictionary）

```gdscript
# 当前绑定的器灵数据（运行时内存，存档时序列化）
{
    "spirit_id": "baishishu",    # String
    "spirit_name": "百世书",      # String
    "level": 0,                   # int (0-6)
    "unlocked_abilities": [],     # Array[String] — 已解锁能力 ID 列表
}
```

### 4.2 器灵配置表（需要新 CSV）

```
☑ 需要新 CSV → spirit_config.csv

CSV 文件名：data/spirit_config.csv
列定义：
  spirit_id,string,,器灵唯一ID
  spirit_name,string,,器灵名称
  unlock_condition,string,,解锁条件（"initial"/"clear_1"/"clear_2"）
  trait_id,string,,特质ID（"immortality"=免死）
  trait_desc,string,,特质描述
  base_hp,int,2000,基础HP
  hp_per_level,int,200,每级HP加成
  energy_rate_bonus_per_level,float,0.1,每级灵气产出速率加成（10%）
```

### 4.3 山峰能力映射（不需要新 CSV，复用 peak_config.csv）

```
在现有 peak_config.csv 中新增列：
  ability_id,string,,修复后解锁的能力ID（"ricochet"/"shield"/"split"/"pierce"/"range"/"damage"）
```

## 5. 信号契约

```
信号 1（复用现有，修改参数）：start_game_requested(spirit_id: String)
  发射者：main_peak_select_panel.gd
  接收者：GameManager
  时机：玩家选定器灵并点击确认
  参数：spirit_id

信号 2（新建）：spirit_bound(spirit_id: String)
  发射者：SpiritManager
  接收者：GameManager、SaveManager
  时机：器灵绑定完成后
  参数：spirit_id

信号 3（新建）：spirit_leveled_up(new_level: int, ability_unlocked: String)
  发射者：SpiritManager
  接收者：GameManager（→通知UI更新+存档标记脏数据）
  时机：山峰修复 → 器灵升级
  参数：new_level — 新等级；ability_unlocked — 新解锁的能力ID

信号 4（新建）：immortality_triggered()
  发射者：SpiritManager
  接收者：GameManager（→强制结束战斗→回桌面态）
  时机：战斗中 HP 归零时
```

## 6. 逻辑流程

### 6.1 器灵选择

```
1. intro_finished → GameManager 切换到 MAIN_PEAK_SELECT
2. UIStateCoordinator 显示 main_peak_select_panel
3. V0.1：面板只显示百世书卡片（默认选中态，金边框）
4. 玩家点击「开始游戏」→ 发射 start_game_requested("baishishu")
5. GameManager 接收：
   → 调用 SpiritManager.bind_spirit("baishishu")
   → SpiritManager 设置内部状态，发射 spirit_bound("baishishu")
   → GameManager 切换到 DESKTOP_IDLE
   → SaveManager 触发首次存档
```

### 6.2 器灵成长

```
1. 山峰修复完成 → MountainManager 发射 peak_repaired(peak_id)
2. GameManager 接收 → 调用 SpiritManager.level_up(peak_id)
3. SpiritManager:
   → level += 1
   → 查 peak_config.csv 获取 ability_id
   → unlocked_abilities.append(ability_id)
   → 应用数值加成（HP += hp_per_level, energy_rate *= 1 + bonus）
   → 发射 spirit_leveled_up(new_level, ability_id)
4. SpiritGrowthPanel 更新进度条 + 已解锁能力文字
5. 器灵外观切换（如有对应精灵表）
```

### 6.3 免死触发

```
1. 战斗中 MainPeak.take_damage() → HP <= 0
2. MainPeak 检查 SpiritManager.get_trait() == "immortality"
3. 触发免死：
   → 暂停战斗（停止敌人移动/弹幕）
   → 播放免死动画（1.5s 百世书虚影+金光）
   → 显示文字「百世轮回，护你真灵不灭」
   → 发射 immortality_triggered()
4. GameManager 接收：
   → 切换到 BATTLE_RESULT（失败结算）
   → 结算为无惩罚（不掉材料/灵气）
   → 切换到 DESKTOP_IDLE
```

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 器灵选择（卡片） | 暗云背景居中。百世书卡片 240×320，金边框+发光。下方「开始游戏」按钮。 |
| 器灵选择（确认后） | 卡片选中态保持，按钮短暂变灰→场景 0.5s 淡入过渡到桌面态 |
| 成长进度（桌面态） | 7 个圆点横向排列，已修复金色填充+连线金色。下方文字列出已解锁能力。 |
| 免死（触发） | 1.5s 全屏金光+书影动画 + 文字。结束后 0.5s 过渡回桌面态。 |
| 免死（回桌面后） | 正常桌面态。无死亡惩罚提示。 |

## 8. 边界条件与互斥

```
☑ 器灵选择中退出游戏？→ 未绑定，不保存。下次启动无存档→重新走选择。
☑ 6 座山峰全部修复后还能升级吗？→ 不能，level max=6。
☑ 免死触发后 HP 状态？→ 回桌面态自动回满。
☑ 免死能触发多次吗？→ 每次战斗触发一次。V0.1 无次数限制。
☑ 战斗中 Boss 击杀瞬间同时 HP 归零？→ 免死优先触发，战斗结束（不算胜利）。
```

## 11. 验收标准

### 器灵选择
1. 首次启动 → 开场黑幕 → 器灵选择界面 → 只显示百世书卡片
2. 卡片默认选中态（金色边框），「开始游戏」可点击
3. 点击「开始游戏」→ 过渡 → 桌面态，存档中 spirit_id="baishishu"
4. 选完器灵后退出再启动 → 无存档（V0.1 首次流程），但存档已创建 → 下次启动进主菜单

### 器灵成长
5. 初始 level=0，无已解锁能力
6. 修复剑峰 → level=1，解锁「弹射+1」，进度条更新
7. 修复 6 座山峰 → level=6，全部能力解锁
8. 读档后 → 等级和能力与存档一致

### 免死
9. 战斗中 HP 归零 → 不死亡，触发免死动画 → 回桌面态
10. 免死后灵气/女娲石/秘宝不减少
11. 免死可在同一局战斗中重复触发（如果 HP 回血后再归零）

### 器灵绑定
12. 绑定后不可更换（无更换界面入口）
13. 新游戏→重新选择→新绑定覆盖旧存档
