# 三态切换系统 — 功能需求文档

> 版本：v0.1 | 日期：2026-07-31 | 状态：策划中
> GDD 依据：[开仙门-GDD-v3.0.md](../../01-愿景/开仙门-GDD-v3.0.md) §一.2

---

## 1. 功能概述

**一句话**：游戏在三种界面状态之间无缝切换——全屏战斗态 ⇄ 桌面放置态 ⇄ 最小化悬浮小窗。

**详细描述**：开仙门有三种窗口形态：全屏战斗态（1280×720+，类吸血鬼幸存者）、桌面放置态（1280×120 px 横条，贴屏幕底部）、最小化态（60-100 px 器灵卡通小窗，可拖动到桌面任意位置）。三态通过 Godot 窗口 API 动态切换分辨率/位置/置顶属性。切换时挂机数据持续计算（灵气累积/离线计时），战斗状态正确暂停/恢复。目标是让玩家感觉这是"同一个游戏的不同视图"，而非三个独立应用。

## 2. 模块影响分析

```
触及的现有模块：
  1. GameManager — 修改：新增加 DESKTOP_IDLE / MINIMIZED / BATTLE 三态 + 切换逻辑
  2. UIStateCoordinator — 修改：管理三种界面面板的显示/隐藏/过渡
  3. EnergyAccumulator（新建）— 修改：桌面态/最小化态灵气持续累积，战斗态暂停

需要新建的模块：
  1. WindowStateManager（scripts/managers/window_state_manager.gd，RefCounted）
     职责：Godot 窗口 API 调用——set_size/set_position/set_always_on_top/切换过渡动画
  2. StateTransitionEffect（scripts/effects/state_transition_effect.gd）
     职责：状态切换时的过渡动画（缩放/淡入淡出/滑动）

不需要动的模块：
  - 战斗内模块 — 战斗态独立运行
  - 存档 — 切换状态不触发存档（定时存档独立运作）
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式（桌面→战斗） | 点击 [⚔️ 挑战] 按钮 |
| 触发方式（桌面→最小化） | 点击 [_ 最小化] 按钮 |
| 触发方式（最小化→桌面） | 点击悬浮小窗 |
| 触发方式（战斗→桌面） | 战斗结算完成 / 战斗中手动退出（P1） |
| 切换时长 | 过渡动画 0.3-0.5s |
| 互斥规则 | 同一时间仅一种状态，不可状态叠加 |

## 4. 数据定义

### 4.1 三种窗口配置

| 状态 | 分辨率 | 位置 | 置顶 | 无边框 | 可拖动 |
|------|--------|------|------|--------|--------|
| 桌面放置态 | 1280×120 | 贴屏幕底部居中 | ✓（可选） | ✓ | ✗ |
| 全屏战斗态 | 1280×720（或显示器分辨率） | 屏幕中央 | ✗ | ✗ | ✗ |
| 最小化态 | 100×100 | 上次拖动位置（默认右下角） | ✓ | ✓ | ✓ |

### 4.2 状态间数据流

| 数据 | 桌面态 | 战斗态 | 最小化态 |
|------|--------|--------|---------|
| 灵气累积 | ✓ 实时 | ✗ 暂停 | ✓ 实时 |
| 离线计时 | ✓ | ✗ | ✓ |
| 山峰状态 | ✓ 展示 | ✗ 不展示 | ✗ 不展示 |
| 器灵 HP | 满（自动回复） | 实时 | 满（自动回复） |
| 战斗进度 | — | 实时 | 暂停 |

□ 不需要新 CSV — 窗口配置暂用常量，V0.2 可迁入 settings_config.csv

## 5. 信号契约

```
信号 1（新建）：state_transition_requested(from: String, to: String)
  发射者：DesktopIdlePanel / SettlementPanel / MinimizedPanel
  接收者：GameManager
  时机：玩家触发切换操作
  参数：from — 当前状态；to — 目标状态

信号 2（新建）：state_transition_started(from: String, to: String)
  发射者：GameManager
  接收者：WindowStateManager、StateTransitionEffect、UIStateCoordinator
  时机：切换确认、过渡开始

信号 3（新建）：state_transition_completed(new_state: String)
  发射者：GameManager
  接收者：UIStateCoordinator（→刷新对应状态的 UI）、EnergyAccumulator（→启动/暂停灵气累积）
  时机：过渡动画完成、窗口调整完毕

信号 4（新建）：window_drag_ended(new_position: Vector2)
  发射者：MinimizedPanel
  接收者：WindowStateManager（→保存位置偏好，下次最小化用此位置）
  时机：玩家拖动最小化窗口结束
```

## 6. 逻辑流程

### 6.1 桌面态 → 战斗态

```
1. 玩家点击 [⚔️ 挑战]
2. DesktopIdlePanel → state_transition_requested("desktop_idle", "battle")
3. GameManager 检查灵气 ≥ 100 → 不足：拒绝切换；足够：执行
4. state_transition_started("desktop_idle", "battle"):
   → EnergyAccumulator.stop() — 暂停灵气累积
   → Warehouse.consume_energy(100) — 扣除挑战消耗
   → WindowStateManager.switch_to_battle():
     → 取消置顶（如有）
     → 恢复窗口边框
     → set_size(1280×720) 或全屏
     → 窗口居中
   → StateTransitionEffect.play("expand"):
     → 桌面横条从底部向上展开（0.3s）
   → UIStateCoordinator 隐藏桌面 UI → 显示战斗 UI
   → 3 秒倒计时开始
5. 倒计时结束 → state_transition_completed("battle")
```

### 6.2 战斗态 → 桌面态

```
1. 战斗结算完成 → SettlementPanel 发射 settlement_closed()
2. state_transition_requested("battle", "desktop_idle")
3. state_transition_started("battle", "desktop_idle"):
   → 清理战斗资源（敌人/弹幕/挂件/祝福）
   → WindowStateManager.switch_to_desktop():
     → set_size(1280×120)
     → 贴屏幕底部 → set_position(x, screen_bottom - 120)
     → set_always_on_top(true)（可选）
     → 无边框
   → StateTransitionEffect.play("collapse"):
     → 全屏从上下向中间收缩至横条（0.3s）
   → EnergyAccumulator.start() — 恢复灵气累积
4. state_transition_completed("desktop_idle")
5. DesktopIdlePanel 刷新资源数字 + 结算获得的 buff 图标
```

### 6.3 桌面态 ⇄ 最小化态

```
桌面→最小化：
1. 点击 [_ 最小化]
2. state_transition_started("desktop_idle", "minimized"):
   → 保留灵气累积（EnergyAccumulator 继续）
   → WindowStateManager.switch_to_minimized():
     → set_size(100×100)
     → 移到上次记忆位置或默认右下角
     → 置顶+无边框+可拖动
   → StateTransitionEffect.play("shrink_to_spirit"):
     → 横条收缩至器灵小窗（0.3s，缩放+淡出其他元素）
3. state_transition_completed("minimized")
4. MinimizedPanel 显示器灵打坐动画 + 可选灵气数字

最小化→桌面：
1. 点击悬浮小窗
2. state_transition_started("minimized", "desktop_idle"):
   → WindowStateManager.switch_to_desktop():
     → 恢复 1280×120 + 贴底部
   → StateTransitionEffect.play("expand_from_spirit"):
     → 小窗展开至横条（0.3s）
3. state_transition_completed("desktop_idle")
```

### 6.4 战斗中最小化（P1）

```
1. 战斗中按 Esc 或特定按钮 → 确认弹窗"战斗中离开将暂停战斗，确定？"
2. 确定 → 战斗暂停（get_tree().paused = true）
   → 切换到最小化态
3. 最小化态点击 → 弹窗"继续战斗？"
   → 确定 → 恢复桌面态或直接回战斗态
```

## 7. UI 表现

| 过渡 | 动画 | 时长 |
|------|------|------|
| 桌面→战斗 | 横条从底部向上展开至全屏 | 0.3s |
| 战斗→桌面 | 全屏从上下向中间收缩至横条 | 0.3s |
| 桌面→最小化 | 横条收缩+聚焦至器灵（其他元素淡出） | 0.3s |
| 最小化→桌面 | 小窗展开至横条（其他元素淡入） | 0.3s |

| 元素 | 桌面态 | 战斗态 | 最小化态 |
|------|--------|--------|---------|
| 窗口边框 | 无 | 有 | 无 |
| 置顶 | 是（可配置） | 否 | 是 |
| 可拖动 | 否 | 否 | 是 |

## 8. 边界条件与互斥

```
☑ 切换过程中再次触发切换？→ 忽略，过渡动画期间禁用切换按钮
☑ 战斗中桌面态精灵？→ 隐藏，等战斗结束更新
☑ 最小化态退出游戏？→ 保存当前状态（桌面/最小化位置），下次启动恢复
☑ 多显示器？→ V0.1 只支持主显示器。V0.2 支持记忆显示器
☑ 最小化态被其他窗口遮挡？→ 置顶保证始终可见
☑ 桌面态遮挡任务栏？→ 贴底部时检查任务栏高度，避免遮挡
☑ Godot 窗口 API 兼容性？→ Window 类在 Godot 4.7 稳定，需测试 set_always_on_top 在 Windows 的表现
```

## 11. 验收标准

### 桌面→战斗
1. 桌面态点击 [⚔️ 挑战] → 横条从底部展开至全屏（0.3s）→ 3 秒倒计时
2. 灵气不足 → 按钮抖动 + "灵气不足"，不切换

### 战斗→桌面
3. 战斗结算完成 → 全屏收缩至横条（0.3s）→ 资源栏更新
4. 桌面态灵气恢复自动增长

### 桌面⇄最小化
5. 点击 [_ 最小化] → 横条收缩至 100×100 小窗 → 器灵打坐动画
6. 点击小窗 → 展开回 1280×120 横条 → 所有元素出现
7. 拖动小窗到桌面新位置 → 下次最小化时在此位置出现

### 数据连续性
8. 桌面态灵气 500，切换到最小化 → 5 秒后切回 → 灵气约 550（持续累积）
9. 战斗中不累积灵气（能量累积暂停）
10. 最小化态退出游戏 → 下次启动 → 桌面态，离线收益计算正确

### 窗口属性
11. 桌面态/最小化态窗口置顶，不被他窗口遮挡
12. 战斗态窗口正常（非置顶，可 Alt+Tab 切换）
