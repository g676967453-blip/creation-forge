## 1. 功能概述

**一句话**：纯数值仓库。三种资源以 int 存储，桌面态底部资源栏常驻显示。无格子、无图标仓库界面、无挂件存储。

**详细描述**：EconomyManager（新建 Autoload）管理三种资源（灵气/女娲石/流派秘宝）的 int 数值。各系统通过 EconomyManager 的 add/spend 方法增减资源。桌面态底部半透明资源栏常驻显示当前数量。资源增减时数字即时刷新。V0.1 不做背包界面，挂件不入仓库。

## 2. 模块影响分析

```
需要新建的模块：
  1. EconomyManager（autoload/economy_manager.gd，Autoload）
     职责：资源存取/校验/变更信号发射
  2. ResourceBar（scenes/ui/resource_bar.tscn + scripts/ui/resource_bar.gd）
     职责：桌面态底部资源栏 UI（显示三种资源的图标+数字）

触及的现有模块：
  1. GameManager — 初始化时创建 EconomyManager 实例；状态切换时显隐 ResourceBar
  2. SaveManager — 存档时从 EconomyManager 读取资源数据；读档时写入

不需要动的模块：
  - MountainManager / WaveManager / Enemy相关 — 它们调用 EconomyManager API 即可
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式（增减） | 各系统调用 EconomyManager API |
| 触发方式（显示） | DESKTOP_IDLE 状态下 ResourceBar 常驻显示 |
| 互斥状态（隐藏） | INTRO / MAIN_PEAK_SELECT / MAIN_MENU 状态下不显示资源栏 |
| 可重复性 | 增减可无限次 |

## 5. 信号契约

```
信号 1（新建）：resource_changed(type: String, new_value: int, delta: int)
  发射者：EconomyManager
  接收者：ResourceBar（更新显示）、GameManager（存档触发判断）
  时机：任何资源变更后发射
  参数：type — "energy"/"stone"/"treasure:peak_id"；new_value — 变更后数值；delta — 变化量（正+负）

信号 2（新建）：resource_insufficient(type: String, required: int, current: int)
  发射者：EconomyManager
  接收者：GameManager（用于弹提示）
  时机：spend 时余额不足
  参数：type/required/current
```

---

## 6. 逻辑流程

```
1. 增加资源：
   EconomyManager.add_energy(amount) / add_stone(amount) / add_treasure(peak_id, amount)
   → _value += amount（clamp 到 0 以上）
   → 发射 resource_changed(type, new_value, amount)

2. 消耗资源：
   EconomyManager.spend_energy(amount) / spend_stone(amount) / spend_treasure(peak_id, amount)
   → 检查余额
     → 足够 → _value -= amount → 发射 resource_changed
     → 不足 → 发射 resource_insufficient → 返回 false

3. 秘宝存取：
   EconomyManager.add_treasure("jianfeng", 1)
   → _secret_treasures["jianfeng"] += 1
   → 发射 resource_changed("treasure:jianfeng", new_value, 1)
```

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 资源栏（常态） | 桌面态底部，半透明深色底栏，横向排列 3 类资源。每类：圆形图标(28×28) + 数字(14px bold) + 标签(10px) |
| 资源栏（增减） | 数字即时跳变。V0.1 无动画，V0.2 做数字滚动动画。 |
| 资源栏（有秘宝时） | 显示拥有的秘宝种类（如剑峰秘宝×2）。不显示数量为 0 的秘宝 |
| 资源栏（无秘宝时） | 只显示灵气+女娲石，不显示秘宝区域 |
| 资源栏（战斗态） | 不显示。战斗中有独立的战斗 HUD（见战斗系统策划案） |
| 资源不足提示 | V0.1 按钮置灰+tooltip。V0.2 弹 Toast |

## 8. 边界条件与互斥

```
☑ 资源变为负数？→ spend 时余额不足拒绝操作。add 接收负值时 clamp 到 0。
☑ 灵气超过 int 上限？→ Godot int 为 64 位有符号，上限 9e18，远超实际需求。不加额外限制。
☑ 挂件捡到第 4 个？→ 旧挂件被替换消失，不触发仓库操作。
☑ 多系统同时修改同一资源？→ EconomyManager 方法加锁（mutex）或 GDScript 单线程无需加锁。
```

## 11. 验收标准

1. 启动游戏首次进入桌面态 → 资源栏显示灵气=0、女娲石=0
2. 挂机 60s → 灵气 +60（速率 1/s），资源栏数字即时刷新
3. 战斗胜利 → 女娲石 +1，资源栏数字更新
4. 修复剑峰（消耗灵气 500）→ 灵气 -500，数字实时减少
5. 灵气不足时点击修复 → 按钮置灰，操作被拒绝
6. 存档后再读档 → 资源数量与存档时一致
7. 离线收益结算 → 灵气增加离线量，资源栏显示
8. 资源栏在开场黑幕/器灵选择/主菜单中不显示
