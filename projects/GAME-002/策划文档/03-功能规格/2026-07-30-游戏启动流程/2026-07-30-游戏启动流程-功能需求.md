## 1. 功能概述

**一句话**：游戏启动后检测存档，有档进主菜单，无档直接走首次流程（开场黑幕→器灵选择→桌面态）。

**详细描述**：游戏进程启动后，在渲染任何 UI 之前执行存档检测（`<100ms`）。有存档 → 显示主菜单（继续游戏/新游戏/设置）。无存档 → 跳过主菜单，直接进入开场黑幕，之后经过器灵选择界面进入桌面放置态，首次自动存档。所有界面切换使用 0.5s 淡入淡出过渡。

## 2. 模块影响分析

```
触及的现有模块：
  1. GameManager — 修改启动状态机逻辑（新增 SAVE_CHECK 状态 + 分支判断）
  2. UIStateCoordinator — 新增 MAIN_MENU 状态，修改 INTRO→MAIN_PEAK_SELECT→DESKTOP_IDLE 链条
  3. intro_screen.gd — 现有文件，逻辑可沿用（逐段播放+跳过），需确认路径和信号不变
  4. main_peak_select_panel.gd — 现有文件，逻辑可沿用（单选+确认），需确认信号不变
  5. DataManager — 仅读（存档文件存在性检查，不涉及 CSV）

需要新建的模块：
  1. MainMenu — 主菜单场景+脚本（main_menu.tscn + main_menu.gd）
    职责：显示标题+3 按钮，处理按钮点击，发射信号给 GameManager
  2. SettingsPanel — 设置弹窗场景+脚本（settings_panel.tscn + settings_panel.gd）
    职责：音量滑块+窗口模式选择，读写配置，即时生效
  3. SaveManager — 存档管理器（save_manager.gd，Autoload）
    职责：存档存在性检测、读档、存档、离线收益计算
    注：具体存档数据结构见「存档系统」策划案，此处只定义检测接口

不需要动的模块（明确排除）：
  - WaveManager — 启动阶段不涉及战斗
  - CardManager — 已废弃（GDD v3.0 砍掉卡牌系统）
  - MountainManager — 启动阶段不涉及山峰
  - Enemy 相关 — 启动阶段无敌人
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式 | 游戏进程启动（自动触发） |
| 触发对象 | GameManager._ready() 中首个逻辑 |
| 前置游戏状态 | 无（游戏刚启动） |
| 互斥状态 | 无（此时没有任何状态） |
| 可重复性 | 每次启动执行一次 |

### GameManager 状态枚举（需修改）

```gdscript
enum GameState {
    SAVE_CHECK,        # 新增：存档检测（<100ms，无 UI）
    MAIN_MENU,          # 新增：主菜单
    INTRO,              # 现有：开场黑幕
    MAIN_PEAK_SELECT,   # 现有：器灵选择
    DESKTOP_IDLE,       # 新增：桌面放置态（替代旧 PREPARATION）
    BATTLE,             # 现有：全屏战斗态
    BATTLE_RESULT,      # 新增：战斗结算
    MINIMIZED,          # 新增：最小化悬浮窗
}
```

### 状态转移

```
SAVE_CHECK
  ├─ 有存档 → MAIN_MENU
  └─ 无存档 → INTRO

MAIN_MENU
  ├─ [继续] → DESKTOP_IDLE（经读档+离线收益）
  ├─ [新游戏] → INTRO（经确认弹窗+清档）
  └─ [设置] → 弹窗（不切换状态）

INTRO
  └─ intro_finished → MAIN_PEAK_SELECT

MAIN_PEAK_SELECT
  └─ start_game_requested → DESKTOP_IDLE（首次自动存档）
```

```
  发射者：MainMenu
  接收者：GameManager
  时机：玩家点击「设置」按钮

信号 5（复用现有）：intro_finished()
  发射者：intro_screen.gd
  接收者：GameManager

  发射者：main_peak_select_panel.gd
  接收者：GameManager

  发射者：GameManager
```

## 6. 逻辑流程

### 主流程

```
1. GameManager._ready()
   → 设置状态为 SAVE_CHECK
   → 调用 SaveManager.check_save_exists()

2. SaveManager.check_save_exists()
   → 检查 user://save_data.json
   → 文件存在 + JSON 解析成功 + 必填字段完整 → has_save = true
   → 文件不存在 → has_save = false
   → 文件存在但解析失败 → has_save = false，记录 warning 日志
   → 发射 save_check_complete(has_save)

3. GameManager 接收 save_check_complete
   → has_save == true → 切换到 MAIN_MENU 状态
     → UIStateCoordinator 显示主菜单场景
   → has_save == false → 切换到 INTRO 状态
     → UIStateCoordinator 显示 intro_screen，开始逐段播放

4. [分支 A：主菜单 → 继续游戏]
   → 玩家点击「继续游戏」
   → MainMenu 发射 continue_game_requested
   → GameManager 调用 SaveManager.load_game()
     → 成功 → 计算离线收益 → 显示离线收益弹窗
       → 玩家确认 → 进入 DESKTOP_IDLE
     → 失败 → 弹提示「存档读取失败」→ 回 MAIN_MENU

5. [分支 B：主菜单 → 新游戏]
   → 玩家点击「新游戏」
   → MainMenu 显示确认弹窗
     → 确定 → 发射 new_game_requested
       → GameManager 调用 SaveManager.delete_save()
       → 切换到 INTRO 状态
     → 取消 → 关闭弹窗

6. [分支 C：主菜单 → 设置]
   → 玩家点击「设置」
   → MainMenu 发射 settings_requested
   → GameManager 通知 MainMenu 显示设置弹窗（不切换状态）

7. [分支 D：无存档直接进 INTRO]
   → INTRO 状态 → intro_screen 播放
   → intro_finished → MAIN_PEAK_SELECT
   → 器灵选择 → start_game_requested(spirit_id)
   → 切换到 DESKTOP_IDLE
   → 发射 desktop_idle_entered(is_first_launch=true)
   → SaveManager 执行首次自动存档

8. [所有分支终点]
   → DESKTOP_IDLE 状态
   → 桌面放置态 UI 接管（见「桌面放置态」策划案）
```

### 分支流程

- **存档损坏**：SaveManager 检测到文件无法解析 → has_save=false + warning 日志 → 走分支 D。V0.1 不做「存档损坏」弹窗提示（会直接走首次流程），V0.2 加入。
- **读档失败**：继续游戏时 load_game() 返回 null → 弹提示回主菜单，不自动走新游戏。
- **快速连续点击**：主菜单按钮在发射信号后立即禁用（防止双击触发两次），状态切换完成后恢复。

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 主菜单（正常） | 深蓝紫渐变背景，标题「开仙门」金色大字居中，3 个按钮纵向排列，间距 16px。按钮：宽 220×高 48，暗色半透明底+细边框。 |
| 主菜单（hover） | 按钮边框变金色，背景微亮（rgba(187,153,102,0.1)），过渡 0.2s。 |
| 主菜单（点击后） | 按钮保持 hover 态 + 发射信号后立即 `disabled = true`，防止重复点击。 |
| 设置弹窗（打开） | 半透明黑色遮罩覆盖主菜单，弹窗居中。V0.1 直接 display 切换（无动画），V0.2 加缩放淡入。 |
| 设置弹窗（操作） | 音量滑块拖动即时生效（AudioServer.set_bus_volume_db）。窗口模式切换即时生效（DisplayServer.window_set_mode）。 |
| 确认弹窗（新游戏） | 居中弹出，警告文案「当前进度将丢失，确定开始新游戏？」，确定按钮红色，取消按钮灰色。 |
| 离线收益弹窗 | 居中弹出，显示离线时长 + 灵气数量。玩家点击「确认」或 3s 后自动关闭。 |
| 界面过渡 | 全屏淡入淡出黑屏 0.5s。实现：ColorRect(纯黑, 全屏) + Tween(modulate.a: 0→1→0)。过渡期间 GameManager 不响应其他输入。 |
| 开场黑幕 | 纯黑背景 #000000，白色文字逐段 fade-in/fade-out。详见「开场黑幕」策划案。 |
| 器灵选择 | 暗云背景渐变，单张器灵卡片。详见「器灵选择」策划案。 |

## 8. 边界条件与互斥

```
☑ 能重复操作吗？怎么阻止？
  主菜单按钮点击后立即 disabled，状态切换完成后恢复。
  器灵选择确认后不可更改（永久绑定），面板销毁。

☑ 有数值上下限吗？
  音量：0-100，步长 1。
  窗口模式：全屏 / 窗口化 1280×720，V0.1 不做更多分辨率。

☑ 和其他功能互斥吗？
  SAVE_CHECK 状态无 UI，不与其他任何功能冲突。
  MAIN_MENU 状态下，战斗/山峰/挂机等未启动，天然互斥。
  INTRO 状态下不响应任何其他输入（除 skip 操作）。
  设置弹窗打开时，主菜单按钮不可点击。

☑ 数据不够时：禁用 / 弹窗 / 静默失败？
  存档文件不存在 → 走首次流程（非错误，是正常分支）。
  存档损坏 → V0.1 静默走首次流程。V0.2 弹提示。
  读档失败 → 弹提示回主菜单。

☑ 极端值处理：0、负数、空字符串、null？
  音量=0 → 静音，合法值。
  窗口尺寸=0 → 不可能发生（取自项目设置配置）。
  存档文件内容为空 → 视为损坏，走首次流程。
  存档 JSON 解析返回 null → 视为损坏。

☑ 快速连续点击会怎样？
  - 主菜单按钮：第一次点击后 disabled，后续点击无效。
  - 开场黑幕 skip：0.3s 冷却（现有 intro_screen.gd 已实现）。
  - 器灵选择确认：点击后面板销毁，不可重复确认。

☑ 操作中途切换状态会怎样？
  - 设置弹窗打开时按 ESC → 关闭弹窗（V0.2）。
  - 开场黑幕播放中无法切换状态（只有 skip 和等待完成）。
  - 器灵选择中无法返回（不可逆操作）。
```

## 11. 验收标准

### 启动检测

1. 删除存档文件后启动游戏 → 不显示主菜单，直接进入开场黑幕
2. 有存档文件时启动游戏 → 显示主菜单，三个按钮均可点击
3. 存档文件内容为空 `{}` 时启动 → 视为无存档，走首次流程
4. 存档文件被篡改（JSON 语法错误）→ 视为无存档，走首次流程，不崩溃

### 主菜单 — 继续游戏

5. 点击「继续游戏」→ 读档成功 → 显示离线收益弹窗 → 确认 → 进入桌面放置态
6. 读档失败 → 弹提示「存档读取失败」→ 点击确认回主菜单

### 主菜单 — 新游戏

7. 点击「新游戏」→ 弹出确认弹窗「当前进度将丢失，确定开始新游戏？」
8. 点击「确定」→ 清档 → 进入开场黑幕 → 器灵选择 → 桌面态
9. 点击「取消」→ 关闭弹窗，留在主菜单
10. 新游戏流程完成后 → 自动创建存档文件

### 主菜单 — 设置

11. 点击「设置」→ 弹出设置弹窗，显示音量滑块（默认 80）+ 窗口模式下拉（默认窗口化）
12. 拖动音量滑块 → 音量即时变化
13. 切换窗口模式 → 窗口即时切换（全屏/窗口化 1280×720）
14. 点击「关闭」→ 弹窗关闭，设置保留

### 过渡与防呆

15. 任何界面切换 → 0.5s 淡入淡出过渡，过渡期间不响应输入
16. 主菜单按钮快速双击 → 只触发一次（button.disabled 生效）
17. 器灵选择后确认 → 不可返回重新选择

```markdown
## 游戏启动流程

### 1. 概述
**一句话**：启动后检测存档，有档进主菜单，无档直接走首次流程。
**详细描述**：GameManager._ready() 首个逻辑调用 SaveManager 检测存档。有档→主菜单（3按钮）。无档→开场黑幕→器灵选择→桌面态+首次存档。所有切换 0.5s 淡入淡出。

### 2. 模块影响
触及：GameManager（状态机修改）、UIStateCoordinator（新增状态）、intro_screen.gd（复用）、main_peak_select_panel.gd（复用）、DataManager（读存档文件）
新建：MainMenu（主菜单场景+脚本）、SettingsPanel（设置弹窗）、SaveManager（Autoload，存档管理）
不动：WaveManager、CardManager、MountainManager、Enemy相关

### 3. 触发条件
- 触发方式：游戏进程启动时自动触发
- 触发对象：GameManager._ready()
- 前置状态：无
- 互斥状态：无
- 可重复性：每次启动执行一次

### 4. 数据
涉及现有数据：存档文件存在性（SaveManager.has_save()）、当前游戏状态（GameManager.current_state）
新 CSV？否
新 Resource？否（SaveData 见存档系统策划案）

### 5. 信号契约
- save_check_complete(has_save: bool) — SaveManager → GameManager — 检测完成
- continue_game_requested() — MainMenu → GameManager — 点击继续
- new_game_requested() — MainMenu → GameManager — 点击新游戏（确认后）
- settings_requested() — MainMenu → GameManager — 点击设置
- intro_finished() — intro_screen → GameManager — 黑幕结束（复用现有）
- start_game_requested(spirit_id: String) — main_peak_select_panel → GameManager — 器灵选定（复用现有）
- desktop_idle_entered(is_first_launch: bool) — GameManager → SaveManager+DesktopUI — 进入桌面态

### 6. 逻辑流程
SAVE_CHECK → has_save? → MAIN_MENU : INTRO
MAIN_MENU → 继续/新游戏/设置 → DESKTOP_IDLE / INTRO / 弹窗
INTRO → 逐段播放+跳过 → intro_finished → MAIN_PEAK_SELECT
MAIN_PEAK_SELECT → 选择+确认 → start_game_requested → DESKTOP_IDLE（首次存档）
[详细分支见第6节]

### 7. UI 表现
主菜单：渐变背景+金色标题+3按钮纵向排列，hover金色边框
设置弹窗：遮罩+居中卡片，音量滑块+窗口模式下拉
确认弹窗：警告文案+红色确定+灰色取消
离线收益弹窗：离线时长+灵气数字，确认关闭或3s自动关闭
过渡：ColorRect全屏黑+Tween 0.5s淡入淡出

### 7-附. 美术与体验需求
P0：主菜单背景(1920×1080)、按钮底板(220×48)、弹窗底板(400×280)、场景过渡特效
P1：弹窗按钮(100×36)、标题字体、按钮hover光效
P2：设置滑块、标题呼吸光、云层漂移、弹窗入场动画、灵气粒子
V0.1 无音效需求。

### 8. 边界条件
按钮点击后 disabled 防连点。音量 0-100。存档损坏静默走首次流程（V0.2 弹提示）。读档失败弹提示回主菜单。ESCAPE 关闭弹窗（V0.2）。过渡期间不响应输入。

### 9. 三层归属
表现层：main_menu、settings_panel、offline_reward_panel、confirm_dialog
逻辑层：game_manager.gd（修改状态机）、save_manager.gd（新增Autoload）、ui_state_coordinator.gd（新增状态）
数据层：save_manager.gd（存档数据结构）
跨层检查：表现层不读CSV、逻辑层不操作UI节点、数据层不通知UI ✓

### 10. 反模式自查
不制造上帝Manager ✓ 无硬编码路径 ✓ 逻辑不操作UI ✓ 无双轨数据 ✓ 无循环信号依赖 ✓

### 11. 验收标准
1. 无存档启动 → 直接进开场黑幕
2. 有存档启动 → 显示主菜单
3. 继续游戏 → 离线收益 → 桌面态
4. 新游戏 → 确认弹窗 → 清档 → 首次流程 → 自动存档
5. 设置修改即时生效
6. 0.5s 过渡 + 防连点
```
