## 1. 功能概述

**一句话**：桌面常驻横板挂机界面，器灵打坐修炼，灵气自动累积，山峰分布两侧，是游戏的主循环中枢。

**详细描述**：桌面放置态是游戏三大界面状态中的"常态"。玩家启动游戏并选择器灵后即进入此状态。横板 1280×120 px 贴屏幕底部，器灵在中央 C 位打坐修炼。灵气随时间自动增长（基础速率 + 器灵加成 + 已修复山峰加成）。六座山峰分布器灵两侧，已修复的亮起、未修复的灰暗。底部资源栏显示灵气/女娲石/秘宝。玩家可在此状态操作：点击山峰修复、点击器灵爆灵气、点击[⚔️ 挑战]进入全屏战斗、点击[_ 最小化]切换最小化态。

## 2. 模块影响分析

```
触及的现有模块：
  1. GameManager — 新增 DESKTOP_IDLE 状态处理、灵气自动增长逻辑
  2. UIStateCoordinator — 新增 desktop_idle_panel 的显示/隐藏管理
  3. MountainManager — 读（获取山峰状态列表用于 UI 渲染）
  4. SpiritManager — 读（获取灵气产出加成、器灵等级）
  5. SaveManager — 定时自动保存触发
  6. Warehouse（新建） — 读（灵气/女娲石/秘宝数量）

需要新建的模块：
  1. DesktopIdlePanel（scenes/ui/desktop_idle_panel.tscn + scripts/ui/desktop_idle_panel.gd）
     职责：桌面态主 UI——山峰列表、器灵区域、资源栏、操作按钮
  2. EnergyAccumulator（scripts/managers/energy_accumulator.gd，逻辑层）
     职责：灵气自动累积计算（基础速率 + 器灵加成 + 山峰加成），发射 energy_changed 信号

不需要动的模块：
  - Enemy / WaveManager / BattleHUD — 战斗专属，桌面态不涉及
  - IntroScreen / MainPeakSelectPanel — 前置流程，完成后不再触发
```

## 4. 数据定义

### 4.1 灵气累积规则

| 参数 | 值 | 来源 |
|------|-----|------|
| 基础速率 | 10 灵气/秒 | 常量（可后续迁入 CSV） |
| 器灵加成 | 基础速率 × spirit_level × 0.1 | SpiritManager |
| 已修复山峰加成 | 已修复山峰数 × 2 灵气/秒 | MountainManager |
| 离线累积上限 | 24 小时 | 常量 |
| 点击器灵爆发 | +20 灵气/次 | 常量 |
| 点击器灵 CD | 5 秒 | 常量 |

### 4.2 涉及现有数据

| 数据字段 | 类型 | 所在位置 | 操作 | 说明 |
|---------|------|---------|------|------|
| energy | int | Warehouse | 读+加 | 灵气数值 |
| nvwa_stone | int | Warehouse | 读 | 女娲石数量 |
| secret_treasures | Dict | Warehouse | 读 | 各流派秘宝数量 |
| spirit_level | int | SpiritManager | 读 | 器灵等级 |
| repaired_peaks | Array[String] | MountainManager | 读 | 已修复山峰 ID 列表 |

### 4.3 是否需要新 CSV？

```
□ 不需要新 CSV — 灵气累积参数先用常量，V0.2 迁入 game_config.csv
```

## 5. 信号契约

```
信号 1（新建）：energy_accumulated(current: int, delta: int)
  发射者：EnergyAccumulator
  接收者：DesktopIdlePanel（→更新资源栏数字）
  时机：每次灵气累积 tick（每秒）
  参数：current — 当前灵气总量；delta — 本次增量

信号 2（新建）：spirit_clicked()
  发射者：DesktopIdlePanel
  接收者：EnergyAccumulator（→爆发灵气）+ 播放点击动画
  时机：玩家点击器灵区域，且 CD 已过

信号 3（新建）：challenge_requested()
  发射者：DesktopIdlePanel
  接收者：GameManager（→消耗灵气→切换到 BATTLE）
  时机：玩家点击 [⚔️ 挑战] 按钮

信号 4（新建）：minimize_requested()
  发射者：DesktopIdlePanel
  接收者：GameManager（→切换到 MINIMIZED）
  时机：玩家点击 [_ 最小化] 按钮

信号 5（复用现有）：mountain_repaired(peak_id: String)
  发射者：MountainManager
  接收者：DesktopIdlePanel（→刷新山峰状态）、EnergyAccumulator（→更新加成）
```

## 6. 逻辑流程

### 6.1 进入桌面态

```
1. GameManager 切换到 DESKTOP_IDLE
2. UIStateCoordinator 显示 DesktopIdlePanel
3. DesktopIdlePanel._ready():
   → 读取 MountainManager 获取 6 山峰状态（id/name/repaired/ability_id）
   → 渲染山峰列表（器灵左侧 3 座、右侧 3 座）
   → 读取 Warehouse 获取资源数量
   → 渲染底部资源栏
4. EnergyAccumulator 开始计时（_process 累加 delta）
```

### 6.2 灵气自动增长

```
1. EnergyAccumulator._process(delta):
   → _accumulated += 基础速率 × delta
   → 查询 SpiritManager.get_energy_bonus() → 器灵加成
   → 查询 MountainManager.get_repaired_count() → 山峰加成
   → 每秒发射 energy_accumulated(total, delta_this_second)
2. DesktopIdlePanel 接收 → 更新资源栏灵气数字
```

### 6.3 点击器灵爆发

```
1. 玩家点击器灵区域
2. DesktopIdlePanel 检查 CD（默认 5 秒）
   → CD 未过：无反应（或抖动动画提示）
   → CD 已过：
     → 发射 spirit_clicked()
     → EnergyAccumulator 立即 +20 灵气
     → 播放器灵闪烁/弹跳动画 + "💨 +20" 浮动文字
     → CD 计时器重置
```

### 6.4 山峰修复入口

```
1. 玩家点击未修复山峰
2. DesktopIdlePanel 发射 peak_repair_requested(peak_id)
3. GameManager → 显示 RepairPromptPanel（复用已有逻辑，修改消耗参数）
4. 修复完成 → MountainManager 发射 mountain_repaired → DesktopIdlePanel 刷新
```

### 6.5 挑战入口

```
1. 玩家点击 [⚔️ 挑战]
2. DesktopIdlePanel 发射 challenge_requested()
3. GameManager 检查灵气是否足够（消耗量待定，如 100 灵气）
   → 不足：按钮抖动 + "灵气不足" 浮动提示
   → 足够：扣除灵气 → 切换 BATTLE → EnergyAccumulator 暂停
```

## 8. 边界条件与互斥

```
☑ 灵气有上限吗？→ V0.1 无上限。V0.2 可考虑软上限（如 99,999）
☑ 点击器灵 CD 中连点？→ 无反应，可加抖动动画提示
☑ 离线回来灵气超 24h 上限？→ 封顶 24h 收益，弹出提示
☑ 战斗中桌面态在干嘛？→ 隐藏/暂停。灵气不增长（已进入战斗消耗）
☑ 修复面板弹出时灵气自动增长？→ 继续增长（修复检查和扣除以最新值为准）
☑ 窗口失去焦点？→ 挂机继续，不暂停
☑ 6 座全修完？→ 所有山峰亮起，无更多修复操作
```

## 10. 反模式自查

```
□ 这个功能是否在制造"上帝 Manager"？
  → 否。EnergyAccumulator 只管灵气累积计算，不涉及 UI/存档/其他业务。

□ 是否有新的硬编码 res:// 或 get_node("路径")？
  → 否。所有引用通过信号 + Autoload 访问。

□ 是否在逻辑代码里直接操作了 UI？
  → 否。灵气变化通过 energy_accumulated 信号通知 UI。

□ 是否有数据在代码和 CSV 中双轨存在？
  → 灵气累积参数暂时硬编码（V0.1 快速验证），V0.2 迁入 game_config.csv。

□ 模块之间是否有循环信号依赖？
  → 否。信号流向：DesktopIdlePanel → GameManager → EnergyAccumulator → DesktopIdlePanel（单向闭环）
```

## 11. 验收标准

### 进入与退出
1. 器灵选择确认 → 自动进入桌面态，看到横板界面
2. 战斗结算完成 → 自动回到桌面态，资源更新
3. 桌面态点击 [_ 最小化] → 切换到最小化态
4. 最小化态点击器灵 → 展开回桌面态

### 灵气累积
5. 桌面态静止不动 → 灵气数字每秒自动增长（基础 10/s）
6. 修复 1 座山峰 → 灵气增长速率 +2/s（基础 10 + 山峰 2 = 12/s）
7. 器灵升级 → 灵气增长速率增加（10 × level × 0.1）

### 点击器灵
8. 点击器灵 → 灵气 +20，"💨 +20" 浮动文字，器灵弹跳动画
9. 5 秒内再次点击 → 无反应
10. 5 秒后再次点击 → 正常 +20

### 山峰交互
11. 点击未修复山峰 → 弹出修复面板
12. 点击已修复山峰 → 无弹窗（V0.1），或展示已解锁能力（V0.2）

### 挑战入口
13. 灵气 ≥ 100 → [⚔️ 挑战] 可点击，点击后进入战斗
14. 灵气 < 100 → [⚔️ 挑战] 置灰或点击抖动提示"灵气不足"

### 离线收益
15. 退出游戏 1 小时 → 重新启动 → 弹出"获得 💨 +36,000 灵气"提示
16. 离线超过 24 小时 → 收益封顶 24h，弹出提示
