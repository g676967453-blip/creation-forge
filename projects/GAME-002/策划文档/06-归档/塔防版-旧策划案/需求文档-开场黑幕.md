## 1. 功能概述

**一句话**：游戏启动后播放世界观文字淡入动画，点击跳过进入器灵选择。

**详细描述**：玩家启动游戏后，首先看到纯黑画面。4 段世界观文字逐段淡入（每段 ~0.9s），讲述上古仙门崩塌、法宝化山沉睡、器灵万年苏醒的背景故事。文字全部显示后，底部出现"点击任意处继续"提示。玩家点击或按任意键，第一次快进动画（跳过淡入直接显示全部），第二次结束开场进入器灵选择界面。ESC 键也可跳过。

## 6. 逻辑流程

```
主流程：
  1. GameManager._ready() → 初始化 GameState 为 INTRO
  2. UIStateCoordinator.set_state(INTRO) → intro_screen.visible = true
  3. IntroScreen._ready() → 调用 _build() 构建 UI → 调用 _play_fade_in() 开始动画
  4. 4 段文字逐段淡入（每段 0.9s，Tween 顺序播放）
  5. 最后一段结束后 → 底部提示"点击任意处继续"淡入（0.6s）→ _revealed = true

交互分支：
  - 动画播放中 → 用户点击/按键 → 快进：跳过 Tween，所有文字和提示直接显示（alpha = 1.0）
  - 动画已完成 → 用户点击/按键 → 结束：_finished = true，发射 intro_finished 信号
  - 任意时刻 → 用户按 ESC → GameManager._unhandled_key_input() 在 INTRO 状态下直接切换到 MAIN_PEAK_SELECT

防御分支：
  - intro_screen 节点不存在 → GameManager 跳过 INTRO 状态，直接从 MAIN_PEAK_SELECT 开始
  - intro_screen 被重新显示（visible 从 false→true 且未 _finished）→ 重播淡入动画
```

## 7. UI 表现

| 状态 | 表现 |
|------|------|
| 动画播放中 | 纯黑背景（`Color(0,0,0,1)`）。4 段文字逐段从透明(α=0)淡入至白色(α=1)。底部提示隐藏(α=0)。 |
| 全部显示 | 纯黑背景。4 段文字全部显示(α=1)。底部显示"点击任意处继续"（`#4D4D61`，12px，距底 ~88px）。 |
| 完成退出 | 整个 IntroScreen 节点隐藏（UIStateCoordinator 将 visible 设为 false），过渡到器灵选择界面。 |
| 操作反馈 | 第一次点击/按键：动画立即跳至全部显示状态（快进）。第二次点击/按键：界面消失。 |

**布局规格**（来自 Pixso 设计稿「开场黑幕」frame 2:2）：

| 属性 | 值 |
|------|-----|
| 界面尺寸 | 1280×720（全屏，anchors_preset = FULL_RECT） |
| 背景色 | `Color(0, 0, 0, 1)` 纯黑 |
| 文字区域 | 宽 840px，垂直居中（VBoxContainer + anchor 居中） |
| 正文 | 20px 阿里巴巴普惠体 55 Regular，白色，行高 28px |
| 提示文字 | 12px，色值 `#4D4D61`，底部居中 |
| 段落间距 | 28px（等同于行高） |

> ⚠️ 技术债：当前 UI 为纯代码构建（`_build()` 中用 `Label.new()`/`ColorRect.new()`），无独立 `.tscn` 场景文件。后续规范化时应创建 `scenes/ui/intro_screen.tscn`，将静态节点树移入场景，脚本仅保留动画和交互逻辑。

## 8. 边界条件与互斥

```
☑ 能重复操作吗？不能的话怎么阻止？
   → 不可重复。_finished 标记防止重复发射 intro_finished 信号。

☑ 有数值上下限吗？
   → 无。不涉及数值。

☑ 和其他功能互斥吗？
   → 是。INTRO 状态期间，所有其他 UI 面板（器灵选择/战斗HUD/卡牌选择等）隐藏。

☑ 数据不够时：禁用按钮 / 弹窗提示 / 静默失败？
   → 不涉及数据。

☑ 极端值处理：0、负数、空字符串、null？
   → 不涉及。

☑ 快速连续点击会怎样？
   → 第一次点击快进动画（_revealed = true），第二次点击结束。_finished 标记阻止后续点击重复触发。
     Tween kill 后不会残留回调。

☑ 操作中途切换状态（如从经营进入战斗）会怎样？
   → 仅在 INTRO 状态显示。GameManager 初始化为 INTRO，intro_finished 后切换到 MAIN_PEAK_SELECT。
     不存在"从其他状态切回 INTRO"的路径。
```

## 10. 反模式自查

```
☑ 这个功能是否在制造"上帝 Manager"？
  → 否。新增的 GameManager 逻辑仅 2 处：INTRO 状态枚举 + intro_finished 信号连线。

  → 是——但仅限于 intro_screen.gd 内部的 _build() 代码构建 UI。该文件内无裸写 get_node()，
    节点引用通过 add_child() 后的局部变量管理。Pixso 设计参数以 const 常量形式存在，

☑ 是否在逻辑代码里直接操作了 UI？
  → 否。GameManager 不直接操作 UI，通过 UIStateCoordinator.set_state() 管理显隐。

☑ 是否有数据在代码和 CSV 中双轨存在？
  → 否。世界观文本仅存在于代码中，为设计意图确定的静态叙事内容。

☑ 模块之间是否有循环信号依赖？
  → 否。intro_finished 单向：IntroScreen → GameManager。
```

## 11. 验收标准

1. 启动游戏 → 纯黑画面出现，第 1 段文字开始淡入
2. 等待动画播放 → 4 段文字依次淡入，最后"点击任意处继续"提示出现
3. 动画播放中途点击鼠标 → 所有文字和提示立即全部显示（快进效果）
4. 全部显示后点击鼠标 → 画面切换至器灵选择界面
5. 动画播放中按任意键（非 ESC） → 同点击，快进到全部显示
6. 全部显示后按任意键（非 ESC） → 切换至器灵选择界面
7. 任意时刻按 ESC → 直接跳至器灵选择界面
8. 快速连续点击 3 次 → 正常过渡到器灵选择，不报错、不重复触发
9. intro_screen 节点缺失时启动游戏 → 跳过开场黑幕，直接进入器灵选择界面
