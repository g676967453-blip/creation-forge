# 需求文档：召唤物系统

> **状态：[已实现] | 验证日期：2026-07-09**

> 灵狐契（form_beast_01）和御器诀（form_artifact_01）两个功法的核心机制——在战场上创建 AI 驱动的召唤物，自动索敌攻击。
> 数据来源：`form_config.csv` special_param JSON + `card_config.csv` 召唤相关卡牌。

---

## 1. 功能概述

**一句话**：选择灵狐契/御器诀功法后，器灵自动召唤 AI 单位协战。

**详细描述**：战斗阶段中，当器灵装备灵狐契或御器诀时，每帧检查场上召唤物数量，不足目标数则自动创建。灵狐在地面移动、追击最近敌人并近战攻击；法器飞剑环绕器灵旋转、攻击范围内最近敌人。召唤物可被敌人摧毁、随功法切换清除。升级卡牌可增加召唤物数量、伤害、HP、攻速等属性。

---

## 2. 模块影响分析

```
触及的现有模块：
  1. MainPeak/main_peak.gd — _ensure_beasts()、_ensure_artifacts() 创建/管理召唤物
  2. CardManager — 应用 summon_dmg/summon_hp/summon_extra/summon_speed 等效果到 channel
  3. EnemyBase/enemy_base.gd — 召唤物攻击调用 target.take_damage()
  4. FormConfig/form_config.gd — special_param JSON 定义召唤物初始属性
  5. CardConfig/card_config.csv — 8 张召唤相关卡牌

需要新建的模块：
  （无——召唤物逻辑已在 main_peak.gd 中实现）

不需要动的模块：
  - WaveManager — 召唤物不参与波次调度
  - MountainManager — 经营阶段无召唤物
  - Projectile — 召唤物不是投射物，有独立 AI
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式 | 自动触发——MainPeak._physics_process() 中检测 channel["attack_type"] |
| 触发条件 | 器灵装备灵狐契（attack_type="summon", special_mechanic="summon_beast"）或御器诀（special_mechanic="summon_artifact"） |
| 前置游戏状态 | GameState.BATTLE |
| 互斥状态 | PREPARATION / CARD_SELECTION / GAME_OVER 下不创建 |
| 可重复性 | 持续创建——死亡后自动补充至目标数量 |

## 4. 数据定义

### 4.1 灵狐数据（来自 form_config.csv special_param）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| beast_type | String | "fox" | 召唤物类型标识 |
| fox_count | int | 1 | 初始灵狐数量 |
| fox_hp | float | 120 | 灵狐初始 HP |
| fox_atk | float | 8 | 灵狐基础攻击力 |
| fox_speed | float | 180 | 灵狐移动速度（px/s） |
| revive_time | float | 6 | 死亡后复活等待时间（秒） |

### 4.2 法器飞剑数据（来自 form_config.csv special_param）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| sword_count | int | 1 | 初始法器数量 |
| sword_atk | float | 10 | 法器基础攻击力 |
| sword_orbit_radius | float | 80 | 环绕半径（px） |

### 4.3 召唤物通用属性（代码层，meta 存储）

| meta 键 | 类型 | 说明 |
|---------|------|------|
| hp | float | 当前 HP，≤0 时 queue_free() |
| max_hp | float | 最大 HP |
| atk | float | 每次攻击伤害（已含卡牌加成） |
| atk_interval | float | 攻击间隔（秒，已含攻速加成） |
| atk_timer | float | 攻击冷却计时器 |
| channel | Dictionary | 功法 channel 引用，用于能量积累 |

### 4.4 涉及现有 CSV

| CSV 文件 | 用途 |
|----------|------|
| `form_config.csv` | special_param 列定义召唤物初始数值；damage/attack_interval/range 列定义功法基础属性 |
| `card_config.csv` | 8 张召唤相关卡牌（灵兽 4 张 + 法器 4 张） |

### 4.5 卡牌效果对照

| card_id | 效果 | effect_type | effect_value | 影响属性 |
|---------|------|-------------|-------------|---------|
| beast_dmg | 灵兽伤害+25% | summon_dmg | 0.25 | fox.atk *= (1+0.25) |
| beast_hp | 灵兽HP+30% | summon_hp | 0.30 | fox.hp/max_hp *= (1+0.30) |
| beast_revive | 复活时间-3s | summon_revive | 3 | revive_time -= 3 |
| beast_extra | 灵兽上限+1 | summon_extra | 1 | target_count += 1 |
| artifact_dmg | 法器伤害+20% | summon_dmg | 0.20 | sword.atk *= (1+0.20) |
| artifact_speed | 法器攻速+15% | summon_speed | 0.15 | atk_interval /= (1+0.15) |
| artifact_reflect | 法器反弹20%伤害 | summon_reflect | 0.20 | reflect_pct = 0.20 |
| artifact_block | 法器额外拦截1次弹道 | summon_block | 1 | 拦截敌人投射物次数 |

## 6. 逻辑流程

### 6.1 灵狐生命周期

```
  1. MainPeak._physics_process() → 检测 channel["attack_type"] == "summon"
                                   且 special_mechanic == "summon_beast"
  2. _ensure_beasts(channel) → 统计存活灵狐数
  3. 存活数 < 目标数 → _create_fox(channel)
  4. _create_fox:
     a. 创建 Area2D，命名 "SummonFox"
     b. 加入 "summons" + "summon_beasts" 组
     c. 绑定 summon_fox.gd 脚本
     d. 设置 meta: hp/max_hp/atk/atk_interval/speed/channel
     e. 随机偏移出生位置（±40, -30~10）
     f. _add_to_battlefield()
  5. summon_fox._physics_process(delta):
     a. HP ≤ 0 → queue_free()
     b. atk_timer 递减 → 归零时攻击最近敌人
     c. 向最近敌人移动（speed px/s）
     d. 无敌人时原地待机
  6. 死亡 → 复活计时器（revive_time 秒后重新创建）

分支：
  - 功法切换 → channel 变化 → _summoned_beasts 全部 queue_free()
  - 战斗结束 → battlefield 清理 → 召唤物一并释放
```

### 6.2 法器飞剑生命周期

```
  1. MainPeak._physics_process() → 检测 special_mechanic == "summon_artifact"
  2. _ensure_artifacts(channel) → 统计存活法器数
  3. 存活数 < 目标数 → _create_sword_artifact(channel)
  4. _create_sword_artifact:
     a. 创建 Area2D，命名 "ArtifactSword"
     b. 加入 "summons" + "summon_artifacts" 组
     c. 绑定 summon_artifact_sword.gd 脚本
     d. 设置 meta: atk/atk_interval/orbit_radius/orbit_angle/orbit_speed
     e. 出生位置 = 器灵位置
  5. summon_artifact_sword._physics_process(delta):
     a. 环绕器灵旋转: orbit_angle += orbit_speed * delta
     b. 位置 = peak.global_position + orbit_offset
     c. atk_timer 递减 → 归零时攻击 200px 内最近敌人
     d. 无目标时继续环绕
  6. 法器不死亡（无 HP 属性），随功法切换清除

分支：
  - 功法切换 → 全部 queue_free()
  - reflect_pct > 0 → 法器拦截敌人投射物
```

## 8. 边界条件与互斥

```
☑ 召唤物能超出 battlefield 吗？灵狐会追踪敌人，理论上可移动到任意位置；法器始终环绕器灵
☑ 场上无敌人的表现？灵狐原地待机，法器继续环绕
☑ 功法切换时召唤物如何处理？_summoned_beasts/_summoned_artifacts 全部 queue_free()
☑ 目标数上限？灵狐: 1 + summon_dmg_bonus + summon_count_bonus + 2（while 条件有缓冲），法器: 1 + projectile_extra
☑ 卡牌叠加效果？summon_dmg/summon_hp 乘算叠加（1+bonus1+bonus2+...）
☑ 快节奏战斗中的性能？灵狐+法器总数通常 ≤ 5，性能影响可忽略
☑ 召唤物会被敌人攻击吗？当前敌人无攻击召唤物的逻辑（敌人直冲器灵）
```

## 11. 验收标准

1. 器灵装备灵狐契 → 战斗开始后，器灵旁自动生成 1 只灵狐（橙色圆形）
2. 灵狐向最近敌人移动并攻击 → 敌人 HP 减少
3. 灵狐被摧毁 → revive_time 秒后自动重新生成
4. 器灵装备御器诀 → 器灵周围生成 1 把法器飞剑，环绕旋转
5. 敌人进入法器 200px 范围 → 法器自动攻击
6. 选择"灵兽伤害+25%"卡牌 → 灵狐攻击力提升
7. 选择"灵兽上限+1"卡牌 → 场上出现 2 只灵狐
8. 选择"法器攻速+15%"卡牌 → 法器攻击间隔缩短
9. 切换功法 → 所有召唤物清除
10. 战斗结束 → 召唤物随 battlefield 清理释放
