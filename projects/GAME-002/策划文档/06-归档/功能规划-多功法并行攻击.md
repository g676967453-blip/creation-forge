## 2. 核心规则

### 2.1 攻击通道

- 每座已激活（已修复 + 已选功法）的山峰，给器灵增加一个**攻击通道**
- 每个通道独立拥有：伤害、攻速、弹道数、穿透数、伤害倍率、子弹颜色、子弹造型
- 所有通道同时运行，各自独立计时

### 2.2 激活数量

| 激活山峰数 | 攻击通道数 | 视觉效果 |
|-----------|-----------|---------|
| 0 | 0 | 器灵不攻击（开战按钮不可点击） |
| 1 | 1 | 器灵发射一种子弹/召唤物 |
| 2 | 2 | 器灵同时发射两种子弹/召唤物 |
| 3 | 3 | 器灵同时发射三种子弹/召唤物 |
| ... | ... | ... |
| 6 | 6 | 器灵同时使用六种攻击方式 |

### 2.3 卡牌升级叠加

**已确定方案**：卡牌自带功法标签 + 系统随机抽 + 玩家选。

- 每张卡牌指定所属功法（如 sword_combo_max 仅作用于御剑诀通道，form_id=form_sword_01）
- 卡牌池 = 4 张通用卡 + 6 功法 × 4 张功法专属卡 = 28 张（含普通/稀有双稀有度）
- 升级时从**当前已激活功法**对应的卡牌中随机抽 3 张
- 玩家看到的卡牌会显示功法归属（如"御剑诀·剑气叠加"）
- 选中后仅该功法的通道获得升级



### 2.4 寻敌

- 所有通道共享同一个寻敌逻辑（攻击距离器灵最近的敌人）
- 各通道独立瞄准（可瞄准同一目标或不同目标，取决于各自发射时刻）

## 4. 交互流程

1. 经营阶段 — 玩家修复并升级多座山峰
2. 点击开战 — `game_manager.start_battle()` 调用 `mountain_manager.get_all_activated_form_ids()` 获取功法列表
3. `main_peak` 根据功法列表构建攻击通道
4. 战斗中 `_process()` 遍历所有通道，独立计时、独立发射
5. 升级选卡牌 — `apply_upgrade()` 遍历所有通道叠加效果
6. 结算返回经营 — 通道清空，下次开战重新构建

---

## 5. 边界条件

| 情况 | 处理 |
|------|------|
| 未激活任何山峰点开战 | 按钮置灰不可点击（已有逻辑） |
| 战斗中器灵死亡 | 所有通道停止攻击 |
| 战斗结束返回经营 | 通道清空 |
| 两个通道攻击同一目标 | 各自正常造成伤害，无冲突 |

## 6. 模块边界草图

```
涉及的系统：
  ☑ MainPeak/main_peak.gd — _attack_channels 数组、_perform_attack(channel)、apply_upgrade()
  ☑ MountainManager — get_all_activated_form_ids()
  ☑ GameManager — start_battle 收集 form_ids、_trigger_battle_upgrade 过滤卡牌
  ☑ CardManager — draw_three_cards(active_form_ids)、apply_card 指定通道
  ☑ FormConfig — 每个通道持有 config 引用
  ☑ 数据层 — form_config.csv（功法属性）、card_config.csv（form_id 列）

可能需要新增：
  （无——所有模块已存在）

明确不涉及：
  - 波次/敌人系统 — 不感知功法数量
  - Projectile — 由 MainPeak._perform_attack 创建，projectile 本身不感知通道
  - 山峰修复流程 — 功法选择在经营阶段，并行攻击在战斗阶段
```

## 7. 数据流向草图

```
peak_config.csv（entry_form_id 列）
      ↓
  MountainManager 管理 → get_all_activated_form_ids()
      ↓
  GameManager.start_battle() → 收集 form_id 数组
      ↓
  MainPeak.set_attack_channels(form_ids):
    对每个 form_id:
      DataManager.get_form_config(id) → FormConfig
      构建 channel Dictionary（26 字段）
      加入 _attack_channels
      ↓
  _physics_process → 遍历 channels → 各自计时 → _perform_attack(channel)
      ↓
  card_selected → CardManager.apply_card → apply_upgrade(form_id, effect_type, value)
      → 仅修改匹配 form_id 的 channel
```

## 8. 什么不算在这个功能里

```
本功能不包括：
  1. 功法之间的组合/融合效果 — post-MVP（如飞剑+离火=火焰剑）
  2. 功法切换/重置 — MVP 每座山峰仅一次选择
  3. 功法等级提升 — FormConfig.max_level=10 但升级逻辑待实现

后续版本考虑：
  1. 双功法融合（占两个通道但产生新攻击类型）
  2. 功法等级系统（战斗中经验同时给功法升级）
  3. 通道优先级/资源分配（灵气注入特定通道加速其攻击）
```

## 9. 验收标准

1. 激活 1 座山峰（御剑诀）→ 开战 → 只有青色剑形子弹，6 发弹道
2. 激活 2 座山峰（御剑诀+金刚咒）→ 开战 → 同时有青色剑形 + 金色扇形攻击，各自独立节奏
3. 激活 3 座山峰（御剑诀+金刚咒+~~离火诀~~）→ 开战 → 三种攻击并行（弹道+扇形+火球）
4. 激活 6 座山峰 → 开战 → 全部 6 种攻击方式同时运作（含灵狐+法器召唤物）
5. 战斗中选卡牌 → 仅作用于对应功法通道（非全部）
