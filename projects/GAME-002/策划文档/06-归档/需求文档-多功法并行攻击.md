# 需求文档：多功法并行攻击

> **数据验证日期**：2026-07-09
> **验证来源**：form_config.csv / card_config.csv
> **关键变更**：功法 6（离火诀已删除，burn 通道已移除）、卡牌 28 张

> 支持玩家修复多座山峰后，器灵同时使用多个功法攻击，各功法独立计时、独立升级。
> 数据来源：`form_config.csv`（6 功法）+ `card_config.csv`（28 张，含 form_id 归属）+ `peak_config.csv`（6 山峰的 entry_form_id）。

---

## 1. 功能概述

**一句话**：激活多座山峰后，器灵并行执行所有对应功法的攻击逻辑。

**详细描述**：经营阶段玩家可修复多座山峰并为每座选择功法。战斗开始后，GameManager 从 MountainManager 获取所有已激活的 form_id 列表，传给 MainPeak.set_attack_channels()。MainPeak 为每个功法创建一个攻击通道（channel Dictionary），各通道独立计时、独立发射投射物。卡牌升级按 card_config.csv 的 form_id 过滤——只出现已激活功法的卡牌。卡牌效果作用于对应通道，不影响其他功法。

## 2. 模块影响分析

```
触及的现有模块：
  1. MainPeak/main_peak.gd — 单变量攻击 → _attack_channels 数组；_perform_attack 接受 channel
  2. GameManager/game_manager.gd — start_battle 传入多 form_id；_trigger_battle_upgrade 过滤卡牌
  3. MountainManager/mountain_manager.gd — 新增 get_all_activated_form_ids()
  4. CardManager/card_manager.gd — draw_three_cards 按 active_form_ids 过滤；apply_card 指定 form_id
  5. CardData/card_data.gd — 字段 target_peak_id → form_id
  6. FormConfig/form_config.gd — 每个通道持有 config 引用
  7. DataManager/data_manager.gd — _load_cards() 读 form_id 列

需要新建的模块：
  （无）

不需要动的模块：
  - WaveManager — 波次与功法无关
  - EnemyBase — 敌人不感知功法来源
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式 | GameManager.start_battle() 调用时自动收集已激活功法 |
| 触发条件 | 至少 1 座山峰已修复并选择了功法（entry_form_id 非空） |
| 前置游戏状态 | GameState.PREPARATION → BATTLE 转换时 |
| 互斥状态 | BATTLE / CARD_SELECTION / GAME_OVER 下不可重建通道 |
| 可重复性 | 每轮战斗重建一次；经营阶段可选择不同功法组合 |

## 5. 信号契约

```
复用现有信号（无新增）：

battle_started()
  → GameManager 收集 all_activated_form_ids → MainPeak.set_attack_channels()

card_selected(card_id)
  → CardManager.apply_card(card) → MainPeak.apply_upgrade(card.form_id, card.effect_type, card.effect_value)

mountain_state_changed(peak_id)
  → 山峰状态变化（修复/选择功法）→ GameManager 记录 → 下次 start_battle 使用新组合
```

## 6. 逻辑流程

```
经营阶段：
  1. 玩家修复山峰 → 选择功法 → MountainManager 记录 (peak_id → form_id)
  2. 可重复操作多座山峰

开战流程：
  1. 玩家点击"开始战斗" → GameManager.start_battle()
  2. MountainManager.get_all_activated_form_ids() → 收集已激活的 form_id 数组
  3. MainPeak.set_attack_channels(form_ids):
     for each form_id:
       config = DataManager.get_form_config(form_id)
       创建 channel Dictionary（26 个字段，全部初始化为 0/false/1.0）
       加入 _attack_channels
  4. 状态切换 BATTLE → 倒计时 → 战斗开始

战斗每帧：
  1. MainPeak._physics_process(delta):
     for each channel in _attack_channels:
       channel["timer"] -= delta
       if timer <= 0:
         timer = config.attack_interval
         _perform_attack(channel)  # 按功法类型分支：projectile/sector/summon

升级流程：
  1. 经验满 → GameManager._trigger_battle_upgrade()
  2. CardManager.draw_three_cards(active_form_ids):
     从 card_pool 中筛选 form_id 在 active_form_ids 中的卡牌
     通用卡（form_id="通用"）始终包含
     shuffle → 取前 3 张
  3. 玩家选卡 → CardManager.apply_card(card):
     MainPeak.apply_upgrade(card.form_id, card.effect_type, card.effect_value)
     仅修改匹配 form_id 的 channel
```

## 8. 边界条件与互斥

```
☑ 0 个功法激活时开战？→ form_ids 为空数组，_attack_channels 为空，器灵不攻击
☑ 1 个功法 vs 6 个功法？→ 通道数 = 激活数，性能无明显差异（每帧遍历 + 定时器检查）
☑ 卡牌池不足 3 张？→ draw_three_cards 在 available < 3 时重置 used_cards 并全量补池
☑ 同一功法出现两次？→ get_all_activated_form_ids 按 PEAK_IDS 去重（每峰一个 form_id）
☑ 快速连续开战？→ start_battle 检查 current_state，BATTLE 中不可重复触发
☑ 切换场景/重置游戏？→ _attack_channels 随 MainPeak 实例释放
```

## 11. 验收标准

1. 仅修复剑峰并选择御剑诀 → 战斗中器灵仅发射剑形投射物（6 发/轮）
2. 修复剑峰+佛峰 → 战斗中同时出现剑形投射物 + 扇形音波攻击
3. 修复全部 6 座山峰 → 6 个通道并行，各按自己的 attack_interval 计时
4. 仅激活御剑诀时升级 → 卡牌池仅含 4 通用 + 4 御剑诀专属 = 8 张可选
5. 激活 3 个功法时升级 → 卡牌池含 4 通用 + 3×4 = 16 张可选
6. 选择"剑气叠加"卡牌 → 仅御剑诀通道 combo_max 增加，金刚咒不受影响
7. 下轮战斗仅激活金刚咒 → 卡牌池不再出现御剑诀专属卡
8. 0 功法开战 → 器灵不发射任何投射物（不崩溃）
