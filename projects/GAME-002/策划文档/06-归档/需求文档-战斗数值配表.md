> ⚠️ 本文档已归档。最新版本见 `../03-功能规格/战斗数值配表.md`

> **数据验证日期**：2026-07-09
> **验证来源**：全部 data/*.csv
> **关键变更**：功法 7→6、卡牌 33→28、敌人 4→5、器灵 HP 500→2000

> 定义项目中所有 CSV 配表的 Schema、各 Resource 类的字段映射、以及 DataManager 的加载流程。
> 数值以 `data/*.csv` 为准（2026-07-09 验证），本文档提供结构化说明。

## 1. 功能概述

**一句话**：所有战斗相关配置从 6 份 CSV 加载，通过 7 个 Resource 类传递给逻辑层。

**详细描述**：游戏启动时，CsvLoader（Autoload）解析 `data/` 下的 CSV 文件为 Dictionary 数组，DataManager（Autoload）将每行转换为对应的 Resource 对象并存入 database。逻辑层（GameManager / MainPeak / CardManager / WaveManager / MountainManager）通过 DataManager 的统一 API 读取配置，不直接访问 CSV。策划在 Excel 中编辑 CSV → 保存 → Godot 热重载即生效。

---

## 2. 模块影响分析

```
触及的现有模块：
  1. CsvLoader/autoload/csv_loader.gd — 通用 CSV 解析（load_csv 返回 Array[Dictionary]）
  2. DataManager/autoload/data_manager.gd — 加载入口、database 存储、get_* 查询 API
  3. 7 个 Resource 类（scripts/data/*.gd）— 类型化数据容器
  4. 6 份 CSV 文件（data/*.csv）— 策划编辑的原始配表
  5. MainPeak/main_peak.gd — 从 DataManager 读 FormConfig / MainPeakConfig
  6. CardManager/card_manager.gd — 从 DataManager 读 CardData pool
  7. WaveManager/wave_manager.gd — 从 DataManager 读 wave_database
  8. MountainManager/mountain_manager.gd — 从 DataManager 读 PeakData

需要新建的模块：
  （无——所有文件已存在）

不需要动的模块：
  - EnemyBase — 敌人数据由 WaveManager 创建时注入，不直接读 DataManager
```

## 3. 触发条件与状态约束

| 维度 | 说明 |
|------|------|
| 触发方式 | 自动触发——DataManager._ready() 在游戏启动时加载全部 CSV |
| 前置条件 | CsvLoader 已在 project.godot 中注册为 Autoload（优先级高于 DataManager） |
| 加载失败处理 | CSV 文件不存在 → push_error + 返回空数组，database 为空，逻辑层做空值检查 |
| 热重载 | CSV 文件修改后，auto_reload addon 自动重新加载 |

## 6. 逻辑流程

```
游戏启动
  ↓
CsvLoader._ready() — 注册为 Autoload，早于 DataManager
  ↓
DataManager._ready()
  ├── _load_main_peak()    → 读 main_peak_config.csv → MainPeakConfig Resource
  ├── _load_peaks()        → 读 peak_config.csv → peak_database (Dictionary)
  ├── _load_enemies()      → 读 enemy_config.csv → enemy_database (Dictionary)
  ├── _load_forms()        → 读 form_config.csv → form_database (Dictionary)
  ├── _load_cards()        → 读 card_config.csv → card_database (Dictionary)
  └── _init_waves()        → 读 wave_config.csv → wave_database (Array[WaveEnemyGroup])
  ↓
print loaded summary
  ↓
逻辑层通过 get_* API 读取:
  - DataManager.main_peak_config → MainPeak
  - DataManager.get_form_config(id) → MainPeak.apply_peak_profile()
  - DataManager.get_enemy(id) → WaveManager 创建敌人
  - DataManager.get_card(id) → CardManager
  - DataManager.wave_database → WaveManager
  - DataManager.peak_database → MountainManager

分支：
  - CSV 文件不存在 → push_error + 返回空数据，逻辑层做空值检查
  - CSV 格式错误（列名不匹配/缺列）→ row.get("key", "default") 使用默认值，不崩溃
```

## 7. UI 表现

本模块是数据层，无 UI。但数据变更的间接表现：
- 修改 form_config.csv damage 值 → 器灵攻击伤害变化
- 修改 enemy_config.csv hp 值 → 敌人生成时血量变化
- 修改 card_config.csv effect_value → 升级面板卡牌效果数值变化

## 8. 边界条件与互斥

```
☑ CSV 文件被锁定（Excel 打开中）→ FileAccess.open 失败，使用默认值
☑ CSV 末尾有空行 → CsvLoader 跳过空行
☑ CSV 列顺序变化 → 不依赖列顺序，按 header 名匹配
☑ 数值写负数/0 → 逻辑层各模块自行处理（如 damage≤0 时不发射投射物）
☑ 中文编码 → CSV 使用 UTF-8
☑ 同 form_id 出现两次 → 后出现的覆盖前者（Dictionary key 覆盖）
```

## 11. 验收标准

1. 启动游戏 → 控制台输出 `loaded: peaks=6 enemies=4 cards=29 forms=6 waves=16`
2. Excel 打开 form_config.csv 修改御剑诀 damage 从 6 改为 10 → 保存 → Godot 热重载 → 器灵伤害提升
3. Excel 在 card_config.csv 末尾加一行新卡牌 → 保存 → 升级时可能出现新卡牌
4. 删除 form_config.csv 后启动 → push_error 但不崩溃，form_database 为空
5. enemy_config.csv 加新敌人 → `_load_enemies` 自动注册，wave_config.csv 引用即可生效
6. CSV 列顺序打乱 → 不影响加载（按 header 名匹配）
