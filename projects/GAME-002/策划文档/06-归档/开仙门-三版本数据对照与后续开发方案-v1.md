## 五、功能模块拆分方法

### 5.1 拆分原则

一个大功能 (如"峰主 AI 系统") 拆成可独立开发、测试、提交的模块：

```
大功能
├── 数据层 (1 个 CSV + 1 个 Resource 类)
├── 逻辑层 (1 个 Manager 或 Base 类)
├── 表现层 (1 个 .tscn + 1 个 UI 脚本)
└── 集成 (信号连接 + 数据管道)
```

**每层独立可测**：
- 数据层完成 → 可以在 Godot 编辑器中检查 Resource 属性
- 逻辑层完成 → 可以写独立场景测试核心逻辑
- 表现层完成 → 可以单独打开 .tscn 预览

### 5.2 拆分示例: 峰主 AI 系统

```
峰主AI系统
├── M1: peak_master_config.csv + PeakMasterData.gd
│   └── 交付: CSV 可被 DataManager 加载, Resource 字段可检查
│
├── M2: PeakMasterBase.gd (AI 状态机)
│   ├── 状态: IDLE / SEEKING / ENGAGING / RETURNING
│   ├── 核心方法: _find_target() / _attack() / _should_retreat()
│   └── 交付: 可在独立场景中测试状态切换
│
├── M3: peak_master.tscn
│   ├── Area2D + CollisionShape2D + AnimatedSprite2D + HP Bar
│   └── 交付: 场景可实例化, 可在编辑器中预览
│
├── M4: 峰主-战斗集成
│   ├── BattleFlowController 管理峰主生命周期
│   ├── 峰主与敌人碰撞检测
│   └── 交付: 峰主在战斗中正常攻击/受伤/撤退
│
├── M5: 6 峰差异化配置
│   ├── 每峰峰主的 attack_type / ai_style / 属性差异
│   └── 交付: 6 种峰主行为各不相同
│
└── M6: 峰主晋升/更替
    ├── 晋升条件/消耗/动画
    └── 交付: 完整晋升流程
```

### 5.3 拆分粒度标准

| 模块规模 | 代码量 | 开发时间 | 示例 |
|----------|--------|----------|------|
| S (小) | 1 文件, <100 行 | 0.5-1h | 新增一个 CSV 列 + Resource 字段 |
| M (中) | 1-2 文件, 100-300 行 | 2-4h | 新增一个 effect 脚本 |
| L (大) | 3-5 文件, 300-600 行 | 1-2d | 新增一个 Manager + .tscn + 信号 |
| XL (特大) | 5+ 文件, 600+ 行 | 3-5d | 峰主 AI 完整系统 |

**原则**: 尽量拆到 M/L 级别，避免 XL 模块。如果出现 XL，回到第一步继续拆。

| **UI 面板模板** | 新增一个 UI 面板 | .tscn + 脚本 + 信号连接 |

### 6.2 功法开发模板

#### 文件清单

新增一个功法需要创建/修改以下文件：

```
必做:
├── data/form_config.csv          ← 新增 1 行 (23 个字段)
├── data/card_config.csv          ← 新增 4 行 (4 张专属卡牌)
可选 (仅新机制时需要):
├── scripts/effects/<新效果>.gd   ← 新特殊机制脚本
└── assets/runtime/projectiles/   ← 新弹道素材
```

#### Step 1: 定义功法数据 (form_config.csv)

```csv
form_id,form_name,peak_id,quality,max_level,attack_type,atk_type_label,damage,projectile_count,attack_interval,range,damage_type,defense_type,defense_value,ultimate_name,ultimate_desc,energy_per_hit,special_mechanic,special_param,projectile_color_r,projectile_color_g,projectile_color_b,projectile_shape
form_<peak>_<seq>,<功法名>,peak_<peak>,<品质>,10,<attack_type>,<标签>,<伤害>,<弹数>,<间隔>,<射程>,<伤害类型>,<防御类型>,<防御值>,<大招名>,<大招描述>,<能量/击>,<机制key>,<JSON参数>,<R>,<G>,<B>,<形状>
```

**字段填写指南**:

| 字段 | 如何确定值 | 参考范围 |
|------|-----------|----------|
| `damage` | 理论 DPS = damage × projectile_count / attack_interval | 入门: 15-20 DPS, 进阶: 25-35, 高阶: 40-55, 终极: 60+ |
| `attack_interval` | 攻击节奏感 | 快速: 0.5-0.8s, 标准: 0.9-1.2s, 慢速: 1.3-2.0s |
| `range` | 射程定位 | 短: 80-200, 中: 400-600, 长: 600-800 |
| `projectile_count` | 弹幕密度 | 低: 1-2, 中: 3-5, 高: 6-10 |
| `defense_type` | 峰定位匹配 | 剑=none, 佛=shield, 魔=lifesteal, 兽=block, 器=block, 法=evasion |
| `special_mechanic` | 已有: combo/burn/stun/soul_mark/chain/summon_beast/summon_artifact | 新机制需新建效果脚本 |

#### Step 2: 定义 4 张专属卡牌 (card_config.csv)

```
标配: 2 普通 (stackable=true) + 2 稀有 (stackable=false)
```

**卡牌设计模板**:

| 卡牌 # | 稀有度 | 效果类型示例 | 效果值范围 |
|--------|--------|-------------|-----------|
| 1 | 普通 | 核心机制增强 (如 ~~burn_max~~, combo_max, bounce_up) | +20-40% |
| 2 | 普通 | 数值增强 (如 summon_dmg, ~~burn_dmg~~) | +15-25% |
| 3 | 稀有 | 机制变革 (如 tracking, shield_boost, summon_extra) | 功能性 |
| 4 | 稀有 | 大招增强 (如 ~~explode_boost~~) | +50-100% |

#### Step 3: 已有攻击类型 — 零代码新增

如果新功法使用已有 `attack_type` (projectile/sector/summon) 和已有 `special_mechanic`，则**无需写任何新代码**。`main_peak.gd` 的 `set_attack_channels()` 自动从 CSV 读取并配置。

| attack_type | 可复用机制 | 自动行为 |
|-------------|-----------|---------|
| `projectile` | combo / burn / soul_mark / chain | 自动发射弹道，调用 `_apply_form_effects()` |

#### Step 4: 新特殊机制 — 需要代码

如果新机制不在已有列表中 (combo/burn/stun/soul_mark/chain/summon_beast/summon_artifact)：


**新机制开发检查清单**:
- [ ] projectile 命中时触发？→ `projectile.gd: _apply_form_effects()`

### 6.6 UI 面板开发模板

#### 文件清单

```
必做:
├── scenes/ui/<panel_name>.tscn     ← 场景文件
├── scripts/ui/<panel_name>.gd      ← 逻辑脚本
修改:
└── scripts/managers/ui_state_coordinator.gd ← 注册新面板
```

#### 面板脚本模板

```gdscript
extends CanvasLayer
## <面板用途一句话>

signal <panel_action>  # 面板触发的业务信号

# 子节点引用 (onready)
@onready var _close_btn: Button = $Panel/CloseButton

# 数据
var _data: Array = []


func _ready() -> void:
    _close_btn.pressed.connect(_on_close_pressed)


func show_panel(data = null) -> void:
    if data != null:
        _data = data
    _refresh()
    visible = true


func hide_panel() -> void:
    visible = false


func _refresh() -> void:
    pass  # 根据 _data 更新子节点显示


func _on_close_pressed() -> void:
    hide_panel()
```

#### 面板信号连接规范

面板通过 signal 与 Manager 通信，**禁止**在面板脚本中直接操作业务数据：

```gdscript
# 正确 — 发射信号，让 Manager 处理
card_selected.emit(card_id)

# 错误 — 面板直接修改业务数据
DataManager.some_data = xxx  # 禁止
```
