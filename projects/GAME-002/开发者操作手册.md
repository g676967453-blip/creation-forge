# 开发者操作手册

> 给人类看的。每次开 AI 会话前扫一眼，3 分钟读完。

---

## 会话前（2 分钟）

### 1. 回顾上次干了什么
打开 `开发记录/开发日志.md`，看最后一条记录。知道上次改了什么，本次才知道从哪里接上。

### 2. 明确本次要干什么
心里想清楚：今天要完成哪一件事？不要开多个战线。

### 3. 告诉 AI 上下文
如果上次会话和本次之间发生了什么事（手动改了文件、玩了游戏发现 bug），第一句话就告诉 AI。

---

## 会话中

### 4. AI 提方案时，看它有没有说"文档同步"
AI 说"我来改 X"→ 追问一句："改完 X 后哪些文档需要同步更新？"
如果 AI 没提 → 要求它先查传播清单再动手。

### 5. 不要连续堆功能
每个功能改完后，确认数据完整再开下一个。一个功法缺卡牌数据就补卡牌，别急着加第八个功法。

---

## 会话后（3 分钟）

### 6. 逐项验证
- [ ] 代码改了什么？扫一眼 git diff
- [ ] CSV 改了什么？打开看一眼数值对不对
- [ ] AI 更新了哪些文档？抽查一个看看是不是真的改了

### 7. Git commit
每次会话结束后至少一个 commit。message 写清楚改了什么，别写"update"。
```
git add -A
git commit -m "删除离火诀：form_config -1行 | 同步更新 5 份文档 | 修复器灵 HP/护甲/升级公式"
```

### 8. 更新开发日志
在 `开发记录/开发日志.md` 对应日期下追加今日完成内容。如果 AI 没主动写，提醒它写。

---

## 每周一次（5 分钟）

### 9. 抽查文档新鲜度
随机打开 3 份 `策划文档/` 下的文件，看验证日期是否在 7 天内。发现过期 → 找 AI 更新。

### 10. 检查 CSV 完整性
打开 `开仙门/data/`，扫一眼：
- `card_config.csv` — 每个功法都有卡牌吗？
- `form_level_config.csv` — 每个功法都有等级数据吗？
- `enemy_config.csv` — 敌人属性都合理吗？

---

## 功能开发流程（6 层自上而下）

> 每个功能按此顺序推进。上层没完成，下层不开工。

```
Layer 1  愿景       已有 GDD + 流程设计 → 看方向
Layer 2  系统设计    写功能规划 + 功能需求文档（策划视角 + AI 按模板填）
Layer 3  功能需求    CSV 定义 + 配置设计（字段/结构/关系）
Layer 4  数值任务    具体数值填充（每行/每列/每级）
Layer 5  逻辑任务    代码实现（AI 按需求文档写）
Layer 6  体验任务    美术/音效/特效（与逻辑任务并行）
```

**每次开新功能时**：
1. 告诉 AI "规划 XXX 系统" → AI 用功能规划模板输出
2. 规划确认后 → "写功能需求文档" → AI 用需求模板输出
3. 需求确认后 → AI 自动拆任务到任务管理表
4. 按任务表逐项执行

**器灵系统就是按这个流程走的，作为范例参考。**

---

## 核心原则（记住这三条就够了）

1. **CSV 是唯一真相** — 数值对不对，看 CSV 别看文档
2. **改完代码必须同步文档** — 不传文档 = 制造谎言
3. **每次会话一个 commit** — 12 天只交 1 次不可重来

---

> 这份手册会随着项目推进持续更新。如果你发现某个步骤没用或需要改，直接告诉 AI 修改它。
