## 一、流程总览

```
                        人类决策              AI 执行
                       ─────────            ─────────
第 1 步  需求分析      "我想做什么"    →    探索代码/CSV → 提澄清问题 → 填模板
第 2 步  设计规划      "确认方案"      →    写架构方案 → 拆任务 → 评估工时
第 3 步  开发实现      "确认，开始做"  →    逐任务开发 → 自检 → 报告
第 4 步  测试验证      "我测一下"      →    辅助验证 → 修 bug → 解释根因
第 5 步  变更闭环      "确认完成"      →    查传播清单 → 同步文档 → git commit
```

**五个步骤，每个步骤产出明确，不跳过，不回退。**

## 二、每步详解

### 第 1 步：需求分析（人类说想法 → AI 理解 + 填模板）

**人类做什么**：
- 用自然语言描述想要的功能："我想让 XXX 能 YYY"
- 回答 AI 的澄清问题

**AI 做什么**：
1. 读相关 CSV 和代码，了解当前状态
2. 如有不明确处，提 2-4 个澄清问题
3. 用 **[功能规划文档模板](策划文档/05-元文档/模板/功能规划文档模板.md)** 填初稿：
   - §1 在流程中的位置
   - §2 界面描述（待机/操作/完成态）
   - §3 交互方式
   - **§4 美术与体验需求** ← 新增，必须填
   - §5 模块边界（涉及哪些系统）
   - §6 数据流向
   - §7 与其他功能衔接
   - §8 明确不做什么
   - §9 验收标准
4. 请人类确认

**产出**：`策划文档/03-功能规格/[功能名].md` 初稿

**判断标准**：人类看完能说"对，这就是我想要的"。

---

### 第 2 步：设计规划（AI 出方案 → 人类拍板）

**人类做什么**：
- 审阅规划文档，确认范围无误
- 对关键技术选择给出偏好

**AI 做什么**：
1. 用 **[功能需求文档模板](策划文档/05-元文档/模板/功能需求文档模板.md)** 填详细需求：
   - §1 功能概述
   - §2 模块影响分析（触及/新建/不动）
   - §3 触发条件与状态约束
   - §4 数据定义（涉及 CSV、新 CSV Schema）
   - §5 信号契约（信号名 → 发射者 → 接收者）
   - §6 逻辑流程（主流程 + 分支）
   - §7 UI 表现（各状态描述）
   - **§7-附 美术与体验需求** ← 资源清单 + 规格 + 优先级
   - §8 边界条件与互斥
   - §9 三层归属自查
   - §10 反模式自查
   - §11 验收标准
2. 列出涉及的文件清单 + 预估工时
3. 进入 Plan Mode，请人类确认方案

**产出**：同一个 `策划文档/03-功能规格/[功能名].md` 文件，补充了需求细节

**判断标准**：AI 拿着这份文档可以直接写代码，不需要再问"这个值是多少"。

---

### 第 3 步：开发实现（AI 写代码 → 遵守约束）

**人类做什么**：
- 确认方案后说"开始做"
- 中途如有偏差，随时叫停

**AI 做什么**：
1. 按 CLAUDE.md 约束写代码：
   - CSV 驱动（不硬编码数值）
   - 场景按类型归位
   - 节点路径集中管理
   - 三层架构（表现层/逻辑层/数据层不越界）
2. 每改完一个模块，自检：
   - 代码能不能在 Godot 中跑？
   - 有没有裸写 `get_node("路径/XXX")`？
   - 新数据字段是否在 CSV 中定义？
3. 全部改完后报告改动清单

**产出**：修改的 `.gd` / `.tscn` / `.csv` 文件

**判断标准**：Godot 中 F5 能跑，功能符合 spec 描述。

---

### 第 4 步：测试验证（人类测试 → AI 修 bug）

**人类做什么**：
- 在 Godot 中运行游戏，按验收标准逐条测试
- 发现问题直接描述现象

**AI 做什么**：
1. 听到 bug 描述 → 定位根因 → 修复 → 解释原因
2. 修复后确认不影响其他功能
3. 如果 bug 涉及 CSV 数值，同步更新文档

**产出**：Bug 修复记录

**判断标准**：所有验收标准通过。

---

### 第 5 步：变更闭环（AI 同步文档 → 人类 git commit）

**人类做什么**：
- 最后确认改动无误
- **git commit**（每次功能完成后至少一个 commit）
- 更新开发日志

**AI 做什么**：
1. 查 **[变更传播清单](总指挥-协作原则/04-质量体系/03-变更传播清单.md)**：
   - 改了 CSV？→ 同步数值设计总览、对应 spec 文档
   - 增删功法？→ 同步 GDD、CODE_WIKI.md、CLAUDE.md 计数
   - 改了公式？→ 同步模板、功法文档
2. 更新受影响文档的**验证日期**
3. 在 `开发记录/开发日志.md` 追加今日完成内容

**产出**：同步后的文档 + git commit + 开发日志条目

**判断标准**：grep 检查无过期引用，文档验证日期 = 今天。

## 三、人类职责

### 每次会话前（2 分钟）
- [ ] 看 `开发记录/开发日志.md` 最后一条，知道上次做到哪
- [ ] 想清楚本次要完成的一件事

### 每次会话中
- [ ] AI 提澄清问题时，认真回答——不要"随便"
- [ ] AI 提方案时，追问一句"哪些文档需要同步更新？"
- [ ] 不连续堆功能——一个功能做完、闭环、commit，再开下一个

### 每次会话后（3 分钟）
- [ ] 打开 git diff 扫一眼改动
- [ ] 抽查一个改动的 CSV 或文档，确认数据正确
- [ ] `git add -A && git commit -m "功能描述：改了什么"`
- [ ] 确认 AI 写了开发日志条目

### 每周一次（5 分钟）
- [ ] 随机打开 3 份策划文档，看验证日期是否在 7 天内
- [ ] 打开 `开仙门/data/` 扫一眼 CSV 是否缺行

## 四、AI 职责

### AI 自动遵守（CLAUDE.md 已定义，每会话自动加载）

1. **读文档先看日期**：超过 7 天 → 第一句话提醒"此文档可能过期"
2. **变更后跑传播清单**：不改完不收工
3. **数量问题答 CSV**：不引用文档中的旧数字
4. **矛盾时 CSV 为准**：发现不一致 → 告知用户 → 等指令
5. **新功能前检查完整性**：已有数据不全时提醒先补数据

### AI 禁止行为

- ❌ 跳过传播清单说"改完了"
- ❌ 引用文档中的数值而不核对 CSV
- ❌ 在人类不知情的情况下做架构级决策
- ❌ 说"以后补文档"——当时不补永远不会补
- ❌ 功能没做完就提议做下一个

## 五、变更闭环（最重要的一步）

**改一个 CSV 字段，最少要检查 3 处**：

```
改 form_config.csv 某功法 damage
  → □ 数值设计总览 的功法表
  → □ 该功法的设计文档（如 御剑诀-数值与逻辑文档.md）
  → □ CLAUDE.md 交叉验证表（如果数值变化涉及计数）
```

**改一个公式**：

```
改 mountain_manager.gd 升级花费公式
  → □ templates/功法设计模板.md §9
  → □ 各功法设计文档 §9
  → □ 03-功能规格/山峰修复与功法选择.md
```

完整映射表见 **[03-变更传播清单.md](总指挥-协作原则/04-质量体系/03-变更传播清单.md)**。

| 文件 | 谁读 | 用途 |

| [03-变更传播清单.md](总指挥-协作原则/04-质量体系/03-变更传播清单.md) | AI | 改 A 必须同步 B 的映射表 |

### 策划文档（5 层金字塔）

```
策划文档/
├── 01-愿景/          ← GDD（1 份）
├── 02-系统设计/      ← 战斗体系/数值定位（2 份）
├── 03-功能规格/      ← 每个功能一份 spec（12 份）
├── 04-数据/          ← 数值总览 + 名词表 + 功法范例（3 份）
├── 05-元文档/        ← 模板/路线图/审计/规范（16 份）
├── 06-归档/          ← 已过时（30 份）
└── *.xlsx            ← 数值配表
```

| 层 | 目录 | 放什么 | 模板 |
|----|------|--------|------|
| 愿景 | `01-愿景/` | GDD | — |
| 系统 | `02-系统设计/` | 战斗体系/数值体系/成长体系 | — |
| 规格 | `03-功能规格/` | 每个功能一份 spec | 05-元文档/模板/ |
| 数据 | `04-数据/` | 数值总览/名词表/功法范例 | — |
| 元文档 | `05-元文档/` | 模板/路线图/审计/规范 | — |
