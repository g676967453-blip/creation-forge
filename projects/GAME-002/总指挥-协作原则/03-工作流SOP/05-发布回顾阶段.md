# 03-工作流SOP / 05-发布回顾阶段

> **阶段目标**：完成功能归档、代码提交、经验沉淀，为下一个迭代做准备。
>
> **输入**：验证通过的功能代码 + 验证报告
>
> **输出**：Git commit、更新的工作日志、复盘记录

---

## 一、流程步骤

### 步骤 1：代码归档（AI主导，人类确认）

AI 做：
1. 检查 git status，确认所有变更文件
2. 按逻辑分组提交（而非一个大 commit 塞所有东西）
3. 写清晰的 commit message：
   ```
   feat: XXX功能实装
   
   - 新增：XXX.gd / XXX.tscn
   - 修改：YYY.gd（原因）
   - 数据：ZZZ.csv 新增 N 列
   
   Co-Authored-By: Claude <noreply@anthropic.com>
   ```

人类做：
- 确认要不要提交、是否要分成多个 commit
- 确认 commit message 准确

### 步骤 2：文档归档（AI主导）

AI 做：
1. 更新相关设计文档（如果数值/机制有变化）
2. 将验证报告归档到 `开发记录/` 或 `策划文档/05-元文档/审计/`
3. 更新 `项目文件结构治理规划` 如果新增了文件类型

### 步骤 3：知识沉淀（AI主导）

AI 做：
1. 在 `总指挥-协作原则/AI记忆/` 中新增当日工作日志
2. 如果本次开发中发现了新的模式/坑，写入记忆或规则
3. 更新 `AI记忆/MEMORY.md` 索引

格式参考现有工作日志。

### 步骤 4：复盘（人类与AI共同参与）

使用 `06-持续改进/02-里程碑复盘模板.md`：

1. **What went well**（做得好的）：
   - AI：哪些流程顺畅？哪些决策正确？
   - 人类：对AI的哪些表现满意？

2. **What went wrong**（做错了的）：
   - AI：哪里出现了误判？哪里效率低？
   - 人类：哪里感觉AI不够好用？

3. **What to try next**（下次试什么）：
   - 基于前两项，提出具体的改进措施
   - 如果有规则需要更新，标注"待更新 XXX 文档"

### 步骤 5：展望下一个迭代（人类主导）

人类做：
- 决定下一个做什么功能
- 调整优先级（根据本次开发的经验）

AI 做：
- 如果人类有想法，协助进入需求分析阶段
- 如果没有明确想法，基于项目状态提供建议

---

## 二、门禁检查点

**阶段完成标志**：

- [ ] Git 已提交（或人类决定暂不提交）
- [ ] 工作日志已更新
- [ ] AI记忆索引已更新
- [ ] 复盘已完成（至少简短版）
- [ ] 知识沉淀完成（如有新发现）

---

## 三、人类/AI职责小结

| 谁 | 做什么 |
|----|--------|
| **人类** | 确认提交 → 参与复盘 → 决定下一步方向 |
| **AI** | 整理提交 → 更新文档 → 写工作日志 → 引导复盘 → 提出改进建议 |

---

## 四、常见问题

| 问题 | 应对 |
|------|------|
| 太累了不想复盘 | 最低限度：口述3句话（好的/坏的/下次改），AI帮忙整理 |
| 功能做到一半需要暂停 | 提交 WIP commit，在工作日志中标注"进行中"和暂停原因 |
| 复盘发现问题太多 | 只选最重要的3个改进项，其余的留到下次 |
| 不确定下一步做什么 | AI 查看项目规划文档，列出待办事项供人类选择 |
