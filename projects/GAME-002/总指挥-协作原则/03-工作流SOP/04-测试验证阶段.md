# 03-工作流SOP / 04-测试验证阶段

> **阶段目标**：系统性地验证功能正确性，确保无回归问题。
>
> **输入**：开发完成的功能代码
>
> **输出**：验证报告（通过/发现问题清单/修复记录）

---

## 一、流程步骤

### 步骤 1：功能测试（人类主导，AI辅助）

人类做：
1. 按照需求文档中的"验收标准"逐条验证
2. 尝试边界条件（最小值、最大值、空状态、快速连点…）
3. 记录任何不符合预期的行为

AI 做：
1. 为人类提供测试清单（从验收标准生成）
2. 当人类报告问题时，即时分析原因
3. 小问题当场修复，大问题记录下来统一处理

### 步骤 2：回归检查（AI主导）

AI 主动检查新改动是否影响了现有功能：

1. **代码层面**：
   - 修改的函数是否被其他地方调用？调用方是否需要适配？
   - 新增的信号/方法是否有命名冲突？
   - CSV 列变更是否破坏了其他读取该 CSV 的代码？

2. **数据层面**：
   - 新CSV列是否都有默认值？旧数据加载是否会出错？
   - 数值范围是否合理？（不会出现负数血量、0伤害等）

3. **场景层面**：
   - 修改的场景节点路径是否在其他脚本中被引用？
   - 新增的场景文件是否在正确的位置？

### 步骤 3：问题修复（AI主导）

AI 根据发现的问题逐项修复：
1. 先修阻塞性 bug（游戏崩溃、功能完全不可用）
2. 再修功能性 bug（行为不符合设计）
3. 最后修体验问题（数值感觉不对、UI 不太好看）

每修一项，标注：问题描述 → 根因 → 修复方式 → 验证结果

### 步骤 4：验证报告（AI主导）

AI 生成一份简短的验证报告：

```markdown
## 验证报告 — [功能名称] — [日期]

### 验收标准达成情况
- [x] 标准1 — 通过
- [ ] 标准2 — 发现小问题（已修复）
- [x] 标准3 — 通过

### 回归检查
- 影响到的其他模块：无 / [列出模块]
- 回归问题：无 / [列出问题及修复状态]

### 已知问题（可后续处理）
- [问题描述] — 影响程度：低/中/高
```

---

## 二、门禁检查点

**通过条件**（全部满足才能进入发布回顾阶段）：

- [ ] 所有验收标准已通过
- [ ] 无阻塞性 bug
- [ ] 回归检查无严重问题
- [ ] 验证报告已生成
- [ ] 已知问题已记录（如有）
- [ ] 人类确认"可以发布"

---

## 三、人类/AI职责小结

| 谁 | 做什么 |
|----|--------|
| **人类** | 实际运行测试 → 体验验收 → 报告问题 → 最终确认 |
| **AI** | 生成测试清单 → 回归检查 → 修复问题 → 生成验证报告 |

---

## 四、常见问题

| 问题 | 应对 |
|------|------|
| 验收标准和实际体验不一致 | 不是bug而是设计问题 → 回到需求分析阶段更新标准 |
| 修复一个bug又引入新bug | AI做回归检查时必须覆盖修改函数的调用方 |
| 时间不够，有些验收标准没测 | 标注"未验证"，记录在已知问题中，后续补测 |
| 人类没时间逐条测 | AI选出最关键的3-5个测试点，至少确保核心路径通过 |
