# 03-工作流SOP / 01-需求分析阶段

> **阶段目标**：把一个模糊的想法变成一份清晰、可执行的需求文档。
>
> **输入**：人类的一句/一段想法描述
>
> **输出**：符合模板的功能需求文档（写入 `策划文档/03-功能规格/`）

---

## 一、流程步骤

### 步骤 1：理解想法（AI主导）

AI 做：
1. 仔细阅读人类的描述，识别核心诉求
2. 不要急于跳到"怎么实现"——先理解"要什么体验"
3. 重述你对需求的理解，让人类确认

人类做：
- 确认理解正确 / 纠正偏差 / 补充遗漏

### 步骤 2：探索现状（AI主导）

AI 做：
1. 搜索项目中相关的已有代码、文档、CSV配置
2. 识别可复用的模块、需要扩展的接口、潜在冲突
3. 向人类报告现状：什么已经有了、什么需要新建、什么需要改动

### 步骤 3：澄清问题（AI提问，人类回答）

AI 应主动问清楚以下维度：
- **触发条件**：什么情况下这个功能生效？
- **交互边界**：与现有系统如何交互？（功法、卡牌、敌人、波次…）
- **UI状态**：正常/禁用/空/错误状态分别长什么样？
- **边界条件**：最大值、最小值、特殊情况（如0个敌人时怎么办）
- **数据来源**：数值从哪个CSV来？需不需要新增列？

人类做：
- 回答AI的问题
- 不需要全部回答——"不知道，你先给个建议"也是有效回答

### 步骤 4：填写需求文档（AI主导）

AI 使用 `策划文档/05-元文档/模板/功能需求文档模板.md`，填写所有章节：
1. 功能概述
2. 详细需求（触发条件、行为逻辑、UI表现、边界条件）
3. 数据设计（涉及哪些CSV、新增/修改哪些列）
4. 技术方案概要（涉及哪些文件、模块交互）
5. 验收标准
6. 风险与注意事项

### 步骤 5：门禁检查（AI自检）

文档完成后，AI自检：
- [ ] 所有6个章节都已填写（无"TODO"或空白）
- [ ] 数据来源明确标注了CSV文件名和列名
- [ ] 边界条件有明确定义
- [ ] 验收标准具体可验证（不是"功能正常"这种模糊描述）

---

## 二、门禁检查点

**通过条件**（全部满足才能进入设计规划阶段）：

- [ ] 需求文档已写入 `策划文档/03-功能规格/`
- [ ] 人类已审阅并批准需求文档
- [ ] 文档中无未解决的"待定"项
- [ ] AI已确认理解所有需求细节

---

## 三、人类/AI职责小结

| 谁 | 做什么 |
|----|--------|
| **人类** | 提出想法 → 确认理解 → 回答问题 → 批准需求文档 |
| **AI** | 理解需求 → 探索代码 → 提问澄清 → 填写文档 → 自检完整性 |

---

## 四、常见问题

| 问题 | 应对 |
|------|------|
| 人类的想法很模糊（"加个酷炫的技能"） | AI不要猜，而是问：什么类型的？单体/AOE？什么触发条件？有参考吗？ |
| 人类不确定具体怎么设计 | AI提供2-3个方案供选择，附每个方案的利弊 |
| 探索发现需求与现有系统冲突 | AI及时告知冲突点，说明为什么冲突，提出规避方案 |
| 需求太大，一个文档装不下 | 拆分：先做最小可用版本（MVP），剩余部分标注为"后续迭代" |
