# 03-工作流SOP / 03-开发实现阶段

> **阶段目标**：按照技术方案，将功能实现为可运行的代码和配置。
>
> **输入**：已批准的技术方案 + 已拆分的任务列表
>
> **输出**：可运行的代码、更新后的CSV、新增/修改的场景文件

---

## 一、流程步骤

### 步骤 1：任务执行（AI主导，逐任务推进）

AI 做（每个任务）：
1. **读**：阅读任务涉及的所有现有文件
2. **改**：实施修改（代码 / CSV / 场景）
3. **检**：对照 `04-质量体系/01-交付检查清单.md` 自检
4. **报**：向人类报告"完成了X任务，改了Y文件"
5. **问**：如果遇到设计中未预见的问题，暂停并咨询人类

**执行顺序原则**：
- 先数据后逻辑：先改 CSV / Resource 类 → 再改逻辑代码 → 最后改表现层
- 先独立后依赖：先做不依赖其他任务的任务
- 每完成1-2个任务，停下来让人类确认方向正确

### 步骤 2：中途检查点（人类参与）

当以下情况出现时，AI应主动暂停并报告：
- 完成了前2个任务（确保方向正确再继续）
- 实际改动范围超出原计划
- 发现需要修改设计方案的重大问题
- 累计修改超过5个文件

人类做：
- 快速确认已完成的部分是否符合预期
- 如果发现方向偏差，及时纠正

### 步骤 3：自检验证（AI主导）

所有任务完成后，AI做：
1. 确认所有计划中的文件都已创建/修改
2. 确认 CSV 格式正确（列数一致、数值类型正确）
3. 确认信号连接完整（emit 和 connect 配对上）
4. 确认没有遗留的 TODO 或临时代码
5. 运行 `04-质量体系/01-交付检查清单.md` 的代码检查项

### 步骤 4：人类验收（人类主导）

人类做：
1. 在 Godot 编辑器中打开项目
2. 运行游戏，亲自体验新功能
3. 检查是否有预期外的行为
4. 反馈：通过 → 进入测试验证阶段 / 不通过 → 列出问题，AI修复

---

## 二、门禁检查点

**通过条件**（全部满足才能进入测试验证阶段）：

- [ ] 所有计划任务已完成
- [ ] 代码自检通过（无语法错误、类型正确、无硬编码）
- [ ] CSV 变更验证通过
- [ ] 人类已体验功能，主观感受符合预期
- [ ] 无遗留的临时代码或 TODO 注释

---

## 三、人类/AI职责小结

| 谁 | 做什么 |
|----|--------|
| **人类** | 中途检查方向 → 最终验收体验 → 反馈问题 |
| **AI** | 逐任务实现 → 自检代码质量 → 报告进度 → 修复问题 |

---

## 四、常见问题

| 问题 | 应对 |
|------|------|
| 实现中发现设计缺陷 | 暂停，向人类报告，提议修改方案。不要硬凑 |
| 某个方案行不通 | 提出替代方案（至少2个），说明各自的取舍 |
| 改动范围越来越大（scope creep） | 标注"超出当前计划"，建议是否纳入当前还是另开任务 |
| Godot 编辑器报错 | AI 读错误信息 → 分析原因 → 修复 → 不做猜测性修复 |
| 类型推断失败（`:=` 报错） | 这是已知的 Godot 4 类型系统限制，改用显式类型声明 `: float` |
