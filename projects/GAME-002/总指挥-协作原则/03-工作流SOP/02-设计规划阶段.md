# 03-工作流SOP / 02-设计规划阶段

> **阶段目标**：将需求文档转化为具体的技术实施方案。
>
> **输入**：已批准的需求文档
>
> **输出**：技术方案文档（含文件清单、接口设计、数据变更计划）

---

## 一、流程步骤

### 步骤 1：审阅需求（AI主导）

AI 做：
1. 重新通读需求文档，确保没有遗漏
2. 列出需求中的关键行为、数据变更、UI变更
3. 与人类确认优先级：哪些先做、哪些可以并行、哪些是依赖项

### 步骤 2：技术调研（AI主导）

AI 做：
1. 精读需求涉及的现有代码文件
2. 确认信号连接、节点路径、数据流
3. 识别需要新增/修改/删除的文件
4. 检查是否有可复用的模式和工具函数

输出：一份"现状→目标"的差异清单。

### 步骤 3：架构设计（AI提案，人类确认）

AI 做：
1. 提出模块拆分方案（新功能放哪个目录、是否新建文件）
2. 定义接口（信号、方法签名、数据格式）
3. 规划 CSV 变更（新增列？新表？修改现有数据？）
4. 规划场景变更（新建 .tscn？修改现有场景？）

人类做：
- 确认架构方案合理
- 对不确定的地方提出质疑
- 如果AI的提案有多个方案，选择一个

**⚠️ 复杂功能使用架构审查**：如果功能涉及3个以上模块或新建模块，应使用 `程序规则/AI功能模块架构设计审查提示词.md` 进行正式审查。

### 步骤 4：任务拆分（AI主导）

AI 将实施方案拆分为可独立执行的任务：

```
每个任务 = {
  描述：一句话说清楚做什么
  涉及文件：[文件路径列表]
  依赖：需要先完成的其它任务
  验证方式：怎么知道做完了、做对了
  预估复杂度：小(1文件)/中(2-3文件)/大(4+文件)
}
```

### 步骤 5：编写技术方案文档（AI主导）

汇总以上内容，写入 `策划文档/05-元文档/路线图/` 目录下的功能规划文档。

---

## 二、门禁检查点

**通过条件**（全部满足才能进入开发实现阶段）：

- [ ] 技术方案已文档化
- [ ] 人类已批准架构方案
- [ ] 文件变更清单完整（新增/修改/删除）
- [ ] CSV变更计划明确（列名、类型、默认值）
- [ ] 任务已拆分且依赖关系清晰
- [ ] 每个任务有明确的验证方式

---

## 三、人类/AI职责小结

| 谁 | 做什么 |
|----|--------|
| **人类** | 确认优先级 → 批准架构方案 → 确认任务拆分合理 |
| **AI** | 审阅需求 → 技术调研 → 架构设计提案 → 任务拆分 → 写方案文档 |

---

## 四、常见问题

| 问题 | 应对 |
|------|------|
| 需求太大，拆不出独立任务 | 先做数据层 → 再做逻辑层 → 最后做表现层 |
| 架构方案不确定哪种更好 | 对照 `Godot架构规范与模块化标准.md` 的模块拆分决策矩阵 |
| 发现需求需要调整 | 回到需求分析阶段更新需求文档，不要在设计阶段偷偷改需求 |
| CSV变更影响其他功能 | 在方案中明确标注影响范围，让人类知情决策 |
