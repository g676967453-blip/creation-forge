# 06-持续改进 / 02-里程碑复盘模板

> **用途**：每完成一个里程碑（功能模块/Phase/周）后，系统性回顾并提取改进措施。

---

## 里程碑复盘格式

```markdown
# 里程碑复盘 — [里程碑名称] — [日期]

## 📊 完成情况
- 计划完成：[N] 项
- 实际完成：[N] 项
- 未完成：[列出]（原因：[时间不够/优先级调整/遇到阻碍]）

## ✅ What went well（做得好的）
1. 
2. 
3. 

## ❌ What went wrong（做错了的）
1. 
2. 
3. 

## 🔧 What to try next（下次试什么）
1. 改进措施：[具体行动] — 负责人：[人类/AI] — 截止：[日期]
2. 
3. 

## 📝 规则更新
- [ ] 需要更新的文档：[文件名] — 更新内容：[简述]
- [ ] 不需要更新（当前规则足够）

## 🎯 下一里程碑
- 目标：
- 预估工作量：[N] 个会话
```

---

## 复盘触发条件

| 触发条件 | 复盘深度 |
|----------|----------|
| 一个功能模块完成 | 轻量版（5分钟，What went well/wrong 各1条） |
| 一个 Phase 完成 | 标准版（10分钟，完整填写模板） |
| 一周结束 | 轻量版（5分钟） |
| 遇到重大问题（严重bug、方向错误） | 即时复盘（事件发生后立刻记录教训） |

---

## AI引导复盘的问题清单

AI 在每个里程碑完成时应主动问这些问题（按优先级）：

### 必须问的（3个核心问题）
1. **"这次开发中，哪个瞬间让你觉得'AI真有用'？"** → 强化优势
2. **"哪个瞬间让你觉得'AI怎么这么笨'？"** → 找到改进点
3. **"下次你希望AI多做点什么？少做点什么？"** → 调整分工

### 可选问的（人类时间充裕时）
4. "开发过程中有没有'早知道就XXX'的时刻？"
5. "你觉得我们现在的分工方式合理吗？"
6. "有什么重复性的事情你希望AI完全自动化？"

## 改进措施追踪

复盘中提出的改进措施应记录在案并追踪执行：

```markdown

```

## 原则

- **诚实优于好看**——"做错了的"比"做得好的"更有价值，不要粉饰
- **具体优于抽象**——"沟通可以更好"不如"AI在第3步跳过了确认，导致方向错了2小时"
- **行动优于抱怨**——每个"做错了的"必须对应至少一条改进措施
- **够用就好**——不是每次都要写长篇大论，3句话的复盘也比没有好
