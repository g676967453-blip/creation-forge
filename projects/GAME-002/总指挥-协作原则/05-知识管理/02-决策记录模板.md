# 05-知识管理 / 02-决策记录模板

> **用途**：记录重要的架构、数值、设计决策，让未来的自己（和AI）知道"当时为什么这么做"。

---

## ADR 格式（Architecture Decision Record）

```markdown
# ADR-[编号]: [决策标题]

## 状态
[提议中 / 已采纳 / 已废弃 / 已替代]

## 日期
YYYY-MM-DD

## 背景
为什么要做这个决策？遇到了什么问题？有什么约束？

## 决策
我们决定怎么做？

## 考虑的方案

### 方案A：[名称]
- 优点：
- 缺点：

### 方案B：[名称]
- 优点：
- 缺点：

### 方案C（如有）...

## 选择理由
为什么选了方案X而不是方案Y？

## 影响范围
这个决策影响了哪些模块/文件/数值？

## 后果
（决策执行后填写）
- 正面：
- 负面：
- 如果重来一次会怎么做？
```

---

## 适用场景

以下情况应该写一份决策记录：

| 场景 | 示例 |
|------|------|
| 技术方案选择 | "弹道碰撞检测用 Area2D 还是直接用距离判断？" |
| 数值框架决策 | "伤害公式用乘法叠加还是加法叠加？" |
| 设计方向变更 | "远程怪改为不飞行——与之前的设计文档不一致" |
| 架构重构 | "ENEMY_SPRITES 硬编码字典 → CSV 驱动的决策" |
| 放弃某个方案 | "试了方案A但导致XXX问题，改用方案B" |
| 外部工具/资源选择 | "图标用 Lovart 生成而不是手绘——原因和流程" |

---

## 编号规则

`ADR-YYYYMMDD-NN`

- YYYYMMDD = 决策日期
- NN = 当日序号（01, 02, 03…）

示例：`ADR-20260709-01`

---

## 存放位置

- 技术决策 → `开发记录/memory/YYYY-MM-DD.md` 或独立 ADR 文件
- 设计决策 → 相关 `策划文档/02-系统设计/` 或 `03-功能规格/` 文档中
- 数值决策 → 相关数值配表 Excel 的备注或独立说明

---

## 最小可行版本

如果时间紧迫，至少记录这3行：

```
[日期] [决策] → [为什么] → [影响了什么]
```

示例：
```
2026-07-07 远程怪不飞行 → 天空战场"飞行"概念留给未来无双模式 → enemy_data增加march_style字段
```
