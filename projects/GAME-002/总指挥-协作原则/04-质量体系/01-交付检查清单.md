# 04-质量体系 / 01-交付检查清单

> **用途**：每次代码修改完成后，AI 按此清单自检。人类抽查式确认。

---

## 一、代码交付检查项

### A. 功能正确性
- [ ] 功能行为符合需求文档描述
- [ ] 所有验收标准均已满足
- [ ] 边界条件已处理（空输入、极值、null、freed object）
- [ ] 错误状态有合理的降级处理（而非崩溃）

### B. GDScript 规范
- [ ] 所有变量有显式类型标注（`var x: float = 1.0`，不用 `var x := 1.0` 在有类型推断风险处）
- [ ] 使用 `minf()`/`maxf()`/`clampf()` 而非 `min()`/`max()`/`clamp()`（避免 Variant 返回）
- [ ] `@export var` 用于需要在编辑器中配置的变量
- [ ] 文件 ≤ 200 行（超过则考虑拆分）
- [ ] 函数 ≤ 25 行（超过则考虑提取子函数）

### C. 架构合规
- [ ] 新脚本放在正确的目录（参考 `CLAUDE.md` 的目录树）
- [ ] 新场景放在正确的 `scenes/` 子目录
- [ ] 数据读取通过 `DataManager` 而非直接读文件
- [ ] 节点路径使用 `const` 常量管理（不是裸字符串 `get_node("路径")`）

### D. 信号与依赖
- [ ] `signal` 声明在文件顶部
- [ ] `emit` 和 `connect` 配对完整
- [ ] 无循环依赖（A 依赖 B 且 B 依赖 A）
- [ ] 连接使用 `signal_name.connect(_on_signal_name)` 而非字符串连接

### E. 数据规范
- [ ] 无硬编码数值（所有数值从 CSV 读取）
- [ ] CSV 修改后格式正确（列数一致、数值类型正确）
- [ ] 新增 CSV 列有默认值
- [ ] `class_name` 的 Resource 类字段与 CSV 列名对应

### F. 安全性
- [ ] 访问节点前有 `is_instance_valid()` 检查（如果是动态创建/销毁的节点）
- [ ] `queue_free()` 后有 null 检查或提前 return
- [ ] 数组/字典访问有边界检查（或使用 `get()` 带默认值）
- [ ] 无 `as` 强制转换前没有类型检查

---

## 二、文档交付检查项

### A. 格式规范
- [ ] 使用 Markdown 格式
- [ ] 标题层级正确（# → ## → ### 递进，不跳级）
- [ ] 表格对齐、代码块标注语言
- [ ] 文件命名遵循项目约定

### B. 内容准确性
- [ ] 引用的数值与 CSV 一致（对照 `CLAUDE.md` 的交叉验证表）
- [ ] 引用的文件路径真实存在
- [ ] 提到的类名/方法名与实际代码一致
- [ ] 日期戳正确

### C. 交叉引用
- [ ] 引用了相关的需求文档/设计文档
- [ ] 如有依赖的其他功能，已标注
- [ ] 链接格式正确（相对路径可用）

---

## 三、资源交付检查项

### A. 格式正确
- [ ] 图片资源为 .png 格式（带透明通道如需要）
- [ ] 音频资源为 .ogg 或 .wav 格式
- [ ] 场景文件为 .tscn 格式（Godot 可编辑）

### B. 命名规范
- [ ] 文件名使用 snake_case
- [ ] 文件名有意义的描述（不是 `image_1.png`）
- [ ] 版本号或序号在末尾（`sword_icon_v2.png`，不是 `v2_sword_icon.png`）

### C. 路径合规
- [ ] 运行时资源在 `assets/runtime/` 对应子目录
- [ ] 原始源文件在 `assets/source/` 对应子目录
- [ ] 导出中间产物在 `assets/_exported/`

---

## 四、使用方式

### AI 使用
每次完成代码修改后，逐项自检。发现不通过的项目：
- 小问题：立即修复
- 需要人类判断的：标注"需确认"

### 人类使用
抽查式使用——不需要每项都看，挑2-3个你最关心的维度快速过一遍。
