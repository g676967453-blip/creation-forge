# 01 — 三角协作模型

> **人-Claude-Lovart 协作的核心循环**

---

## 为什么要定义协作模型？

AI 美术生成与传统美术有一个根本区别：**生成器（Lovart）和执行者（Claude）都看不到结果**。只有人类能看到图片。

这意味着协作不是「Claude 替代美术」——而是「人类 + Claude + Lovart」构成一条**三节点的生产线**，每个节点有明确的输入输出和职责边界。

---

## 职责边界

### 人类的职责

| 职责 | 为什么必须是人类 |
|------|-----------------|
| 定义风格方向 | AI 没有审美偏好，只能执行 |
| 判断生成质量 | Claude 看不到图 |
| 决定"够好了" | "完成"是主观判断 |
| 提供具体反馈 | 只有看到图的人才能描述问题 |
| 管理创意一致性 | 跨资产的风格统一需要人类把关 |

### Claude 的职责

| 职责 | 为什么 Claude 适合 |
|------|-------------------|
| Prompt 设计与优化 | 语言模型擅长将描述转化为精确的英文 Prompt |
| 调用 Lovart API | 执行命令、处理参数、等待完成 |
| 后处理 | 脚本化操作（抠除品红、缩放、重命名） |
| 文件管理 | 按约定的目录结构归档 |
| 记录与追踪 | 维护 thread 历史、生成日志 |

### Lovart 的职责

| 职责 | 限制 |
|------|------|
| 文本→图像生成 | 依赖 Prompt 质量 |
| 多模型路由 | Agent 自动选择，也可通过 --prefer-models 指定 |
| 迭代上下文 | 同一 thread 内保留生成历史 |

## 协作循环（标准一次迭代）

```
Step 1: 人类发起
  → "我想要一个像素风格的冷峻剑修角色，银发，青色剑气，用于角色选择界面"
  → Claude 记录需求，从 templates/ 选取 character-portrait.md 模板

Step 2: Claude 组装 Prompt
  → 填入人类的描述
  → 添加强制关键词（pixel art, limited color palette, ...）
  → 选择模型（如果是第一次 → nano_banana_pro 草稿）
  → 执行 chat 命令

Step 3: Lovart 生成
  → Claude 阻塞等待完成（chat --json --download）
  → final_status: done
  → 文件下载到 outputs/

Step 4: Claude 交付
  → 发送本地文件路径 + Lovart 画布链接
  → "剑峰峰主的胸像已生成，请查看"

Step 5: 人类验收
  → 👁️ 查看图片
  → 三种反馈之一：
     A. "可以了" → 进入 Step 6
     B. "头发不够银，眼神不够锐利" → 回到 Step 2（复用 thread_id）
     C. "方向完全不对，换个姿势" → 回到 Step 2（可能开新 thread）

Step 6: 入库
  → Claude 运行后处理（如需品红抠除/缩放）
  → 文件归档到 outputs/{项目名}/{类型}/
  → 记录生成参数到对应的生成日志
```

---

## 反馈质量决定迭代效率

| 反馈质量 | 示例 | 迭代次数（预估） |
|---------|------|-----------------|
| 🔴 无效反馈 | "感觉不对" | 5-10 次（Claude 只能猜） |
| 🟡 模糊反馈 | "风格不太对" | 3-5 次 |
| 🟢 具体反馈 | "头发不够银白，剑气应该更偏青色而不是蓝色" | 1-2 次 |
| 🟢🟢 精确反馈 | "银发钛白值太高，接近纯白，需要偏冷灰银。剑气从 #4080f0 偏到 #4ecca3" | 1 次 |

**原则**：反馈不需要技术术语，只需要**描述你看到的和你想要的之间的差距**。

## 多轮迭代的线程管理

```
同一个主题 = 同一个 thread_id
  ✅ 剑峰峰主胸像迭代（第1版→第2版→第3版） → 共用 thread_id
  ✅ "把背景调暗一点" → 复用上一个 thread_id

换主题 = 新 thread
  ✅ 剑峰峰主 → 佛峰峰主 → 不同 thread
  ✅ "生成一个全新的 BOSS 角色" → 新 thread
```

原因：Lovart Agent 在同一个 thread 内保留上下文记忆，知道"上一张图是什么"，才能精准修改。换 thread 等于从头开始。

## 常见协作场景

### 场景 A：从零开始

```
人类："帮我生成一个____"
Claude：选模板 → 填 Prompt → nano_banana_pro 草稿 → 交付
人类：给反馈
Claude：复用 thread → 调整 Prompt → 再生成 → 交付
...重复直到人类满意...
Claude：后处理 → 入库
```

### 场景 B：基于参考图修改

```
人类：发送一张参考图
Claude：upload 到 CDN → chat --attachments "CDN_URL" --prompt "参考这张图的风格，生成____"
...后续同场景 A...
```

### 场景 C：继续之前的对话

```
人类："上次那个剑修，帮我生成全身像"
Claude：查 threads --json → 找到剑峰 thread → 复用 thread_id → 调整构图 → 生成
```
