# 03 — 工作流阶段

> **草稿探索 → 成品输出 → 集成上线：AI 美术生产的三阶段方法**

---

## 为什么要分阶段？

直接让最贵的模型出成品 = 浪费。一个 Prompt 很少一次完美命中。

三阶段方法的核心逻辑：
- **先用便宜的模型快速试错** → 确定方向
- **再用最贵的模型出精品** → 保证质量
- **最后用脚本后处理** → 保证可用

---

## 三阶段总览

```
Phase 1: 草稿探索           Phase 2: 成品输出           Phase 3: 集成上线
    │                          │                          │
    ├─ 模型: nano_banana_pro   ├─ 模型: midjourney        ├─ 工具: postprocess.py
    ├─ 成本: 低                ├─ 成本: 中                ├─ 成本: 零
    ├─ 速度: 快 (~30s)         ├─ 速度: 中 (~60-90s)      ├─ 速度: 秒级
    ├─ 目标: 验证方向           ├─ 目标: 精修高质量          ├─ 目标: 可用资产
    │                          │                          │
    ▼                          ▼                          ▼
  2-3 个候选项               选定方向精修版              游戏可用的 PNG
```

---

## Phase 1: 草稿探索

### 目标
快速生成 2-3 个不同方向的候选项，让人类判断"哪个方向是对的"。

### 方法
- 使用 `nano_banana_pro`（快速、低成本）
- 如果人类描述模糊，可以用略有差异的 Prompt 生成 2-3 个版本
- 不追求细节完美，只看大方向（构图对不对？色调对不对？风格对不对？）

### 命令模板
```bash
python3 agent_skill.py chat \
  --prompt "..." \
  --include-tools generate_image_nano_banana_pro \
  --json --download
```

### 验收标准（Phase 1 → Phase 2 的门槛）
- [ ] 构图方向正确（取景范围、人物姿态基本符合需求）
- [ ] 色调方向正确（主色符合预期，不需要精确匹配）
- [ ] 风格方向正确（是像素艺术不是 3D/写实/动漫）
- [ ] 人类说"这个方向可以，继续"

### 常见问题
| 问题 | 处理 |
|------|------|
| 3 个候选项都不对 | 说明 Prompt 没表达清楚需求，调整 Prompt 再试 |
| 风格完全跑偏 | 加强技术约束关键词（pixel art / no anti-aliasing 等）|
| 拒绝的概率 | Nano Banana Pro 内容审核更严格，尝试换描述方式 |

---

## Phase 2: 成品输出

### 目标
在 Phase 1 确定的正确方向上，用高质量模型生成精修版。

### 方法
- 使用 `midjourney`（像素艺术理解最佳）
- 将 Phase 1 的 Prompt 精细化（加入更多细节描述、精确配色）
- 每次只调整一个变量（方便定位问题）

### 命令模板
```bash
# 首次成品生成
python3 agent_skill.py chat \
  --prompt "..." \
  --prefer-models '{"IMAGE":["generate_image_midjourney"]}' \
  --json --download

# 迭代修改（复用 Phase 2 的 thread_id）
python3 agent_skill.py chat \
  --prompt "fix ___. Keep everything else the same." \
  --thread-id {THREAD_ID} \
  --prefer-models '{"IMAGE":["generate_image_midjourney"]}' \
  --json --download
```

### 验收标准（Phase 2 → Phase 3 的门槛）
- [ ] 像素艺术保真通过（见 04-质量验收标准.md §1）
- [ ] 色彩合规通过（见 04-质量验收标准.md §2）
- [ ] 构图符合规格
- [ ] 人类说"可以了"

### 迭代策略
```
第一轮：大方向（构图、姿势）
  → 人类反馈 → 调整
第二轮：配色（色调微调、禁止色检查）
  → 人类反馈 → 调整
第三轮：细节（面部表情、服装细节、氛围）
  → 人类确认 → 进入 Phase 3
```

---

## Phase 3: 集成上线

### 目标
将 Lovart 生成的原始图片转化为游戏可直接使用的资产文件。

### 步骤

1. **品红抠除**（如生成时用了品红背景）
2. **NEAREST 缩放**至目标分辨率
3. **命名规范化**（按 `outputs/` 的命名约定）
4. **归档到 outputs/{项目名}/{类型}/**

### 命令模板
```bash
# 后处理
python3 scripts/postprocess.py \
  --input "lovart_output.png" \
  --output "C:/Users/Administrator/Desktop/asset-pipeline-outputs/GAME-002/portraits/GAME-002_portrait_sword-master_bust.png" \
  --width 512 --height 720

# 或直接下载到归档位置
python3 agent_skill.py download \
  --urls "https://a.lovart.ai/artifacts/agent/xxx.png" \
  --output-dir "C:/Users/Administrator/Desktop/asset-pipeline-outputs/GAME-002/portraits" \
  --prefix "GAME-002_portrait_sword-master_bust"
```

### 验收标准（Phase 3 完成）
- [ ] 文件存在且尺寸正确
- [ ] 品红无残留（如适用）
- [ ] 在游戏引擎中可以正确加载
- [ ] 相对路径引用正确
