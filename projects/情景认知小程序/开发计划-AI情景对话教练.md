## 0. 计划摘要

**一句话**：做一个 AI 情景对话教练——用低门槛的日常场景接住用户，让 AI 扮演对方逐回合对话，回合中给即时反馈、回合间给拆解、局末帮用户把零散经验升维成可复用的认知框架；首期场景域 = **接话 / 日常社交沟通**。

**与旧原型的关系（已确认决策）**：
| 维度 | 《中了500万》理财原型（历史参考） | 新方向（计划主线） |
|---|---|---|
| 交互 | 确定性选项 → 规则引擎算钱 | **用户自由输入一句话** → AI 扮演对方回应 |
| 反馈 | 局末一次性 LLM 复盘 | **回合级即时反馈 + 局末升维复盘** |
| 认知机制 | 类魂：死一次学一招 | AI 学习循环：抛场景→给反馈→升认知→变式练→复盘点 |
| 借鉴价值 | 原则库=脊椎、schema 化内容、护栏自动验收、复盘提示词工程 | 全部迁移到"接话"域重写 |

**MVP 最小区块**（载体 = **H5 移动端网页**）：纯文字对话 × 8~12 个接话场景 × 4 条接话原则 × 一局 4~6 回合 → 局末薄弱清单 + 升维点评 + 分享卡。

## 1. 产品定义（需求基线，源自 09-07 构想）

### 1.1 一句话定位
> AI 情景对话教练：通过模拟真实场景中的互动，把知识转化为**可迁移的认知能力**。

### 1.2 要解决的问题 & 目标用户

- **核心问题**：用户不缺知识，缺在真实情境中调用知识的能力。读 100 篇《如何接话》不如在 10 个模拟对话中被纠正 10 次。
- **目标用户**：有具体痛点、认知尚浅的人（聊天冷场/尴尬、想提升沟通力、害怕社交失败）。他们以"低认知问题"入门——「怎么回消息不冷场？」。
- **导流 → 深耕机制**（构想第 14 轮）：用低认知问题接住用户（症状），AI 用高认知问题带用户升级（病因）。设计铁律：**不要让用户先选择，让他先反应**。

### 1.3 产品机制：AI 学习循环（5 步，核心引擎）

| 步骤 | AI 做什么 | 用户经历什么 | MVP 落地形态 |
|---|---|---|---|
| ① 抛场景 | 给出真实对话情境 + 对方开场白 | 本能地打出一句回应 | 场景卡片 → 输入框 → AI 扮演对方 |
| ② 给反馈 | 回合内指出：接住了什么 / 是否终结型 / 更优接法 | 意识到盲区（不打断对话流） | 回合小结气泡（可选展开"为什么"） |
| ③ 升认知 | 把单次回应连接到高阶原则 | 理解"为什么这样接更好" | 每回合一次"教练侧栏"提示，一次只升一级 |
| ④ 变式练 | 同原则换场景再抛一轮 | 把原则练成直觉 | 场景变式参数化（同族换皮） |
| ⑤ 复盘点 | 局末总结反复出现的模式 | 形成自我认知 + 可带走清单 | 薄弱原则统计 + LLM 个性化点评 + 分享卡 |

### 1.4 差异化定位（构想第 19 轮竞品分析后）

| 竞品类型 | 代表 | 他们的做法 | 我们的差异点 |
|---|---|---|---|
| 话术生成工具 | 嘴替SOS / RizzAgent 等 | 给"这句话怎么回" | 不卖话术，卖**"为什么这样回 + 下次同类场景怎么想"**（认知框架） |
| 恋爱/约会导向 | 恋爱大师、Winkply 等 | 场景偏两性、结果导向 | 场景全域：日常社交、职场、亲密关系；不做"套路" |
| 简单评分 APP | 驾校式对错 | 只有评分没有拆解 | 反馈有**依据、分层、可迁移**；情绪理解优先于正确性判断 |
| 通用 AI 聊天 | Character.AI | 陪聊无教练 | 每回合教练介入 + 升维路径 + 学习进度沉淀 |

**一句话**：别人在卖"这句话怎么回"，我们卖"为什么这样回、下次遇到类似情况怎么想"——目前国内外都还没有做深。

### 1.5 核心壁垒（产品护城河，非技术）
1. **场景库质量**：是否覆盖用户真实痛点（含变式规模）
2. **反馈精度**：能否指出用户自己意识不到的盲区
3. **升维路径**：能否把零散练习沉淀为可复用认知框架（用户可感知的"进步"）

## 2. MVP 范围界定（首期：接话/日常社交）

### 2.1 本期范围
- ✅ **载体**：H5 移动端网页（竖版 9:16 布局，真机浏览器可玩、可分享链接）——小程序化在 Phase 3
- ✅ 纯文字对话（一个场景 = 对方角色 + 开场白 + 4~6 回合你来我往）
- ✅ 回合级即时反馈 + 局末复盘升维
- ✅ 原则薄弱清单 + 个性化点评 + 结局分享卡（文字版）
- ✅ 4 条核心原则、8~12 个场景（含变式 ≥ 3 组）
- ✅ 免费体验额度机制（为付费留口）
- ❌ 不做：语音、头像/虚拟角色、多场景域、成长系统、社区/排行榜、精品视频包

### 2.2 首期原则库草案（接话域，原则 = 脊椎）

| # | 原则名 | 核心要义 | 反面错误类型（反馈识别用） |
|---|---|---|---|
| 1 | 接情绪，不接事实 | 先回应对方感受，再处理内容 | 只给事实性评价/建议（"辛苦了早点休息"式空泛） |
| 2 | 接细节，不接概括 | 用具体问题邀请对方展开 | 空泛鼓励、封闭式提问、敷衍 |
| 3 | 接延伸，不接终结 | 把球传回去，推动对话继续 | 话题终结型回应（聊死） |
| 4 | 心里装着对方 | 从"我要表现好"切到"让对方舒服" | 自我中心型（把话题 hijack 成个人秀） |

> 来源 = 构想第 8 轮实测结论；与 8 月理财原则库结构同构（命名好记 + 一条反面）。四条是否够/是否合并，由 Phase 1 场景写作时定稿。

### 2.3 一局对话的结构（回合模型）

```
[进入] 场景卡片：人物/地点/情绪状态  →  AI 抛开场白
   ↓
R1: 用户自由输入（一句话回应）
   ↓ AI：1) 扮演角色接住并回应（继续对话，不打断）  2) 回合小结：命中原则 or 终结型预警 + 一句"如果换个接法"（隐藏，可展开）
   ↓
R2~R4: 同回合模型；第 3 回合后允许 AI 抛"变式"（同原则换情境小转弯）
   ↓
[收尾] AI 角色自然收束 → 局末复盘：
   ① 原则命中统计（哪条绊倒几次） ② LLM 个性化点评（≤100 字，损友风不评判人格）
   ③ 认知升维卡："你三次都停在给建议——对方要的常常不是建议，是被理解" ④ 分享卡
```

### 2.4 功能:情绪配比在本 MVP 的落地（构想第 16 轮 6:4 体系）

| 用户旅程环节 | 配比 | MVP 落地 |
|---|---|---|
| 引流/入口 | 3:7 | 场景选题全部来自真实痛点标题（"被女生说『哦』怎么回"）；分享卡带情绪钩子 |
| 首次体验 | 5:5 | 前 2 回合反馈轻、氛围松（"敢开口"优先），第 3 回合起教练开始点破 |
| 日常练习 | 6:4 | 默认反馈开、可关"教练模式"纯对练 |
| 挫败/瓶颈 | 4:6 | 连续 2 回合终结型 → AI 鼓励性提示 + 降难度变式 |
| 高阶 | 7:3 | 解锁"复盘模式"：不练场景，直接分析自己的历史回应模式 |

### 2.5 内容数据 Schema（草案，JSON 化，规则先行防幻觉）

```json
{
  "id": "rj01",
  "domain": "接话",
  "principle": ["p1", "p3"],
  "npc": { "role": "同事", "mood": "疲惫委屈", "name": "阿凯" },
  "opening": "最近赶项目疯了，天天加班到十点，身体快熬垮了。",
  "scene": "茶水间，你碰到刚开完会的同事阿凯……",
  "difficulty": 1,
  "family": "同事吐槽",
  "variantOf": null,
  "coach_hints": [
    { "trigger": "终结型", "hint": "对方说的不是累，是委屈。先接情绪：『听着好累，最近是不是特别委屈？』" }
  ],
  "closing": { "good": "自然收束", "bad": "对方兴致索然，对话提前结束" }
}
```

> 铁律（迁移自 8 月教训）：**文案承诺的机制必须真实存在**——教练侧栏给的"更优接法"必须可被对话引擎执行，不能在剧本里写死系统不支持的"完美回应"。

### 2.6 反馈与升维的规则骨架（AI 不稳定性的护栏）

- **结构化输出**：回合小结 = 固定 JSON（`{mode: "normal"|"terminator"|"self_center"|"good", principle_hit: [..], hint?: "..."}`），UI 按 mode 渲染，禁止自由发挥格式。
- **一次只升一级**：单回合最多点 1 条原则（构想第 14 轮铁律），升级不跳级。
- **角色与教练分离**：同一上下文双角色（扮演者语气稳定；教练可切换理性），或拆两次调用（成本换稳定，Phase 1 实测选型）。
- **降级预案**：LLM 超时/失败 → 复用模板反馈（按 mode 预写），用户永不干等（迁移 `复盘AI点评提示词.md` 的 3 秒超时策略）。
- **LLM 永不碰数字/进度**：原则统计、次数、等级全部客户端/服务端规则计数。

## 3. 技术方案（拟，Phase 1 再定稿）

### 3.1 总体架构（推荐）

```
H5 移动端页面（验证期前端；竖版 9:16，真机浏览器可玩）
  ├── 场景入口列表 / 一局对话 UI / 复盘页 / 分享卡
  └── 额度与本地进度（原则命中统计可端上计数 + 云端备份）
后端对话网关（云托管 / 云函数，Phase 3 小程序化时零改动复用）
  ├── 鉴权、额度、限流（免费每日 N 局）
  ├── 场景内容库（JSON，随版本发布 or 远程下发）
  ├── LLM 编排：角色回合调用 + 教练小结调用（结构化 schema 约束）
  └── 内容安全过滤（出入双向）
数据：用户/局次/原则统计/复盘记录
```

### 3.2 载体决策（2026-09-08 已定：先 H5 验证）
- **路径**：H5（移动端网页）→ 验证通过 → 微信小程序化
- **为什么先 H5**：
  1. 本项目要验证的核心是**机制**（对话学习循环是否成立、反馈是否有效），不是平台能力——H5 是验证机制最便宜、迭代最快的场地
  2. 小程序类目/AI 内容合规（教育 vs 工具、备案口径）在早期是阻塞项，H5 无审核门槛，可并行跑合规调研而不阻塞开发
  3. 项目已有竖版 9:16 单文件 HTML 原型经验（`prototype/index.html`），可无缝迁移交互形态
  4. 技术栈迁移成本低：H5 对话页 + 同一套后端对话网关 → 小程序 WebView 承载或原生重写，后端零改动
- **小程序化启动条件**：H5 验证通过（§5 指标达标）且合规调研结论允许
- ⚠️ 对话记录全程未讨论载体与合规；README 待办亦列"明确载体"。**Phase 0 仍须完成合规调研**（类目/备案），但不再阻塞开发排期（见 §9）。

### 3.3 LLM 编排与成本（MVP 估算）

| 调用点 | 频次 | 输入/输出量级 | 说明 |
|---|---|---|---|
| 角色回应 | 每回合 1 次 | ~400 / ~80 token | 4~6 回合/局 |
| 回合小结（教练） | 每回合 1 次 | ~600 / ~120 token | 结构化 JSON；可与角色回合合并省一次 |
| 局末复盘点评 | 每局 1 次 | ~800 / ~150 token | 参考 `复盘AI点评提示词.md` 结构重写为接话域 |

- 单局约 5~8 次调用、~6k token；免费额度 3 局/日 → 单日活跃用户成本需实测校准（OpenAI/国产模型价差大，Phase 1 做成本护栏：超支自动降级合并调用）。

## 4. 里程碑路线图

> 排期为相对周数（非承诺日期）；每阶段含 出口验收（Go/No-Go），未过不进入下一阶段。

### Phase 0 — 立项准备（约 1 周）
- **目标**：把"构想"固化为可立项范围；消除最大合规不确定性
- **任务**
  1. 本计划评审：用户确认 §2 范围 / §9 决策项
  2. 载体与合规调研：微信小程序类目（教育类 vs 工具）、AI 生成内容规则、算法备案口径、未成年人保护
  3. 原则库定稿：接话域 4 原则 → 与 3~5 名真实痛点用户小测命名/记忆点
  4. 场景选题池：收集 20+ 真实"冷场/不会接"场景素材（评论区/社群/身边）
  5. 命名与立项：产品名候选 ≥3；更新 `project.json` / `README.md` / 造化仪表盘日志
- **出口验收**：合规结论书面化 + 原则库定稿 + 场景池 20+；未过则继续调研不排期开发

### Phase 1 — H5 交互原型 + 机制验证（约 4~6 周，本轮重点）
- **目标**：以 **H5（移动端网页）** 为载体，跑通"抛场景→反馈→升维→复盘"闭环；验证机制可行性，暂不碰小程序审核/壳
- **任务**
  1. 场景内容生产：8~12 场景 + 每组 ≥3 变式（模板 + LLM 扩写 + 人工审核，流程见 §6）
  2. 对话引擎：角色/教练双角色编排 + 结构化反馈 + 降级预案（§2.6）
  3. **H5 可玩原型**（2 周内出第一版）：直接移植 `prototype/index.html` 竖版 9:16 布局经验，做单文件/轻依赖 H5，验证回合节奏与反馈密度；真机浏览器可玩、可分享链接给内测用户
  4. ~~小程序壳~~ → 顺延 Phase 3（载体已定 H5 先行，小程序壳在小程序化阶段再做）
  5. 复盘点评提示词 v2（接话域）：复用旧复盘四段式 + 接话域 few-shot + 验收清单
  6. 护栏校验脚本：模拟策略（好/坏/随机）× N 局，验证"好回应必得好反馈、终结型必被识别"的识别准确率（迁移难度曲线护栏思想）
  7. 额度与埋点：基础行为埋点（完成率/回合流失点/复盘展开率）
- **出口验收**：H5 原型在真机浏览器跑通全局；内部 10 局测试反馈稳定；终结型识别准确率 ≥ 目标值（建议 ≥80%）；单局成本 < 预算线；原型链接可分发给种子用户

### Phase 2 — H5 内测与学习效果验证（约 2~3 周）
- **目标**：在 H5 原型上回答两个假设——①用户愿不愿意连续练（留存）②练了是否真变强（学习有效）
- **任务**
  1. 种子用户内测（10~30 人，覆盖"真想练"人群）：真实对话场景收集
  2. 学习效果小测：练前/练后各做一次"错误接话类型判断题 + 一段自由回应评分"（构想第 9 轮：模式识别/反应直觉/元认知三维度）
  3. 调优：反馈密度（太啰嗦则默认收起）、难度曲线（新手局是否 ≤10 分钟、是否有挫败保护）
  4. 分享卡验证：内测用户是否愿意发（传播假设）
- **出口验收**：完成率 ≥60%、次日回访 ≥25%（参考值，可调）、练后小测提升显著为正；未达 → 回 Phase 1 调机制

### Phase 3 — 小程序化 + 增长与内容规模化（H5 验证通过后启动）
- **目标**：验证付费 + 建立场景库飞轮 + 迁移到微信小程序分发
- **任务**
  1. **小程序化**：H5 验证通过后，做微信小程序壳（登录/类目审核/合规接入），后端对话网关零改动复用
  2. 场景域横向扩展节奏：接话站稳 → 职场沟通 → 谈判/销售（构想第 9 轮复制域，逐个域重跑 Phase 1 内容流程）
  3. 变式规模化：参数化模板（关系×情绪×话题）× LLM 批量扩写 → 人工审核 → 每周上新
  4. 变现路径：免费额度 + 订阅解锁无限练 / 剧本包（iOS 支付限制 → 混合路径：广告+导流，沿用旧原型决策）；付费点放"瓶颈期用户"
  5. 轻多媒体叠加（按构想第 17 轮顺序）：AI 语音 → 头像角色 → 精品场景视频包（增值，非主路径）
  6. 认知进步可视化："我的薄弱原则变化曲线"——把练习数据变成用户看得见的成长（升维路径的显性化，即壁垒可视化）

## 6. 内容生产线（模板 + LLM 扩写 + 人工审核 + 护栏）

迁移 `AI内容生产规范.md` 的成熟流程，改写为接话域：

1. **编剧（人工）设计场景模板**：原则绑定 + npc 人设 + 开场白 + 教练提示触发点（§2.5 schema）
2. **LLM 离线批量扩写变体**：参数 = 关系（同事/朋友/亲戚/伴侣）× 情绪（委屈/兴奋/吐槽）× 话题（工作/生活/兴趣）；同族互斥标记
3. **人工审核清单（入库前必查）**：
   - [ ] 原则绑定正确（选项语义 ↔ 原则一致，禁止错配）
   - [ ] 机制真实性：教练"更优接法"示例可执行
   - [ ] 真实性：对话符合中国现实语境，无悬浮人设
   - [ ] 合规红线：无具体产品推荐/收益承诺/荐股/敏感话题
   - [ ] 平衡性：坏回应示范只用于"对照"，不教坏
   - [ ] 情绪安全：不羞辱、不评判人格、不诱发焦虑
4. **护栏自动验收**：模拟策略（每原则的优/劣回应）× N 局跑校验脚本，统计识别准确率；任何新场景不得拉低全局识别准确率（护栏参数化，上线后用真实数据校准——迁移 sim.js 难度曲线护栏思想）

## 7. 合规与风控清单（沿用 + 新增）

1. **小程序类目**：教育/知识服务 vs 工具——避开"小游戏"（版号）；需 Phase 0 确认 AI 对话类目限制
2. **生成式 AI 备案**：对话内容生成是否触发算法备案要求（Phase 0 查口径）
3. **内容安全**：出入双向过滤；提示词内置红线；审核重点抽查教练点评与角色回应
4. **不教坏原则**：接话训练只教"善意接球"，禁止教操控/话术套路（与产品价值观一致，也是合规线）
5. **隐私**：对话数据归属、未成年人保护（如适用）、删除机制
6. **免责与边界**：明确"沟通教练非心理咨询"，涉及抑郁/暴力等高风险表述自动引导求助渠道
