# 交互、反馈与恢复规范

## 1. 手势定义

| 手势 | 识别阈值 | 适用场景 | 反馈与限制 |
| --- | --- | --- | --- |
| 点击 | 按下至抬起小于 `200ms`，移动小于 `10px` | 选择、跳转、确认、开关 | 按下 `100ms` 内必须有视觉反馈；不可用项说明原因 |
| 长按 | 按住大于 `500ms` | 预览、更多操作、多选 | 触发前可显示进度圈；触发后轻触感并打开菜单或编辑态 |
| 拖动 / 滑动 | 位移大于 `30px` | 列表滚动、滑条、侧滑操作 | 跟随手指；列表项侧滑不与全页返回手势冲突 |
| 双击 | 两次点击间隔小于 `300ms` | 放大、快捷标记等明确能力 | 必须有替代操作，不能把核心能力藏在双击中 |
| 捏合 | 双指距离持续变化 | 图片、地图、画布 | 实时缩放，提供最小、最大与复位方式 |
| 下拉刷新 | 顶部越界大于 `60px` 后释放 | 可更新的列表、动态内容 | 仅在滚动顶部触发；刷新中不可重复触发 |

任何关键操作必须存在显式控件。复杂手势首次出现时给出可关闭的短引导；手势不应劫持系统返回、截图、缩放等平台行为。

## 2. L1-L4 反馈层级

| 层级 | 时机 | 表现 | 要求 |
| --- | --- | --- | --- |
| L1 即时反馈 | 指针按下后 `100ms` 内 | 按下态、描边、缩放、选中高亮 | 确认系统已接收操作，不等待网络结果 |
| L2 触感反馈 | 关键确认、进入编辑、达成节点 | 轻 `10ms` 或重 `20ms` 触感 | 可在设置中关闭；不用于每次滚动或连续点击 |
| L3 声音反馈 | 可识别的完成、失败、切换 | 短音效 | 不能作为唯一反馈；尊重静音设置 |
| L4 结果反馈 | 状态实际变更后 `200ms` 内 | 原位更新、数量变化、Toast、状态条、弹层 | 明确成功、失败或等待；不让用户猜测结果 |

反馈按需要叠加，不要求每个操作四层全用。高频、低风险操作通常使用 L1 和 L4；高影响操作可增加 L2 或 L3。

## 3. 点击、提交与重复操作

1. 点击按钮后立即显示 Pressed；发起异步操作后切换为 Loading，直至成功、失败或取消。
2. 同一请求的重复点击必须被合并或阻止。禁止通过多次叠加 Toast 表示已收到多次操作。
3. 操作成功后优先原位更新来源组件，必要时再显示简短反馈；不要用整页刷新替代局部更新。
4. 操作失败时保留用户已输入内容和来源页面，上报可理解原因，并给出重试、修改或返回之一。
5. 涉及删除、覆盖、消耗或不可逆结果时，危险操作采用二次确认；确认文案描述结果而不是使用模糊的“确定”。

## 4. 导航、页面栈与关闭

| 场景 | 进入方式 | 返回 / 关闭规则 |
| --- | --- | --- |
| 同级内容 | 底部导航、标签、分段切换 | 直接切换；保留各页自身滚动和筛选状态 |
| 列表到详情 | 横向进入或共享层级转场 | 返回列表原位置，不重置筛选和排序 |
| 详情到复杂选择 | 全屏页或内容弹层 | 完成后回传结果；取消不修改来源状态 |
| 确认弹窗 | 遮罩与居中弹出 | 关闭、取消、系统返回遵循同一结果；危险操作不可点遮罩结束 |
| Tooltip / Toast | 就地显示 | 点外部、超时或目标消失后关闭；不影响页面栈 |

- 页面栈最多五层；超过时关闭中间临时页或回到稳定入口。
- 优先关闭顺序为：Tips -> 下拉浮层 -> 内容弹窗 -> 确认弹窗 -> 当前页面。
- 离开有未保存输入的页面时显示明确确认；自动保存时要给出已保存状态。

## 5. 加载、弱网与恢复

### 5.1 加载节奏

| 等待时间 | 表现 |
| --- | --- |
| `0-300ms` | 保留既有内容或使用原位骨架，不闪烁整页加载。 |
| `300-800ms` | 显示局部骨架、加载点或按钮 Loading，不阻断可继续浏览的内容。 |
| 超过 `800ms` | 对关键任务显示可读的“正在处理”状态，阻止重复提交。 |
| 超过 `5s` | 提示网络或服务异常，可取消、重试或返回；不无限循环。 |

### 5.2 网络失败与恢复

1. 可安全重试的读取请求最多自动尝试 3 次，间隔为 `1s / 2s / 4s`；用户主动重试从第一档开始。
2. 断线时保留已展示内容和用户输入，用非阻塞状态条提示；不要每次断线都弹窗。
3. 重新连接后只刷新可能过期的数据，并维持当前页面、筛选、滚动和选择上下文。
4. 提交结果未知时，显示“正在确认结果”，禁止用户再次提交；确认失败后提供查询状态或重试途径。
5. 从后台回到前台后检查必要状态；若内容已改变，使用局部刷新提示而不是强制跳回首页。

## 6. 状态切换规则

| 变化 | 正确处理 | 禁止处理 |
| --- | --- | --- |
| Loading -> Content | 原位替换骨架，保持容器高度 | 清空页面后再整体闪现 |
| Content -> Empty | 解释为什么为空，并给出相关下一步 | 用错误文案替代空状态 |
| Content -> Error | 保留仍可用内容，仅在失败区域展示错误 | 删除所有已读信息 |
| Available -> Locked | 标出条件并在触发处说明 | 静默禁用，没有任何原因 |
| Available -> Full | 显示当前值 / 上限和管理入口 | 仅显示“无法操作” |
| 在线 -> 断线 -> 恢复 | 非阻塞提醒，刷新必要数据 | 中断用户填写、直接丢弃上下文 |

## 7. 动效与无障碍补充

- 按下、切换、页面、弹层的时长遵循设计总则，不使用超过 `500ms` 的常规交互动画。
- 动效只改变透明度、位移、缩放或表面状态，不让文字在移动中难以阅读。
- 同一屏持续动效不超过三处；自动滚动信息须可暂停或关闭。
- 状态色以外，使用图标、文案、描边或位置表达成功、提醒、错误和锁定。
- 触控热区可大于视觉外框；相邻热区至少保持 `16px` 间隔，避免误触。

## 8. 交互验收清单

1. 所有可点击元素在 `100ms` 内给出 L1 反馈，且禁用、锁定状态原因清楚。
2. 每个提交路径都有加载、成功、失败、重复提交和结果未知的处理。
3. 返回、关闭、取消与系统返回符合页面栈优先级，不误丢输入或选择。
4. 手势有阈值、替代入口和首次引导，不与系统行为冲突。
5. 弱网、断线、重连、回到前台和维护状态均能恢复到可继续完成任务的位置。
