# 工程资源命名与导出规范

> 来源：用户补充的资源出图规则截图 + `design-system.md` 资源管理章节  
> 适用范围：图标、组件图片、页面媒体、可拉伸背景、字体与工程交接清单。

## 1. 出图总原则

1. 所有切图长宽优先使用 `2^N` 尺寸，例如 `64`、`128`、`256`、`512`。
2. 如因工程限制必须使用非 `2^N` 尺寸，长宽至少必须能被 `4` 整除，并在资源清单中说明原因。
3. 常规图标输出固定使用 `64 x 64`、`128 x 128`、`256 x 256` 三档，根据实际使用场景选择。
4. 图标主体必须放在安全区内，并在安全区内保持视觉居中。
5. 横向或纵向至少有一个轴向应撑满安全区，避免图标主体过小、显得松散。

## 2. 常规图标输出尺寸

| 输出尺寸 | 安全区 | 单边留白 | 推荐用途 |
| --- | --- | ---: | --- |
| `64 x 64` | `60 x 60` | `2px` | 小图标、角标、列表辅助图标、功能入口小状态。 |
| `128 x 128` | `112 x 112` | `8px` | 常规功能图标、道具图标、技能图标。 |
| `256 x 256` | `224 x 224` | `16px` | 高精度道具、头像、奖励展示图标、商店展示图。 |

安全区是图标主体的摆放范围，不是必须填满颜色的区域。透明留白、轻微阴影和外发光可以存在，但关键轮廓不得贴近画布边缘。

## 3. 主体摆放规则

| 项目 | 规则 |
| --- | --- |
| 位置 | 主体在安全区内居中摆放。 |
| 尺寸 | 横向或纵向至少一个轴向撑满安全区。 |
| 留白 | 不允许主体贴边；留白按输出尺寸对应安全区控制。 |
| 阴影 / 外发光 | 可以延伸到安全区外，但不得被画布裁切。 |
| 非方形主体 | 以最长边撑满安全区，短边按视觉重心居中。 |
| 组合图标 | 主体优先，角标、数字、品质框不得挤占主体识别区。 |

## 4. 图标命名

格式：

```text
ui_<模块>_<名称>_<状态>_<尺寸>@<倍率>.<扩展名>
```

示例：

```text
ui_bag_elixir_default_128@2x.png
ui_skill_thunder_locked_128@2x.png
ui_reward_chest_selected_256@2x.png
ui_nav_shop_reddot_64@2x.png
```

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `ui` | UI 资源前缀 | `ui` |
| `<模块>` | 所属系统或页面 | `bag`、`skill`、`reward`、`nav` |
| `<名称>` | 资源语义名称 | `elixir`、`thunder`、`chest` |
| `<状态>` | 当前状态 | `default`、`pressed`、`selected`、`disabled`、`locked` |
| `<尺寸>` | 输出画布尺寸 | `64`、`128`、`256` |
| `<倍率>` | 工程倍率 | `1x`、`2x`、`3x` |

状态词必须与 `component-spec.md` 的状态矩阵一致，不使用同义词混写。

## 5. 组件图片命名

格式：

```text
ui_<模块>_<组件>_<变体>_<状态>_<宽>x<高>@<倍率>.<扩展名>
```

示例：

```text
ui_action_button_primary_default_360x104@2x.png
ui_overlay_dialog_confirm_default_840xauto@2x.png
ui_card_item_selected_231x320@2x.png
```

组件图片必须说明是否可拉伸。可拉伸背景优先使用 `.9.png`，并在交付清单中标注拉伸区域、内容安全区和不可拉伸边框。

## 6. 页面媒体命名

格式：

```text
page_<页面>_<区域>_<用途>_<宽>x<高>@<倍率>.<扩展名>
```

示例：

```text
page_home_bg_default_1080x1920@2x.png
page_result_hero_success_720x480@2x.png
page_shop_banner_event_984x320@2x.png
```

页面媒体不直接替代组件。若一个图形会在多个页面复用，应拆为 `ui_` 组件资源。

### 6.1 资源包命名规则（`sp_`）

使用资源包命名的项目，文件由前缀、类型、所属功能、描述和后缀依次拼接。字段为 `/` 时表示该字段按实际需要省略，不保留空字段或占位下划线；同一项目不得混用 `ui_`、`page_` 与 `sp_` 三套前缀规则。

| 资源示例 | 前缀 | 类型 | 所属功能 | 描述 | 后缀 | 最终输出 |
| --- | --- | --- | --- | --- | --- | --- |
| 装备图标 | `sp` | `_icon` | `_equipe` | `/` | `_001` | `sp_icon_equipe_001` |
| 页签 | `sp` | `_tab` | `_alliance` | `_on` / `_still` / `_disable` | `/` | `sp_tab_alliance_on` |
| 按钮 | `sp` | `_btn` | `_alliance` | `_add` | `/` | `sp_btn_alliance_add` |
| 全屏背景大图 | `sp` | `_base` | `_alliance` | `/` | `_ignore` | `sp_base_alliance_ignore` |
| 非全屏背景 | `sp` | `_base` | `_mail` | `_mainbg` | `/` | `sp_base_mail_mainbg` |
| Buff | `sp` | `_buf` | `_battle` | `_powerup` | `/` | `sp_buf_battle_powerup` |
| 图片 | `sp` | `_pic` | `_mail` | `_activitytheme` | `/` | `sp_pic_mail_activitytheme` |
| Banner | `sp` | `_banner` | `_mail` | `_activitytheme` | `/` | `sp_banner_mail_activitytheme` |
| 普通单个图标 | `sp` | `_icon` | `_mail` | `_title` | `/` | `sp_icon_mail_title` |

类型、功能、描述均使用小写英文语义词；同一资源的状态词沿用 `default`、`pressed`、`selected`、`disabled`、`locked` 等既定状态命名，不用同义词混写。

**通用资源补充**：以下词组用于通用模块；与上表同名字段含义一致。

| 资源示例 | 前缀 | 类型 | 所属功能 | 描述 | 后缀 | 最终输出 |
| --- | --- | --- | --- | --- | --- | --- |
| 道具 | `sp` | `_icon` | `_item` | `/` | `_001` | `sp_icon_item_001` |
| 弹窗 | `sp` | `_base` | `_common` | `_dlg` | `_info` | `sp_base_common_dlg_info` |
| 背景 | `sp` | `_base` | `_mail` | `_mainbg` | `/` | `sp_base_mail_mainbg` |
| 页签 | `sp` | `_tab` | `_common` | `_first` / `_second` / `_third` | `/` | `sp_tab_common_first` |

### 6.2 通用按钮命名

通用按钮使用 `sp_btn_<用途代号>_nml_<尺寸>` 格式。`nml` 表示普通按钮样式；若存在非普通视觉变体，应以清晰语义词替换，不额外复用用途代号表达状态。

| 按钮用途 | 前缀 | 类型 | 用途代号 | 描述 | 尺寸后缀 | 最终输出 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通 | `sp` | `_btn` | `_a` | `_nml` | `_big` / `_middle` / `_small` | `sp_btn_a_nml_big` |
| 引导点击 | `sp` | `_btn` | `_b` | `_nml` | `_big` / `_middle` / `_small` | `sp_btn_b_nml_big` |
| 警示 | `sp` | `_btn` | `_c` | `_nml` | `_big` / `_middle` / `_small` | `sp_btn_c_nml_big` |
| 付费 | `sp` | `_btn` | `_d` | `_nml` | `_big` / `_middle` / `_small` | `sp_btn_d_nml_big` |
| 置灰 | `sp` | `_btn` | `_g` | `_nml` | `_big` / `_middle` / `_small` | `sp_btn_g_nml_big` |

同一功能的按钮尺寸仅使用 `big`、`middle`、`small` 三档。`_g` 是置灰按钮美术资源的用途代号；组件交互状态仍使用 `disabled`，两者不在同一文件名中重复叠加，也不使用 `grey`、`gray` 等同义后缀。

### 6.3 类型词典

| 资源类别 | 类型码 | 用途 |
| --- | --- | --- |
| 背景 | `_base` | 页面、弹窗、模块或全屏背景底图。 |
| 按钮 | `_btn` | 可点击操作按钮。 |
| 图标 | `_icon` | 道具、功能、状态与独立小图标。 |
| 文字 | `_txt` | 已烘焙的美术文字图。 |
| 技能 | `_skill` | 技能图标、技能展示资源。 |
| 头像 | `_photo` | 玩家、角色或 NPC 头像。 |
| 进度条 | `_bar` | 进度、血量、经验等条形资源。 |

### 6.4 多语言后缀

包含烘焙文字的图片、Banner、按钮字图和活动主题图，需要在完整资源名末尾追加地区或平台后缀。该后缀位于用途、状态、尺寸等业务字段之后，扩展名之前；不含文字的通用图标和背景不重复导出多语言版本。

| 地区 / 平台 | 后缀 |
| --- | --- |
| 微信 | `_wx` |
| 意大利 | `_it` |
| 葡萄牙 | `_po` |
| 西班牙 | `_sp` |
| 英语地区 | `_en` |
| 法语 | `_fr` |
| 德语 | `_ge` |
| 中文 | `_cn`（默认不加，仅在需要与其他中文变体区分时使用） |

示例：

```text
sp_pic_mail_activitytheme_en.png
sp_banner_mail_activitytheme_fr.png
sp_btn_a_nml_big_ge.png
sp_tab_common_first_wx.png
```

1. 中文为默认资源，命名中默认省略 `_cn`；仅当同批资源同时存在简体、繁体或渠道专属中文版本时，才使用 `_cn` 明确区分。
2. 资源已有业务后缀时，多语言后缀必须追加在最后，例如 `sp_base_common_dlg_info_en.png`，不得插入类型、功能或描述字段中间。
3. 同一资源的全部语言版本必须使用相同画布尺寸、安全区、透明边与导出倍率；仅替换文字内容和因文字长度产生的必要排版调整。

## 7. 全屏背景出图

全屏背景按独立资源画布导出，不按 `1080 x 1920` 页面设计稿裁切。默认输出尺寸为 `1334 x 1750`，以画布中心点对齐；背景主体、场景焦点和不可被 UI 遮挡的关键视觉信息必须限制在居中的 `1334 x 750` 核心内容区内。

| 项目 | 规格 | 说明 |
| --- | --- | --- |
| 输出画布 | `1334 x 1750` | 全屏背景的固定导出尺寸。 |
| 对齐方式 | 中心点对齐 | 适配时以画布中心为基准，不以顶部或底部单边对齐。 |
| 核心内容区 | 居中 `1334 x 750` | 角色、建筑主体、标题留白、关键装饰和叙事焦点均放在此区域。 |
| 上下延展区 | 核心区以外区域 | 仅承载可裁切、可延展的天空、地面、纹理、远景或弱装饰。 |
| 左右边界 | 与画布同宽 `1334` | 不额外预留横向裁切区；边缘不放置需要完整识别的元素。 |

1. 核心内容区在画布中水平、垂直居中，坐标范围为：`x: 0-1334`、`y: 500-1250`。
2. 核心内容区外的上下区域必须可被裁切，不得放置角色脸部、主体轮廓、可读文本、按钮底图、奖励物或关键剧情信息。
3. 背景主体可延伸到核心区外，但其视觉重心必须落在核心区内；需要与 HUD、底部导航或弹窗共存时，应为对应 UI 预留干净背景。
4. 导出前按中心裁切检查 `1334 x 750` 范围：即使只保留该区域，仍应能识别场景主题和主要信息层级。
5. 全屏背景必须带 `_ignore` 后缀，避免被程序压缩；资源包命名使用 `sp_base_<功能>_ignore`，例如 `sp_base_alliance_ignore`。使用通用页面媒体命名的项目，也必须保留该后缀，例如 `page_home_bg_ignore_1334x1750@2x.png`。

## 8. 导出倍率

| 倍率 | 用途 |
| --- | --- |
| `@1x` | 低内存、编辑预览、部分工程基准资源。 |
| `@2x` | 默认交付倍率。 |
| `@3x` | 高精度展示、头像、奖励展示、高清设备。 |

同一批资源必须使用统一倍率策略。若只交付 `@2x`，需要在资源清单中说明工程端缩放策略。

## 9. 状态图交付

| 状态 | 是否建议出图 | 说明 |
| --- | --- | --- |
| `default` | 必须 | 默认可见状态。 |
| `pressed` | 按需 | 若可由材质、描边或透明度程序化实现，可不单独切图。 |
| `selected` | 必须 | 选中态需要明确边框、底色或角标。 |
| `disabled` | 按需 | 若统一灰度策略可程序化，不单独切图。 |
| `locked` | 必须 | 需包含锁图标或遮罩规则。 |
| `loading` | 按需 | 骨架、转圈、占位可由组件实现。 |
| `error` | 按需 | 状态色和图标组合应可复用。 |
| `full` | 按需 | 容量类组件需要明确满容量表现。 |

若某状态不单独出图，必须在交付说明中写明由工程如何实现。

## 10. 交付清单

每批资源交付时至少包含：

1. 资源文件夹。
2. 资源清单表，包含文件名、尺寸、倍率、状态、用途、来源页面。
3. 安全区说明，尤其是 `64`、`128`、`256` 图标安全区。
4. 全屏背景的 `1334 x 1750` 画布与居中 `1334 x 750` 核心内容区标注。
5. 可拉伸资源的拉伸区域和内容安全区标注。
6. 字体文件、字重、授权状态和应用层级。
7. 废弃或替换说明，确保旧资源可追溯。

## 11. 禁止项

- 不输出任意奇数尺寸图标。
- 不把图标主体贴到画布边缘。
- 不用 `icon1.png`、`new.png`、`final.png` 这类不可追溯命名。
- 不在同一批资源中混用 `selected`、`select`、`active` 表达同一状态。
- 不用放大低分辨率资源冒充高倍率资源。
- 不把全屏背景的主体、可读文字或关键剧情信息放在 `1334 x 750` 核心内容区外。
- 不省略全屏背景的 `_ignore` 后缀，避免程序压缩导致背景资源失真。
