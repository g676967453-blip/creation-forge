# [2026-08-07] 本周AI如何做游戏设计系统踩坑记录

> 来源：交互规范系统 v1.0→v2.0 + TREA/Codex/Claude 多 Agent 协作实录

## 一句话总结

让AI做游戏设计系统，换了三个Agent、踩了四个坑，最后发现：AI能帮你跑周全，但「周全的方向」得你自己先想清楚。

---

## 一、目标是什么

为「交互设计规范」项目建立一套**游戏设计系统**，初衷很简单：

- 统一策划案原型图的基础设计规范
- 为后续「原型图 → 效果图」做衔接
- 最终产出可分发、可生产的设计系统交付物

不是做一套好看的设计文档——是要能直接用于下一张界面生产的工具。

---

## 二、坑是什么

### 坑1：我又犯了——期望AI一口气给周全

第一反应：「帮我做一套游戏设计系统」。AI确实给了一份很周全的东西——717行HTML预览页，什么都有。但美术和开发都不看。

不是因为内容少，是因为**没有先定义边界**。我要的是游戏HUD规范，AI给的是APP页面规范。方向错了，越周全越没用。

### 坑2：AI默认输出的是APP设计系统

让AI做设计系统，它天然偏向APP模式：

| APP设计系统 | 游戏设计系统 |
|------------|------------|
| 品牌色 | 稀有度色阶（白/绿/蓝/紫/橙） |
| 操作按钮（确认/取消） | 游戏按钮（升级/升星/领取/前往） |
| 页面跳转流 | HUD叠层 + 弹窗 |
| 列表 + Tab | 卡牌网格 + 底部导航 |

AI不是不聪明——是训练数据里APP比游戏多100倍，它默认走熟路。

### 坑3：多Agent切换，理解断层

一周内换了三个Agent做同一个设计系统：

- **TREA**：理解游戏设计系统的需求，给得比较周全，但视觉产出弱
- **Codex**：HTML视觉效果出彩，但理解不够周全，偏向APP设计系统
- **Claude**：最终统一基线，拆成三份交付物

每个Agent擅长的东西不一样。换AI不能换方向，但我一开始没有明确的基线文档给下一个Agent看。

### 坑4：先做HTML后写MD，顺序反了

一开始直接让AI生成HTML——好看，但结构是散的。后面才反过来：**先MD定义结构和边界，再HTML设定排版与视觉**。顺序一换，效率完全不同。

---

## 三、反思什么

### 反思1：期望管理——AI不能替你「想清楚」

「帮我做一套设计系统」这句话包含了100个未说出口的决策。AI会替你填满这些空白——但填的方向不一定是你要的。**定义边界这件事，省不了。**

### 反思2：多AI脑暴——各取所长，合并周全

单个Agent有盲区，但三个Agent各跑一遍，不同视角拼起来就更周全：
- TREA 周全度 ✓ | 视觉 ✗
- Codex 视觉 ✓ | 理解深度 ✗
- Claude 统一 ✓

不是「哪个Agent更强」，是**怎么组合他们的长处**。

### 反思3：MD先于HTML——结构清晰了，视觉才有根

```
❌ 直接写HTML → 好看但结构散
✅ 先MD定义边界和结构 → 再HTML排版 → 锁定基线
```

### 反思4：游戏设计系统 ≠ APP设计系统

下次让AI做游戏设计系统，第一句话不是「帮我做设计系统」，而是：

> 「这是游戏UI设计系统，不是APP——用稀有度色阶替代品牌色，用HUD叠层替代页面流，用升级按钮替代操作按钮。」
