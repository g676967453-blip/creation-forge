# 2026-07-29 功能策划案 HTML 模板 — 从零设计到半成品固化

---

## 📋 问题解决日志

### 遇到了什么

项目缺少统一的策划案文档格式。之前有 `功能开发-流水线.md`（4 阶段 Markdown），但流程太重，一份功能要产出 4 份文档。需要一个轻量的一站式替代方案。

### AI 怎么协作的

1. **起手**：用户说「测试功能开发工作流」，AI 读了现有 `功能开发-流水线.md` 和 `独立游戏-功能开发流程-v0.1.md`，提出了精简版方案。

2. **迭代 1 — 结构定型**：用户要求「一份 HTML = 完整策划案」，包含 4 区（简介/规则/流程图/资产需求）。AI 做了第一版 HTML 模板。

3. **迭代 2 — 页签化**：用户要求改为一级 tab 结构（功能简介/功能规则/流程图/资产需求），资产需求下含 5 个二级 tab（UI/原画/动作/特效/3D）。AI 重构为 tab 切换式。

4. **迭代 3 — 参考对齐**：用户提供「五一首冲活动」Excel 导出的 HTML 作为功能规则的写法参考，另有截图说明界面说明的「左图右文」格式。AI 把功能规则改为 Excel 层级格式（● 绿色底线 → 一./1./1）/① 缩进 → 示意：举例），界面说明改为 16:9 原型框 + 编号锚点。

5. **迭代 4 — 动态交互**：用户要求增加「动态交互」tab 做可点击的功能模拟，并指出缺少「入场→退场」的动画演示。AI 加了完整状态机（idle → showing → selecting → done）。

6. **迭代 5 — 界面说明优化**：用户指出右侧说明应该写「功能效果/规则/多种状态」，不写美术数值；左侧需要编号标注点。AI 修改了说明内容和标注方式。

7. **实例验证**：用「天赋卡选择界面」和「卡牌背包」两个功能走了一遍模板，验证可用性。

8. **固化**：更新流程定义文档，标注为「半成品」，列出已知待改进项，更新工作流 README。

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：游戏策划案怎么写才能同时服务人类阅读和 AI/程序提取？
- 为什么这是个问题：传统 Markdown 策划案要么是散落的多个文件，要么格式不统一，程序拿不到结构化数据
- 如果没有 AI 会怎样：策划写 Word/Excel → 程序手动翻文档找数据 → 美术再问一遍需求 → 信息传递损耗

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「把功能流程定义简化」「参考这个 Excel 的写法」「界面说明要左图右文」「动态交互要有入场和退场动画」
- AI 给了什么方案：一个自包含的 HTML 文件，5 个 tab 页签，CSS 变量做设计 token，JS 做动态交互，`<meta>` 和 `<script type="application/json">` 做机器可读标记
- 中间有什么调整/追问：反复调整了 5 轮——从结构到写法到交互细节到标注方式
- 最终方案是什么：一份 HTML = 简介/规则/界面说明/动态交互/资产需求，浏览器打开即可预览，AI 可解析结构化数据

### 第三幕：效果展示

- 最终效果：复制模板 → AI 协作填充 → 浏览器打开 → 5 个 tab 可切 → 动态交互可点击演示
- 演示方式：直接打开 HTML 文件截图
- 学到的关键点：格式越简单越容易被采纳——Excel 层级写法比 Markdown 卡片更适合策划的思维习惯

### 一句话总结（金句候选）

> 一份 HTML 就是一份策划案——人看得懂，机器读得动。
