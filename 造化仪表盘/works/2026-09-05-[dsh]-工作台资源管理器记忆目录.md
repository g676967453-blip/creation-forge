# [2026-09-05] 工作台资源管理器：记住每个窗口上次浏览的目录

> 📌 本文件存放于 `造化仪表盘/works/`；文件名 = `YYYY-MM-DD-[dsh]-简述.md`。

## 📋 问题解决日志

### 遇到了什么

用户反馈：工作台（dsh-worktable 插件）里「资源管理器」窗口输入的地址「被锁定」——即使换到其他地址，切换窗口/页面后再回来，就会还原到默认地址（当前会话/项目的默认目录）。

根因：资源管理器是内置窗（`ExplorerPane`），其当前目录只存在组件本地 state（`rootPath`/`pathDraft`），窗口切换导致组件卸载重挂时 `initRoot()` 一律用会话 cwd 重新初始化，用户上次浏览的目录没有持久化，也没有恢复逻辑。

### AI 怎么协作的

1. 先向用户确认目标（工作台内置资源管理器、期望「记忆上次目录」而非「固定某个默认地址」）。
2. 定位到运行中的 GUI 加载的是 desktop profile 的 `dsh-worktable`（repo 内 `造化仪表盘/tools/dsh-harness/plugins/dsh-worktable` 的 lib 与之字节一致，为当前权威构建；注意 repo 的 `src/` 比 lib 旧，不能直接重 build）。
3. 在编译版客户端 `lib/client.js` 的 `ExplorerPane` 内加入最小改动：
   - 新增按「会话目录 | 布局 id | 窗行 | 窗位」生成的内存 key + `readMemPath`/`writeMemPath`（localStorage）；
   - `initRoot()` 挂载时先尝试恢复上次记忆目录（先向 `/api/worktable/fs` 校验仍存在，失败则回退默认 cwd）；
   - `rootPath` 每次变化（地址栏回车/前往/上一级/刷新成功）时写回记忆。
4. 用 `node --check` 校验语法；将修补后的 `lib/client.js` 同步到三处（repo 权威构建、`~/.dsh/plugins-cache`、desktop profile 的 node_modules），哈希一致。

### 产出结果

- `造化仪表盘/tools/dsh-harness/plugins/dsh-worktable/lib/client.js`：ExplorerPane 增加目录记忆（会话目录+布局+窗位为 key 的 localStorage 持久化 + 挂载恢复 + 变更回写）
- 同步副本：`~/.dsh/plugins-cache/dsh-worktable/lib/client.js`、`~/.dsh/profiles/desktop/node_modules/dsh-worktable/lib/client.js`
- 生效方式：重启 DSH Desktop（或工作台页面强刷）后，资源管理器切换窗口/页面回来会停留在上次浏览的目录

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：工作台资源管理器每次切窗口回来都跳回默认目录，用户输入的地址不保留
- 为什么这是个问题：多窗口并行查看项目文件时，每次都要重新导航，频繁打断工作流
- 如果没有 AI 会怎样：得去读 dsh-worktable 的客户端源码找组件状态生命周期，自己改还得自己打包同步

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「工作台资源管理器输入的地址被锁定、切页面后被还原到默认地址」
- AI 给了什么方案：确认需求（记忆上次目录）→ 定位 ExplorerPane 本地 state 无持久化 → 补 localStorage 记忆 + 挂载恢复
- 中间有什么调整/追问：确认目标是内置「资源管理器」窗且期望记忆目录；确认运行实例对应的构建副本（desktop profile，非 web profile）
- 最终方案是什么：编译版 client 内 ExplorerPane 增加按窗位 key 的目录记忆，恢复前校验目录仍存在，语法校验后同步到三处副本

### 第三幕：效果展示

- 最终效果：切换窗口/页面回来，资源管理器停留在上次浏览的目录
- 学到的关键点：改「运行中插件的编译产物」要同步全部加载副本（repo/plugins-cache/profile），且要认清 repo src 可能落后于 lib，不能盲目重 build

### 一句话总结（金句候选）

> 用户记住目录，工作台才记得住窗口——状态该持久化的别只留在组件里。
