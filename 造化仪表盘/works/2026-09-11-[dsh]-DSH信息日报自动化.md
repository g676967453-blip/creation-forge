# [2026-09-11] DSH 信息日报：首期基线 + 每工作日自动推送

> 📌 本文件存放于 `造化仪表盘/works/`；产出见 [reports/dsh-daily/](../reports/dsh-daily/README.md) 与 [tools/dsh-report/](../tools/dsh-report/)

## 📋 问题解决日志

### 遇到了什么

用户要两件事：(1) 一份 DSH 当前版本 / 模型版本 / 基础信息汇报；(2) 之后要**定期**把网络上 DSH 相关信息收缩成「偏向怎么用」的内容推给他，辅助他用 DSH 完成工作。

难点不在写报告，而在**「定期」怎么落地**：

- DSH 自带的 `@deepseek-ai/dsh-schedule` 插件只能做**会话内**提醒（官方 README 明确 session-local delivery only，冷会话无外部通知，且只支持固定间隔、无日历规则）—— 做不到「每工作日 09:00」；
- PowerShell 的 `Invoke-RestMethod` 在本机连 `registry.npmjs.org` 直接 TLS 失败，但 Node 原生 `fetch` 正常 —— 联网采集必须走 Node；
- 仓库根没有 `package.json`，也**没有** `markdown-it`，且板块1 明令禁止 `npm i` —— Markdown→HTML 只能自写子集渲染；
- headless 无人值守时默认 `workspace-write` 且**没有审批人**，报告只能写仓库内路径。

### AI 怎么协作的

1. **先勘察再设计**：动手前把「DSH 版本、模型、profile、插件、沙箱策略、可用 profile 模板、仪表盘静态服务、根依赖」逐项查实，发现 `dashboard-server.ts` 已经 `app.use("/board", express.static(REPORTS_DIR))` —— 于是**零改动**就能让日报出现在 `http://127.0.0.1:3456/board/dsh-daily/`，砍掉了一整块服务器改造。
2. **用问题收拢用户选择权**：把「推送渠道 / 自动化方式 / 内容位置」三个只有用户能拍板的点一次性问清，得到：本地文件+仪表盘网页、每工作日 09:00 自动、`reports/dsh-daily/`。
3. **分层设计，硬事实与联网内容解耦**：采集器（Node，零依赖）确定性产出环境快照，断网也出报告；headless 只负责「动态」和「怎么用」。这让日报不会因为一次网络抖动变成空白。
4. **升级建议不吹不黑**：采集器发现 `dsh-worktable` 本地 0.3.0、上游 0.3.3，但**仓库里是本地优化版**（自加了可编辑地址栏、右键文件操作等），且上游 0.3.3 只声明测过 DSH 0.1.2-rc.1、**没有**声明兼容本机的 0.1.5-rc.1 —— 报告里明确写出这两条风险，而不是甩一句「建议升级」。
5. **机器边界如实反馈**：计划任务注册被 Windows 拒绝（连最小 `schtasks /create` 都是 Access is denied），没有硬撑，改为补一条**零权限的登录自启**方案，并保留计划任务脚本供提权后使用。
6. **让自动跑出来的第一期反过来审自己的工具链**：09-11 那期由 headless 全自动生成，它在报告里指出「提示词让模型把正文写回 `_data/<日期>.prompt.md` 而不是日报路径」—— 回去查证属实（两个文件都是 12339 字节），已修。

### 产出结果

- `造化仪表盘/tools/dsh-report/` —— 采集器 `collect-dsh-env.mjs`、渲染器 `render-dsh-daily.mjs`、模板 `report-template.md`、编排 `run-dsh-daily.ps1`、挂载 `register-dsh-daily-task.ps1`

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

想让 AI 每天早上把「DSH 更新了什么、跟我有什么关系」送到眼前，但发现：自带的定时插件只能在自己开着聊天窗口时提醒；换个机器就全废；想省 token 又想拿到真信息。

- 核心问题：AI 工具的「情报」要不要人肉去追？
- 为什么这是个问题：版本、模型、插件兼容性散落在 GitHub Releases、npm、本地配置、插件仓库四处，追一次十分钟，追完就忘。
- 如果没有 AI 会怎样：每个版本更新靠刷到别人的帖才知道，插件升级踩坑靠自己踩。

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「针对 deepseek HARNESS 做定期的信息日报……偏向使用信息，辅助我更好的用 DSH 完成我的工作范围事。」
- AI 给了什么方案：先勘察（发现 `/board/` 静态服务可白嫖）→ 问清三个选择 → 硬事实与联网内容解耦 → 三级兜底。
- 中间有什么调整/追问：AI 发现计划任务被系统拒绝，没有硬来，改加了登录自启；自动生成的第一期**反过来报了工具链自己的 bug**。
- 最终方案是什么：Node 采集器 + headless 整理 + 自写渲染器 + 双挂载（计划任务/登录自启）。

### 第三幕：效果展示

- 最终效果：`http://127.0.0.1:3456/board/dsh-daily/` 每天一份，含环境快照、更新提醒、上游动态、使用技巧。
- 演示方式（截图/GIF/屏幕录制）：仪表盘入口条「🧪 DSH 日报」→ 打开日报网页；`register-dsh-daily-task.ps1 -Action status` 的执行结果。
- 学到的关键点：**让自动化跑第一期，然后用它来审自己的工具链**——这是最省力的验收。

### 一句话总结（金句候选）

> 与其每天追版本号，不如让 AI 把它变成早上的一份报纸。
