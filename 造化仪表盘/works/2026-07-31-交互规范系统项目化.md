## 📋 问题解决日志

### 遇到了什么

交互规范生成系统 v1.0 的核心资产（规范文档、工具链、技能包）分散在 `docs/specs/`、`tools/`、`.claude/skills/` 三处，没有作为正式项目管理。同时 HTML 展示图存在大量 1x 逻辑像素与 720 画布（约 2x）之间的缩放错误——胶囊、热区、触控目标、文字标签全部偏小一倍。

### AI 怎么协作的

**第一阶段：项目化迁移**

1. 探索全部文件依赖关系（45 次文件读取），确认 import 路径、硬编码引用、npm 脚本
2. 创建 `projects/interaction-spec-system/` 统一项目目录，迁移 20 个文件（7 规范 + 3 工具 + 8 技能 + README）
3. 全局更新 8 处路径引用（`package.json`、`CLAUDE.md`、工作流文档、技能文件）
4. 修复 `build-interaction-spec.ts` 的 ROOT 路径深度变化
5. 仪表盘注册新项目，数据采集脚本新增 project/assets 条目

**第二阶段：切页（Tab）改造**

1. 分析 19 个章节的逻辑分组，设计 5 页签体系：基础信息/视觉规范/布局组件/交互反馈/交付标准
2. 重构 `renderHTML()`——新增 sticky 页签导航 CSS + 原生 JS 切换（支持 URL hash）+ 5 组 tab-panel
3. MD 文件不做任何修改（渲染器是内容唯一控制点）

**第三阶段：展示数据全面审计与修正**

核心发现：渲染器大量使用 1x 逻辑像素值（iPhone 375×812 基准），但设计画布是 720×1280（约 1.92x），导致展示图所有元素偏小约一倍。

修正清单（共 12 项）：

| 类型 | 修正项 | 原值（1x） | 修正方式 |
|------|--------|:--:|------|
| 显示 | 手机框大小 | 375px | → 420px |
| 显示 | 手机框宽高比 | Math.round 破坏 | → 不取整，精确保持 |
| 显示 | 拇指热区 Y 值 | 500/800/1100 硬编码 | → phoneH × 比例（横版不再超屏幕） |
| 显示 | 微信胶囊 | 87×32px | → `canvas_w × 23%` |
| 显示 | 触控热区 | 44px 1x | → `phoneW × 44/375` |
| 显示 | 图标按钮 | 48px 1x | → `phoneW × 48/375` |
| 显示 | Toggle 开关 | 30×16 固定 | → `phoneW × 51/375` |
| 显示 | 布局模板图标 | 22px 1x | → `phoneW × 22/375` |
| 显示 | 布局模板文字 | font-size Xpx 固定 | → `fs(X)` = X × phoneW/320 |
| 文字 | 热区标签 | 44×44 | → 动态 canvas 比例（720→84、1334→157） |
| 文字 | 图标按钮标签 | 48×48 | → 动态 canvas 比例 |
| 文字 | 开关标签 | 34×18 | → 动态 canvas 比例 |

修正原则：所有物理约束值（触控目标、设备特性、人体工效）改用画布比例计算，不再硬编码。

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：交互规范系统的 HTML 展示图里，所有元素看起来都偏小——胶囊按钮像芝麻、触控区像针尖、文字像蚂蚁。根本原因是把 iPhone 1x 逻辑分辨率（375px）的尺寸直接套到了 720 画布（约 2x）上。
- 为什么这是个问题：设计规范是拿来看的，展示图不准 = 规范无效。设计师参考了一个缩水一倍的触控标准去做 UI，做出的按钮根本点不到。
- 如果没有 AI 会怎样：需要逐行排查 1100 行渲染器代码，手工换算 375→720 的所有尺寸。至少半天。

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「我们的基准画布是 720×1280，你确定数据对吗？」—— AI 发现了 Math.round 破坏宽高比的 bug。
- AI 给了什么方案：不是头痛医头，而是建立了一套「比例驱动」的修正原则——物理约束用 `canvas_w × 比例`，展示值用 `phoneW × 比例`，文字用 `fs()`/`sp()` 辅助函数。
- 中间有什么调整：连续迭代 5 轮——胶囊→热区→触控→文字→布局模板文字，每次用户说「这个也小了」，AI 就扩展审计范围。
- 最终方案是什么：12 处修正全部统一为比例驱动，`spec-renderer.ts` 不再有裸的 1x 逻辑像素。

### 第三幕：效果展示

- 最终效果：打开 HTML，切到任何一个页签，展示图尺寸与真实手机比例一致。胶囊占屏宽 23%、触控区 12%、文字清晰可读。
- 演示方式：浏览器打开竖版/横版规范 HTML，切换 5 个页签对比
- 学到的关键点：展示系统的数值必须与画布密度挂钩。用比例公式替代硬编码，一次修正永久适配所有画布尺寸。

### 一句话总结（金句候选）

> 展示图里的每一个像素，背后都该有一个比例公式。
