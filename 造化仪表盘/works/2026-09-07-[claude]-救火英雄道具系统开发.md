## 📋 问题解决日志

### 遇到了什么

会话开始：`fire-hero-godot` 检查后继续开发。上次开发停在 09-04（v0.1.3 美术资源接入），README 下一项是「道具最小集（钱袋/长条/锤子/灭火器/1UP）」——但灭火器无「蹦床着火」来源就没有实际用途，需要产品决策。

### AI 怎么协作的

1. **检查阶段**：headless 导入 + 启动 240 帧验证无错误；顺带修正工程文档里过时的引擎路径（实为 C:\软件\ Godot 4.7.1）与 project.godot/README 版本号不一致
2. **范围决策问用户**：规则文档强调「正负道具并存是 IAA 付费设计（复活广告钩子）」，用 AskUserQuestion 确认 → 用户选 **6 种 = P0 5 种 + 火球**
3. **实现**：以 HTML 原型（`fire-hero-iaa.html` 的 maybeDropItem / applyItem / timerBoost）为数值权威逐条对齐：掉率 28%+1.5%/关、权重表、480 帧=8 秒限时、接取判定盒
4. **验证**：写临时集成冒烟场景，真实加载 main.tscn 逐种道具掉落→接取→断言（15/15 PASS，含 8 秒真实等待限时还原）；跑完删除

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

移植 HTML 玩法原型到 Godot 时，玩法「道具」迟迟没进引擎版——从零做一套掉落/接取/效果系统，正负道具博弈还是 IAA 商业设计的一环，砍了会影响复活广告钩子。

- 核心问题：Godot 版玩法系统不全（道具/角色/音效缺失）
- 为什么这是个问题：核心循环的付费设计点没落地
- 如果没有 AI 会怎样：对着 2000 行 HTML 手抄道具数值，容易漏效果或抄错权重

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「检查项目 + 继续开发」
- AI 给了什么方案：健康检查 → 列出 README 路线 → 用 HTML 原型作权威源逐条对齐（不是重新发明数值）
- 中间有什么调整/追问：灭火器无火可灭 → 追问用户把范围扩到「P0 5 种 + 火球」，一次做齐正负博弈闭环
- 最终方案是什么：item.gd 掉落物理 + GameRoot 结算，6 种效果数值与 HTML 一致；临时集成冒烟 15/15 通过后再交付

### 第三幕：效果展示

- 最终效果：灭掉火砖会掉道具，蹦床接取即生效（钱袋加币/长条加宽 8 秒/锤子收窄/1UP 升级灭火/火球把蹦床点燃、再吃丢命）
- 演示方式（截图/GIF/屏幕录制）：本机 F5 录屏待用户
- 学到的关键点：移植游戏玩法时，「上一版原型」就是需求文档——先定位权威实现，再谈新设计

### 一句话总结（金句候选）

> 移植不是重写：先找到上一版的「权威数值」，再动手。
