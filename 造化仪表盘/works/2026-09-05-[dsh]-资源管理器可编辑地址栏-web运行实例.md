# [2026-09-05] 工作台资源管理器：可编辑地址栏（运行实例 web profile）

## 📋 问题解决日志

### 遇到了什么

用户反馈工作台里配置为「资源管理器」的窗口，顶部地址"被锁死"，无法输入/修改路径。排查后确认：运行实例加载的是 **web profile** 的 dsh-worktable（官方 v0.3.1），其 `ExplorerPane` **本就没有可编辑地址栏**——顶栏只有 ⬆/↻ 加一段只读路径文本，根路径写死为会话默认目录（scope cwd），用户无法跳转任意目录。

> 此前两轮补丁失败复盘：repo / plugins-cache / desktop profile 三份是同源本地优化 0.3.0，**不是运行实例读的那份**（运行实例 = `~/.dsh/profiles/web/node_modules/dsh-worktable/lib/client.js`，官方 0.3.1，经 `/plugins/dsh-worktable/client.js` 逐字节 SHA1 比对确认）。第一版补丁还因整段替换误删 `changeBindFolder` 导致渲染崩溃、工作台消失——已用官方 tgz 还原基线后重做。

### AI 怎么协作的

1. 用官方 GitHub release v0.3.1 tgz 还原运行实例基线（SHA1 86E65092…，与最初一致），确认工作台结构恢复。
2. 用 `git diff` 约束改动范围：只动 `ExplorerPane` 内部与 `pickFolder` 内部，相邻函数一字未动，语法 `node --check` 通过。
3. 在 `ExplorerPane` 内新增：
   - `pathDraft` 可编辑状态 + `expMemKey/readMemPath/writeMemPath`（按 会话目录|行|位 记忆上次浏览目录，localStorage）；
   - `navigateTo(raw)`：回车/「前往」跳转任意绝对路径（含上一级 goUp、刷新当前目录均复用）；
   - `initRoot()`：挂载时先恢复记忆目录（向 `/api/worktable/fs` 校验仍存在，失效回退默认 cwd）；
   - 顶栏只读 span → 可编辑 `<input>`（回车提交 / Esc 还原 / 失焦空值还原）+「前往」按钮，输入框复用 DSH 主题变量内联样式。
4. 文件换行实际是 **LF**（此前 CRLF 匹配导致补丁未落盘），改按 LF 精确落盘；全程抓服务端实际提供 bundle 与磁盘 SHA1 比对，确保改动已生效。

### 产出结果

- `~/.dsh/profiles/web/node_modules/dsh-worktable/lib/client.js`：资源管理器地址栏可编辑（输入路径回车/前往跳转）+ 记忆上次目录；`pickFolder` 超时兜底应用内路径输入
- 服务端 `/plugins/dsh-worktable/client.js` 与磁盘 SHA1 一致（改动已生效）
- 生效方式：完全退出 DSH Desktop（含托盘）重新打开（桌面端 Ctrl+F5 无效）

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：资源管理器地址只读，无法跳到别的目录
- 表面认知："地址被锁死" → 实际是这份 0.3.1 根本没做地址输入框
- 附加教训：改了"看起来像"的副本（repo 本地优化版），但运行实例读的是另一份

### 第二幕：AI 怎么协作解决的

- 先抓运行实例实际提供的 client bundle，SHA1 定位真实加载文件（web profile 0.3.1）
- 用官方 tgz 还原干净基线，diff 约束只动目标函数
- 给 ExplorerPane 加 pathDraft + navigateTo + 记忆恢复，顶栏换成可编辑输入框

### 第三幕：效果展示

- 最终效果：地址栏可直接输入目录、回车/前往跳转；切窗/重开回到上次浏览目录
- 学到的关键点：**改运行中的桌面应用，先确认它加载的是哪一份 bundle**（SHA1 比对），别凭目录名猜

### 一句话总结（金句候选）

> 锁死的不是地址，是没装'输入框'的版本——先找准运行的那一份再动手。
