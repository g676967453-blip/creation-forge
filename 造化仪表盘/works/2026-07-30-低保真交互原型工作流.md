## 📋 问题解决日志

### 遇到了什么

做游戏 UI 原型时，从策划案直接跳到高保真 HTML，缺少一个低成本验证交互流的环节。一旦流程有问题，返工成本高。需要一套「低保真交互原型」方法论——在进入高保真之前，用线框图快速验证。

### AI 怎么协作的

1. **调研参考源**：搜索 GitHub 上 9 个 Claude Code 设计系统技能（garden-skills / hue / material-3-skill / nothing-design-skill 等），选定 garden-skills/web-design-engineer 的六步工作流为参考骨架。
2. **改造工作流**：将 Web 六步工作流改造为游戏专用版——5-Dial 设计审读 → 状态机+焦点导航、oklch 色彩 → 4色线框、25风格配方 → 游戏UI组件清单、反Web通用美学 → 反游戏UI 7大坑。
3. **建立技能文件**：创建 `.claude/skills/game-lo-fi-prototype/` 完整技能包（8 文件），含 SKILL.md + 4 份参考文档（视觉规范/交互规范/组件库/反模式）+ manifest.json + README。
4. **建立规范文档**：创建 `docs/specs/game-lo-fi-prototype-spec.md` 作为人类参考规范。
5. **实战验证**：用卡牌背包功能策划案走通完整六步流程——场景梳理（单弹窗叠加）→ 交互骨架（三栏布局状态机+焦点导航）→ 视觉规范（4基础色+4稀有度色）→ 线框图（01-kapai-beibao-lo-fi.html 可交互原型）→ 走查清单（2 项黄色项）。
6. **增加快速启动模式**：在完整六步之上新增 3 步快速启动模式（选平台 → 交互规则声明 → 视觉系统声明），15 分钟完成规范声明后直接画线框图。支持竖版/横版/PC/主机多平台。
7. **安全隔离**：收紧触发条件（仅「低保真原型」「lo-fi 原型」「线框图验证」三个关键词），标记 🧪 测试中，不干扰 game-ui-ux / godot-ui-control / 界面交互UI工作流。

## 🎬 视频生产草案（三幕结构）

### 第一幕：遇到了什么问题

- 核心问题：从策划案直接跳到高保真 HTML UI——做了半天发现流程不对，返工成本爆炸。
- 为什么这是个问题：没有「低保真验证」环节——跳过了设计中最便宜、最该犯错的阶段。
- 如果没有 AI 会怎样：需要手动查阅设计方法论、自己写线框规范、手绘所有布局——至少 2 天。

### 第二幕：AI 怎么协作解决的

- 我是这样问 AI 的：「帮我搜索 GitHub 关于视觉设计系统的 SKILL，只推荐不下载」→ 搜索 9 个设计系统技能。
- AI 给了什么方案：参考 garden-skills 六步工作流，改造为游戏UI专用的低保真原型方法论。
- 中间有什么调整：稀有度需要颜色（功能信息不能用线型区分）→ 在4色基础上增加4稀有度色。触发条件太宽会干扰现有工作流 → 收紧为仅3个关键词+🧪测试标记。
- 最终方案是什么：8文件技能包 + 快速启动3步模式 + 完整六步模式 + 实战验证。

### 第三幕：效果展示

- 最终效果：说出「低保真原型」→ AI 自动走六步流程 → 产出可点击的线框图 HTML。
- 演示方式：在浏览器中打开 `01-kapai-beibao-lo-fi.html`，展示筛选/选择/详情交互。
- 学到的关键点：设计流程中最便宜的错误阶段是低保真——线框改一笔 vs 高保真改整个 HTML。AI 同时是方法论参谋（搜索+改造 garden-skills）和加速器（直接生成线框图）。

### 一句话总结（金句候选）

> 在便宜的阶段犯错——用线框图验证交互流，而不是用高保真。
