# [2026-09-04] 五板块拆分重构 B0–B5 完成（feature: refactor/zaohua-board-split）

## 📋 问题解决日志

### 遇到了什么

单 git 仓库（remote: creation-forge）内五大职能混居：仪表盘工具链在根 `tools/`、日志在根 `works/`、管理数据（目标规划/个人待办）与知识库 `docs/` 物理混叠、美术管线与自媒体埋在 `projects/` 深处。需要重构为**五板块自治 + 平台共享层**，并借机把仪表盘从「单页 7 页签」升级为「五板块总览 + git 变动监控」，同时让 GH Pages 部署链路（每小时 cron）不吃到中间态坏页面。

### AI 怎么协作的

先产出一份完整批次计划（B0→B5，每批一次中文 conventional commit、单 feature 分支、全部完成后才合并 main），用户批准后逐批执行。过程中的关键判断：

- **物理 move 而非 `git mv`**：`mv` + `git add -A` 让 git 自动识别 rename，且不会漏掉被 .gitignore 命中的文件（asset-pipeline 有 ~16MB 桌面产出段）
- **中文 pathspec 转码坑**：Windows cmd 继承下 `execSync` 字符串形式会把中文 argv 变乱码 → 板块统计一律 `execFileSync("git", [...args])` 直传 wide-char
- **git rename 不回溯历史**：板块 git 统计必须带 `legacyPaths` 别名并集（b1 的 works/reports/旧 tools 路径等）才能还原完整历史
- **CI 自包含**：仓库根无 package.json → workflow 移除 `npm install`，改 `npx --yes tsx` 在线取 tsx
- **数据单向下沉**：板块间只经显式相对链接引用；板块1 是唯一工作日志/待办/目标区
